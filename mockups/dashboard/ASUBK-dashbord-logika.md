## 1. Рамка

**Дашборд показывает** — седьмой модуль, его глагол «показывает» (`ADR-0212`). Он не считает (это статистика), не
выпускает документов (отчётность) и не поручает работы (задания). Экран — мебель: своей даты и своего паспорта у
него нет, паспорт у каждой плитки (`ИО-15`).

Дашборд отвечает на два вопроса: **«как у нас дела?»** — обзорные плитки — и **«сколько ждёт меня?»** — ссылочные
плитки (`ДБ-7`). Это главная страница после входа у всех (`ДБ-8`) и для всех внутренних ролей (`ДБ-9`). Внешних
пользователей у дашборда нет.

Вопрос обзорной плитки дашборд не держит: он живёт в отчёте отчётности, плитка на него ссылается и решает, что из
ответа и как показать (`ДБ-99`, `ADR-0286`). Отчётность объявляет вопрос, дашборд его показывает — глаголы не
смешиваются.

Отвергнутые рамки: дашборд как раздел отчётности (`ADR-0212`: раскладки, роли и показ — свои) или статистики
(`ADR-0212`); плитка со своим вопросом рядом с отчётом (`ДБ-1`, переигран `ДБ-99`: два записанных вопроса
расходятся); дашборд как рабочий стол со списками дел и кнопками (`ДБ-7`: второй список дел рядом с заданиями);
дашборд только для руководства (`ДБ-9`).

## 2. Сущности

| сущность | что это | хранит |
|---|---|---|
| **Плитка** | ссылка на отчёт или вид и способ показать его ответ (`ДБ-99`, `ДБ-100`) | отчёт или вид · значения его объявленных параметров (с относительными: «я», «сегодня») · главное и второе число из ответа (`ДБ-116`) · база сдвига; ряд — тот же отчёт на других датах (`ДБ-107`) · умолчания пяти видов (`ДБ-127`) · светофор · подпись · версия |
| **Обзорная плитка** | плитка, отвечающая «как дела» | главный клик — провал отчёта по узлу (`ДБ-105`) |
| **Ссылочная плитка** | плитка, отвечающая «сколько ждёт меня» | вопрос и адрес объявляет модуль-владелец очереди (`ДБ-108`) |
| **Каталожная плитка** | плитка, опубликованная администратором дашборда | + состояние: черновик → опубликована → снята; отчёт — общий или официальный |
| **Личная плитка** | плитка, поставленная пользователем для себя | на любой открытый ему отчёт или вид; стоит только в его раскладках; в каталог — через администратора |
| **Объявленная раскладка** | стартовый набор плиток роли | одна на роль на всю систему; порядок, секции |
| **Личная перекладка** | раскладка пользователя поверх объявленной | порядок, скрытые, добавленные, секции; хранится отдельно |
| **Память видов** | выбор человека внутри видов плитки (`ДБ-121`) | человек × плитка: вид → разрез, пара разрезов, длина ряда, колонки таблицы |
| **Свой экран** | именованный экран пользователя (до 5) | набор плиток · порядок · секции · сохранённый фильтр панели · плитки, закреплённые раскрытыми, и их вид (`ДБ-122`) |
| **Секция** | именованный разделитель в раскладке | имя · свёрнута ли; своей даты, фильтра и чисел нет |
| **Журнал** | изменения и выгрузки поимённо, просмотры счётчиками | см. §14 |

Ни одна сущность не хранит чисел (`ИДБ-2`). Технический кэш — §14. Подписки своей у дашборда нет: 🔔 на плитке
ставит сигнал отчётности (`ДБ-106`, §11.3).

**Очередь модуля** — именованный отбор реестра модуля-владельца, который модуль объявляет сам: «Ждут моего голоса»,
«Невыясненные поступления». Ссылочная плитка ведёт в очередь; её фильтр по смыслу совпадает с вопросом плитки, и за
это отвечает модуль. Это не «рабочий список» отчётности (замороженный состав выпуска).

## 3. Плитка — ссылка на отчёт

1. **Вопрос живёт в отчёте** (`ДБ-99`, `ДБ-100`, `ADR-0286`, `ИДБ-3`; переигрывает `ДБ-1`). Объект, показатели,
   разрезы, фильтр и параметры объявляет отчёт или вид отчётности. Правка отчёта доходит до всех плиток, которые на
   него ссылаются, — плитка и открытый отчёт не расходятся. Своего фильтра, разреза или показателя у плитки нет; к
   ссылке она добавляет только то, что отчёт объявил местом для потребителя:
   - **значения параметров** — как у выпуска: шаблон объявляет параметр, потребитель даёт значение (канон отчётности
     §3 п. 5). Один отчёт «Просрочка по срокам» — плитка Куратора (куратор = я) и плитка Руководства (куратор =
     все);
   - **выбор из ответа** — главное и второе число (`ДБ-116`) и умолчания пяти видов: разрез, пара разрезов, длина
     ряда, колонки таблицы (`ДБ-127`);
   - **показ** — светофор, подпись (§5).

   Перегруппировка в полосе — на время просмотра (`ДБ-126`): объект, показатели, фильтр и параметры остаются
   отчёта, меняется только раскладка строк.
2. **Собрать плитку** (`ДБ-103`). «+ Плитка» на дашборде: выбрать готовый отчёт из доступных или «Собрать» —
   открывается конструктор отчётности поверх дашборда (он же предупреждает «похожий уже есть», `ОГ-22`).
   «Сохранить и поставить» создаёт личный отчёт на полке автора и плитку на него. Из любого отчёта или вида —
   «📌 на дашборд». Своего конструктора вопроса у дашборда нет (`ADR-0232`); своих показателей и разрезов дашборд
   не заводит (`ADR-0150` §5).
3. **Каждое число — от статистики, через отчёт** (`ДБ-11`, `ИДБ-7`). Отчёт берёт число на дату только у
   статистики (`ИО-35`, `ИС-51`, `ADR-0222`); плитка — только у отчёта. Ссылочные плитки («Мои задания» — объект
   статистики «Задание») спрашивают вопрос, объявленный владельцем очереди (`ДБ-108`, `ADR-0291`).
4. **Внешние данные — только через модуль-владельца** (`ДБ-10`, `ADR-0288`). API, Excel и чужие базы входят в
   систему импортом своего модуля (план — справочник плановых показателей, курсы — в справочник), оттуда идут в
   статистику, а из неё — в отчёт и плитку. Поля «источник: API / файл» нет ни у отчёта, ни у плитки.
5. **Один объект, до четырёх показателей** (`ДБ-18`, `ИДБ-8`). Таблица — до четырёх колонок, основа — главное и второе число.
   Строки у колонок общие, поэтому клик однозначен и паспорт один. Разные объекты — разные отчёты и разные плитки
   («Кредитов» и «Заёмщиков» — две плитки). **«📌» проверяет пригодность** (`ДБ-109`, по умолчанию): выбрано до
   четырёх колонок одного рода (`ДБ-92`); виды, которым нечего показать, гаснут сами (`ДБ-119`); даты — по §4. Основной объект у отчёта один, поэтому правило выполняется
   само.
6. **Относительные значения параметров** (`ДБ-28`, `ДБ-58`, `ДБ-101`): «я», «моё подразделение», «моё
   подразделение и ниже», «сегодня ± N дней» (для полей-дат: «срок ≤ сегодня + 7»), календарные периоды. Это
   значения, которые параметр отчёта принимает и подставляет по смотрящему при каждом показе. Одна каталожная плитка
   «Мои кредиты» работает у каждого куратора. Охват режет сверху: значение сужает, но не расширяет (`ИДБ-12`).
   Заявка отчётности: сейчас значения параметра отбора у неё только конкретные.
7. **Версия** (`ДБ-55`, `ДБ-113`, по умолчанию): правка значений параметров, выбора из ответа, умолчаний видов, светофора или
   подписи — новая версия той же плитки, она меняется у всех. Правка вопроса — версия отчёта (`ИО-41`), плитка
   показывает отметку «отчёт изменён» (`ДБ-110`). Другой отчёт — новая плитка.
8. **Объекты плиток — 17** (`ДБ-11`, `ДБ-60`…`ДБ-64`). С `ДБ-114` это объекты отчётов каталога: решения о составе
   плиток (здесь, п. 9–11 и §13) — требования к общим отчётам, на которые ссылаются каталожные плитки; один отчёт
   кормит несколько плиток. Отчёты каталога собирает администратор дашборда и становится их владельцем (`ADR-0279`
   п. 6). Объект попадает на дашборд, когда статистика его объявила и
   у роли есть вопрос, на который другие объекты не отвечают: плитка держит один объект (`ИДБ-8`), числа другого к
   ней не добавить. Волна — когда плитки объекта могут встать в раскладку (§14.3).

   |---|---|---|
   | Кредит | Кредиты | 1 |
   | Заёмщик | Заёмщики | 1 |
   | Кредитная программа | Кредитные программы | 1 |
   | Требование взыскания | Взыскание | 1 |

   Не берутся (`ДБ-64`): расчёт реструктуризации, залоговый договор, член группы совместного риска, предложение
   имущества; сотрудник и документ — позже.

   **Разрезы объекта — все разрезы его записи в реестре статистики** (`ДБ-66`). Дашборд их не отбирает: что
   статистика объявила, то и предлагает конструктор отчётности. У заёмщика их 16 и 10 слотов классификаторов администратора
   (схема статистики §2.2). Свёрнутые по портфелю — худшая категория, худшая просрочка (ступени), подгруппа —
   единственны на дату, поэтому клиент с тремя кредитами попадает в один столбец, по худшему. Макет показывает
   выборку — разрезы, которые отвечают иначе, чем у кредита: у заёмщика это территория заёмщика (регистрация лица,
   не территория выдачи кредита), подразделение и ведущий куратор, худшая категория, худшая просрочка по портфелю,
   подгруппа платёжеспособности, тип лица, отрасль заёмщика; с `ДБ-81` — ещё состояние портфеля, состояние лица,
   валюта портфеля, дата первого договора (когорта) и чёрный список, всего 13.
9. **Фильтр — часть вопроса, а не показатель** (`ДБ-68`…`ДБ-70`, `ADR-0289`; с `ДБ-111` — фильтр отчёта). Счёта
   «с фильтром» в реестре нет: агрегат — функция из закрытого списка, без фильтров. «Требований открыто»,
   «Невыясненные» — показатель реестра плюс фильтр **отчёта**, на который ссылается плитка; своих именованных счётов
   дашборд не заводит, у статистики их не просит. Плитка печатает фильтр отчёта, а не свой.

   **Доля, где числитель отличается от знаменателя только условием** («Заёмщиков с просрочкой» из «Заёмщиков»),
   собирается в отчёте разрезом-корзиной («договоров с просрочкой: 0 · больше 0») и встроенным расчётом «% от итога
   группы» (`ADR-0281` п. 1); плитка берёт ячейку «больше 0». Фильтр числителя плитки (`ДБ-70`, `ADR-0289`) переигран
   `ДБ-111`.

   **«Действующие» по умолчанию** (`ДБ-68`, `ДБ-69`, `ДБ-94`) — заявка конструктору отчётности (`ДБ-111`). Строки
   заёмщика, кредита и программы живут после закрытия всегда. Выбран такой объект — конструктор отчёта сам ставит
   фильтр «действующие» (у заёмщика — «состояние портфеля = действующий») у остатков и счёта, а у потоков — нет:
   поток с ним теряет последний платёж закрытого в периоде договора (`ДБ-Д24`). Фильтр снимается или меняется на
   «погасившие» (ТЗ `:679` — оба счёта); подсказка без него: «складывает действующих и погасивших».
10. **Заёмщик — клиент и признаки лица** (`ДБ-67`). Объект отвечает о том, на что кредит не отвечает: сколько
   клиентов, каких, и сколько денег на клиентах того или иного признака лица (отрасль лица, тип лица, худшая
   категория клиента). Итог денег портфеля — у кредита.
   - **Показатели — все записи реестра** (`ДБ-67`, как разрезы `ДБ-66`): счёт, деньги портфеля, дни (худшая
     просрочка, до ближайшего платежа, стаж). Деньги заёмщика без разреза лица собрать можно, но конструктор
     отчётности подсказывает (заявка отчётности, `ДБ-111`): «итог денег — у объекта Кредит; у заёмщика охват по ведущему куратору» — у куратора клиент с
     кредитами двух кураторов уходит к ведущему, и «Задолженность» по заёмщику и по кредиту расходятся. В стартовых
     раскладках денег заёмщика нет.
   - **Движение клиентов** (`ДБ-71`; с `ДБ-181` — переходами, §5.12): вид «Движение» для счёта заёмщиков —
     начало (действующих) → + новые (строки заёмщика на базе не было) → + вернулись (на базе «весь портфель
     погашен», сегодня «действующий») → − погасили всё (наоборот) → − прочее (смерть, ликвидация, перевод долга —
     старше «погасили всё») → пришли / ушли из охвата (сменился ведущий куратор) → конец. Считается по состоянию
     портфеля `d_pstate` на двух датах; даты погашения всего портфеля, корзины «месяц» у первого договора и потоков
     счёта от статистики не нужно — плитки больше не черновики.
   - **Виды** (`ДБ-77`, по умолчанию; с `ДБ-118` — пять видов плитки): все пять. Разрез в своём порядке (бывшие «ступени», `ДБ-150`) — у худшей
     просрочки по портфелю, худшей категории, подгруппы. «Движение» — у счёта клиентов и у денежных потоков портфеля (нарастающим итогом, как у кредита).
   - **Сдвиг счёта клиентов** (`ДБ-78`, по умолчанию) — как у остатков (§5.3).
   - **«Работать со списком»** (`ДБ-79`, по умолчанию) — реестр заёмщиков модуля «Заёмщик» с фильтром плитки.
   - **Подпись куратора** (`ДБ-75`, по умолчанию): плитки на объекте «Заёмщик» с «я» печатают «клиенты, где вы
     ведущий куратор» — счёт заёмщиков и счёт кредитов у куратора законно расходятся (`ДБ-Д20`).
   - **Три ступени, заявленные статистике** — корзины над числами строки заёмщика, как у худшей просрочки:
     **совокупный долг клиента** до 1 · 1–10 · 10–50 · 50+ млн (черта 50 млн — п. 11 пп. 2 Порядка: анализ
     финансово-хозяйственного состояния обязателен при задолженности заёмщика больше 50 000 000 сомов; `ДБ-82`);
     **договоров у клиента за всё время** 1 · 2 · 3+ — повторные клиенты (`ДБ-83`); **кредитная история** —
     худшая просрочка за всю историю: без просрочек · 1–30 · 31–90 · 91+, ступень 91+ совпадает с порогом проверки
     карточки «Кредитная история» (`ДБ-84`).
   - **Две проверки карточки — в статистику** (`ДБ-86`): число обязательств Порядка со сроком «вышел» (пакет
     финансовых документов, анализ ФХД, вынос долга на комитет) и «нет действующего канала связи». Остальные
     проверки карточки либо уже покрыты (состояние лица, чёрный список, кредитная история, суды — дело взыскания),
     либо узки.
   - **Не берутся:** средний долг на клиента — при сосредоточенном долге не описывает типичного клиента, отвечают
     ступени размера (`ДБ-85`); группы совместного риска — клиент бывает в нескольких, `ДБ-64` в силе (`ДБ-87`).

11. **Кредитная программа — состав и состояние, деньги у кредита** (`ДБ-89`…`ДБ-97`). Объект отвечает: состав и состояние программ: сколько действует, из каких источников,
    какие скоро кончаются. Деньги программы — срез **кредита** по разрезу «Программа» (СС-114), мер у программы нет.
    Показатель — счёт «Программ», по умолчанию с фильтром «действующие» (`ДБ-94`). Разрезы — девять записей реестра:
    состояние, источник финансирования, линия кредитования, валюта, вид кредита, назначение, решение правительства,
    отрасль, дата начала; дата окончания — заявка статистике (`ДБ-93`, `ДБ-96`). **Лимита программы нет** ни у
    одного владельца (`ADR-0244` §4); цель «сверху» — план из справочника плановых показателей (`ADR-0288`), плитка
    освоения плана встанет вместе с ним (`ДБ-90`, переигрывает `ДБ-23`). Кредит берёт у своей программы источник
    финансирования и линию — разрезами через ключ программы (`ДБ-97`, заявка статистике). В таблице и числе —
    показатели одного рода: у плитки одна дата или один период (`ДБ-92`).

## 4. Время

**Дата — параметр отчёта; сдвиг и ряд — тот же отчёт на других датах** (`ДБ-107`). Отчёт объявляет параметр даты
или периода, плитка даёт ему значение. Сдвиг на основе плитки спрашивает тот же отчёт ещё и на базе сдвига (§5.3), вид «Ряд» —
на 6/12/24 концах месяцев или кварталов (`statSeries`). Объявленные колонки-даты отчёта (`ОГ-35`) плитка может просто
выбрать. Отчёт без параметра даты (официальная форма на 1 января) плитка не перекраивает. Правила ниже — какие
значения плитка даёт.

1. **Режим даты по умолчанию — «сегодня»** (`ДБ-12`): строка сегодняшнего дня статистики, паспорт «на 14:15 · день
   не закрыт». Значением параметра можно выбрать «последний закрытый день» или «конец прошлого месяца» — для
   официальных цифр. Оба режима — ответы одной статистики (`ADR-0264`).
2. **Обновление** (`ДБ-13`): при открытии, по кнопке «Обновить» и тихо раз в 5 минут — только плитки «сегодня»
   и только пока вкладка видна. Плитки на закрытую дату не перезапрашиваются. Весь экран обновляется одним пакетным
   запросом (`ADR-0191`).
3. **Общей даты у экрана нет** (`ДБ-14`): «машины времени» нет. Прошлое показывают ряд, сдвиг, отчётность и анализ.
4. **Периоды потоков — только календарные** (`ДБ-15`): сегодня · текущий месяц · прошлый месяц · текущий квартал ·
   прошлый квартал · с начала года · прошлый год. Скользящих окон и фиксированных дат нет: закрытый месяц хранит
   только последний день (`ADR-0264` §8), и окно «30 дней» в начале месяца отказывало бы. Период «сегодня» работает
   всегда: база — вчерашняя строка, а последний день месяца хранится.
5. **Начало месяца — честно** (`ДБ-16`): период не подменяется. Подпись сама называет месяц и день: «за октябрь ·
   идёт 1-й день». При выборе «текущий месяц» дашборд подсказывает поставить рядом плитку на «прошлый месяц».

## 5. Основа, виды и показ

1. **Одна основа и пять видов** (`ДБ-115`, `ДБ-116`, `ДБ-118`, `ДБ-119`; переигрывают восемь форматов `ДБ-17`;
   основа — по `ДБ-130`…`ДБ-145`, `ADR-0294`). **Основа** — у всех плиток, размер 1×1, высота по содержимому, до
   145 px (`ДБ-163`; переигрывает `ДБ-130`), три строки:

   ```
   Просрочено · действующие                 ☰ ⋯    ← название и уточнение; значки — при наведении
   179 млн  ▲ 7,4 млн к 30.09                      ← главное число и сдвиг
   [4,6 %] портфеля · > 4 %                        ← второе число; плашка светофора и граница порога
   ```

   **Второе число** — любой показатель того же объекта на ту же дату: доля, «из N» или другой показатель
   («3 861 млн · 1 241 кредит»). Светофор можно повесить на него; сдвиг — по главному. Мини-ряда и кнопок видов на
   плитке нет (`ДБ-130`, `ДБ-132`): ряд — вид «Ряд», кнопки — в шапке полосы (§5.8). Целиком на 1920 × 1080 у
   Руководства видно 12 плиток из 12, у куратора кредита — 11 из 13 (`ДБ-163`; переигрывает `ДБ-130`).

   | элемент | как выглядит |
   |---|---|
   | название | подпись 13,5 px · 500, второй тон текста — темнее уточнения, не больше двух строк, целиком — при наведении; при наведении синяя, подчёркнутая, с «↗» — ссылка на отчёт (`ДБ-136`; кегль и цвет — `ДБ-162`, переигрывает `ДБ-136`) |
   | очередь | у ссылочной плитки строкой над названием — синяя ссылка 12 px «Ждёт меня · Задания», с прописной первой буквы, не заглавными (`ДБ-162`) |
   | уточнение | 12,5 px, серое (`ДБ-162`), в строке названия через «·»; дата, выбранная автором, — тут же: «· действующие · на 30.09» (`ДБ-131`) |
   | метка отличия | пилюля за названием, когда паспорт отличается от обычного (§5.11) |
   | сигнал | маленький синий колокольчик за названием, пока сигнал включён (§11.3, `ДБ-135`) |
   | главное число | 30 px · 600 · тёмное, плотнее (−0,022 em); единица («млн», «тыс.», «%») — 15 px · 500 · серая (`ДБ-161`; переигрывает `ДБ-138`); суммы — §5.7 |
   | сдвиг | в строке с числом, 13 px, серый, цветная только стрелка; не влез — переносится (§5.3, §5.5) |
   | второе число | 13 px: значение 600 тёмное, подпись обычная (`ДБ-142`) |
   | светофор | плашка на оцениваемом числе и граница порога рядом (§5.5) |
   | «☰», «⋯» | при наведении поверх правого края шапки, одноцветные, название не сдвигают; на телефоне — §9.6 (`ДБ-135`) |

   **Показ решает автор плитки** (`ДБ-141`): второе число, сдвиг и его база, светофор (на каком числе, показывать ли
   зелёный) — часть версии плитки, у всех смотрящих одинаковы. Не скрываются никогда: название, уточнение, главное
   число, метки отличий. Смотрящий может скрыть плитку у себя или поставить свою плитку на тот же отчёт («📌»).

   Шесть видов открываются в полосе (§5.8): пять — кнопками в строке полосы, Когорты — из «⋯» (`ДБ-225`, `ДБ-232`).
   **Кнопку получает вид с новым вопросом** (`ДБ-222`, `ИДБ-20`): он отвечает на то, на что другие виды не отвечают,
   строится из ответа отчёта и работает на любом уровне глубже с «☰ N»; итог и разница — где сумма строк и база
   что-то значат (у Когорт итога нет, `ДБ-225`). Тот же вопрос другим рисунком — **режим** существующего вида (ниже):

   | вид | отвечает | что показывает |
   |---|---|---|
   | Ряд | когда | столбцы с суммой над каждым: шаг — месяц или квартал, 6/12/24 точки, последняя точка — дата среза; под точкой — разница к прошлой (§5.13) |
   | Разрез | где, у кого | строки «название · сумма · разница · ☰ · полоса» по всем значениям списка разреза, «пусто» — последним (§5.12); топ-N + «ещё N», итог — сумма строк; вид «доли»; разрез с объявленным порядком — те же строки в своём порядке |
   | Карта | где и насколько | матрица двух разрезов с итогами строк и столбцов, цвет — величина или разница |
   | Движение | почему изменилось | начало → переходы объектов полосами от нуля → конец: каждый объект сравнивается с собой на двух датах и стоит ровно в одной строке; у Остатка и Нераспределённого изменение у прежних — денежными потоками, «прочее» — настоящий остаток (§5.12, `ДБ-176`, `ДБ-181`) |
   | Таблица | все числа | разрез в строках, до 4 показателей в колонках; первая — показатель плитки |
   | Когорты | какие выдачи хуже | строки — период начала (квартал, месяц), колонки — месяцев с начала, в ячейке — показатель плитки цветом; итогов нет; у объектов с датой начала — кредит, заёмщик, дело взыскания, заявка (§5.12, `ДБ-225`) |

   **Режимы видов** (`ДБ-223`, `ДБ-224`, `ДБ-226`…`ДБ-228`, `ADR-0308`) — другой рисунок того же вопроса, без своей
   кнопки:

   | режим | вид | когда | что показывает |
   |---|---|---|---|
   | доли | Разрез | по выбору | доля строки в итоге (`ДБ-118`) |
   | Переходы | Карта | оси «значение на дату базы × сегодня» у разреза со значением на базу | матрица миграции: правее диагонали — хуже, левее — лучше (`ДБ-223`) |
   | план-факт | Разрез | сам, когда второе число плитки — доля к показателю рода «план» | факт, метка плана, процент исполнения, недобор (`ДБ-224`) |
   | воронкой | Разрез | сам, у разреза, объявленного продвижением по этапам («докуда дошла») | «дошли до этапа» нарастающим итогом, процент перехода, потери с причиной (`ДБ-226`) |
   | по разрезу | Ряд | по выбору «итог \| по разрезу ▾» | строка — мини-ряд значения разреза на одной шкале (`ДБ-227`) |
   | «крупнейшие» | Разрез | выбор разреза «крупнейшие» | первые N объектов по показателю и «остальные N» одной строкой, накопленная доля (`ДБ-228`) |

   Как рисуется каждый вид и режим — §5.12, разница и «Сумма | Изменение» — §5.13. Круговой нет: доли честнее
   показывает Разрез с режимом «доли». Не берутся и каскад (`ДБ-155`), календарь по дням (закрытый месяц хранит
   последний день, `ADR-0264` §8), спидометр, дерево-прямоугольники, Sankey (`ДБ-231`). Точечная — позже, режимом
   Таблицы «две колонки — осями», когда у плитки роли появится разрез на десятки значений (`ДБ-230`). Географической
   карты нет — Разрез по области точнее; позиция проекта на подтверждение заказчику (`ДБ-229`). Кнопка вида, которому
   нечего показать, стоит в шапке
   полосы на своём месте погашенной, причина — при наведении: «Движение недоступно: у счёта программ нет оборотов» (`ДБ-119`); так же пункт
   «Когорты» в «⋯». Карта
   нужна двум разрезам, Движение — потоки у показателя, Ряд — параметр даты у отчёта, Когорты — дата начала у объекта. У ссылочных плиток та же основа и те же виды, разрезы — у вопроса владельца очереди (`ДБ-120`).
2. **Доля — способ показа, а не показатель** (`ДБ-19`, `ИДБ-8`). Числитель и знаменатель — показатели одного
   объекта. Плитка печатает процент и под ним оба числа: «5,7 % · 184 из 3 213 млн». Изменение доли — в п.п. Доля
   между объектами запрещена. Доля бывает двух видов: **две колонки отчёта** («просрочено / остаток», своя формула
   отчёта или два показателя) или **«% от итога группы»** — строка разреза-корзины к итогу (`ДБ-111`, §3.9;
   переигрывает фильтр числителя `ДБ-70`, `ADR-0289`): «Заёмщиков с просрочкой · 412 из 903» = отчёт по заёмщикам
   (фильтр «действующие») · разрез «договоров с просрочкой: 0 · больше 0» · ячейка «больше 0». Провал числителя —
   провал этой ячейки. `ИС-32` не меняется. Цвет стрелки сдвига доли — по направлению **числителя** в реестре: рост доли просрочки красный, рост доли
   поступлений зелёный (`ДБ-Д15`). У доли обоих видов «☰» узла в строке полосы печатает числитель и группу, как
   второе число плитки: «☰ 412 из 903»; клик открывает числитель — «кто в этом числе». Итог в теле полосы — сумма
   строк, у разреза по полю числителя это вся группа: «☰ 903» (`ДБ-174`, уточняет `ДБ-149`).
3. **Сдвиг — из закрытого списка баз** (`ДБ-21`, `ИДБ-11`). У остатков: к концу прошлого месяца, к началу года, к
   концу того же месяца прошлого года. У потоков: только законченный период к предыдущему такому же (м/м, кв/кв,
   г/г). У потока за неполный период сдвиг погашен с причиной «неполный период не с чем честно сравнить». Текущий
   месяц сравнивается с **планом этого месяца** (прогресс к цели), а не сдвигом.

   **Формат** (`ДБ-140`): в единицах главного числа с базой — «▲ 7,4 млн к 30.09», «▲ 2 к 30.09», у доли «▼ 0,4 п.п.
   к 30.09». Процент изменения — при наведении и в полосе. На месте погашенного сдвига — серое «без сдвига»,
   причина — при наведении; у текущего месяца — прогресс к плану «412 из 500 млн по плану» (`ДБ-143`, уточняет
   `ДБ-129`). Автор не поставил сдвиг — место пусто.

   **В полосе — та же база и те же запреты** (`ДБ-159`, `ДБ-160`). Разница в строках, ячейках и итогах (§5.13)
   считается к базе сдвига плитки, в Ряде — к прошлой точке. Незакрытый период потока не сравнивается и там: под
   незакрытым месяцем — «без сдвига» или прогресс к плану, «Изменение» погашено с причиной «неполный месяц не с чем
   сравнить». Нет базы у плитки — «Изменение» погашено так же. У одного числа на плитке и в полосе — один сдвиг.
4. **План-факт** (`ДБ-22`, `ДБ-23`): «ожидалось по графику» (показатель кредита), «План» и «Исполнение плана»
   (`CONTEXT.md`) — показатели статистики. Цель «сверху» — план из справочника плановых показателей (`ADR-0288`); лимита программы нет (`ДБ-90`,
   переигрывает `ДБ-23`). На плитке — доля:
   «96 из 104 по графику · 92 %», «выдано 412 из 500 млн по плану». Отдельного «целевого показателя» нет.
5. **Цвет** (`ДБ-24`; уточнён `ДБ-133`, `ДБ-134`, `ДБ-139`). У сдвига цветная только стрелка ▲▼ — по направлению
   показателя в реестре (рост просрочки — красный), у нейтральных серая; сумма и база серые. Светофор (зелёный /
   жёлтый / красный по значению) задаёт автор плитки: мягкая плашка под оцениваемым числом, главным или вторым.
   Полосы по краю и точки нет — края плитки нейтральны и не путаются с жёлтой рамкой «устарело». Зелёный — по
   выбору автора. Рядом с окрашенным числом 12 px серым печатается граница, давшая цвет: «4,6 % портфеля · > 4 %»,
   «3 просрочено · > 0»; у главного числа — в конце строки со сдвигом. Полный порог — при наведении на плашку и на
   число узла полосы (`ДБ-146`). Порог — это настройка, а не число данных. Нормативные пороги («обеспеченность ниже 120 %», «181+ дней») — фильтр вопроса, а
   не цвет.
6. **Наведение** (`ДБ-20`; «Развернуть ⤢» снят `ДБ-117`). Над любой точкой, полосой или ячейкой — подсказка:
   значение, доля, дата, закрытие. На плитке: над числом — паспорт, над сдвигом — процент изменения, над плашкой —
   полный порог, над меткой — её текст, над обрезанным названием — название целиком (`ДБ-131`, `ДБ-134`, `ДБ-136`,
   `ДБ-140`). В полосе над числом узла — паспорт, порог и всё, что ушло из строки (`ДБ-146`); над разницей —
   процент (`ДБ-152`); над ячейкой Карты и месяцем Ряда — «☰ N» (`ДБ-149`). Масштаб и смену разреза дают полоса
   (§5.8) и путь вглубь (§5.9). Зума внутри плитки нет.
7. **Валюта** (`ДБ-59`, по умолчанию): суммы в сомах по курсу на дату паспорта (`ИС-44`). «В валюте договора» —
   отдельный показатель. **Единицы** (`ДБ-137`): не выше «млн» — от 100 млн целыми с разрядами («3 861 млн»), от 1
   до 100 млн с одним знаком («64,2 млн»), меньше 1 млн — «тыс.» («61 тыс.»). «Млрд» на плитке нет: одно правило у
   всех плиток, без настройки. Счётчики и доли — как есть.
8. **Полоса** (`ДБ-117`, `ДБ-121`, `ДБ-122`, `ДБ-126`…`ДБ-128`; вид — `ДБ-146`…`ДБ-148`). Вид открывается полосой под
   рядом плиток, на всю ширину, со стрелкой к своей плитке; одна раскрытая плитка на ряд, ряды ниже сдвигаются
   целиком. **Полоса белая, без карточки внутри** (`ДБ-147`): серая рамка и стрелка, одна тонкая линия отделяет
   строку от графика; синяя рамка — только у открытой плитки. **Высота — по содержимому, до 520 px** (`ДБ-164`;
   переигрывает `ДБ-148`): длиннее — прокрутка внутри, строка остаётся; при смене вида верх стоит, ряд ниже
   сдвигается. С потолком плитка и полоса помещаются на 1920 × 1080 под первым рядом (655 px).

   **Строка полосы** (`ДБ-146`) — одна, над графиком:

   ```
   Просрочено › Ошская  29,2 млн  ▲ 1,2 млн · +4,3 % к 30.09  [Программа ▾]   на 14:15 · … · видно 2 149
                                         [Ряд|Разрез|Карта|Движение|Таблица]  [☰ 50] [Работать со списком] ⋯ ✕
   ```

   | всегда | пока есть место | уходит первым → последним |
   |---|---|---|
   | путь крошками (он же заголовок), число узла, выбор разреза без подписи, пять видов словами, «☰ N», «⋯», «✕» | сдвиг узла с процентом, «Работать со списком», паспорт | паспорт → кнопка (в «⋯») → сдвиг → середина пути «…» |

   Уходит по ширине строки: экран и длина пути. Ушедшее — при наведении на число узла или в «⋯»; порог — при
   наведении; отличие паспорта — меткой (§5.11). На 1920 (строка 1 574 px, `ДБ-165`) в частом случае видно всё. В
   строке кнопки пяти видов и выбор разреза: сверху разрезы, объявленные отчётом, ниже — остальные разрезы объекта из
   реестра статистики (`ДБ-66`). Перегруппировка — на время просмотра, паспорт полосы печатает «разрез на время
   просмотра»; чтобы вид остался, его сохраняют отчётом (📌). Показатели в Таблице — так же: объявленные отчётом
   сверху, до четырёх колонок одного рода. **Умолчание** каждого вида — разрез, пара разрезов, длина ряда, колонки —
   задаёт автор плитки; не задал — первые разрезы отчёта (`ДБ-127`). **Память:** выбор человека внутри вида
   помнится у него; раскрытие — нет, утром главная закрыта (`ДБ-121`). Закрепить плитку раскрытой можно только на
   своём экране (`ДБ-122`, §9.3). На телефоне полоса — под плиткой, в одну колонку.

   **Когорты — пунктом «⋯»** (`ДБ-232`, уточняет `ДБ-225`): шестой вид кнопки в строке не получает, пять кнопок
   остаются. Где нечего показать — пункт погашен с причиной («у залога нет даты начала»); открытые Когорты стоят
   нажатой пилюлей сразу за пятью кнопками, клик по любой из пяти возвращает (по умолчанию). Выбор режима — в теле
   полосы над графиком, рядом с «Сумма | Изменение»: оси Карты, «итог | по разрезу» у Ряда, разрез «крупнейшие» — в
   выборе разреза; план-факт и воронка включаются сами (`ДБ-233`, по умолчанию).
9. **Глубже** (`ДБ-123`, `ДБ-129`). В полосе клик по строке или ячейке сужает полосу до неё и предлагает
   следующий разрез; путь печатается крошками «Просрочено › Ошская › 181+», по ним — назад. Все пять видов работают
   на любом уровне. «☰ N» у строки — «кто в этом числе» (§6): в Разрезе, Таблице и Движении — тихой колонкой
   всегда, в Карте — в углу ячейки, в Ряде — под месяцем, оба при наведении (`ДБ-149`). Разрезы объекта кончились — клик открывает
   список. Путь крошек — фильтр на время просмотра: его несут список и «работать со списком»; панель фильтров
   (§7.3) действует и в полосе.
10. **Слияние** (`ДБ-125`, `ИДБ-15`). Одна плитка — один главный показатель. Плитки, которые отличаются только видом
    — форматом, разрезом, длиной ряда, долей к итогу, — сливаются в одну, их настройки становятся умолчаниями видов.
    Другой показатель, фильтр или период — другая плитка или второе число той же. Раскладки §13 собраны так.
11. **Паспорт — подсказкой, отличия — меткой** (`ДБ-131`; `ИО-15` в силе — паспорт у плитки, а не у экрана).
    Обычный паспорт («на 14:15 · день не закрыт · сом, курс 11.10 · видно 2 149») на плитке не печатается: он виден
    при наведении на число и в строке полосы, пока там есть место (`ДБ-146`). Отличие от обычного печатает метка за названием, полный текст — при
    наведении на неё:

    | метка | вид | когда |
    |---|---|---|
    | ◷ вчера | серая — справка | плитка на последний закрытый день (§4.1) |
    | ◷ только ночью | серая | плитка «сегодня» на источнике без журнала изменений: его колонки держат значение на 02:00, днём не обновляются — штатно (статистика §2.5); при наведении — «на 02:00, источник обновляется ночью» (`ДБ-171`) |
    | ≈ смешанно | серая | в числе есть незафиксированные дни (§10) |
    | ⊘ без фильтра | янтарная — внимание | фильтр панели к плитке неприменим (§7.3) |
    | ✎ отчёт изменён | янтарная | отчёт плитки получил новую версию, смотрящий её ещё не открывал; при наведении — «отчёт изменён 14.10 (Асанова): фильтр»; пропадает, когда смотрящий открыл отчёт (§10, `ДБ-110`, `ДБ-172`) |
    | ⚠ большое необъяснённое | янтарная | в полосе, у строки «прочее» денежного Движения (Остаток, Нераспределённый): «прочее» больше 25 % изменения и больше 1 % начала; ниже порога «прочее» — серым (§5.12, `ДБ-182`) |
    | ⚠ устарело | янтарная, плитка в жёлтой рамке | сбой — отстало против плана (§10); у ночного источника — ночной прогон не прошёл (`ДБ-171`) |

    Дата, выбранная автором («на 30.09», «конец прошлого месяца»), — не метка, а часть уточнения. Выгрузка несёт
    паспорт целиком (`ИДБ-10`).
12. **Как рисуются виды в полосе** (`ДБ-149`…`ДБ-151`, `ДБ-154`…`ДБ-156`, `ДБ-160`). Виды рисуются для полосы
    1 574 px (экраны от 1920; `ДБ-165`) и не растягиваются: сумма стоит рядом с названием, пустое место — справа.
    Разрез, Движение и Таблица — строки одной формы:

    ```
    Агрокредит        12,4 млн   ▲ 0,9   ☰ 21   ████████████████████████
    Малый бизнес       9,1 млн   ▲ 0,6   ☰ 17   █████████████████
    …ещё 3             0,9 млн   ▼ 0,1   ☰ 2    ██
    Итого             29,2 млн   ▲ 1,2   ☰ 50
    ```

    | вид | как |
    |---|---|
    | Разрез | «название · сумма · разница · ☰ N · полоса», полоса заполняет остаток; разрез с объявленным порядком — те же строки в своём порядке, остальные — по убыванию; первые N, «ещё N», итог. Ступеней нет (`ДБ-150`, уточняет `ДБ-118`). Какие строки — ниже, «Строки разреза» |
    | Ряд | столбцы и у остатка, и у оборота, сумма над каждым, подписаны все месяцы, месяц — 131 px; что значит точка — строкой над графиком («остаток на конец месяца», «за месяц»); незакрытая точка светлее и подписана («окт · на 14:15», «окт · 1–14») (`ДБ-151`) |
    | Карта | названия 220 px, ячейки делят остаток поровну (на 1920 — 236 × 42 px), 13 px; в ячейке одно число — то, что нарисовано цветом; итог строки справа, итог столбца снизу, в итогах под числом мелко — второе (`ДБ-154`) |
    | Движение | «на базу» и «на сегодня» — числами без полос; каждая строка перехода — полоса от общей линии нуля: пришло — вправо, ушло — влево, цвет по направлению показателя, «прочее» и «нет ответа» серым; шкала — по самой большой строке; под ними цепочка-пояснение «26,6 + 3,4 − 0,9 − … = 29,2» без «✓» (`ДБ-155`, `ДБ-182`). Какие строки — ниже, «Строки Движения» |
    | Таблица | названия 220 px, числа колонками по 170 px, «☰ N» последней; первая колонка — показатель плитки, по ней порядок; в итоге — оба числа (`ДБ-156`) |

    **Строки разреза** (`ДБ-167`…`ДБ-170`, `ИДБ-18`, `ADR-0301`). **Объект разреза не пропадает: итог равен сумме
    строк**, как у уровней статистики (`ИС-24`). Строки — все значения списка разреза плюс значения, встреченные у
    объектов вне списка; печатаются всегда, нули тоже. Список ведёт статистика и держит его полным (`ДБ-168`): у
    «Срока просрочки» первая корзина — «нет просрочки», у статусов — весь справочник. Значение вне списка (справочник
    пополнили раньше реестра) встаёт строкой после объявленных — сигнал реестру, а не норма. Где признак к части
    объектов не применим, **«пусто» — последнее значение списка со своим именем** (`ДБ-170`): «нет решения», «нет
    категории», «нет исхода»; где пусто невозможно (область кредита), такого значения нет.

    ```
    Просрочено › Нарынская · Срок просрочки        На рассмотрении · Решение
    нет просрочки   0         ☰ 0                  Положительное    0   ☰ 0
    1–30            4,1 млн   ☰ 9                  С условиями      0   ☰ 0
    31–90           0         ☰ 0                  Отрицательное    0   ☰ 0
    91–180          1,2       ☰ 2                  нет решения     18   ☰ 18
    181+            0         ☰ 0                  Итого           18   ☰ 18
    Итого           5,3 млн   ☰ 11
    ```

    Неупорядоченный разрез — так же: нулевые строки уходят вниз и в «ещё N». Карта — то же по обеим осям.

    **Разрез по полю фильтра экрана с несколькими значениями — только отмеченные** (`ДБ-209`, по умолчанию): при «Область:
    Ошская, Джалал-Абадская» Разрез, Таблица и Карта по области печатают две строки, а не семь областей с нулями — фильтр
    уже сказал, что других на экране нет. Полный список (`ДБ-168`, `ДБ-169`) — когда поля в фильтре нет; одно значение
    закрепляет разрез, как прежде (§7.3). Итог по-прежнему равен сумме строк (`ИДБ-18`): все объекты выборки — в
    отмеченных значениях.

    **У разреза без объявленного списка** (куратор, подразделение, программа) строки — значения поля у объектов в
    охвате смотрящего после панели экрана и пути вглубь, но не после фильтра плитки (`ДБ-169`): Руководство с панелью
    «Ошское РП» видит по куратору кураторов Ошского РП, а не всех; куратор без просрочки внутри вопроса — строка «0».
    Объявленный список (шкала, справочник) печатается целиком при любой панели и пути — кроме поля самой панели с
    несколькими отмеченными значениями (`ДБ-209`, выше). Значения на выбор в
    конструкторе — по тому же правилу, по охвату автора. **У показателя «наибольший» строка «ещё N» — наибольшее из
    скрытых строк, не сумма** (`ADR-0301`); итог — наибольшая строка.

    **Строки Движения** (`ДБ-176`…`ДБ-183`, `ИДБ-19`, `ADR-0302`). **Каждый объект сравнивается с собой на двух
    датах** — строка статистики на базу против сегодняшней — и стоит ровно в одной строке; у каждой строки свой «☰ N»
    (объекты этой строки, сумма списка равна строке). Остатка без объяснения нет.

    ```
    Просрочено · Ошская
    на 30.09                                26,6
    + новые в просрочке          ☰ 12       +3,4   не было на 30.09, есть сегодня
    − погасили                   ☰ 4        −0,9
    − реструктурированы          ☰ 1        −0,4
    − списаны                    ☰ 1        −0,1
    − прочее                     ☰ 1        −0,1   ушла без платежа, решения и списания
    + выросла у прежних          ☰ 21       +1,2   просрочены в обе даты
    − снизилась у прежних        ☰ 9        −0,6
    + пришли в охват             ☰ 1        +0,3   сменился куратор или подразделение
    − ушли из охвата             ☰ 1        −0,2
    на сегодня                              29,2
    26,6 + 3,4 − 0,9 − 0,4 − 0,1 − 0,1 + 1,2 − 0,6 + 0,3 − 0,2 = 29,2
    ```

    - **Ушедшие — по причине, одна на объект** (`ДБ-177`): погасили (выросло погашено) · реструктурированы
      (включился признак) · списаны (выросло списано) · прочее (иначе: перевод долга, исправление учёта). Две
      причины — по старшинству: списан → реструктурирован → погасил → прочее. У залога реализовано старше
      освобождено, у заёмщика «прочее» (смерть, ликвидация, перевод долга) старше «погасили всё».
    - **«Нет ответа источника ☰ N»** (`ДБ-178`) — объект, по которому источник не ответил на одну из дат: известная
      сумма со своей даты. Пусто — не ноль (`ADR-0208` §1); сбой не выдаётся за «вылечился», цепочка сходится с
      числами плитки.
    - **Какие строки видны** (`ДБ-179`, по образцу `ДБ-169`): строки событий — всегда, нули тоже («списаны 0» —
      «не было»); «пришли / ушли из охвата» — только где охват может меняться (у «весь портфель» их нет); «нет
      ответа» — только при сбое.
    - **Движение и дата плитки** (волна 10 макета, по умолчанию): Движение кончается датой плитки. При дате «конец
      прошлого месяца» — только за прошлый месяц, «текущий» погашен с причиной; при иной не‑сегодняшней дате, не
      конце месяца, вид погашен с причиной. Так конец Движения всегда равен главному числу плитки.
    - **«Новые в просрочке», а не «вышли в просрочку»** (`ДБ-180`): плитка «Вышли в просрочку» (`ДБ-62`) считается
      по эпизодам и видит вышедших и вылечившихся внутри месяца. Подсказка строки: «просрочены сегодня, на 30.09 —
      нет; кто вышел и вылечился внутри периода — плитка „Вышли в просрочку“».
    - **Пять Движений — одно правило** (`ДБ-181`). Где владелец отдаёт денежные потоки, изменение у прежних
      раскрывается ими, а «прочее» — настоящий остаток (то, чего потоки не покрыли):

      | показатель | строки |
      |---|---|
      | Просрочено | как выше |
      | Остаток задолженности | выдано · начислено % · погашено · списано · пришли / ушли из охвата · нет ответа · прочее |
      | Заёмщиков (§3.10) | новые · вернулись · погасили всё · прочее · охват · нет ответа |
      | Залоговая стоимость | принято · переоценка ↑ · переоценка ↓ · освобождено · реализовано · охват · нет ответа |
      | Нераспределённый остаток | поступило без распределения · распределено · возвращено · прочее |

      У Остатка кредит, пришедший в охват, даёт «пришли в охват» своим остатком на базу, а все его потоки периода
      считаются в новом охвате. В «прочем» Остатка сейчас — начисленные комиссии и расходы взыскания (потоков
      нет), пеня и курсовая (⚑ у ядра).
    - **Без «✓ сходится»** (`ДБ-182`, уточняет `ДБ-155`): у переходов сумма сходится по построению. Цепочка
      остаётся пояснением. У денежных Движений «прочее» больше четверти изменения и больше 1 % начала — янтарное
      «⚠ большое необъяснённое», ниже — серым.
    - **В узле разреза — «пришли из … / ушли в …» по значениям** (`ДБ-183`): узел разреза с историей — тоже охват.
      «91–180» получает «пришли из 31–90 ☰ 9 +7,4» и «ушли в 181+ ☰ 4 −5,1» — так видно, что долг стареет. Строки —
      только значения со вкладом, в объявленном порядке; охват роли — одной строкой.

    **Когорты и режимы** (`ДБ-223`…`ДБ-228`, `ADR-0308`). Рисуются на той же сетке полосы, что и пять видов:

    | что | как |
    |---|---|
    | Когорты | строки — период начала (квартал по умолчанию, месяц — на выбор), слева — объём когорты на старте; колонки — 3, 6, … 24 месяца с начала; ячейка — показатель плитки на тот месяц когорты, цвет — величина (одна синяя шкала, как у Карты); у молодых когорт колонок меньше — «треугольник». Итогов строк и столбцов нет: сумма по возрастам не значит ничего. Данные — ряд на 24 конца месяца (`statSeries`) по разрезу «период начала», сдвинутый к началу когорты (`ДБ-225`) |
    | Переходы (Карта) | строки — значение на дату базы, колонки — сегодня; колонка «ушли» (погашены, списаны — по причине `ДБ-177`) и строка «новые»; итоги строк — число на базу, столбцов — сегодня. Цвет — направление по объявленному порядку: правее диагонали красным, левее — зелёным, диагональ нейтральна, тон — по величине. Те же данные, что у Движения в узле (`ДБ-183`, `ДБ-223`) |
    | план-факт (Разрез) | строка: название · «факт из плана» · процент исполнения (по светофору плитки, если задан) · серая полоса до плана, факт поверх, метка плана · недобор; порядок — от худшего исполнения, у разреза с объявленным порядком — свой; итог — оба числа и процент (`ДБ-224`) |
    | воронкой (Разрез) | строки — этапы по порядку, полоса — «дошли до этапа» (сумма строк от этой и ниже), слева — процент перехода от прошлого этапа, справа — «−N» потерь с причиной; заявки «в работе» — серым внутри полосы. Без режима тот же разрез — обычные строки «докуда дошла», итог — все поданные (`ДБ-226`, `ИДБ-18`) |
    | по разрезу (Ряд) | строка — название · число на дату плитки · мини-столбцы 6/12/24 точек · разница за период; шкала одна на все строки; незакрытая точка светлее (`ДБ-151`); первые N и «ещё N», итог строкой; клик по строке — Ряд узла (`ДБ-227`) |
    | «крупнейшие» (Разрез) | строки — первые N объектов по показателю плитки, «остальные N» одной строкой, итог — сумма; колонка накопленной доли («10 крупнейших — 6,2 %»); в «Изменении» объект сравнивается с собой на базе (`ДБ-228`) |

    **«☰ N»** (`ДБ-149`): в Разрезе, Движении и Таблице — тихой колонкой всегда; в Карте и Когортах — в углу ячейки, в Ряде —
    под месяцем, при наведении; у доли в строке полосы — «☰ 412 из 903» (§5.2, `ДБ-174`). **Итог** — во всех видах,
    кроме Когорт (`ДБ-160`, `ДБ-225`). **Единицы** — по §5.7, не выше «млн».
13. **Разница и «Сумма | Изменение»** (`ДБ-152`, `ДБ-153`, `ДБ-157`, `ДБ-159`, `ДБ-160`; `ИДБ-17`). Разница к базе
    видна в полосе всегда, без переключения: в Ряде — строкой под каждым месяцем к прошлому, в Разрезе — колонкой
    «к 30.09» рядом с суммой, в итогах Карты и Таблицы — мелко под числом. У Таблицы пар колонок «на 14:15 | к 30.09»
    нет (`ДБ-156`): в ячейках разница стоит в «Изменении», в итоге — оба числа. База — база сдвига плитки (§5.3), в
    Ряде — прошлая точка; цвет — по направлению показателя (§5.5), процент — при наведении. В теле полосы над графиком (не в
    строке полосы) — переключатель **«Сумма | Изменение»**: какое из двух чисел рисовать. Второе остаётся числом.

    | вид | «Изменение» рисует |
    |---|---|
    | Ряд | разницу к прошлому месяцу столбцами вверх и вниз от нуля; под месяцем — сумма |
    | Разрез | разницу полосами влево и вправо от нуля, порядок — от роста к падению; первые N — самые большие сдвиги в любую сторону, «ещё N» — в середине; во второй колонке — сумма. Разрез с объявленным порядком держит свой порядок, разница — полосой в своей строке (`ДБ-173`) |
    | Карта | цвет ячейки — по разнице: красный — показателю хуже, зелёный — лучше |
    | Таблица | разницу в ячейках, порядок — по разнице показателя плитки; у разреза с объявленным порядком — свой порядок (`ДБ-173`) |
    | Движение | переключателя нет — вид сам про изменение |
    | Когорты; Карта в режиме Переходов | переключателя нет — вид сам сравнивает когорты / две даты (`ДБ-233`, по умолчанию) |
    | Ряд по разрезу | разницу к прошлому месяцу столбцами вверх и вниз в каждой строке, как в Ряде (`ДБ-233`) |
    | план-факт, воронкой, «крупнейшие» | как Разрез (`ДБ-233`) |

    Переключатель **один на полосу** (`ДБ-157`): держится при смене вида и при ходе глубже, в Движении сохраняется до
    возврата; новое открытие полосы — «Сумма». Высота полосы в обоих положениях одна. **Нет честной базы — нет
    разницы** (`ДБ-159`): у незакрытого периода потока под точкой — «без сдвига» или прогресс к плану, как на плитке
    (`ДБ-143`); «Изменение» погашено с причиной «неполный месяц не с чем сравнить»; у плитки без базы сдвига —
    погашено так же.

    **База — по значению разреза на свою дату** (`ДБ-175`, `ADR-0302`). Сегодняшнее число группируется по
    сегодняшнему значению разреза, число на базе — по значению на дату базы: строка статистики на базу несёт свои
    дни просрочки, категорию, подразделение, куратора, статус. Кредит, перешедший из 31–90 в 91–180, даёт «−» в 31–90
    и «+» в 91–180; переданный из Ошской в Джалал-Абадскую — «−» у Ошской и «+» у Джалал-Абадской. Правило одно для
    Разреза, Карты, Таблицы и пути вглубь; охват роли и панель экрана на базе — тоже по значению на дату базы
    (подразделение кредита на 30.09), а не по сегодняшнему (волна 10 макета, ревью). Разница строки складывается из двух наборов объектов; кто перешёл, показывает
    Движение в узле (§5.12).

    ```
    Срок     на 30.09   сегодня   изменение
    31–90      2,0        0         −2,0     КД-2041: 80 дн. → 96 дн.
    91–180     0          2,1       +2,1
    ```

## 6. Клик и два действия

1. **У каждого числа два действия** (`ДБ-26`, `ИДБ-9`; `statistika-logika.md` §8.4):
   - **«Кто в этом числе»** — провал отчёта по этому узлу (`ДБ-105`): объекты на ту же дату из того же снимка, сумма
     списка равна числу (`ИО-45`, `ADR-0280` §5); под ним — `statRows`, полный список или отказ (`ADR-0178`).
     Нужно, чтобы проверить и оспорить число. **В списке и в его счёте «☰ N» — только объекты с ненулевым вкладом**
     (`ДБ-158`): у «Просрочено» Руководства — 287 кредитов с просрочкой, а не 1 248 действующих; сумма «☰» по
     строкам разреза равна «☰» узла. У счётных показателей это одно и то же.
   - **«Работать со списком»** — реестр модуля-владельца с фильтром отчёта и значениями параметров плитки, на
     сегодня, с подписью «в реестре 49, в срезе было 47»: все объекты по фильтру, в том числе с нулевым вкладом.
     Нужно, чтобы делать работу.
2. **Главный клик** (`ДБ-124`; уточняет `ДБ-25`, переигрывает `ДБ-105` в части главного клика; клик по мини-ряду
   снят `ДБ-130`). У обзорной плитки клик по главному числу раскрывает полосу последним выбранным видом (у новой —
   Разрез); в полосе клик по узлу ведёт глубже (§5.9). **«Кто в этом числе»** — значком «☰» в шапке плитки (при
   наведении, `ДБ-135`) и «☰ N» у строки полосы. **Заголовок плитки — ссылка на отчёт** («Просрочено ↗», «↗» — при
   наведении): отчёт открывается с теми же значениями
   параметров и фильтром панели. У ссылочной плитки клик по числу — её очередь модуля. «Работать со списком» всегда
   доступно в меню «⋯».
3. **Выше порога** (`ДБ-54`, по умолчанию): «Кто в этом числе» честно отказывает: «1 248 строк — сузьте разрезом
   или возьмите выгрузкой». Рядом предлагаются «Работать со списком» (в реестре листать можно) и полоса с
   разрезом (§5.8). Список открывается боковой панелью поверх дашборда, строка ведёт в карточку объекта.

## 7. Права, охват, фильтры

1. **Два замка — круг отчёта и область видимости; круг проверен при публикации** (`ДБ-104`, `ИДБ-4`; уточняет
   `ДБ-3`). Плитку видит тот, кому открыт её отчёт (личный — автору, общий — названному кругу, официальный — кругу
   подразделений, канон отчётности §13 п. 1). Число режется областью видимости смотрящего (`ADR-0152`, `ADR-0203`),
   паспорт пишет «видно N». Пустой охват — законный ответ. Автопроверка публикации каталожной плитки требует, чтобы
   круг отчёта покрывал всех держателей ролей, в раскладках которых плитка стоит («круг отчёта не покрывает 3
   держателей роли: РП Нарын»), поэтому человек на практике упирается только в замок у данных. Требование ТЗ о
   «разграничении прав к панелям» (`:163`) закрывают права на данные, круг отчёта и объявленная раскладка роли. Заёмщик виден по ведущему куратору; Проблемные кредиты видят его ещё и через
   требования, которые ведёт их подразделение, как дело взыскания (`ДБ-76`, по умолчанию).
2. **Недоступная плитка не прячется** ни в каталоге, ни в раскладке: «Нельзя: показатель не открыт вашей роли»,
   «Нельзя: отчёт не открыт вашему подразделению» — если круг сузили после публикации (`ДБ-35`, `ДБ-104`).
3. **Панель фильтров** (`ДБ-27`, `ДБ-102`, `ДБ-189`…`ДБ-191`): поля — область, подразделение, программа; в поле
   можно отметить несколько значений, между полями — «и». В ряду вкладок — кнопка «Фильтр», по клику — окно с полями
   и пояснением; выключен — строки фильтра нет, включён — синие фишки «Область: Ошская ×» и «Сбросить» тонкой
   строкой под вкладками. У каждой вкладки свой фильтр до конца сеанса; между входами не сохраняется (кроме своего
   экрана, §9.3); плитка его не хранит. Он сужает ответ отчёта по
   разрезу его основного объекта, как область видимости, — во всех плитках, где такой разрез есть. Каждая
   отфильтрованная плитка несёт «фильтр: Ошская» в паспорте (при наведении; панель над сеткой его уже называет),
   неприменимая — янтарную метку «⊘ без фильтра» (`ДБ-131`, §5.11). Фильтр сужает и не расширяет
   (`ИДБ-12`). Клик и выгрузка отфильтрованной плитки несут фильтр с собой.

   Поле режет плитку по разрезу **её** объекта. У заёмщика «Область» — территория регистрации лица («Территория
   заёмщика» реестра), а не территория выдачи кредита; паспорт плитки печатает «Ошская · по регистрации заёмщика»
   (`ДБ-72`). Клиентов по РП даёт поле «Подразделение» — подразделение ведущего куратора. «Программа» у заёмщика не
   действует — у клиента их бывает несколько (`ДБ-73`, по умолчанию). У объекта «Кредитная программа» «Программа»
   режет по самой программе, «Область» и «Подразделение» неприменимы (`ДБ-95`, по умолчанию).

   **Значения полей — по охвату смотрящего** (`ДБ-210`, по умолчанию), как значения на выбор в конструкторе — по
   охвату автора: в окне фильтра поле предлагает только значения, которые есть у объектов его охвата там, где поле
   действует (на вкладке роли — охват роли, на своём экране — всех ролей человека). Куратор Чуйского РП видит в
   «Подразделении» одно «Чуйское РП», в «Области» — «Чуйская»; Руководство — всё, что есть в портфеле: подразделения,
   которые ведут объекты (8 из 12; головной офис и отделы без своих объектов не предлагаются — фильтр по ним дал бы ноль
   на каждой плитке). Поле, у которого
   в охвате значений нет, так и говорит: «В вашем охвате значений нет». Значение, пришедшее из сохранённого фильтра
   своего экрана и ставшее вне охвата (роль сняли, охват сузился), остаётся в фильтре, но **не сужает**: оно — серая
   фишка «Подразделение: Ошское РП · вне вашего охвата» и строка под полем в окне; × снимает только его.

   **Разрез по полю фильтра** (`ДБ-209`): одно значение в поле закрепляет разрез; несколько — разрез, Таблица и Карта по
   этой оси печатают только отмеченные значения (§5, «Строки разреза»).

## 8. Кто собирает плитки

| кто | что собирает | куда попадает |
|---|---|---|
| администратор дашборда | каталожные плитки на общие и официальные отчёты; общие отчёты каталога; объявленные раскладки ролей | каталог; раскладки ролей |
| любой пользователь | личные плитки на открытые ему отчёты и виды, своя перекладка, свои экраны | только своё |

**Каталог — витрина, «+ Плитка» — мастерская** (`ДБ-197`…`ДБ-199`). Каталог показывает готовые плитки, которые
выпустил администратор: «возьми и поставь». Секции — по объекту (Кредит, Заёмщик, Взыскание, Имущество, Заявки…); в
строке плитки — значения параметров («куратор: я», «за прошлый месяц») и число в охвате смотрящего; поиск,
переключатель «только доступные мне». Пустой поиск ведёт в мастерскую. «+ Плитка» начинается с показателя («Кредит ·
Просрочено»): мастерская предлагает отчёты с ним (первым — кормящий больше плиток), нет подходящего — «собрать личный
отчёт» с этим показателем; отчёт виден как источник; дальше — плитка (подпись, параметры, числа, сдвиг, светофор) с
предпросмотром.

**Пустой охват по параметру плитки — «у вас пусто», а не 0** (`ДБ-211`, по умолчанию). Если у смотрящего нет ни одного
объекта под относительным параметром плитки («куратор: я» у Руководства, а сам он не куратор; «специалист: я» не у
специалиста), строка каталога вместо числа пишет серое «у вас пусто» с подсказкой «Плитка считает кредиты, где вы
куратор; у вас таких нет»; такие строки — в конце своей секции. «Добавить» остаётся: пустой охват — законный ответ
(§7.1), человек может ставить плитку на будущее. Ноль при непустом охвате («куратор: я», кредиты есть, а в
реструктуризации ни одного) — по-прежнему число.

1. **«Администратор дашборда» — отдельная системная роль** (`ДБ-29`). Её назначают аналитику или методологу, она
   совмещается с любой ролью. Право одно на всю систему; держателей — несколько, на запуске два (`ДБ-202`). Каждый
   держатель — соавтор всех отчётов каталога автоматически, владелец — собравший; роль сняли — владение переходит к
   другому держателю, последнего снять нельзя. Общие отчёты каталога он собирает конструктором отчётности
   и становится их владельцем (`ДБ-114`, `ADR-0279` п. 6).
2. **Личные плитки ставит любой** (`ДБ-4`, `ДБ-103`, `ИДБ-5`): «+ Плитка» на дашборде или «📌» в отчёте. Вопрос
   собирается конструктором отчётности; личный отчёт остаётся на полке автора. Плитки видны только автору и не
   покажут лишнего, потому что права у данных и у круга отчёта.
3. **Публикация через автопроверку, без второго ключа** (`ДБ-30`, `ДБ-109`, `ИДБ-14`): отчёт общий или
   официальный, его круг покрывает держателей ролей (`ДБ-104`), выбор из ответа пригоден (§3.5), предпросмотр без
   отказа. Плитка, отчёт которой ещё не отвечает, остаётся черновиком. Цикл: **черновик → опубликована → снята**.
4. **Делиться** (`ДБ-31`, `ДБ-114`, `ДБ-200`): отчётом — кругом отчётности (коллега ставит на него свою плитку),
   плиткой — только через каталог: «Предложить в каталог» ставит плитку в очередь администратора в реестре плиток — с
   предпросмотром и автопроверкой. «Принять»: личный отчёт копируется в общий (владелец — администратор), личная
   плитка автора заменяется каталожной; «Отклонить» — с причиной. Автор получает уведомление, у плитки — «предложена ·
   ждёт». Копий коллегам нет.
5. **Зависимость идёт через отчёт** (`ДБ-112`, `ADR-0177`, `ИО-42`). Плитка зависит от отчёта, отчёт — от
   показателей; обратный индекс статистики держит отчёты. Вывод показателя ломает отчёт, а через него — плитки
   поимённо; отчёт с плитками не удаляется, только в архив. Своих ссылок плиток в индексе статистики нет.
6. **Снятие каталожной плитки** называет, где она стоит: роли, число личных раскладок и своих экранов (`ДБ-201`).
   Можно указать замену: в личных раскладках и своих экранах — заглушка «снята, замена: … · Заменить · Убрать», живёт,
   пока человек её не уберёт. В реестре плиток — «открывали за 90 дней»; плитка без открытий 90 дней и вне раскладок
   ролей помечена «кандидат на снятие», снимает администратор. Открытие — то, что человек сделал с плиткой: открыл
   полосу или кликнул по числу (список, очередь); перерисовка главной, фильтр и смена вида в открытой полосе — не
   открытие (`ДБ-Д57`).

## 9. Раскладка и экраны

1. **Объявленная раскладка — одна на роль на всю систему** (`ДБ-5`, `ИДБ-6`), её ведёт администратор дашборда.
   Слоя подразделения нет. Вкладки — по одной на каждую системную роль человека (`ДБ-38`), всегда, и при одинаковых
   раскладках (`ДБ-186`).

   **Верх экрана отвечает «что я сейчас вижу»** (`ДБ-184`): чей набор (вкладка), в каком охвате, с каким фильтром.
   Один ряд: вкладки ролей, за ними свои экраны со значком, «+ экран»; справа — серая подпись «охват: весь портфель»
   (всегда), «Фильтр» и «⋯» экрана: «Переложить», «Вернуть как объявлено», «Выгрузить экран (PDF)», у своего экрана —
   ещё «Переименовать», «Удалить» (`ДБ-185`, `ДБ-188`). Под рядом — фишки фильтра, только когда он включён. Цель — не
   больше 150 px от верха окна до первой строки содержимого (заголовка секции или плитки) на 1920 (`ДБ-196`). При
   входе открыта последняя открытая вкладка; её больше нет — первая роль (`ДБ-187`).
2. **Личная перекладка** — переставить, скрыть, добавить из каталога, свои личные плитки. Хранится отдельно; «Вернуть
   как объявлено» стирает её целиком. Новая плитка роли встаёт в конец личной раскладки, удалённая исчезает. Правка
   объявленной раскладки действует сразу после сохранения (`ДБ-203`): администратор собирает правку на экране раскладки
   («Не сохранено: +2, −1 · Затронет N держателей роли · Отменить · Сохранить»), у держателей роли — разовая плашка
   «Раскладка роли обновлена 17.10: +2, −1 · Показать», новые плитки помечены «новая» до первого просмотра.
3. **Свои экраны** (`ДБ-32`) — до 5 на человека. Свой набор плиток (каталожные и личные), секции и, по желанию,
   **сохранённый фильтр** панели, напечатанный вверху экрана («Совещание по Ошу»). «+ экран» спрашивает имя и
   предлагает копию текущей вкладки с её фильтром (по умолчанию) или пустой экран; копия — снимок, дальше экран живёт
   отдельно (`ДБ-192`). Сохранённый фильтр меняется только явно: отличается от него — у фишек «изменён · Сохранить в
   экран · Вернуть» (`ДБ-193`). Это «сохранение шаблонов» по ТЗ
   (`:162`). Объявленные раскладки ролей свои экраны не трогают. На своём экране плитку можно закрепить раскрытой
   выбранным видом — для совещания и проектора (`ДБ-122`); на главной и в раскладках ролей — нет.
4. **Сетка** (`ДБ-33`, `ДБ-115`): 4 колонки, все плитки 1×1 — размер по формату снят. Полоса вида — на всю ширину
   под рядом (§5.8). Плитки перетаскиваются мышью, а стрелки остаются для клавиатуры.
5. **Секции** (`ДБ-34`): в любой раскладке можно вставить именованный разделитель и свернуть его. Свёрнутая секция
   помнится для человека на этой вкладке; её плитки чисел не спрашивают, в заголовке — «4 плитки», красный светофор
   внутри — точкой у заголовка (`ДБ-194`). Ради точки плитка со светофором спрашивает одно число светофора — без
   сдвига, второго числа и вида.
6. **Телефон** (`ДБ-56`, по умолчанию): сетка складывается 4 → 2 → 1 колонка, полоса вида — под своей плиткой.
   Верх — выпадающий список «Экран: Руководство ▾», «Фильтр» и «⋯» (в нём только выгрузка), охват — серой строкой
   под списком (`ДБ-195`, по умолчанию). На
   телефоне только просмотр, перекладки нет. Наведения нет: «⋯» на плитке виден всегда, «☰» — первым пунктом меню,
   подсказки — по касанию (`ДБ-144`).
7. **Роль без своей раскладки** (`ДБ-50`, уточняет `ДБ-8`) получает минимальную раскладку: «Мои задания» и ссылку
   «добавить из каталога». Пустой главной нет.
8. **Вид экрана** (`ДБ-165`, `ДБ-166`, `ADR-0300`). Формы — по перекраске главной, цвета и шрифт — общие для всех
   макетов модулей (акцент, синяя основная кнопка, цвета статусов, палитра графиков, системный шрифт). Фон страницы
   серый, плитки белые — скругление 12 px, лёгкая тень; полоса — скругление 14 px, тень, серая рамка и стрелка;
   сетка — 16 px; кнопки и поля — скругление 8 px; переключатели — серая дорожка с белой выбранной пилюлей. Меню
   слева белое, в шапке — «Обновить» и «Уведомления» со значками, аватар с инициалами в пилюле пользователя; контент
   на всю ширину — на 1920 × 1080 сетка 1 612 px, плитка 391 px. Тёмной темы нет. Название раздела и своего экрана
   вводится в окне на странице, не в системном; первая колонка Таблицы — на мягком синем; пульс скелета и выезд ящика
   — только когда система разрешает движение.

## 10. Состояния плитки (`ДБ-35`)

| состояние | что видно |
|---|---|
| загрузка | серый скелет плитки — не «0» и не прошлое значение |
| норма | число; паспорт — при наведении (§5.11) |
| устарело | число со своей датой, жёлтая рамка и метка «⚠ устарело»; причина — при наведении на метку («ночной прогон не прошёл») (`ДБ-145`) |
| смешанно | метка «≈ смешанно», при наведении — «9 из 12 зафикс.»; в Ряду незафиксированные точки светлые |
| ноль — это ответ | «0 · посчитали — нет» |
| прочерк — это ответ | «— · не из чего выбирать» |
| пустой охват | «видно 0» и почему |
| нет доступа | «показатель не открыт вашей роли», «отчёт не открыт вашему подразделению» — плитка не прячется |
| отказ поимённо | «не отвечается: …, владелец — …» — только для настоящих отказов шва |
| сломана объявлением | «показатель выведен из реестра», «в отчёте „Портфель“ нет колонки „доля“», «отчёт в архиве» — выбранное стало невозможным, как у вида (`ДБ-110`, `ИО-43`), [Скрыть у себя] |
| в очереди (перегруз) | последний ответ из кэша со своей датой и «⚠ устарело · на 14:02, сейчас считается»; нет его — скелет и «в очереди»; ответ пришёл — замена сама, без «Повторить» (`ДБ-217`) |
| у вас пусто | охват по параметру плитки пуст («куратор: я», а смотрящий не куратор) — серое «у вас пусто» с причиной, не «0» (`ДБ-220`, как в каталоге `ДБ-211`) |
| ошибка доставки | «статистика не ответила» — ничего вместо числа, [Повторить]; только при ошибке, не при очереди (`ДБ-217`) |

Сверх состояния плитка с изменённым отчётом несёт янтарную метку «✎ отчёт изменён», при наведении — «отчёт изменён
14.10 (Асанова): фильтр» (`ДБ-110`, `ДБ-172`, `ADR-0286` п. 3) — до первого открытия отчёта смотрящим (§5.11).

«Сломана» — только по главному числу. Выведен показатель второго числа — плитка не ломается: на месте второго числа
«—» с причиной («показатель «…» выведен из реестра статистики 14.10»), главное число отвечает как обычно (`ДБ-Д34`).

**Порог «устарело»** — сбой, а не план (`ДБ-171`): у плитки «сегодня» — очередь пересчёта отстала больше чем на 15
минут, а у источника, который обновляется только ночью, — ночной прогон не прошёл (значение старше сегодняшних
02:00); у плитки на закрытый день — дата старше вчерашней. Ночной источник по плану — не «устарело», а серая метка
«◷ только ночью» (§5.11). Устаревшее число показывается со своей
датой, а не прячется: его дала статистика, и паспорт честен.

**Состояния полосы** (`ДБ-212`…`ДБ-215`). Полоса честна по частям: показывает всё, что посчитано, на месте
непосчитанного — «—» с причиной в той же клетке или строке; одна неответившая часть не гасит вид, числа не
подменяются нулём или прошлым значением. Нет ответа на дату базы — «Изменение» погашено с причиной («нет ответа на
30.09 — статистика не ответила»), открыта «Сумма», Движение погашено той же причиной. Открытая полоса держит один
снимок («на 14:15»): пришли данные новее — в строке полосы «есть данные на 14:20 · Обновить», путь и вид сохраняются;
плитка над открытой полосой тоже ждёт. Закреплённая раскрытой плитка своего экрана обновляется сама, пока в ней не
провалились вглубь. Загрузка — скелет по частям: строка полосы сразу, тело — серый скелет формы вида, «Сумма» раньше
базы видна, «Изменение» — «…»; дольше 10 с — «считается дольше обычного · Отменить»; высота не прыгает. При перегрузе
полоса прошлых чисел не показывает — скелет и «в очереди».

**Поток «сегодня» на ночном источнике — отказ с причиной** (`ДБ-205`). Значение на 02:00 у потока — поступления с
00:00 до 02:00, почти ноль весь день; плитка отвечает «поступления за сегодня — после ночного прогона; за вчера —
18,4 млн» (вчерашнее число — серой подсказкой). Остаток на ночном источнике — число на вчерашний конец дня с «◷ только
ночью».

## 11. Наружу и сигналы

1. **Выгрузка только со штампом** (`ДБ-36`, `ДБ-113`, `ИДБ-10`; переигрывает `ADR-0212` п. 7). PDF плитки или
   экрана, Excel с числами плитки (агрегаты) — по правилам выгрузки отчётности (`ИО-49`): паспорт (отчёт, значения
   параметров, дата, закрытие, охват, фильтр), «Не является официальным документом», кто и когда выгрузил; строка
   журнала выгрузок. Строки объектов выгружает статистика своей выгрузкой (`ADR-0178`). Официальный документ —
   только выпуск отчётности (`ADR-0161`).
2. **Реакция — повод в заданиях** (`ДБ-37`, `ИДБ-13`). То, что требует исполнителя и срока, заводят задания по
   своим правилам (`ADR-0210`); на дашборде это видно через «Мои задания».
3. **🔔 — сигнал отчётности** (`ДБ-106`; переигрывает прежнюю подписку на смену цвета `ДБ-57`). Пункт «Сигнал по
   порогам» в «⋯» плитки ставит сигналы `ADR-0287` на тот же отчёт с теми же значениями параметров — по условию на каждый порог светофора
   («доля просрочки > 4 %», «> 5 %»). Проверка — раз в день после ночного снимка; сигнал приходит один раз, когда
   условие стало выполняться: «Доля просрочки — 5,2 % (было 4,6 %)», в системе и ссылкой на почту, с правами
   подписчика. Список «на что я подписан» и доставка — у отчётности. Это информирование, а не поручение; срочное —
   повод в заданиях (п. 2). Пока сигнал включён, за названием плитки стоит маленький синий колокольчик; снять — там
   же, в «⋯» (`ДБ-135`). Плановой рассылки PDF с дашборда нет: подписка на отчёт — у отчётности (`ОГ-18`).

## 12. Плитки обязательств (`ДБ-6`)

Отчётность объявляет объект статистики **«Обязательство»** (форма · подразделение · срок · состояние · дата сдачи ·
«числа изменились после сдачи»). Плитки «Просрочено», «Срок ≤ 7 дн.», «Итог сдачи» — обычные обзорные плитки:

отставания нет. Особого формата, паспорта «сейчас» и живого чтения `reportObligations` нет (`ИДБ-7`). Список
ближайших сроков — это работа: повод «срок сдачи формы близко или прошёл» в заданиях (`ADR-0291`).

## 14. Эксплуатация

1. **Журнал** (`ДБ-51`). Поимённо пишутся: создание, правка, публикация и снятие плиток, их версии, изменения
   объявленных раскладок. Выгрузки — в журнал выгрузок отчётности (`ДБ-113`, `ИО-49`); показ строк объектов в
   провале — в журнал просмотров отчётности (`ИО-55`). Просмотры и клики плиток — только обезличенными счётчиками
   («открывали 312 раз за месяц»), чтобы администратор видел, что нужно, а что нет.
2. **Кэш** (`ДБ-52`, `ДБ-113`, `ADR-0212` п. 3). Короткий общий кэш с ключом «отчёт и его версия + значения
   параметров + охват»; разные охваты не смешиваются.
   Ответ «сегодня» живёт не больше минуты, ответ на закрытый день — до следующего прогона. Паспорт показывает время
   расчёта, а не время показа. **Прогрев** (`ДБ-216`): после ночного прогона дашборд сам спрашивает числа на закрытые
   даты (база сдвига, вчера, прошлый месяц) для плиток объявленных раскладок ролей в охвате каждого держателя; утром
   считается только «сегодня». Личные плитки, свои экраны и полоса — по требованию.
3. **Запуск волнами** (`ДБ-53`, `ДБ-218`, `ИДБ-14`). Предусловие всего дашборда — модуль отчётности и отчёты
   каталога. В раскладку попадает только отвечающая плитка; неготовые ждут черновиками. Роль получает свою раскладку,
   когда отвечает не меньше половины плиток её объявленной раскладки (плитки-ссылки не в счёте, `ДБ-219`), до этого
   у неё минимальная. Волны ниже — прогноз порядка, а не даты.
   - Волна 1 — Руководство, Куратор кредита, Бухгалтерия, Залог, Проблемные кредиты: объекты кредит, платёж,
     поступление, предмет залога, требование, дело взыскания, заявка на реструктуризацию уже есть.

## 15. Что модуль берёт у соседей

| шов | владелец | зачем |
|---|---|---|
| ответ отчёта или вида со значениями параметров | отчётность | основа, шесть видов и режимы; перегруппировка на время просмотра по любому разрезу и с любыми показателями объекта (`ДБ-126`, `ДБ-128`); ответ — дерево уровней, итог узлом; пакетом за экран (`ADR-0191`); тот же перегруппированный ответ на дату базы сдвига — для разницы в строках, ячейках, итогах (`ДБ-153`); сам отчёт спрашивает `statSlice` / `statSeries` (`ДБ-99`, `ДБ-107`) |
| провал отчёта | отчётность | «кто в этом числе»: объекты на ту же дату с ненулевым вкладом, сумма равна ячейке (`ИО-45`, `ДБ-158`); под ним `statRows` — полный список или отказ (`ДБ-105`); по пути крошек полосы (`ДБ-123`) |
| ответ по объектам на двух датах | отчётность | Движение: строка объекта на базу и сегодняшняя рядом, с признаком перехода; «☰ N» строки Движения — её объекты, сумма равна строке (`ДБ-176`, `ДБ-181`, `ADR-0302`) |
| строка объекта на дату базы со своими значениями разрезов | статистика | база разницы по значению на свою дату (`ДБ-175`); уже есть: строка на конец дня, у закрытого месяца — последний день (`ADR-0264` §8) |
| подразделение и куратор объектов кредита на дату — из строки кредита | статистика | платёж, эпизод, обращение, предмет залога на дату режутся как их кредит (`ДБ-206`, `ADR-0303`) |

| соавторство отчётов каталога держателям роли | отчётность | несколько администраторов дашборда (`ДБ-202`) |
| конструктор отчётности поверх дашборда | отчётность | «+ Плитка» → «Собрать» (`ДБ-103`) |
| круг отчёта, отметка изменения, архив | отчётность | автопроверка публикации (`ДБ-104`); «отчёт изменён» и «сломана» (`ДБ-110`); отчёт с плитками не удаляется (`ИО-42`) |
| сигнал по условию | отчётность | 🔔 на плитке (`ДБ-106`, `ADR-0287`) |
| выгрузка и журнал выгрузок | отчётность | выгрузка плитки со штампом (`ДБ-113`, `ИО-49`) |
| выгрузка строк | статистика | строки выше порога — асинхронным заданием |
| список значений разреза | статистика | полный, с «пусто» последним по имени, в объявленном порядке — строки разреза (`ДБ-168`, `ДБ-170`, `ADR-0301`) |
| разрез «период начала» (квартал, месяц) у объектов с датой начала | статистика | Когорты (`ДБ-225`); у заёмщика есть «дата первого договора» (`ДБ-81`), у кредита, дела взыскания, заявки — нет |
| ответ «первые N объектов по показателю с итогом остальных» | статистика, через отчётность | разрез «крупнейшие» (`ДБ-228`) |
| последний пройденный этап и исход объекта | заявка (по мере надобности — реструктуризация, взыскание); в реестр — статистика | разрез «докуда дошла» и режим «воронкой» (`ДБ-226`) |
| «обновляется только ночью» в метаданных | статистика | серая метка «◷ только ночью», «устарело» — только когда ночной прогон не прошёл (`ДБ-171`) |
| реестр модуля с фильтром | модуль-владелец объекта | «работать со списком» |
| очереди модулей | заявка, комиссия, платежи, залог, задания, отчётность | вопрос и адрес ссылочной плитки (`ДБ-108`) |

## Журнал решений
