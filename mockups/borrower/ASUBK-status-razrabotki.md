## Нумерация

`СП-*` — решения по **экрану списка заёмщиков** (сессия-гриллинг 26.07.2026).
Отдельный префикс взят потому, что `Р-1…Р-10` в этом модуле заняты сессией
23.07.2026 (`docs/superpowers/specs/2026-07-23-borrower-rework-design.md`), а
`Р-11 / Р-20 / Р-22` внутри `borrower.html` — ссылки на решения **залогового**
модуля в зеркальных комментариях. `ОВ-*` продолжает сквозную нумерацию открытых
вопросов модуля (заняты ОВ-2, ОВ-4, ОВ-6).

Сессия шла в два прохода: СП-1…СП-14 — экран списка покомпонентно, СП-15…СП-21 —
открытые вопросы ОВ-7…ОВ-12, оставшиеся после первого прохода.

### Что именно изменилось в коде

- **Панель фильтра.** Вписанных значений в разметке больше нет — все справочники
  строит `fillFilterDicts()` из `SUBJECTS` и `REGION_OF`. Полей стало 9 (было 7),
  из них `f-name` / `f-inn` / `f-group` / `f-sub` удалены, добавлены
  `f-q` (в тулбар), `f-region`, `f-grp`, `f-curator`, `f-ovFrom`, `f-ovTo`, `f-def`.
- **`REGION_OF`** поднята из локальной области сид-функции на верхний уровень —
  один источник и для сида, и для каскада фильтра.
- **`subgroupOf()`** получила ступень «нет долга — нет класса»: `'none'` решается
  до лестницы, `'closed'` — после неё (иначе терминальные 3.2 и 5, где кредиты тоже
  закрыты, потеряли бы свой класс). `groupOf()` вне лестницы отдаёт `null`,
  `solvencyOfGroup()` не принимает такие коды за «Неплатёжеспособные».
- **`listRow()`** отдаёт `debt`, `mid`, `curatorNames`, `gaps` — фамилия куратора
  больше не подавляется дырой, а сортировка по колонке идёт только по фамилиям.
- **`sortVal('def')`** возвращает составной ключ `[стоп, высокие, всего]` вместо
  `(стоп ? 1000 : 0) + всего`; сравнение — новая `cmpVal()`.
- **Удалено:** `renderCards`, `listView`, `LIST_VIEW_KEY`, `setListView`, `#segTable`,
  `#segCards`, `#cardsWrap`, `#tbOpen`, `gTop`, CSS `.bcard-*` / `.cards-*`.
  CSS `.viewseg` **сохранён** — им пользуются переключатели внутри карточки
  («Взыскание»: по процессам / по кредитам, «Обеспечение»: по кредитам / по предметам).
- **Сид:** добавлен ОсОО «Нарын Агро Плюс» (ИНН 11101199900111) — предрегистрация
  без единого кредита. Без такой записи ветка СП-7 «Кредитов не было» в макете
  недостижима, а прежняя база выдавала ровно ей «1.1 Производят погашение по графику».

### Что изменилось по СП-15…СП-21

- **Панель фильтра.** `#fAddCond` и кнопка-шестерёнка удалены. Это был типовой
  конструктор условий Jmix — он стоит на каждом списочном экране целевого приложения
  (`requirements/tz/04-zaemshchik.md` §4.1 и то же в разделах 05/06/07), но обработчиков
  в макете не имел. Произвольная пара условий возвращает ровно тот дефект, который СП-3
  погасил структурно. Механику отдаём платформе, знание осталось в СП-4/СП-5/СП-20.
- **Пустое состояние** строит `renderEmpty()`: метки из `FIELD_LABEL`, значения через
  `condValLabel()` — коды (`na`, `none`, `stop`, «2» как вся группа) наружу не выходят.
  Кнопка вызывает `resetFilter()`, который чистит все `FIELDS`, включая `f-q`: поиск лежит
  в тулбаре и в счёт активных условий не идёт, но «Сбросить» должно давать чистый реестр.
- **Плашки-пресеты.** `PRESETS` — три набора значений полей фильтра. `presetOn()` **выводит**
  состояние из `active`, а не хранит флаг: значение, введённое руками в панели, включает
  соответствующую плашку. Повторное нажатие снимает только свои значения, прочие условия
  не трогает. Сохранения, имён и прав нет — в макете их пришлось бы держать в `localStorage`,
  то есть на браузер, а не на пользователя.
- **Форма создания.** Одно модальное окно (`#mBack`) на создание и на подтверждение
  удаления. Вход — только ИНН; `onInnInput()` выбирает ветку: `SUBJECTS.find` нашёл →
  `foundHtml()` (реквизиты только для чтения + «Открыть карточку»), не нашёл →
  `createFieldsHtml()`. Дубль ИНН недостижим формой, а не отлавливается валидацией —
  это важно, потому что `inn` первичный ключ всех выводимых значений (`subgroupOf`,
  `totalDebt`, И-4). Обязательны 8 полей (`CREATE_REQ`): ИНН, тип, наименование, отрасль,
  район, вид/номер/дата документа, дата регистрации. Отрасль и район обязательны **по
  построению**: без них запись выпадает из фильтров СП-4/СП-5 — существует, но не находится.
  Остальные реквизиты — в свёрнутом `<details class="fsect">`. `legalForm` показывается
  только юр. лицу: у ИП и физлиц этого поля в модели нет.
- **Удаление.** `deleteBlockers(inn)` собирает препятствия из `subjectRoles()` и
  `SUBJECT_EVENTS`; `askDelete()` при непустом списке показывает отказ с перечнем и
  объяснением, что завершённый заёмщик закрывается событием, а не удалением. Кнопка в
  карточке заперта с причиной в `title` — до нажатия, а не после отказа. `doDelete()`
  проверяет препятствия повторно.
- **Добавлена `fromISO()`** рядом с `toISO()`: `<input type="date">` отдаёт ISO,
  модель хранит ДД.ММ.ГГГГ.

## Открытые вопросы

- **ОВ-13 · Идентичность пользователя.** `[admin]` — литерал в шапке макета
  (`borrower.html`, топ-хедер) и в оттиске экспорта; среди кураторов сида
  (Сламкулов, Асанова, Токтосунов, Осмонова, Мамытова) его нет. Поэтому пресет
  «мои» в СП-20 не сделан: вычислить его нечем, а выдуманное сопоставление
  «пользователь → куратор» соврало бы. Сюда же уходят имена и права сохранённых
  списков из ОВ-7 — им место рядом с моделью пользователя, а не на экране списка.
- **ОВ-14 · Контрольный разряд ИНН.** СП-18 проверяет только длину (14) и состав
  (цифры). Алгоритм контрольного разряда ИНН КР в репозитории нигде не описан —
  в макете не выдумывался.
- **ОВ-15 · Редактирование реквизитов субъекта.** Создание есть (СП-17/18),
  удаление есть (СП-19), правки — нет: в целевом приложении все поля карточки
  `readonly=true` (`requirements/tz/04-zaemshchik.md` §3.2–3.3), то есть механизм
  правки там тоже не наблюдается. Опечатка в наименовании сейчас исправляется
  только удалением и повторным созданием, и то лишь пока на лице нет связей.
