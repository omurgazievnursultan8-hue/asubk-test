## 0. Краткая суть

Модуль отвечает на вопрос **«что за документ, где он сейчас, к какому делу относится и чем
кончилось его исполнение»**.

Десять решений, определяющих логику:

1. **Видов три: входящий, исходящий, внутренний.** Всё прочее (претензия, акт сверки, иск,
   приказ) — тип внутри вида, строка справочника.
2. **Этап хранится, исполнение выводится.** Цепочка этапов одна для всех видов:
   Черновик → Согласование → Подпись → Зарегистрирован → В деле (плюс «Аннулирован»).
   Отдельного хранимого статуса исполнения нет. Сводку собирают из резолюций и заданий.
3. **Зарегистрированный документ не удаляется.** Ошибка регистрации исправляется действием
   «Исправить» (реквизит) или «Аннулировать» (документ целиком; номер остаётся занятым).
4. **Номер выдаёт журнал вида при регистрации.** Рядов три, каждый начинается с 1 в новом
   году по правилу. Номер исходящего выдаётся здесь, а не в «Отчётности».
5. **Резолюция — отдельная запись с одним ответственным.** Резолюции идут каскадом; срок
   нижней не позже срока верхней.
6. **Каждый шаг, ждущий человека или роль, — задание модуля «Задания».** Своей очереди
   «на мне» у документооборота нет.
7. **Документ привязан к делу.** Обязательность привязки задаёт тип. Без обязательной
   привязки регистрация недоступна.
8. **Даты вводятся один раз, в документе.** Мера взыскания, связанная с документом, читает
   номер и даты из него и своих полей для них не имеет.
9. **Подписывает только тот, у кого есть право подписи** по справочнику: сотрудник × типы
   документов × срок доверенности.
10. **Отправка ведётся по каждому адресату.** «Отправлен» — не этап. На карточке видна
    сводка: «отправлено 2/3: вручено 1, возврат 1».

### 1.2. Справочник видов и типов

Видов три, они зашиты в модель: новый вид означает новый ADR, а не строку справочника.
Типы ведёт администратор документооборота. У каждого типа есть:

- вид;
- наименование;
- цель по умолчанию;
- «требует ответа» по умолчанию (только у входящих);
- **обязательная привязка**: набор видов объектов (например, «кредит + фаза взыскания»);
- **дело по умолчанию** из номенклатуры текущего года;
- срочность по умолчанию;
- признак «только для перенесённых» (тип «Документ (из старой системы)»);
- признак «действует» (тип не удаляется, а выводится из употребления).

Переименование типа меняет только наименование. Ссылки и фильтры строятся по устойчивому
идентификатору. В старой системе переименование меняло идентификатор и ломало ссылки (дефект
легаси §10 п. 9).

**Стартовый набор:**

| Вид | Тип | Требует ответа | Обязательная привязка |
|---|---|:--:|---|
| Входящий | Заявление заёмщика | да | заёмщик |
| Входящий | Письмо заёмщика или поручителя | да | заёмщик |
| Входящий | Решение или определение суда | нет | кредит + фаза взыскания |
| Входящий | Исполнительный лист | нет | кредит + фаза взыскания |
| Входящий | Ответ на претензию | нет | кредит + фаза взыскания |
| Входящий | Запрос госоргана | да | — |
| Входящий | Письмо банка или организации | нет | — |
| Входящий | Документ (из старой системы) | нет | — (только для перенесённых) |
| Исходящий | Письмо · Уведомление · Извещение · Претензия · Акт сверки · Исковое заявление · Ходатайство · Возражения · Апелляционная жалоба · Кассационная жалоба · Частная жалоба · Заявление · Соглашение · Служебная записка · Извещение по восстановлению залога | — | задаётся при настройке типа |
| Внутренний | Служебная записка · Заявление сотрудника · Приказ · Протокол · Договор · Нормативный документ | — | — |

Вид отправителя входящего: Заёмщик · Суд · Госорган · Банк · Прочее.

### 1.3. Участник

Участник — сотрудник в **роли** по документу. Роль хранится явно. В старой системе ролей не
было: кто согласующий, а кто исполнитель, восстанавливалось по задачам (легаси §3).

| Роль | Вид | Кто назначает |
|---|---|---|
| автор | исх., внутр. | создатель черновика |
| согласующий (0…n) | исх., внутр. | автор |
| подписант (ровно 1) | исх., внутр. | автор, из списка допустимых по праву подписи (§8.2) |
| регистратор | все | роль «Регистратор»; фиксируется тот, кто зарегистрировал |
| получатель | вх., внутр. | регистратор (вх.) или автор (внутр.) |
| ответственный и соисполнители резолюции | вх., внутр. | автор резолюции (§4.1) |
| контролёр | вх., внутр. | регистратор (флаг «на контроле») |

Видимость по участию считается от этих ролей (§8.3).

### 1.4. Резолюция

Самостоятельная запись (`ДО-19`, ADR-0266):

- автор и дата;
- текст: фраза из справочника фраз, её можно дописать;
- **ответственный** — ровно один;
- соисполнители — ноль и более;
- срок;
- родительская резолюция (пусто — резолюция верхнего уровня);
- исход: «Исполнено» (с текстом результата) или «Отказать» (с основанием); пока исхода нет,
  резолюция открыта.

### 1.5. Привязка

Ссылка документа на объект системы. У документа может быть несколько привязок (`ДО-6`).

Виды объектов: заёмщик · кредит · процедура взыскания · фаза взыскания · событие (мера)
взыскания · договор залога · объект имущества · заявка · госрешение · ведомство.

- При выборе кредита заёмщик подставляется сам (`ДО-22`).
- Обязательность задаёт тип (§1.2). Документ без обязательной привязки не регистрируется.
- Бланк из «Отчётности» приносит привязку сам: объект бланка становится привязкой черновика
  (§10.2).
- Перенесённые документы от требования освобождены.
- В карточках заёмщика, кредита, фазы, залога и имущества есть вкладка «Документы». Она
  читает привязки и своего списка не ведёт.

### 1.6. Отправка адресату (исходящий)

Строка на каждого адресата исходящего (`ДО-13`):

- адресат: субъект системы, орган или свободная строка;
- способ отправки — из справочника способов (`ДО-40`): заказное письмо (почта), нарочно,
  курьер, e-mail, СЭД, публикация;
- дата отправки;
- почтовый идентификатор (для почты);
- исход доставки: вручено или возврат, с датой;
- подтверждающий файл (уведомление о вручении, отметка о получении, квитанция СЭД).

Состав подтверждения задаёт **способ**, а не тип документа. Справочник подтверждений
(во взыскании — `DELIVERY_PROOF`, ADR-0078 п. 16) переезжает в справочник способов
документооборота (`ДО-40`).

### 1.7. Вложение

- **роль файла**: проект · подписанный · приложение · подтверждение вручения · скан входящего;
- **имя даёт система**: `ИСХ-2026-215_подписанный.pdf`, `…_проект_v3.docx`,
  `…_приложение-1.pdf`, `…_вручение_адресат-2.pdf`. Исходное имя файла не сохраняется: в именах
  старой системы стоят ФИО (ПДн);
- версия: до регистрации замена файла создаёт новую версию, старые видны в истории;
- форматы: PDF, DOCX, XLSX, JPG, PNG; не больше 20 МБ на файл;
- размер и контрольная сумма хранятся.

### 1.8. Комментарий

Запись в ленте карточки: автор, время, текст, упоминания (@сотрудник). **Неизменяем**:
не правится и не удаляется (`ДО-30`). Упомянутый видит отметку на карточке и счётчик
«вас упомянули». Уведомления нет (ADR-0230: уведомления только о работе).

### 1.9. Журнал действий документа

Append-only. Пишет каждое действие: создание, отправку на согласование, «согласовано» или
«отказ» с комментарием, подпись, регистрацию с номером, исправление «было/стало»,
аннулирование с основанием, отправку и вручение по адресату, резолюции и их исходы,
ознакомление, сдачу в дело, выдачу и возврат оригинала, комментарии. Каждая запись несёт
автора и время. «Выполненные действия» из ТЗ — это этот журнал.

### 1.10. Ряд номеров

Счётчик: вид × год (§3). Номер выдаётся под блокировкой, уникальность проверяется в пределах
года и ряда.

### 1.11. Право подписи

Справочник: сотрудник × набор типов документов × основание (доверенность или должность) ×
срок действия «с — по». Замещение — по признаку приказа «с правом подписи» (§8.2).

### 1.12. Номенклатура дел и выдача оригинала

**Дело** — запись номенклатуры года: индекс, название, подразделение, срок хранения, место
хранения (кабинет, шкаф, полка).

**Выдача оригинала** — строка журнала выдачи: документ, кому выдан, когда, до какого числа,
дата возврата (§7).

## 2. Этапы и переходы

### 2.1. Этапы

```
                  ┌──────── отказ согласующего / подписанта (с комментарием) ───────┐
                  ▼                                                                  │
   ┌──────────┐  на согласование  ┌─────────────┐  все согласовали  ┌─────────┐ подписал  ┌────────────────┐  сдать в дело  ┌────────┐
   │ Черновик │ ────────────────► │ Согласование│ ────────────────► │ Подпись │ ───────► │ Зарегистрирован│ ─────────────► │ В деле │
   └──────────┘                   └─────────────┘                   └─────────┘           └────────────────┘                └────────┘
     │  │   (согласующих нет — сразу в «Подпись»)                                                  │
     │  └────────── входящий: «Зарегистрировать» ──────────────────────────────────────────────────┤
     ▼                                                                                            ▼ аннулировать (если не отправлено)
   удалён (номера не было)                                                                   ┌────────────┐
                                                                                             │ Аннулирован│
                                                                                             └────────────┘
```

Этапов шесть: **Черновик · Согласование · Подпись · Зарегистрирован · В деле · Аннулирован**.
Этап — хранимое поле (`ДО-15`): это движение самого документа, а не вывод из чужих фактов.

**Чем этап не является:**

- **«Отправлен» — не этап.** Отправка ведётся по адресату, на карточке видна сводка (§5).
- **«Исполнен» — не этап.** Исполнение выводится (§4.6). Документ в этапе «Зарегистрирован»
  бывает в работе, просрочен или исполнен.

### 2.2. Переходы

| Из | Действие | В | Кто | Условие |
|---|---|---|---|---|
| — | Создать черновик | Черновик | любой сотрудник (исх., внутр.); регистратор (вх.) | — |
| Черновик | Удалить | — | автор | номера нет; удаление логическое, след остаётся в журнале |
| Черновик | На согласование | Согласование | автор | назван подписант; есть файл с ролью «проект»; обязательная привязка заполнена |
| Черновик | На подпись | Подпись | автор | согласующих нет |
| Согласование | Согласовать | — / Подпись | согласующий | когда согласовали все, документ переходит в «Подпись» |
| Согласование | Отказать | Черновик | согласующий | комментарий обязателен |
| Подпись | Подписать | Зарегистрирован* | подписант | право подписи на тип на дату (§8.2) |
| Подпись | Отказать | Черновик | подписант | комментарий обязателен |
| Черновик (вх.) | Зарегистрировать | Зарегистрирован | регистратор | обязательная привязка; скан входящего |
| Зарегистрирован | Исправить | — | регистратор | только реквизиты из §2.5 |
| Зарегистрирован | Аннулировать | Аннулирован | регистратор | основание обязательно; ни одному адресату не отправлено |
| Зарегистрирован | Сдать в дело | В деле | архивариус или регистратор | исполнение и отправка закончены (§7) |

\* Подпись исходящего и внутреннего не регистрирует документ сама. Она ставит его в общую
очередь роли «Регистратор» (задание «зарегистрировать», §10.1). Документ остаётся в этапе
«Подпись» с отметкой «подписан», пока регистратор не нажмёт «Зарегистрировать». Скан
подписанного экземпляра регистратор прикладывает **после** выдачи номера, проставив номер штампом
(§3.3, `ДО-38`); без него отправка и сдача в дело недоступны. Отметка «подписан» — факт журнала, а
не отдельный этап: между подписью и регистрацией документ ни для кого не меняется (`ДО-10`).

### 2.3. Маршрут согласования

- Согласующие смотрят **параллельно**. Подписант получает документ только после всех
  согласований (`ДО-9`).
- **Любой отказ возвращает документ в «Черновик»** с комментарием. Согласования этого круга
  при возврате сбрасываются. Следующий круг начинается заново, а прежние отметки остаются в
  журнале.
- Замена файла с ролью «проект» после того, как кто-то согласовал, **сбрасывает согласования**
  и возвращает документ в «Черновик» (`ДО-27`).
- В старой системе согласование не блокировало утверждение, а отказ согласующего терялся
  (легаси §4.3). Здесь оба поведения исправлены.

### 2.4. Маршрут по видам

**Входящий.** Регистратор создаёт черновик, прикладывает скан, заполняет отправителя,
корреспондента, даты, тип, получателей и привязки, затем регистрирует. Согласования и подписи
у входящего нет. Дальше получатели дают резолюции (§4).

**Исходящий.** Автор создаёт черновик сам или из бланка «Отчётности» (§10.2). Дальше идут
согласование, подпись, регистрация и отправка по адресатам. Исполнение исходящего — его
отправка. Резолюций у исходящего нет.

**Внутренний.** Маршрут до регистрации как у исходящего. После регистрации документ уходит
получателям в режиме «на ознакомление» или «на исполнение» (§4.5).

### 2.5. Исправить и аннулировать

**Исправить** (`ДО-17`) — правка опечатки в реквизите зарегистрированного документа. Журнал
пишет «было/стало, кто, когда, основание».

- **Исправляются:** тема, дата документа, дата поступления, номер и дата корреспондента,
  отправитель, адресаты и даты отправки и вручения по ним, привязки, срочность, цель.
- **Не исправляются:** вид, тип, номер, дата регистрации. Ошибка в них означает аннулирование
  и новую регистрацию.
- Исправление даты документа или даты вручения сразу видно мере взыскания, которая на неё
  ссылается (§10.3). Сама мера при этом не правится: она читает дату из документа.

**Аннулировать** — документ переходит в этап «Аннулирован».

- Основание обязательно.
- **Номер остаётся занятым** и виден в журнале с основанием.
- Отмены регистрации с возвратом номера нет.
- Аннулировать нельзя, если хотя бы одному адресату уже отправлено. Ушедшая бумага — факт:
  отозвать её можно только новым исходящим.
- Аннулирование снимает открытые задания по документу (повод отпадает, §10.1).
- Мера взыскания, ссылающаяся на аннулированный документ, получает метку расхождения. Сама
  мера не сторнируется: сторно — решение взыскания, а не документооборота.

## 3. Регистрация и нумерация

### 3.1. Три ряда

| Вид | Формат | Ряд |
|---|---|---|
| Входящий | `1234` | один на организацию |
| Исходящий | `<код отдела>/<номер>`, например `19-03-01/215` | номер сквозной на организацию; код отдела — только префикс |
| Внутренний | `<код отдела>/ВН-<номер>` | свой сквозной ряд на организацию |

- **Все ряды начинаются с 1 каждый год по правилу** (`ДО-21`), а не вручную. В старой системе
  счётчик входящих обнуляли руками в базе (легаси §5).
- **Код отдела** — подразделение автора документа на дату регистрации, из «Оргструктуры».
- **Номер выдаётся при регистрации под блокировкой.** Уникальность проверяется в пределах года
  и ряда. В старой системе блокировки не было, и в базе есть дубли.
- Год номера — год даты регистрации. На карточке и в поиске номер показывается с годом:
  `1234 / 2026`.
- Формат ряда — свойство вида, а не строка с токенами. Разбор строковых форматов в старой
  системе был с ошибками (`{ГГ}`/`{ГГГГ}`, повторные токены).

### 3.2. Сознательное отклонение от буквы ТЗ

ТЗ 948: «по каждому из указанных шаблонов ведётся отдельный журнал регистрации и учёта». Это
требование выполнено **журналом-списком** с фильтром по типу и печатной формой этого списка.
**Отдельного счётчика на тип нет.** Причина: канцелярия ведёт один ряд исходящих на
организацию уже семь лет (по базе 2019–2026). Счётчик на тип разрезал бы этот ряд на 24, и
номер `19-03-01/215` стал бы неоднозначным. Отклонение вносится в ТЗ и в письмо заказчику.

### 3.3. Номер на бумаге

Номер исходящего и внутреннего появляется **после подписи** (`ДО-38`):

1. автор готовит проект (из бланка «Отчётности» или свой файл);
2. согласующие и подписант работают в системе; бумагу подписант подписывает вручную
   (`ДО-10`, ЭЦП — позже отдельной задачей);
3. регистратор нажимает «Зарегистрировать», система выдаёт номер;
4. регистратор проставляет номер и дату на подписанном экземпляре (штамп канцелярии) и
   прикладывает его скан с ролью «подписанный».

Наружу уходит подписанный экземпляр с номером. Pdf-снимок «Отчётности» остаётся
доказательством того, какие числа были в бланке (ADR-0157), но номера не несёт. Так обходится
противоречие: номер выдаётся только тому, что подписано, а заморожено то, что подписывали.

## 4. Исполнение

### 4.1. Резолюция и каскад

- Резолюцию даёт **получатель** документа или **исполнитель резолюции выше** (`ДО-24`).
- В резолюции один ответственный, соисполнители (0 и более) и срок.
- **Каскад:** исполнитель может дать свою резолюцию ниже. Её срок не может быть позже
  **действующего** срока родительской (с учётом утверждённых продлений, §4.7).
- Каждому исполнителю резолюции создаётся задание (§10.1).
- **Резолюция исполнена, когда исполнен ответственный.** Соисполнители его не блокируют:
  их задания закрываются вместе с резолюцией исходом «снято» с причиной «резолюция
  исполнена».
- **Документ исполнен, когда исполнены все резолюции верхнего уровня.**
- Исходы резолюции: **«Исполнено»** (текст результата) или **«Отказать»** (основание).
  «Отказать» означает отказ в исполнении документа по существу (например, отказ в просьбе
  заёмщика), а не «это не моя работа». Чтобы снять с себя чужую работу, исполнитель
  отказывается от задания в модуле «Задания», и задание переназначает автор резолюции
  (ИЗ-23).
- Резолюция верхнего уровня с исходом «Отказать» закрывает свою ветку. Документ с такой
  резолюцией попадает в показатель «отказано в исполнении» (§9.2).

### 4.2. Срок резолюции по умолчанию

Срочность документа задаёт срок по умолчанию: Обычно — 10, Срочно — 3, Немедленно — 1
рабочий день от даты регистрации (`ДО-23`). Автор резолюции может срок изменить. Значения
10/3/1 — на подтверждение по приказу ФКФ о сроках, если такой приказ есть (§14, вопрос 2).

### 4.3. Входящий «требует ответа»

Флаг в типе, регистратор может изменить его у конкретного документа (`ДО-18`).

- **Флаг стоит.** Поручение гаснет, когда зарегистрирован ответный исходящий (входящий указан
  в его основании) **и отправлен отправителю входящего**. Отметка исполнителя «Исполнено» без
  ответа такую резолюцию не закрывает.
- **Флага нет.** Поручение гаснет по отметке исполнителя «Исполнено» с текстом результата.
- **Один исходящий может закрыть несколько входящих:** в его основании их несколько.
- Дата исполнения такого входящего — дата отправки ответа отправителю.

### 4.4. «На контроле»

Флаг ставит регистратор и указывает контролёра. Ответственный, отметивший «Исполнено», не
закрывает резолюцию, пока контролёр не подтвердит исполнение. Контролёр может вернуть
резолюцию с комментарием, и тогда ответственный снова получает задание (повтор, ИЗ-24).
Подтверждение контролёра — отдельный шаг документа и отдельное задание (§10.1). Контролёр
модуля «Задания» на этом шаге не назначается: независимую ось (ИЗ-7) даёт сам документ.

### 4.5. Внутренний документ у получателей

Номер один, у автора. Второго (входящего) номера у получателя нет (`ДО-20`). Каждый получатель
назначается в одном из режимов:

- **«на ознакомление»** — отметка «Ознакомлен» с датой и временем. Есть лист ознакомления и
  сводка «ознакомлены 12/15» со списком не ознакомившихся.
- **«на исполнение»** — каскад резолюций, как у входящего (§4.1).

«Обмен файлами» из ТЗ — действие «Направить на ознакомление» с файлом (`ДО-30`).

### 4.6. Сводка исполнения — вывод, а не поле

Исполнение не хранится полем документа (`ДО-15`, ADR-0265). Сводка собирается из двух
источников:

| Что | Откуда |
|---|---|
| исход шага: исполнено, отказано, ознакомлен | факт документа (отметка в карточке) |
| действующий срок, продления, просрочка | задание модуля «Задания» по этому шагу |

На карточке это выглядит так: «поручений 2: исполнено 1, просрочено 1»; «ознакомлены 12/15»;
«отправлено 2/3: вручено 1, возврат 1».

### 4.7. Срок и продление

Срок резолюции становится **собственным сроком повода** (вид повода «несёт собственный срок»,
§10.1). Продление запрашивает исполнитель в модуле «Задания», утверждает автор резолюции
(ЗН-3). Документооборот второго механизма продления не заводит. Действующий срок он читает
у заданий: им проверяется каскад (§4.1) и считается «в срок» (§9.2).

## 5. Отправка и вручение

- Отправка — по каждому адресату (§1.6): способ, дата отправки, почтовый идентификатор, исход
  доставки (вручено или возврат) с датой, подтверждающий файл.
- Отметить отправку и вручение вправе регистратор. Отправку по e-mail может отметить и автор
  (`ДО-24`).
- Дата отправки не позже сегодняшней и не раньше даты регистрации. Дата вручения или возврата
  не раньше даты отправки.
- Сводка на карточке: «отправлено 2/3: вручено 1, возврат 1».
- **Отправка исходящего закончена**, когда у каждого адресата есть дата отправки. Вручение
  ждать не обязательно: возврат — тоже исход доставки.
- Дата вручения по адресату-должнику уходит в меру взыскания чтением, а не копией (§10.3).

## 6. Вложения

- Роль файла выбирает пользователь, имя даёт система (§1.7).
- **До регистрации** замена файла создаёт новую версию. Замена «проекта» после согласования
  сбрасывает согласования (§2.3).
- **После регистрации файлы нельзя удалить или заменить**, только добавить.
- Удалить или заменить файл может только автор документа и только до регистрации. Права
  проверяются на сервере. В старой системе файл мог удалить любой, кто знал ссылку.
- 38,6 тыс. файлов старой системы при переносе переименовываются по тому же правилу (§11).

## 7. Архив

- **Номенклатура дел ведётся на год** (§1.12). У типа задано дело по умолчанию.
- **«Сдать в дело»** нажимает регистратор или архивариус, когда исполнение и отправка
  закончены. Дело подставлено из типа, его можно сменить. Документ переходит в этап «В деле»
  (`ДО-28`).
- Документ без бумаги (пришёл по e-mail или СЭД, бумажного оригинала нет) сдаётся в дело без
  места хранения.
- **Журнал выдачи оригинала:** кому выдан, до какого числа, когда возвращён. Если оригинал не
  вернули к сроку, получившему приходит задание «вернуть оригинал» (§10.1).
- Сдача в дело закрывает документ для правки по существу. Исправление реквизита (§2.5) и
  добавление файлов остаются доступны: исправленная опечатка не возвращает документ из дела.
- Срок хранения — реквизит дела. Уничтожение по истечении срока хранения в этой волне не
  моделируется (§14, долг 5).

## 8. Права и видимость

### 8.1. Права на действия (`ДО-24`)

| Действие | Кто |
|---|---|
| Создать черновик исходящего или внутреннего | любой сотрудник |
| Создать черновик входящего, зарегистрировать, исправить, аннулировать, отметить отправку и вручение | роль **«Регистратор»** (отправку по e-mail может отметить и автор) |
| Согласовать | согласующий, которого назначил автор |
| Подписать | подписант с правом подписи на тип на дату (§8.2) |
| Дать резолюцию | получатель документа или исполнитель резолюции выше |
| Отметить исполнение резолюции | ответственный по ней |
| Подтвердить на контроле | контролёр |
| Ознакомиться | получатель в режиме «на ознакомление» |
| Сдать в дело, вести журнал выдачи оригиналов | роль **«Архивариус»** (сдать в дело может и регистратор) |
| Вести справочники типов, фраз, способов, номенклатуру, право подписи | роль **«Администратор документооборота»** |

**Все права проверяются на сервере.** Скрытая кнопка правом не считается. В старой системе
состояние приходило скрытым полем формы, а админский редактор открывался любым
залогиненным (легаси §7).

### 8.2. Право подписи

- Справочник «право подписи»: сотрудник × типы документов × основание × срок «с — по».
- У автора в списке подписантов только те, у кого на сегодня есть право на тип документа.
- На шаге «Подписать» право проверяется ещё раз, на дату подписи. Если доверенность истекла,
  документ возвращается автору выбрать другого подписанта.
- **Замещающий подписывает за замещаемого** на срок замещения, **только если это прямо указано
  в приказе о замещении** (`ДО-24`): приказ в «Сотрудниках» несёт признак «с правом подписи»
  (`ДО-ДС-8`). Тогда замещающий подписывает те же типы, что замещаемый. Замещение без этого
  признака права подписи не даёт (`ДО-36`).

### 8.3. Видимость (`ДО-12`)

Документ видят:

1. участники в любой роли (§1.3);
2. руководитель — документы подчинённых по оргструктуре на дату;
3. замещающий — то же, что замещаемый, на срок замещения;
4. канцелярия (роль «Регистратор») и руководство (перечень должностей задаёт администратор) —
   все документы;
5. кто видит объект привязки — не видит документ автоматически. Вкладка «Документы» в
   карточке кредита показывает только то, что смотрящему видно по пп. 1–4.

Чувствительные документы (кадровые приказы, ПДн) в этой волне не выделяются: вопрос
`ДО-ВЗ-5` (§14).

## 9. Журналы, поиск, показатели

### 9.1. Журналы и поиск (`ДО-33`)

- **Журналы:** Входящие · Исходящие · Внутренние · «Мои» (где я участник). По умолчанию новые
  сверху.
- «Мои» — это журнал, а не очередь работы. Работа «на мне» живёт в модуле «Задания».
- **Поиск одной строкой** по реквизитам: номер (новый и старый), номер корреспондента, тема,
  отправитель или адресат, ИНН или имя заёмщика, номер кредита.
- **Группировка** по типу, этапу, отправителю, исполнителю, отделу и месяцу, с итогами по
  группам.
- **Наборы фильтров** можно сохранять.
- **Печатная форма журнала** с фильтром по типу заменяет «отдельный журнал по шаблону» (§3.2).
- Поиска по тексту сканов (OCR) нет.

### 9.2. Показатели ТЗ 711–721

Считаются в модуле «Статистика» новой записью реестра объектов — объект **«документ»**
(`ДО-26`, ADR-0272). Документооборот отдаёт множество документов и их реквизиты на дату и
своих витрин не строит.

| Показатель ТЗ | Как считается |
|---|---|
| внутренних / входящих / исходящих | зарегистрированные в периоде, по виду; аннулированные — отдельной строкой |
| в работе | зарегистрирован, не исполнен, не аннулирован |
| в работе с истёкшим сроком | в работе, и действующий срок хотя бы одной открытой резолюции верхнего уровня прошёл |
| исполнено | исполнение завершено в периоде |
| исполнено в срок | дата исполнения не позже действующего срока (с учётом продлений); отдельной строкой «из них с продлением» |
| исполнено с опозданием | дата исполнения позже действующего срока |
| отказано в исполнении | резолюция верхнего уровня «Отказать» или окончательный отказ подписанта |
| процент исполнения | исполнено в срок ÷ исполнено |

- **Дата исполнения**: для «требует ответа» — дата отправки ответа отправителю; иначе — дата
  исполнения последней резолюции верхнего уровня.
- **Возврат на доработку отказом не считается.**
- **Окончательный отказ подписанта** — черновик, удалённый автором после отказа подписанта.
- **Аннулированные** — отдельной строкой, в остальные показатели не входят.
- **Исходящий** «исполнен», когда отправка закончена (§5); срока у него нет, и в «в срок» или
  «с опозданием» он не попадает.

## 10. Швы с соседними модулями

### 10.1. Задания — шаги документа (`ДО-29`, ADR-0271)

**Каждый шаг, ждущий конкретного человека или роль, — задание модуля «Задания»** с видом
повода семейства «документ». Документооборот отвечает на опрос заданий, отдаёт полное
множество поводов на дату и гасит повод, когда шаг выполнен. Уведомления, просрочку,
продление, переназначение и замещение даёт модуль «Задания» (ADR-0230). Своей очереди
«на мне» в документообороте нет.

**Виды повода** (владелец — документооборот):

| Вид повода | Объект ключа | Адресат | Срок | Повод отпадает, когда |
|---|---|---|---|---|
| `doc-revise` доработать черновик | документ | автор (из повода) | 3 р.д. | документ снова отправлен на согласование или удалён |
| `doc-approve` согласовать | документ × согласующий | согласующий (из повода) | 2 р.д. | согласовал или отказал; круг сброшен |
| `doc-sign` подписать | документ | подписант (из повода, лично) | 2 р.д. | подписал или отказал |
| `doc-register` зарегистрировать | документ | **очередь роли «Регистратор»** | 1 р.д. | зарегистрирован |
| `doc-dispatch` отправить | документ | очередь роли «Регистратор» | 2 р.д. | отправка закончена (§5) |
| `doc-review` рассмотреть входящий (дать резолюцию) | документ × получатель | получатель (из повода) | 2 р.д. | получатель дал резолюцию или отметил «к сведению» |
| `doc-execute` исполнить резолюцию | резолюция × исполнитель | ответственный или соисполнитель (из повода) | **собственный срок резолюции** | исход резолюции поставлен; для «требует ответа» — ответ отправлен |
| `doc-control` подтвердить на контроле | резолюция | контролёр (из повода) | 2 р.д. | контролёр подтвердил или вернул |
| `doc-acquaint` ознакомиться | документ × получатель | получатель (из повода) | 3 р.д. | отметка «Ознакомлен» |
| `doc-file` сдать в дело | документ | очередь роли «Архивариус» | 5 р.д. | документ в деле |
| `doc-return` вернуть оригинал | выдача | получивший оригинал (из повода) | срок выдачи | оригинал возвращён |

Сроки 2/3/5 р.д. — значения правил по умолчанию. Их меняет администратор заданий записью
правила, а не правкой кода.

**Как это ложится на механизм заданий** (уточнения ADR-0210/0227/0228/0262, принятые в
ADR-0271):

1. **Адресат назван поводом** (`ДО-36`). У вида повода «документ» адресат приходит в самом
   поводе: согласующего выбрал автор, ответственного — автор резолюции. Формула кураторства
   из ADR-0262 к этим видам не применяется. Замещение из «Сотрудников» применяется как обычно.
   Исключение — `doc-sign`: адресат помечен «лично», замещающего подставляет сам
   документооборот, и только по приказу о замещении с признаком «с правом подписи» (§8.2).
2. **Очередь роли** (`ДО-37`). `doc-register`, `doc-dispatch` и `doc-file` адресованы роли, а
   не человеку. Задание видят все носители роли. «Взять в работу» закрепляет исполнителя. Если
   задание в очереди просрочено, эскалация идёт руководителю подразделения, к которому
   относится роль (канцелярия), а за ним — администратору документооборота.
3. **Исполнение — отпадением повода с атрибуцией** (`ДО-35`). Шаг делается в карточке
   документа, а не кнопкой «сдано» в заданиях. Повод отпадает и несёт, кто выполнил шаг.
   Выполнил адресат задания или действующий за него — исход **«исполнено»** без заявки в
   заданиях. Выполнил кто-то другой (например, регистратор зарегистрировал документ из чужой
   очереди) — исход тоже «исполнено», с пометкой «выполнил другой». Если повод исчез, потому
   что документ аннулирован или удалён, — исход **«снято»** с причиной. Разбора «отпало»
   у видов «документ» не бывает: у документооборота всегда известно, почему шаг закончен.
4. **Опрос по документу — частый** (`ДО-34`). Вид повода «документ» объявляет частоту опроса
   **5 минут** вместо ночного прогона. Согласование, которое появляется у человека только
   завтра, не работает. Принцип PULL не меняется: задания по-прежнему спрашивают, а
   документооборот только отвечает.
5. **Повтор после возврата.** Второй круг согласования приходит тем же ключом
   «документ × согласующий». Закрытое задание не переоткрывается, рождается новое «повтор
   после З-…» (ИЗ-24). Счётчик повторов показывает, сколько кругов прошёл документ.
6. **Свёртка** (ИЗ-26). Пачка из сотни бланков на подпись приходит одним вал-заданием по
   порогу вида повода. Подписывать её можно пачкой одним действием, но в журнал каждого
   документа подпись пишется отдельно (`ДО-41`).

### 10.2. Отчётность — бланк становится черновиком исходящего (`ДО-11`, ADR-0268)

- Бланк, выпущенный окончательно с названным получателем, **становится черновиком
  исходящего** в документообороте. Pdf-снимок прикладывается с ролью «проект», объект бланка
  становится привязкой, получатель — адресатом, тип исходящего задан шаблоном бланка.
- **Номер выдаёт журнал исходящих при регистрации** (§3.3), а не серия шаблона в момент
  выпуска. Серия исходящих на шаблоне бланка, ручная серия и диапазоны ручной серии
  упраздняются для бланков, которые уходят как исходящие.
- **Рабочая бумага** (график погашения, ADR-0223) черновиком исходящего не становится, номера
  не получает и остаётся как была.
- Служебная записка, выпущенная бланком, становится черновиком **внутреннего** документа
  (ряд ВН).
- Неизменность сохраняется: снимок «Отчётности» морозит числа, документооборот хранит
  подписанный скан. Документ ссылается на выпуск, а выпуск — на документ.
- Пачка выпусков даёт пачку черновиков с общим маршрутом (§10.1 п. 6).

### 10.3. Взыскание — мера читает документ (`ДО-31`, ADR-0270)

- У вида меры появляется реквизит **«документ документооборота»**: исходящий · входящий ·
  внутренний · не требуется. Он согласован с источником вида меры: «наш документ» — исходящий
  или внутренний, «входящий документ» — входящий.
- Мера такого вида **регистрируется из документа**: действием «Зарегистрировать меру» в
  карточке документа либо выбором документа в форме меры.
- **Мера читает из документа:**

  | Поле меры | ← из документа |
  |---|---|
  | номер | регистрационный номер |
  | событие (дата меры) | дата документа |
  | получение (входящий документ) | дата поступления |
  | направлено (дата · канал) | дата и способ отправки адресату-должнику |
  | вручено (дата · подтверждение) | дата вручения адресату-должнику и подтверждающий файл |

  Форма меры этих полей не принимает. Исправление даты в документе мера видит сразу, след
  остаётся в журнале документа.
- **Адресат-должник** — та строка отправки, чей адресат совпадает с обязанным лицом цели меры
  (ADR-0024). Если мера на двух целях, у неё две строки доставки, по строке отправки на
  каждого.
- Набор каналов у вида меры (ADR-0034 п. 3) остаётся реквизитом вида, но его значения берутся
  из справочника способов отправки документооборота (`ДО-40`).
- Регистрация меры (системный штамп, ADR-0039 п. 2) остаётся штампом момента сохранения меры.
  Дата регистрации документа — другой штамп, и они не сливаются.
- Меры по документам, перенесённым из старой системы, и меры видов с признаком «не требуется»
  ведутся как сейчас.

### 10.4. Статистика (`ДО-26`, ADR-0272)

Объект «документ» в реестре объектов статистики (ADR-0149 §4 пересмотрен). Одна строка на
документ на дату. Разрезы: вид · тип · этап · подразделение автора · отправитель (вид) ·
исполнитель · месяц регистрации · из старой системы. Показатели — §9.2. Срок и продление
резолюций статистика берёт у заданий по ключу повода `doc-execute`.

### 10.5. Сотрудники и оргструктура

Документооборот берёт:

- код отдела на дату регистрации (номер, §3);
- руководителя по цепочке и замещение на дату (видимость, §8.3);
- должность автора (поле ТЗ «должность исполнителя»).

Справочник права подписи ведёт сам документооборот. Признак «с правом подписи» у приказа о
замещении ведут «Сотрудники» (`ДО-ДС-8`).

### 10.6. Карточки объектов

Заёмщик, кредит, фаза взыскания, договор залога, объект имущества — вкладка «Документы» по
привязке (§1.5). Своего списка документов карточка не ведёт.

## 11. Перенос из старой системы (`ДО-5`, `ДО-32`)

- Переносится всё **только для чтения**: 74 тыс. документов, 38,6 тыс. файлов, журнал
  действий (342 тыс. записей), история задач (273 тыс.). Все с пометкой «из старой системы».
- **Открытые задачи старой системы (86 тыс.) при переносе закрываются** и заданиями не
  становятся.
- Старые документы **сохраняют свои номера, включая дубли** (5 входящих и 2 исходящих в одном
  году). Уникальность проверяется только среди новых номеров.
- **Счётчики текущего года** (входящий, исходящий) ставятся на максимум, выданный старой
  системой в этом году. Новая система продолжает со следующего номера. Ряд ВН начинается
  с 1: в старой системе внутренние документы нумеровались по подразделениям.
- Тип: все входящие получают тип «Документ (из старой системы)». Старые виды 4–7 становятся
  типами: 35 «Претензий» — исходящими типа «Претензия», 1 акт сверки — исходящим типа
  «Акт сверки» (`ДО-25`).
- Файлы переименовываются по правилу §1.7.
- Обязательная привязка к перенесённым не применяется. Косвенные связи старой системы
  (контрагент как отправитель или адресат, «Информация» по объекту) переносятся привязками
  там, где их можно установить однозначно, — §14, долг 4.
- Поиск по старому номеру работает (§9.1).

## 13. Что решено и почему

### 13.1. Решения разбора (`ДО-1`…`ДО-33`)

Полные формулировки — `requirements/legacy/09-docflow.md` §13 (п. 1–14 = `ДО-1`…`ДО-14`) и §15
(п. 1–19 = `ДО-15`…`ДО-33`). Здесь — решение и причина.

| № | Решение | Почему |
|---|---|---|
| `ДО-1` | Спад 2026 года — меньше работы, учёт полный | данные старой системы можно считать полными при переносе |
| `ДО-2` | Регистратор — роль на нескольких сотрудниках; входящий журнал один на организацию | сейчас все 37 тыс. входящих завёл один человек |
| `ДО-3` | Внутренний документооборот делается полностью | ТЗ 914–948; за 7 лет в старой системе 37 документов — потому что механизм не работал |
| `ДО-4` | Архив бумаги делается и связан с документом | в старой системе реестр архива пуст и ни с чем не связан |
| `ДО-5` | Перенос всего только для чтения; открытые задачи закрываются | 86 тыс. висящих задач — не работа, а мусор |
| `ДО-6` | Документ привязывается к нескольким объектам | ТЗ 635: исходящий обязан знать своё дело |
| `ДО-7` | Поручения — в модуле «Задания» | второй список дел запрещён ADR-0210 |
| `ДО-8` | Исходящий: `<код отдела>/<сквозной номер>`, с 1 каждый год по правилу | так канцелярия работает уже семь лет |
| `ДО-9` | Согласование параллельное; подписант после всех; отказ — автору | в старой системе отказ терялся |
| `ДО-10` | Подпись — отметка в системе; бумага подписывается руками; ЭЦП позже | без ЭЦП электронная подпись юридически ничего не значит |
| `ДО-11` | Бланк с получателем — черновик исходящего; номер даёт журнал | два источника номера исходящих — дыры и дубли |
| `ДО-12` | Видимость: участники, руководитель, замещающий, канцелярия и руководство | в старой системе администратор не видел чужого, а по ссылке видел любой |
| `ДО-13` | Отправка по каждому адресату с датой вручения, дата уходит во взыскание | от вручения зависит пакет в ДПО (п. 20.1 Порядка) |

| `ДО-15` | Этап хранится, исполнение выводится из заданий | как ADR-0227: итог выводится, а не хранится |
| `ДО-16` | Одна цепочка этапов; «Отправлен» — не этап | отправка по адресатам не укладывается в одно значение |
| `ДО-17` | Черновик удаляется, зарегистрированный — только аннулируется; «Исправить» с журналом | номер — обязательство перед журналом канцелярии |

### 13.2. Решения сборки (`ДО-34` — из ТЗ 23, `ДО-35`…`ДО-44` — канона) — на подтверждение

Эти решения не прозвучали в разборе прямо, но без них модель не собирается. Каждое выведено
из решений выше. Если какое-то не подходит, модель от этого не ломается: меняется
соответствующий пункт.

| № | Решение | Почему так | Что отвергнуто |
|---|---|---|---|
| `ДО-34` | Поводы «документ» опрашиваются каждые 5 минут, а не ночью (принято в ТЗ 23) | согласование, пришедшее завтра, не работает | push от документооборота в задания — нарушает ИЗ-2 |
| `ДО-35` | Шаг делается в карточке документа; задание закрывается отпадением повода с атрибуцией, исход «исполнено» | иначе каждое согласование в карточке давало бы «отпало — ждёт разбора» | кнопка «сдано» в заданиях дублирует действие в документе |
| `ДО-36` | Адресат приходит в поводе; формула кураторства не применяется; подпись — «лично», замещение только по праву подписи | согласующего выбрал автор, а не кураторство | вычислять адресата формулой правила — правило не знает, кого выбрал автор |
| `ДО-37` | Регистрация, отправка и сдача в дело — задания на очередь роли; «взять в работу» закрепляет исполнителя | регистраторов несколько, кто свободен, тот и берёт | назначать регистратора по кругу — канцелярия так не работает |
| `ДО-38` | Номер исходящего ставится после подписи штампом на подписанном экземпляре; снимок «Отчётности» номера не несёт | номер получает только подписанное, а снимок морозит то, что подписывали | впечатывать номер в замороженный pdf — правка снимка |
| `ДО-39` | Мера взыскания регистрируется из документа по реквизиту вида меры «документ документооборота» | ТЗ 635 и `ДО-31` вместе | мера со своими полями дат и ссылкой «для справки» — две правды |
| `ДО-40` | Справочник способов отправки — один, у документооборота; состав подтверждения — реквизит способа | у взыскания и документооборота были бы два списка каналов | оставить `DELIVERY_PROOF` во взыскании — документ отправляется до того, как стал мерой |
| `ДО-41` | Пачка бланков — пачка черновиков с общим маршрутом; подпись пачкой, запись по каждому | 11 тыс. уведомлений в год | пачка как один документ — у каждого письма свой адресат и своя доставка |
| `ДО-42` | «Исправить» не трогает вид, тип, номер и дату регистрации | от них зависят ряд, привязка и дело | разрешить правку типа — меняется обязательная привязка задним числом |
| `ДО-43` | Объект статистики — документ; резолюция отдельным объектом не заводится | показатели ТЗ — о документах | объект «резолюция» — второй счётчик той же работы рядом с заданиями |
| `ДО-44` | Шаги по принципу `ДО-29` сверх перечисленных в §15 п. 15: доработать черновик, отправить, рассмотреть входящий, сдать в дело | каждый ждёт человека или роль | оставить их без заданий — они повиснут, как 86 тыс. задач старой системы |

## 15. Словарь терминов

| Термин | Значение |
|---|---|
| **Документ** | запись документооборота одного из трёх видов: входящий, исходящий, внутренний |
| **Вид документа** | одно из трёх значений, зашитых в модель |
| **Тип документа** | строка справочника внутри вида: претензия, иск, приказ… |
| **Этап** | хранимое положение документа в цепочке Черновик → Согласование → Подпись → Зарегистрирован → В деле (или Аннулирован) |
| **Регистрация** | выдача номера из ряда вида; с неё документ существует для журнала канцелярии |
| **Ряд номеров** | счётчик вида на год |
| **Аннулирование** | вывод зарегистрированного документа из оборота с основанием; номер остаётся занятым |
| **Исправление** | правка опечатки в реквизите с записью «было/стало» |
| **Резолюция** | поручение по документу: автор, текст, один ответственный, соисполнители, срок |
| **Каскад резолюций** | резолюция исполнителя ниже по дереву; её срок не позже срока родительской |
| **Требует ответа** | флаг входящего: исполнен, когда ответ отправлен отправителю |
| **На контроле** | флаг: исполнение подтверждает названный контролёр |
| **Привязка** | ссылка документа на объект системы (заёмщик, кредит, фаза…) |
| **Отправка** | строка доставки исходящего одному адресату: способ, дата, вручение или возврат |
| **Право подписи** | строка справочника: кто, какие типы, на каком основании, на какой срок |
| **Номенклатура дел** | перечень дел года с индексом, сроком и местом хранения |
| **Сдача в дело** | перевод исполненного и отправленного документа в этап «В деле» |
| **Выдача оригинала** | строка журнала: кому выдан бумажный оригинал и до какого числа |
| **Очередь роли** | задание, адресованное роли; исполнителем становится взявший его |
