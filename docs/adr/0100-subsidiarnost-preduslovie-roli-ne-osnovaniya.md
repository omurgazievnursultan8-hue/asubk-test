# Субсидиарность — предусловие роли, а не только основания «привлечение обеспечителя»

**Статус:** принято · 2026-08-06 · модуль «Взыскание задолженности» · уточняет
[ADR-0050](0050-osnovanie-otkrytiya-rekvizit-trebovaniya.md) и
[ADR-0005](0005-poruchitelstvo-obespechitelnyy-dogovor.md), опирается на
[ADR-0045](0045-predusloviya-vida-vmesto-konturnoy-lestnicy.md)

[ADR-0050](0050-osnovanie-otkrytiya-rekvizit-trebovaniya.md) записал: «субсидиарность
становится предусловием **этого основания**» — имея в виду одно значение словаря,
«привлечение обязанного лица по обеспечительному договору». Формулировка привязала
предусловие к конкретному пункту меню, а не к лицу.

Прочитанная буквально, она оставляет дыру. У субсидиарного поручителя без подтверждённого
отказа заёмщика нет права быть обязанным по кредиту вообще — но открыть требование к нему
можно тремя другими путями, которые про субсидиарность ничего не спрашивают: заявить его
личное банкротство (второе основание словаря) или его ликвидацию/смерть/безвестное
отсутствие (третье). Оба ставятся вручную тем же человеком, что выбирает основание —
ничто не мешает выбрать любое из них вместо запрещённого четвёртого и получить тот же
результат в обход предусловия.

## Решение

**Предусловие субсидиарности гейтит роль, а не основание.** Пока по договору
поручительства не зафиксирован отказ основного должника, это лицо **не является
обязанным лицом по этому кредиту** ни для одной строки закрытого словаря
([ADR-0050](0050-osnovanie-otkrytiya-rekvizit-trebovaniya.md)) — не только для
«привлечение обеспечителя». Список подходящих кредитов, из которого куратор открывает
требование, обязан исключать такую строку целиком, а не отклонять её только при выборе
одного конкретного значения. При солидарной ответственности предусловия нет с самого
начала — оно бессмысленно и для любого из четырёх оснований разом.

Формулировка ADR-0050 «предусловием **этого** основания» читается впредь как «предусловием
**роли**, которое чаще всего впервые встречается на этом основании» — практика открытия не
меняется (второе требование по-прежнему обычно рождается решением привлечь обеспечителя),
меняется только то, где стоит проверка: не в обработчике одного пункта меню, а в самом
источнике списка обязанных лиц по кредиту.

## Отвергнутые варианты

**Оставить проверку внутри обработчика основания №4.** Отвергнут: дыра описана выше — два
других ручных основания её обходят, а бумажный запрет («в форме основания №4 есть
предупреждение») ничего не мешает открыть требование мимо формы.

**Проверять на сабмите формы, а не на этапе построения списка.** Отвергнут: список
подходящих кредитов уже обязан приходить очищенным от недопустимых строк — там же, где он
исключает кредиты с уже открытым требованием и кредиты вне работы. Показать строку и
отклонить её только после клика — рассинхрон с уже принятым правилом того же списка и
лишний повод для жалобы «почему нельзя, можно же было выбрать».

## Последствия

- Список подходящих кредитов при ручном открытии требования (`docs/tasks/p14-collection-tasks.html`,
  P14-R29) строит фильтр по обеим причинам одним проходом: дедуп по паре «кредит × лицо» и
  предусловие субсидиарности по роли — обе на этапе построения списка, не на сабмите.
  P14-R8 сохраняет только автоматическое основание «просрочка».
- Термин «Ответственность поручителя» в [CONTEXT.md](../../CONTEXT.md) не меняется — ось
  «вид» (солидарная/субсидиарная) была определена верно; расширена запись термина
  «Обязанное лицо», где предусловие названо явно.
