# Производный транш не расходует сумму договора

**Статус:** принято · 2026-08-12 · модуль «Кредиты» · частный случай
[ADR-0001](./0001-proizvodnye-ne-hranyatsya.md) · применяет
[ADR-0092](./0092-restrukturizaciya-delit-transh-perenos-datirovan.md) (транш рождается
освоением либо разделением по ДС; перенос — датированная операция) к гейту `Г-3`

## Контекст: гейт считает траншы, а деньги считает освоение

`Г-3` — гейт создания транша: сумма транша не может вывести Σ сумм траншей за сумму договора.
Он же кормит две плитки вкладки «Транши» — «Распределено по траншам» и «Доступно к
распределению» (`mockups/loan-credit/credit.html:4587–4589`):

```js
const allocated   = c.tranches.reduce((a,t) => a + (t.amount || 0), 0);
const allocatable = c.contractAmount - allocated;
```

Пока транш рождался только освоением, «сколько траншей завели» и «сколько договора роздано»
были одним числом. `ADR-0092` их развёл: производный транш несёт **перенесённую** базу, а не
новую выдачу. С его появлением `Σ t.amount` растёт без единого нового сома по договору —
и гейт начинает врать в обе стороны. Он рапортует превышение суммы договора там, где выдача не
менялась, и запрещает завести транш, деньги под который по договору есть.

Разделение по ДС при этом приходит зеркалом и человеком не заводится (`Р-16`): гейт срабатывает
на данных, которые кредит не создавал и отменить не может.

## Решение: распределение меряется происхождением, а не количеством траншей

`Г-3` и обе плитки видят **только траншы происхождением «освоение»**. Производный транш не
участвует в распределении вовсе — ни в базе, ни в вычете.

Происхождение **выводится** (`ADR-0001`): есть входящий перенос ⇒ транш рождён разделением по
ДС, иначе — освоением. Поля на транше нет; оно завело бы второй источник истины рядом с самим
переносом.

Плитка «Распределено по траншам» получает подпись «+ N производных на X (перенос по ДС, в
распределение не входят)» — когда такие есть. Молчаливое несовпадение двух чисел на экране
хуже, чем явное.

## Отвергнуто

- **Вычитать сумму переноса из `allocated`.** Арифметически сходится, но плитка отвечает на
  вопрос «сколько договора ещё можно раздать», а сумма переноса к этому вопросу отношения не
  имеет. После двух реструктуризаций число перестаёт читаться, и всякий, кто сверит его с
  реестром освоения, получит расхождение без объяснения.
- **Хранить происхождение полем транша.** Прямо против `ADR-0001`: признак выводится из
  переноса, который и так датирован и имеет основание. Поле разъедется с журналом при первой
  же правке.
- **Считать производный транш выдачей.** `ADR-0092` уже отверг это для отчётов об освоении;
  здесь то же для гейта — иначе объём распределения по договору вырастет ровно на величину
  реструктуризаций.
- **Снять `Г-3` вовсе.** Гейт защищает от настоящей ошибки — транша сверх договора при обычном
  освоении. Реструктуризация не повод отменять проверку, которая в своей области верна.

## Последствия

- **Σ сумм траншей кредита может превышать сумму договора, и это нормальное состояние.**
  Первое место модуля, где два натуральных числа расходятся законно; всякий отчёт «сколько
  роздано» обязан считать по происхождению, а не по траншам.
- `Г-8` сюда **не входит**. Вторую ветку — график производного транша строится от даты
  вступления ДС, а не от освоения, которого не будет, — решил `ADR-0092` §1, где производному
  траншу прямо дана дата начала и свой график. Волна её реализует, а не решает.
- Инвариант `И-3` кредита переформулируется отдельно (`ADR-0092` §«Последствия»): у
  производного транша освоений нет, его сумма равна сумме переноса.
- Смоук кредита получает кейс «`Г-3` не видит производных»: без него правка тихо откатится
  первым же рефакторингом `derive`.
