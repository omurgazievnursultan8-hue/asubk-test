# Признак «текущее» лежит в строке массивом имён величин

**Статус:** принято · 2026-09-17 · модуль «Статистика» (служебные колонки строки, волна 22) ·
**исполняет** [ADR-0205](./0205-velichina-neset-priznak-na-datu-ili-tekushchee.md) (`ИС-39`:
признак «на дату / текущее» у каждой величины, строка его хранит) — физическая форма хранения ·
опирается на [ADR-0181](./0181-objectrows-yadro-derzhit-formu-perechislyaet-vladelec.md)
(реквизиты из `objectRows` приходят текущими),
[ADR-0237](./0237-svoya-tablica-strok-u-obekta-kolonku-zavodit-reliz.md) (реестр ссылается на
колонки) · снимает запись первого круга разбора «датировка хранится в реестре» (в репозиторий
не попадала) · долг — `СС-Д17`, `СС-Д18`

**Нумерация:** блок `0237`–`0245`, см. `ADR-0237`.

## Контекст: признак почти всегда один и тот же

`ADR-0205` требует хранить признак рядом с каждой величиной: шов отдаёт одни величины «на
дату», другие — «текущими», и строка обязана это помнить. Первый круг разбора физической
схемы записал признак в реестр — одной пометкой на показатель. `ADR-0205` это прямо
запрещает: признак принадлежит **шву**, и после починки шва он меняется, а реестр остался бы
прежним.

На практике исключений единицы:

- **ночной прогон за сегодня** — «текущее» почти совпадает с «на дату»; исключение —
  величины графика (`РЯ-Д1`: ядро берёт график в сегодняшней редакции);
- **догон и перезапись прошлых дней** — к ним добавляются реквизиты объекта (территория,
  отрасль), которые `objectRows` отдаёт в сегодняшнем виде.

Колонка-флаг на каждую величину давала у кредита около семидесяти колонок, почти всегда
`false`.

## Решение

**В каждой таблице строк — колонка `now_cols text[] NOT NULL DEFAULT '{}'`: имена величин,
собранных в этой строке «текущими». Величина, не названная в массиве, — «на дату».**

1. **Имя величины, а не колонки.** `i_npay` в массиве закрывает и `i_npay_v`, и `i_npay_som`;
   `d_industry` — и `_id`, и `_lbl`.

2. **Массив заполняет прогон по ответу шва.** Величина, у которой шов признака не объявил,
   попадает в массив — «по худшему предположению» (`ADR-0205` §2).

3. **Признак замерзает со строкой** (`ADR-0205` §5). Копия строки на следующий день
   (`ADR-0238` §1) переносит массив как есть; пересчёт строки пишет его заново.

4. **Паспорт считается одним оператором.** Для запрошенных величин:
   ```sql
   SELECT CASE WHEN bool_and(NOT now_cols && ARRAY['i_npay']) THEN 'на дату'
               WHEN bool_and(now_cols && ARRAY['i_npay'])     THEN 'текущее'
               ELSE 'смешанно' END
   FROM stat_row_credit WHERE slice_date = :d;
   ```

5. **Имя сверяется с реестром.** Каждое имя в `now_cols` обязано быть записью реестра этого
   объекта; опечатка ловится сверкой, а не отчётом.

6. **Правило общее для всех одиннадцати таблиц строк**, включая события.

## Отвергнуто

- **Колонка `boolean` на каждую величину.** Около семидесяти колонок у кредита, почти все
  `false`; новая величина — ещё одна колонка-флаг в релизе.
- **Битовая маска по номеру величины.** Читается только через реестр, номер бита закреплён
  навсегда, при разборе строки глазами ничего не видно.
- **Пометка в реестре на показатель.** Запрещено `ADR-0205` («Отвергнуто», последний пункт):
  признак принадлежит шву и меняется после его починки.
- **`jsonb` «величина → признак».** В схеме `jsonb` нет, а массив имён даёт то же одним
  оператором `&&`.

## Границы

- **Не колонка источника.** Источник — на каждого соседа (`src_*`, `ADR-0216` §4), признак —
  на каждую величину (`ADR-0205`, «Границы»).
- **Не отсутствие.** Величина молчавшего соседа — `NULL` и в `now_cols` не попадает: её нет,
  а не «текущая» (`ADR-0208` §1).
- **Не признак фиксации.** Окончательная строка первого числа может нести непустой массив.

## Последствия

- В каждой таблице строк одна служебная колонка `now_cols`.
- Паспорт ответа получает «на дату · текущее · смешанно» по запрошенным величинам без
  обращения к реестру.
- Доля строк с непустым `now_cols` — готовая мера зрелости швов (`ADR-0205`, «Последствия»).
