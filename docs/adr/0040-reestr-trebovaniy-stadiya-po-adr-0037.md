# Реестр требований отражает стадию по ADR-0037; состояние лица — бейдж из журнала, гейт эскалации не трогаем

**Статус:** принято · 2026-07-31 · модуль «Взыскание задолженности» · применяет [ADR-0037](./0037-mashina-faz-vedet-odin-marshrut.md)

Волна ПМ/РМ (29-30.07.2026) сознательно не тронула контуры К0…К7 — вне периметра плана
(`ASUBK-vzyskanie-logika.md:1425`). Ревизия страницы «Требования (реестр)» нашла, что
код списка (`stageOf`/`PHASE_STAGE`/сайдбар/фильтр «Контур→Фаза») всё ещё гоняет
дореформенную модель, а `CONTEXT.md` (§Стадия, §Подгруппа) уже описывает целевую —
конфликт лежал незамеченным с 29.07.2026.

Решено довести список требований до ADR-0037 в отображении, не трогая гейт
регистрации мер:

- **Сайдбар и фильтр.** «Стадия» = 4 канонных значения (наблюдение · досудебный
  порядок · судебный порядок · исполнительное производство); фильтр-пара
  «Контур → Фаза» становится «Стадия → Фаза». Отдельной фильтрации по К2/К5/К6/К7 в
  этой волне нет — при надобности искать по обязанному лицу/тексту.
- **`PHASE_STAGE`.** Фаза «Досудебное урегулирование» получает свою стадию
  «Наблюдение» — раньше молча падала в «Досудебный порядок» через фолбэк
  `stageOf = phase => PHASE_STAGE[phase] || 'Досудебный порядок'`.
- **Состояние лица** (банкротство, правопреемство) — новый факт `p.personState[]` на
  деле, в границах одного дела (проверенной кросс-деловой связки субъекта нет —
  остаётся за периметром волны). Бейдж у столбца «Обязанное лицо» читает журнал мер
  напрямую (вид меры + исход), отдельного флага на мере не заводим —
  `MEASURE_KINDS`/`setsPhase` не трогаем.
- **Отображаемая фаза/стадия** во время активного состояния лица замораживается на
  последней реальной роут-фазе — тем же приёмом, что уже используется для оверлея
  реструктуризации (`displayPhase()`, §3.6). Сырой `phaseOf(r)`, который читает гейт,
  не меняется.
- **Гейт последовательности вех** (`sequenceReason`/`CONTOUR_LEVEL`/`SECTION_CLEVEL`) и
  сам словарь `CONTOURS`/`contourOf` — не трогаем. ADR-0037 сам называет перевод гейта
  на стадию отдельным следствием; это отдельная, более тяжёлая волна — нужно развести
  эскалацию по треку / состоянию лица / исходу порознь, а не одной лестницей К0…К7.
- «Вне-маршрутного» больше нет: К2/К5/К6/К7 не обходят маршрут — они живут в треке
  модуля обеспечения / состоянии лица / терминальном исходе параллельно с ним. Значит
  ни пятого сайдбар-пункта, ни подписи «вне маршрута — контур X» не нужно — обе идеи
  решали до-переводную задачу и снимаются.

## Отвергнуто

**Снять `setsPhase` у мер банкротства/правопреемства заодно.** Ломает
`CONTOUR_LEVEL`-эскалацию: без `setsPhase` `phaseOf(r)` никогда не доходит до фаз К6,
и гейт «Банкротство» перестаёт считать так, как считал раньше. Гейт остаётся на старой
модели до отдельной волны — тронуть только половину было бы хуже, чем не трогать совсем.

## Последствия

- `CONTOURS` перестаёт быть источником отображаемой стадии, но остаётся источником для
  `sequenceReason` — один словарь, два потребителя с разной судьбой до следующей волны.
- Мёртвый `stageOfProc` и стальный 5-й сайдбар-пункт «Отчуждение активов» удаляются;
  `STAGE_RANK` пересобирается под реальные 4 значения.
- §14.1 в `ASUBK-vzyskanie-logika.md` (всё ещё пишет «Контур → Фаза») правится следом.
