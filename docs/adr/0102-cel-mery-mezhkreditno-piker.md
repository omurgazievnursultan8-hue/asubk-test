# Цель меры — межкредитно: состав пикера, дефолт, точка входа

**Статус:** принято · 2026-08-07 · модуль «Взыскание задолженности» · уточняет
[ADR-0002](./0002-vzyskanie-edinica-raboty.md) (многие-ко-многим объявлено в общем виде) ·
опирается на [ADR-0021](./0021-rekvizity-mery-v-razreze-trebovaniya.md),
[ADR-0025](./0025-ohvat-rekvizit-mery.md), [ADR-0029](./0029-ssylka-na-osnovanie-mery-i-rabota-po-celyam.md)

[ADR-0002](./0002-vzyskanie-edinica-raboty.md) уже объявил связь мера↔требование
многие-ко-многим и в числе отвергнутых альтернатив прямо назвал «один иск на трёх
договорах» — своим же примером того, что «процесс = кредит» не выдержал бы. Реализация
(`measureTargetsHtml`, `mockups/collection/collection.html`) построила только половину
этого примера: кандидаты пикера — исключительно `solidaryWith(r)`, солидарные содолжники
**того же** кредита (иск ко всем ответчикам, п. 32). Ось «другой кредит того же лица» из
собственного примера ADR-0002 в пикере не появилась вовсе.

Вопрос вскрылся сравнением с legacy: там одна претензия сама сводила просрочку сразу по
нескольким кредитам заёмщика (МП «Кредит(ы)» — множественное число на карточке фазы,
`requirements/legacy/05-collection.md`). В целевой модели то же самое архитектурно уже разрешено
ADR-0002 — не хватало только пикера, который бы это предлагал.

## Решено

1. **Кандидаты пикера — объединение двух осей, не их произведение.** Ось А (уже
   реализована): другое лицо, тот же кредит — солидарные содолжники, `solidaryWith(r)`.
   Ось Б (новая): тот же человек, другое требование (другой кредит) этого же обязанного
   лица. Пикер = А ∪ Б. Цели, различающиеся **обеими** координатами разом — другое лицо
   **и** другой кредит одновременно — не предлагаются: такой мере не отвечает ни один
   реальный документ, исковое заявление либо ко всем ответчикам одного договора, либо по
   всем договорам одного ответчика, а не к произвольной комбинации людей и кредитов.
2. **Дефолт — только своя цель.** Требование, с карточки которого открыта форма, отмечено
   и заблокировано (снять нельзя). Все прочие кандидаты обеих осей — сняты; куратор
   отмечает вручную. Многоцелевая мера — осознанный выбор при регистрации, не побочный
   эффект дефолта. Ровно то поведение, что уже есть у оси А сегодня (`row(x,false,false)`),
   без исключений для новой оси.
3. **Точка входа — только карточка требования.** Отдельного действия «зарегистрировать
   меру» с карточки дела нет. Оператор всегда стартует с одного конкретного требования и
   расширяет состав целей внутри той же формы.

## Почему

**Объединение, не произведение.** Процессуально не существует документа третьего рода:
претензия/иск/ИЛ либо адресуют состав ответчиков **по одному договору** (солидарная
ответственность), либо состав договоров **одного** ответчика (единая просрочка одного
лица по нескольким кредитам). Комбинация «Иванов по кредиту №1 и Петров по кредиту №2 в
одном исковом» не отвечает ни одному основанию иска — у них нет общего предмета
требования, который годился бы одной формулировкой резолютивной части. Разрешить
произведение — значит дать пикеру рисовать документы, каких не существует.

**Дефолт выключен.** Ось Б расширяет пространство кандидатов заметно шире, чем ось А
(там — только содолжники одного и того же уже открытого договора; здесь — все кредиты
человека, потенциально много). Автоотметка лишнего кредита в мере — не отменяемая задним
числом ошибка (тело меры замораживается регистрацией, [ADR-0027](./0027-mera-odin-dokument-pometki-rekvizity.md)):
куратор, открывший форму с карточки кредита №1, не должен рисковать неосознанно завести
иск и по кредиту №3 с этим же лицом.

**Вход только с требования.** Модуль уже целиком стоит на требовании как единице работы
([ADR-0002](./0002-vzyskanie-edinica-raboty.md)): гейт, форма, пометки — всё ключуется от
`curReq`. Отдельная точка входа с карточки дела повторила бы вычисление кандидатов,
дефолта и гейта на другом объекте ради возможности, которую и так даёт требование теперь,
когда ось Б открыта. Второй вход — второе место, которому нужно синхронно повторять
правило 1 и правило 2.

## Отвергнутые варианты

**Точка входа с карточки дела** («зарегистрировать меру» без стартового требования,
пикер — все требования дела разом). Отвергнут по правилу 3: не даёт ничего, чего не даёт
требование-первый вход после открытия оси Б, зато требует отдельной реализации гейта и
дефолта.

**Пикер как произведение осей** (любая комбинация лиц и кредитов дела). Отвергнут по
правилу 1: результату не соответствует ни один реальный тип документа; усложняет охват,
исход и гейт по цели ([ADR-0025](./0025-ohvat-rekvizit-mery.md),
[ADR-0103](./0103-ishod-mery-rekvizit-svyazi.md), [ADR-0029](./0029-ssylka-na-osnovanie-mery-i-rabota-po-celyam.md))
комбинаторно, без единого реального сценария, который требовал бы именно комбинации.

## Последствия

- `measureTargetsHtml` и `renderMClaims` (`mockups/collection/collection.html`) — оба
  места сегодня строят список кандидатов через один и тот же `solidaryWith(r)`; обоим
  нужна ось Б, независимо друг от друга (два разных рендера одного и того же состава
  целей).
- Гейт-исключение по цели ([ADR-0029](./0029-ssylka-na-osnovanie-mery-i-rabota-po-celyam.md),
  правило 4) из краевого случая (все цели — один кредит, обычно одна фаза на всех)
  становится частым: цели оси Б рутинно расходятся по фазе, паузе, состоянию дела.
  Реализация `saveMeasure`/`measureTargetsHtml` по этому правилу — самостоятельная задача,
  ADR её не создаёт заново, он уже принят.
