# Уведомлений двенадцать: переадресация и два вида о продлении срока

**Статус:** принято · 2026-10-05 · модуль «Задания» · **расширяет** закрытый список
[ADR-0230](./0230-granicy-podsistemy-uvedomleniya-vnutri-audit-i-chislo-snaruzhi.md)
(`ИЗ-14`) штатным путём, который тот сам назвал · `ЗН-4`, `ИЗ-21`

**Нумерация:** `0263` — следующий за `0262`. Проверено 05.10.2026.

## Контекст

`ADR-0230` закрыл список из девяти уведомлений: «не пополняется без отдельного решения».
Волна 5 добавила три события, о которых человек обязан узнать:

| событие | кому | цена молчания |
|---|---|---|
| переадресовано (`ЗН-2`, `ЗН-6`) | прежнему исполнителю | двойная работа или два человека на одном объекте |
| запрошено продление (`ЗН-3`) | утверждающему | запрос висит до повода самоопроса через 1 р.д. |
| решение по продлению (`ЗН-3`) | исполнителю и контролёру | исполнитель не знает, какой срок действует |

## Решение

Список расширен до **двенадцати**:

| # | уведомление |
|:--:|---|
| 1–9 | прежние: повод появился · поручено · принято · срок близко · срок истёк · эскалация · возвращено · повод отпал · закрыто |
| 10 | **переадресовано** — прежнему исполнителю (новому уходит «поручено») |
| 11 | **запрошено продление** — утверждающему |
| 12 | **решение по продлению** — исполнителю и контролёру; текст говорит «утверждено / отклонено» и действующий срок |

«Срок близко» и «срок истёк» шлются однократно **на каждый установленный срок**: утверждённое
продление открывает их заново.

## Почему не иначе

- **Втиснуть в девять** («решение по продлению» как «поручено» с новым сроком) — подмена смысла
  вида; исполнитель прочтёт новую работу вместо ответа на свой запрос.
- **Без уведомлений** — очередь показывает состояние, но не будит человека.

## Последствия

- Список остаётся закрытым: тринадцатый вид — снова ADR.
- Макет: три новых вида в закрытом списке и проверка «вне списка — ошибка».
