# Кредит публикует очередь погашения; допущение Д-8 снимается лестницей (P15-R24)

Дата: 10.08.2026 · Мокап: `mockups/loan-credit/credit.html` · Основание:
[`ADR-0060`](../../adr/0060-transh-schet-oblast-ochered.md) §3 и §4 · Задача:
`P15-R24` в `docs/tasks/p15-kredit-tasks.html`.

Область правки: расчётный слой (`buildLedger` в части замораживания начисления, три
новые чистые функции), контракт `derive()` (+`queue`), вкладка «Платежи», шапка макета,
`scripts/inspect/credit-check.mjs`, `mockups/payments/ASUBK-platezhi-logika.md` §12,
`mockups/loan-credit/ASUBK-status-razrabotki.md`. **Не трогаем:** модель кредита,
`overdueOf` / `riskBasisOf` / категорию риска, `payments.html`, гейты.

## Задача

`ADR-0060 §4` («Очередь публикует кредит») принят 02.08.2026 — позже, чем собирался
бэклог `P15-R1…P15-R23` (26.07.2026). Публикация очереди не попала ни в одну карточку и
ни в одну строку макета. Обнаружено 07.08.2026 сверкой мокапов: `payments.html` уже
потребляет `DATA.queue` и несёт пилюлю «очередь публикует КРЕДИТ», а в `credit.html`
вхождений `ADR-0060` — ноль.

Четыре дефекта, все проверены на файле 10.08.2026:

1. **Перечня нет.** `credit.html` знает только `bc.queue` — текстовый параметр
   старшинства статей («по договору», `:1532`), выводимый полем на вкладке «Расчёты»
   (`:6358`). Это правило порядка, а не список позиций на дату.
2. **Имя занято не тем.** Поле `bc.queue` подписано «Очередь погашения», хотя
   `CONTEXT.md:241` требует для правила имя **«Очерёдность»** и прямым `_Avoid_`
   запрещает называть его очередью погашения; имя «Очередь погашения» зарезервировано
   за перечнем (`CONTEXT.md:252`).
3. **Шапка утверждает обратное ADR.** Открытый вопрос №4 (`:675`): «очередь и
   разнесение платежа по статьям принадлежат МОДУЛЮ ПЛАТЕЖЕЙ, кредит принимает их
   готовыми». То же на вкладке «Платежи» (`:6414`, `:6405`).
4. **Д-8 жив, хотя ADR его отверг.** Доля долга под решением суда берётся
   пропорцией к телу (`frozenShareAt`, `:3550`; помечено Д-8 в `:656`, `:3547`, `:3586`).
   `ADR-0060 §3` эту пропорцию называет отвергнутой: «врёт предсказуемо — просрочка
   накапливается неравномерно, у старого транша её больше, и пропорция всегда занизит
   его долю». То же в `ASUBK-platezhi-logika.md` §12: «допущение Д-8 отменяется».

Сырьё для перечня в макете уже есть целиком: `buildLedger(c, asOf)` (`:3524`) даёт по
каждому траншу и каждой позиции графика дату наступления и непогашенные остатки
(`principalOverdue`, `interestOverdue`, `penaltyBal`), плюс `feeRows` по комиссиям.
Публиковать нечего изобретать — надо упорядочить и отдать.

## Решение

### 1. Одна лестница, два потребителя

Лестница `ADR-0060 §3` («самое раннее просроченное → дальше») нужна дважды: очереди —
чтобы упорядочить перечень, составу слоя — чтобы распределить присуждённое по траншам.
Две реализации одного правила разошлись бы молча — ровно дефект, ради которого писались
[`ADR-0001`](../../adr/0001-proizvodnye-ne-hranyatsya.md) и `ADR-0060 §4`.

Мешает цикл: `buildLedger` нужен слой строки, чтобы посчитать `interestFrozen` и
`penaltyFrozen` по режиму этого слоя, а назначению слоя нужны непогашенные остатки,
которые считает `buildLedger`. Цикл рвётся тем, что **назначению слоя пеня не нужна** —
только основной долг и проценты. Дешёвая половина обхода выносится вперёд:

```js
/* ЛЕСТНИЦА (ADR-0060 §3) — позиции, наступившие на дату, с непокрытыми остатками ОД и
   процентов, в порядке «самое раннее просроченное → дальше». Ни пени, ни слоёв: этой
   функцией пользуются ДО того, как слой известен. */
function ladderAt(c, date){ /* → [{key, trancheNo, no, date, principalBal, interestBal}] */ }

/* СОСТАВ СЛОЯ — производная НА ДАТУ АКТА, не поле (ADR-0060 §3). Каждое решение суда
   прогоняет лестницу на СВОЮ дату и метит позиции, пока присуждённое не исчерпается.
   asOf нужен только чтобы отсечь решения ПОЗЖЕ даты среза — те же, что уже отсекает
   courtLayersOf; сам обход от даты среза не зависит. */
function layersByLadder(c, asOf){ /* → Map key → layerId */ }
```

`ladderAt` — это первый проход нынешнего `buildLedger`, вынутый и обеднённый.

Позиция достаётся **первому по дате** решению, которое до неё дотянулось: слои идут в
порядке даты акта, каждый следующий начинает обход с уже помеченных позиций и берёт
только непомеченные. Одна позиция принадлежит ровно одному слою — иначе её начисление
подчинялось бы двум режимам сразу.

### 2. `buildLedger` перестаёт делить пропорцией

`frozenShareAt(dt)` (`:3550`) удаляется вместе с `body`, `awardedI`, `awardedP`. Вместо
доли строка получает **свой** слой из `Map`, и режим берётся у этого слоя:

```
было:  r.interestFrozen = r.interestDue * frozenShareAt(pd(r.date)).i    // доля тела
стало: const L = layerOf(r);   // Map.get(r.key) → id, id → запись courtLayers; нет → free
       r.interestFrozen = (!L || L.mode.interest) ? 0 : r.interestCharged
```

То же для пени, с сохранением нынешнего правила «только за дни ПОСЛЕ решения: до него
пеня начислялась по договору и решением не отменяется» (`:3583`). Огрубление «доля на
дату среза, дни от ПЕРВОГО решения» (там же) снимается: у строки теперь ровно один слой
и ровно одна дата решения.

Позиции, не помеченные ни одним слоем, принадлежат **свободному слою** — начисление по
договору, ничего не приостановлено.

### 3. Идентичность слоя

`courtLayersOf` (`:3513`) сегодня возвращает решения без идентификатора —
`{date, kind, il, amount, mode}`. Добавляется `id`: `L-1`, `L-2`… по возрастанию даты
решения (сортировка там уже есть). Свободный слой — `free`.

Строка очереди несёт **и id, и подпись**. В `payments.html` потребитель разворачивает id
через `c.layers` (`payments.html:4094`); у кредита такого справочника в модели нет и
разворачивать некому, поэтому владелец отдаёт готовое имя.

### 4. Контракт `d.queue`

Форма зеркалит `DATA.queue` из `payments.html:1119`, чтобы потребитель читал одно и то же:

```js
{ asOf:'23.07.2026', rows:[
  { due:'05.06.2026', layer:'L-1', layerLabel:'Слой решения от 12.06.2026 · ИЛ №…',
    tranche:1, article:'Основной долг', urg:'over', amount:120000, future:false },
  …
]}
```

Строится `buildQueue(c, ledger, asOf)` и кладётся в возврат `derive()` (`:3997`) рядом с
`ledger`, `debt`, `courtLayers`.

**Что попадает в строки.** Четыре статьи `DEBT_ARTICLES` (`:3689`): основной долг,
проценты, пеня, сборы и комиссии. Расходов по обращению взыскания в очереди нет — они
приходят зеркалом взыскания и в остаток кредита не входят (`:6309`, `ADR-0004`);
публиковать чужое кредит не вправе.

**Ненаступившее.** Позиции графика с датой позже среза идут теми же строками с
`future:true`, `urg:'cur'`, слой всегда `free` — присуждённое их не покрывает по
построению. Так же их показывает `reconQueue` в `payments.html` (серым, «не наступило»).

**Срочность.** `urg:'over'` — наступившее и непогашенное, `urg:'cur'` — ненаступившее.
Третьего значения нет: в макете позиция с прошедшим сроком и непокрытым остатком
считается просроченной сразу (`scheduleRowStatus`, `:3375`).

**Сортировка** — одна, по дате наступления. Внутри даты — по очерёдности статей
(расходы → комиссия → основной долг → проценты → пеня,
[`ADR-0087`](../../adr/0087-ochered-pogasheniya-pyat-statey-snimok-resheniem.md), `CONTEXT.md:241`),
внутри статьи — по номеру транша. `urg` и `future` строку только подписывают и ключами
сортировки не служат: у наступившего дата меньше даты среза, у ненаступившего больше, и
хвост встаёт в конец сам.

**Допущение Д-10** (Д-9 занято, `:662`): комиссии живут на кредите (`c.fees`), транша у
них в модели нет, и в очереди они публикуются строкой «по кредиту». `ADR-0060 §2`
требует, чтобы строка называла транш, но сказано это про строку **разнесения** («иначе
не сойдётся ни леджер транша, ни зеркало кредита»), а не публикации. Выдумывать транш
комиссии макет не станет.

### 5. Экран — секция на вкладке «Платежи»

Секция «Очередь погашения» встаёт **между** «Задолженность по статьям» и «Счета и код
оплаты» (`:6420`). Порядок чтения — «свод → перечень»: агрегат по четырём статьям
сверху, его построчная развёртка снизу. Выше обеих — входящая половина зеркала (сами
платежи), так что двусторонность `ADR-0060 §4` видна одним экраном: наверху **чем
погашено**, внизу **что подлежит гашению**.

Вкладка выбрана не случайно: лестница **межтраншевая по построению** (`ADR-0060 §2` —
«срочность упорядочивает взносы по дате наступления, независимо от того, чьи они»), а
«Платежи» не входят в `SCOPED_TABS` (`:5359`) и всегда показывают кредит целиком. На
«Расчётах» очередь пришлось бы держать не слушающей шапку рядом с гридом, который её
слушает.

**Пилюля — зеркальная, а не та же.** В `payments.html` стоит `публикует КРЕДИТ` —
подпись «откуда взялось». Здесь встаёт `отдаётся в ПЛАТЕЖИ` — «куда уходит».
`lockHtml()` («зеркало») в этой секции не ставится: она собственный вывод кредита, и
замок соврал бы ровно наоборот.

**Колонки:** Срок · Слой · Транш · Статья · Сумма. Срочность — пилюлей под датой, как в
`reconQueue`. Ненаступившие строки серые с подписью «не наступило».

**Подписи среза** — три случая, все уже вычислены в `derive()`:

- обычный — «непогашенное на `cardAsOf`»;
- закрытый кредит (`d.calcStopped`) — очередь публикуется на дату остановки начисления,
  не на дату среза;
- предварительный расчёт (`d.calcProvisional`) — снимок зеркала платежей старше среза,
  значит хвост очереди посчитан по не приехавшим платежам. Та же оговорка, что уже стоит
  на «Расчётах» (`:6285`).

**Инвариант в подвале секции:** Σ сумм строк с `urg:'over'` равна `d.overdueAmount` из
свода выше. Расхождение означало бы, что лестница и `debtOf` разошлись — то самое
молчаливое расхождение двух лестниц, против которого писан `ADR-0060 §4`.

### 7. Что сознательно не делаем

`ASUBK-platezhi-logika.md` §12 к правкам волны 2 добавляет пятую: «дни просрочки
перестают быть числом у кредита — величина принадлежит слою (§6.7)». В макете
`overdueDays` — одно число на кредит, и оно кормит `riskBasisOf` → категорию риска
([`ADR-0012`](../../adr/0012-kategoriya-owned-kreditom-podgruppa-zerkalo.md)) и гейты. Довести §6.7
до конца значит переписать `riskBasisOf`, `overdueOf` и `buildStateFlags` и уронить
smoke в части риска — это далеко за границей `P15-R24`.

Остаток фиксируется дважды, чтобы не повторилась история самой `P15-R24` (ADR приняли,
в бэклог не занесли, дыру нашли случайно пять дней спустя):

- **КР-58** в `mockups/loan-credit/ASUBK-status-razrabotki.md`, статус «отложено»;
- **P15-R25** в `docs/tasks/p15-kredit-tasks.html`, `state:'debt'`, плюс строка реестра
  в `TODO.md` — иначе команда разработки о §6.7 не узнает.
