# Фильтр реестра кредитов — приоритет, ширины, раскладка

Дата: 03.08.2026 · Мокап: `mockups/loan-credit/credit.html` · Область правки: только
блок реестра (`renderList()` / `readFilters()` / `passFilters()` / `resetFilters()`
и CSS `.filter-*`). Модель кредита, `derive()`, колонки грида — не трогаем.

## Задача

Сейчас фильтр реестра — 15 полей в плоской сетке `repeat(4, minmax(0,1fr))`, все
одной ширины, порядок случайный (Заёмщик · Номер · Дата · Область · Район · Программа ·
Куратор · Категория · Подгруппа · ЖЦ · Освоение · Проблемность · Просрочка). Вся панель
свёрнута, включая поиск по заёмщику — самое частое действие в реестре спрятано за кликом.

Три дефекта подачи:

1. **Нет иерархии.** Поиск по заёмщику и «Подгруппа заёмщика» стоят как равные, хотя
   первым пользуются каждый вход, вторым — раз в месяц.
2. **Ширина не связана с содержимым.** Селект со значениями «низкий/средний/высокий»
   получает те же ~280px, что и «Подгруппа заёмщика», где значение вида
   `K-1 · <расшифровка>` в 280px не помещается.
3. **Каскад Область→Район разорван** сеткой: два поля в двух ячейках, при переносе строки
   расходятся по разным строкам.

## Решение

### 1. Два яруса

**Ярус 1 — быстрая строка**, всегда видна, живёт в `.tb-actions` под кнопками действий:

| контрол | ширина | почему здесь |
|---|---|---|
| Поиск: заёмщик · ИНН · № договора | `flex:1`, `min-width:280px` | каждый вход в реестр, все пять ролей |
| ЖЦ договора | 168px | фоновое условие любой работы |
| Куратор | 200px | начальник отдела и куратор — ежедневно |
| кнопка «⚙ Фильтры ·N» | auto, справа | раскрывает ярус 2 |

**Ярус 2 — панель «Фильтры реестра»**, свёрнута по умолчанию, три смысловые строки
в порядке убывания частоты:

- **риск** — Просрочка (от—до) · Проблемность · Категория риска · Состояние освоения
- **привязка** — Программа · Подгруппа заёмщика · Область / Район
- **период** — Дата договора (от—до)

Порядок внутри строки — по значимости слева направо. Строка риска первая: панель
открывают в основном ради неё, остальное — отчётные срезы.

### 2. Два слияния контролов

**`fQ` + `fNum` → одно поле поиска.** Placeholder «Заёмщик, ИНН или № договора».
Ищет по трём токенам сразу: `borrower.name`, `borrower.inn`, `num`. Риск ложного
совпадения («56» найдёт и договор 56, и ИНН, содержащий 56) снимается сортировкой:
точное совпадение по `num` поднимается в начало выдачи.

**`fRegion` + `fDistrict` → одно поле «Область / Район»** с двумя селектами внутри
(вёрстка как у `.range-pair`). Каскад — одно измерение выборки, не два; текущий разрыв
даёт лишнюю ячейку сетки и разъезжается при переносе.

Счёт до и после: контролов 15 → 14, визуальных полей 15 → 11 (3 в быстрой строке,
8 в панели), измерений фильтрации 13 → 12 (слились только `q` и `num`).

### 3. Сетка и ширины

`.filter-body` переводится с `repeat(4, minmax(0,1fr))` на `repeat(12, minmax(0,1fr))`;
каждое поле получает `grid-column: span N` по своему содержимому. При рабочей ширине
панели ≈1154px (грид реестра `min-width:1194px` минус паддинги 2×20px) и `gap:16px`
колонка ≈81px.

```
┌ span3 ─────┬ span3 ─────┬ span2 ──┬ span4 ────────┐
│ Просрочка  │Проблемность│Категория│Состояние      │  риск
│ [от]—[до]  │            │ риска   │освоения       │
├ span4 ─────┼ span4 ─────┼ span4 ──────────────────┤
│ Программа  │ Подгруппа  │ Область / Район         │  привязка
│            │ заёмщика   │ [обл ▾]  [район ▾]      │
├ span4 ─────┴────────────┴────────────┬────────────┤
│ Дата договора  [от]—[до]             │[Сбросить]  │  период
└──────────────────────────────────────┴────────────┘
   259px      259px    178px    340px
```

Обоснование ширин:

| span | px | поля | почему столько |
|---|---|---|---|
| 2 | 178 | Категория риска | «низкий/средний/высокий» — самое длинное значение 7 символов |
| 3 | 259 | Просрочка, Проблемность | пара числовых по ~118px; «Активная реструктуризация» обрежется в закрытом виде, полный текст виден в раскрытом списке |
| 4 | 340 | Состояние освоения, Программа, Подгруппа, Область/Район, Дата договора | «Полностью освоен», названия программ, `K-1 · <расшифровка>`, два `input[type=date]` по ~150px |

Каждая строка закрывается ровно в 12 — дыр от переноса нет.

### 4. Поведение

**Дефолт ЖЦ = «Действует».** Реестр открывается с тем, с чем реально работают; счётчик
пишет «41 из 59».

**Чипы активных условий — обязательное сопровождение дефолта.** CSS `.filter-chips` /
`.fchip` в мокапе уже есть, JS-рендера нет. Включить: чип на каждое активное условие
(`ЖЦ: Действует ×`, `Просрочка: 30—∞ ×`), `×` снимает условие и перерисовывает выдачу.
Чипы видны и при свёрнутой панели. Без чипа молчаливый дефолт прячет закрытые и проектные
кредиты, человек ищет кредит и не находит — самый дорогой сорт ошибки в реестре.

**Счётчик условий чинится.** `activeFilterCount()` считает непустые ключи `filters`,
поэтому заполненный диапазон дат даёт 2 вместо 1, а бейдж показывает «·5» при трёх
заданных условиях. Считать условия, а не поля: пара `dateFrom/dateTo` = 1,
`odMin/odMax` = 1, `region/district` = 1.

## Что не меняется

- Набор значений в списках (программы, кураторы, подгруппы, категории) — строятся из
  данных, как сейчас.
- `passFilters()` — кроме ветки `f.q`, которая начинает искать ещё и по `num`, и удаления
  отдельной ветки `f.num`.
- Колонки грида, сортировки, пейджер, тулбар действий.
- Плитки-пресеты над списком (`.tiles` CSS существует, в реестре не используется) —
  отдельный вопрос, в эту волну не входит.

## Приёмка

1. Быстрая строка видна без раскрытия панели; поиск «Кара-Балта» и поиск «56» оба дают
   непустую выдачу, точное совпадение № 56 стоит первым.
2. Открытие реестра даёт «41 из 59» (или сколько окажется по демо-данным) и чип
   «ЖЦ: Действует»; клик по `×` чипа возвращает 59 из 59.
3. Бейдж на свёрнутой шапке при заданных ЖЦ + диапазоне дат + просрочке показывает «·3».
4. Панель на трёх строках без пустых хвостов; «Категория риска» уже «Программы».
5. «Сбросить фильтры» очищает все 14 контролов, включая объединённый поиск и оба
   селекта каскада, и возвращает ЖЦ к дефолту «Действует».
6. Консоль без ошибок.

Проверка — скриптом `scripts/inspect/` по образцу `credit-list-merge-shot.mjs`.
