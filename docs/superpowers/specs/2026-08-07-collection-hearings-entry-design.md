# Дизайн: интерактивный ввод судебных заседаний (макет «Взыскание», вкладка «Суд»)

**Дата:** 2026-08-07
**Файл макета:** `mockups/collection/collection.html` (единый self-contained HTML/JS)
**Контекст:** [ADR-0026](../../adr/0026-zhurnal-mer-edinstvennyy-istochnik-sostoyaniya.md),
[ADR-0031](../../adr/0031-sudebnoe-proizvodstvo-cepochka.md)

## Проблема

Панель «Суд» (`panelSud()`) показывает две карточки требования: «Судебные акты» и
«Судебные заседания». Акты уже интерактивны — это меры расщеплённого судебного вида,
попадающие в карточку автоматически через обычную форму «Зарегистрировать меру»
(`openMeasureModal`/`saveMeasure`) с полем `basedOn`. У заседаний той же дороги нет:
`hearingsOf(r)` читает `p.hearings[]`, но массив наполняется только затравкой
(`buildSeed`, автоген при `court`+`defendantAppeared` и ручные записи по демо-делам) —
ни формы «назначить», ни формы «внести исход» в макете не существует. Реестр «Заседания
(реестр)» — тоже только чтение того же массива.

Это расходится с явным правилом ADR-0026: заседание — не мера (фазу не двигает), но
собственный факт «состоялось · отложено · кто явился», который куратор обязан заносить
отдельно, ADR-0031 п.4 добавляет — крепится к мере-обращению. Модель это допускает,
ввода нет.

## Цель

Два действия на панели «Суд», по образцу уже существующей пары
«Вынести вопрос» / «Внести решение» (`openCommitteeQuestionModal`/`openDecisionModal`
в `panelKomitety`):

1. **«Назначить заседание»** — новая запись в `p.hearings[]`, без исхода.
2. **«Внести исход»** — по конкретному ещё не закрытому заседанию: явка/участники + исход.

## Не-цель (YAGNI)

- Не трогаем `hearingDeadlines()`/`dlOf()`/реестр «Заседания» — они уже читают
  `p.hearings` вживую (ADR-0001), новые записи появятся в очереди сроков и реестре сами.
- Не заводим новый справочник видов заседания. В коде и так ровно два значения
  (`HEARING_NO_OUTCOME_KINDS` уже их различает): «Извещение о назначении судебного
  процесса» (без исхода по природе) и «Судебный процесс» (с исходом). Форма — жёсткий
  список этих двух, не свободный текст и не расширение набора.
- Не даём редактировать исход после сохранения. Заседание — не мера, сторно-пары у него
  нет, но дисциплина та же: дыра («исход не внесён») закрывается один раз. Если позже
  понадобится исправление — отдельная задача, не в этом заходе.
- Не меняем схему `p.hearings[]` (уже `{measureNum, kind, place, when, participants[],
  outcome}`) и не поднимаем версию `STORE_KEY` — форма только заполняет существующие поля.
- Не заводим отдельный экран/модалку регистрации явки как самостоятельной сущности —
  явка остаётся строкой в `participants` (как в затравке: `"Ответчик явился"` /
  `"Ответчик не явился"`), правится тем же полем, что и «Внести исход».

## Кандидаты «мера-основание»

ADR-0031 п.4: заседание крепится к мере-обращению — иску, жалобе, заявлению. Вместо
нового флага на видах меры используется уже существующая пара полей из справочника
`MEASURE_KINDS`:

```js
const candidates = (curProc.measures||[]).filter(m => {
  if(m.storno) return false;
  const kd = kindOf(m.kind);
  return kd && kd.resultIsDocument && kd.source === 'наш документ'
    && (m.targets||[]).includes(curReq.id);
});
```
(без `?.` — в файле его нигде нет, стиль `kd && kd.поле`, как в `renderMBasedOn`.)

Проверено по справочнику: `resultIsDocument:true` встречается ровно у 13 видов, и все —
в судебном разделе (Исковое заявление, Заявление о выдаче судебного приказа/ИЛ, жалобы
и т.д.). Ложных срабатываний вне судебного трека нет, свой список дублировать не нужно.
Пусто — как у поля «Основание» в форме меры (`renderMBasedOn`): кнопка «Назначить
заседание» выключена, текст «заседание можно будет назначить после регистрации меры
вида … — она ещё не зарегистрирована».

## Модалка «Назначить заседание»

`openHearingModal()`, класс `modal form` (как у вопроса на комитет — форма среднего
размера, не полная `modal measure`). Кнопка — в новом `gtoolbar` над секцией «Судебные
заседания» (тот же паттерн, что у «Вопросы на коллегиальные органы»), видна при
`canRegisterMeasures()` (тот же гейт роли/подразделения, что и у мер — заседание ведёт
тот же куратор дела).

Поля:

| Поле | Виджет | Примечание |
|---|---|---|
| Мера-основание | `select` | кандидаты выше; обязательно |
| Вид события | `select` | «Извещение о назначении судебного процесса» / «Судебный процесс» |
| Место | `input` | название суда, текст |
| Дата | `input type=date` | `dinp()` |
| Время | `input type=time` | новый хелпер `tinp()` по образцу `dinp()` |
| Участники | `textarea` | по строке на участника; первая строка предзаполнена `"<текущая роль> (представитель ФКФ)"` |

Save (`saveHearing()`) блокирован, пока не выбраны мера-основание, вид, место, дата и
время. Пишет:

```js
{ measureNum, kind, place, when: `${ruDate(date)} ${time}`, participants, outcome:'' }
```

в `curProc.hearings` (создаётся, если пуст), лог в `curProc.history` (`"Заседание
назначено: <вид> · <место> · <дата время>"`), затем `closeModal(); renderPanels();` —
персист (`persistState()`) уже вызывается изнутри `renderPanels()`, отдельно дёргать не
нужно.

## Модалка «Внести исход»

`openHearingOutcomeModal(hearingIndex)` — кнопка в новом последнем столбце таблицы
«Судебные заседания» (пустой заголовок, как колонка действия у вопросов на коллегиальный
орган), видна только когда `!hDone(h) && hApplicable(h)` — то есть у прошедших и
предстоящих «Судебных процессов» без исхода, но не у «Извещений» (у них исхода не
бывает — `hApplicable` уже это знает).

Шапка модалки — только чтение (мера-основание, вид, место, дата/время, для контекста).
Редактируемые поля:

- **Участники** — `textarea`, предзаполнена текущим значением; на момент назначения явка
  ещё не известна, здесь дописывается по факту.
- **Исход** — `input`, обязателен (Save блокирован при пустом значении).

Save (`saveHearingOutcome()`) пишет `h.outcome`, `h.participants`, лог в историю
(`"Исход заседания внесён: <исход>"`), `closeModal(); renderPanels();`. Кнопка «Внести
исход» после сохранения у этой строки больше не рисуется (`hDone(h)` стал истинным).

## Затронутые функции

- Новые: `openHearingModal`, `saveHearing`, `openHearingOutcomeModal`,
  `saveHearingOutcome`, `tinp` (хелпер).
- Правится: `panelSud()` — добавляется `gtoolbar` над секцией заседаний и последний
  столбец действия в таблице `hear`.
- Без изменений: `hearingsOf`, `hearingDeadlines`, `hDone`, `hApplicable`, `hLeft`,
  `hRep`, реестр «Заседания (реестр)», схема `p.hearings[]`.
