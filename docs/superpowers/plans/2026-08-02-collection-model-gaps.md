### Task 3: Слой долга — поле «присуждено» на связи меры с целью (МП-1, МП-2, МП-4)

**Что делает:** заводит то, чего в модели нет вовсе. Слой — строка связи «мера-решение ×
требование» с присуждённой суммой. Взыскание слой **публикует**; начисление по слоям остаётся
у кредита, разнесение платежей — у платежей (`ADR-0013` §3 границы не двигает).

**Files:**
- Modify: `mockups/collection/collection.html`
  - рядом с `isLiveFor` (:1620) и `measureSetsPhase` (:1626) — новый блок «слой долга»:
    `LAYER_SOURCE_KINDS`, `LAYER_KILLERS`, `layersOf(r)`, `layerKey(m, reqId)`
  - структура меры: `m.awarded = { [reqId]: сумма }` — строка в разрезе цели, рядом с уже
    существующим по той же форме `m.stornoTargets` (:1620)
  - `normalize()` (:5499–5560) — валидация: `awarded` только у видов из `LAYER_SOURCE_KINDS`,
    ключи `awarded` ⊆ `m.targets`

**Depends on:** **Task 2** — два вида «Определение об отмене…» гасят слой, и до их появления
`LAYER_KILLERS` некому заполнить.

- [ ] **Шаг 1: что слой образует**

Слой образуют три вида (`Решение суда` · `Судебный приказ` · `Мировое соглашение`), и второго
списка не заводится — источник `LAYER_SOURCE_KINDS` из Task 2. Исход читается наравне с видом
(`ADR-0038`):

- `в иске отказано` — слоя **не образует** (присуждать нечего);
- `иск удовлетворён частично` — образует слой **меньше притязания**;
- `иск удовлетворён полностью` — слой на всё притязание цели.

- [ ] **Шаг 2: свободный слой выводится, а не хранится**

Остаток договорного долга, не втянутый ни в одно решение, — свободный слой. Считается как
`долг требования − Σ присуждённых по живым слоям`. Хранимого поля не заводить (`ADR-0001`).

- [ ] **Шаг 3: апелляция слоя не образует**

`layersOf(r)` обходит журнал мер и применяет акты вышестоящих инстанций к слою **первой**
инстанции:

| исход постановления | что делает со слоем |
|---|---|
| `оставлено в силе` | ничего |
| `изменено` | правит присуждённую сумму существующего слоя; **режим начисления остаётся по дате первого решения** |
| `отменено, на новое рассмотрение` | гасит |
| `отменено, в иске отказано` | гасит |

Тем же порядком гасят два новых определения об отмене (по вновь открывшимся и по новым
обстоятельствам) — `LAYER_KILLERS`. Комментарий обязан назвать все три довода `ADR-0043`:
ИЛ выдаётся по акту первой инстанции (апелляции нет в его `basisKinds`); режим прилипает к
решению навсегда (`ADR-0013` §3); глоссарий называет смертью слоя именно акт об **отмене**,
а не об изменении.

- [ ] **Шаг 4: ключ слоя**

`layerKey(m, reqId)` возвращает пару «id меры-решения × id требования». Номер ИЛ — способ
**распознать** слой в платёжном документе, а не сам ключ: между вступлением решения в силу и
выдачей листа слой уже начисляется по своему режиму, а лист выдаётся на каждого ответчика и
ключ бы размножился. Никакой функции, ключующей слой номером ИЛ, в файле остаться не должно.

- [ ] **Шаг 5: правка присуждённого — третий случай `ADR-0036`**

`awarded` — послесобытийная пометка: пуста при регистрации, дозаполняется. Её изменение
вышестоящим актом — не исправление ошибки: след ведёт на меру-акт, а не на человека. В

## Вне наряда — что остаётся расходиться намеренно

Чтобы это не искали как забытое:

- **Открыватель паузы читается из хранимого `r.states`, а не из журнала мер** (`pauseOpenerOf`,
  :1729) — нарушение `ADR-0032` п. 2 и §12 спеки. Состояние урегулирования хранится
  **наполовину**: вердикт «пауза действует» считается (`pauseClosed`/`stateActive`, :1717–1726),
  но хранимый флаг `active` остался у соглашений — мирового и добровольного исполнения
  (пишется :5613, синхронизируется `msSyncStates` :7214, читается веткой `s.active !== false`
  :1726). В шесть решений и семь пунктов остатка это не входит и ни одной задачей не
  закрывается. Отдельная волна.
- **Показ карантинного дела** — сознательный отказ (`ADR-0044`), не пробел: строку-заголовок
  дела в реестре требований волна ПЛ сняла намеренно, и возвращать её ради карантина нельзя.

## Порядок и точки контроля

Задачи строго последовательны. Три жёсткие зависимости, ради которых порядок именно такой:

1. **Виды мер (Task 2) — прежде затравки (Task 9).** Затравка не может сеять то, чего нет в
   справочнике.
2. **Поле «присуждено» (Task 3) — прежде «Взыскано» (Task 4).** Сворачивать не на что, пока
   слоя нет.
3. **Машина (Task 5) — прежде пересева данных (Task 9).** Хребет `SPINE` сеет цепочки по
   контурам; переписывать его до снятия лестницы значит чинить то, что через задачу удаляется.

Остальной порядок — производный: закрытие и карантин (Task 6) после машины, потому что
«требование закрыто» стало запрещающим обстоятельством записи вида; экран настроек (Task 7)
после обоих, чтобы правился один раз; линия лица (Task 8) до пересева; показ (Task 10) после
терминалов.

**Глазами** мокап стоит открыть после Task 7 и после Task 9 — линейки проверяют данные и
правила, но не то, что экран читается. Это не прогон и ноутбук не нагружает.

**Критерий готовности волны:**

```bash
node scripts/inspect/collection-data-audit.mjs   2>&1 | tail -1   # ИТОГО находок: 0
node scripts/inspect/collection-seed-coverage.mjs      | tail -1   # ситуаций: 40 · тонких (<2): 0
node scripts/inspect/collection-check.mjs        2>&1 | tail -5   # 0 провалов, 0 ошибок консоли
```

плюс: в `collection.html` нет ни одного вхождения `CONTOUR`, `sectionClevel`, `contourPhases`,
`sequenceReason`; в §17 спеки нет ⚠️, закрытых этой волной; в статус-доке есть раздел «Волна МП».
