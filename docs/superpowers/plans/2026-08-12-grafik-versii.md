# «График» — версии перестают быть тупиком (КВ-27, КВ-28) — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Снять с главного экрана вкладки «График» грид версий, который у обычного кредита
несёт одну ничего не говорящую строку, а у реструктурированного — тупик (`verRows` не
кликабельны, позиции всегда от действующей версии). Волна 1 (КВ-27) прячет грид за раскрытие и
ставит на его место строку-контекст, появляющуюся только когда ей есть что сказать. Волна 2
(КВ-28) делает грид переключателем: любая версия открывается в таблице позиций — ради ДС-версии,
чьи строки приняты из приложения и никаким пересчётом не проверяются.

**Architecture:** Правится один файл — `mockups/loan-credit/credit.html` (самодостаточный
HTML-макет: один `<script>`, логика в `window.CR`, UI перерисовывается целиком). **Модель не
меняется ни на байт** — ни полей, ни миграций: обе волны это рендер `tabGrafik` плюс два
состояния в памяти (`grafikVersOpen`, `grafikVer` + ключ). Единственная правка чужой функции —
необязательный третий аргумент `rows` у `trancheScheduleTotals`. Тесты — новые кейсы в
headless-смоуке `scripts/inspect/credit-check.mjs`.

**Tech Stack:** ванильный ES2020 в одном `<script>`, шаблонные строки вместо шаблонизатора,
Node 24 + `node:vm` для смоука, JSDOM для `tests/scope.test.mjs`. Сборки нет.

## Global Constraints

- **Язык интерфейса и комментариев — русский.**
- **Комментарий объясняет «почему»**, с отвергнутой альтернативой — идиома файла
  (`:7322-7326`, `:7348-7360`).
- **Производные не хранятся.** Ни «какая версия действующая», ни «есть ли будущая», ни состав
  колонок в модель не переезжают: всё выводится при рендере.
- **§0.3 — не молчаливый отказ.** Заблокированная «Сформировать график» остаётся видимой:
  `disabledBtn` + `title` с причиной.
- **Элемент появляется, когда ему есть что сказать** — правило волны (решение 6 спеки) и
  грамматика самого файла (`rf.length?`, `multiYear?`, `ir2.length?`, `scheduleArticleCols`).
- **Порядок секций скрипта фиксирован:** utils → `seedDb` → чистая логика → мутации →
  `window.CR` → DOM-блок. Правки ложатся в свои секции.
- **Прогон — ОДИН, в самом конце** (Task 3), а не после каждой задачи: полный набор нагружает
  машину. Кейсы пишутся в своих задачах и до Task 3 остаются непрогнанными — это осознанно, а
  не забыто.
- **Смоук сам переписывает `credit.html`** — впечатывает стамп `SMOKE (node) …` в шапку; после
  прогона файл изменён и входит в коммит Task 3.
- **Базовые числа до начала работ:** `credit-check.mjs` — **133/133 PASS** (последний ярлык —

  унаследованы и не чинятся этой волной.
- **Номера строк — снимок ДО работ.** Каждая задача сдвигает файл; место правки искать по
  тексту-якорю.
- **Спека:** [`docs/superpowers/specs/2026-08-12-grafik-versii-design.md`](../specs/2026-08-12-grafik-versii-design.md).

**Interfaces:**
- Consumes: `scheduleAt` (`:3710`), `schedValidFrom` (`:3709`), `validTo` (`:3717`), `cgrid`.
- Produces: `schedBasisLabel(s)` — общая для строки-контекста и грида; разметка.

- [ ] **Step 1: Вынести `schedBasisLabel(s)`**

Выражение основания сейчас живёт внутри `verRows` (`:7334-7336`). Поднять в чистую логику рядом
с `validTo`: `by.kind==='ДС'` → пилюля с `by.ref`; иначе `by.basis.ref || by.basis.kind ||
by.label || 'Перестроение графика'`. `verRows` зовёт её же. Второй трактовки основания не
заводим — иначе строка-контекст и грид со временем разойдутся.

- [ ] **Step 2: Предикат «версиям есть что сказать»**

Рядом же — `schedNeedsContext(t, asOf)`: версий > 1, ИЛИ есть `by.kind==='ДС'`, ИЛИ есть
`schedValidFrom(s) > asOf`, ИЛИ у действующей `generatedAt !== validFrom`. Для области «по
кредиту» — тот же предикат, применённый к любому траншу (`c.tranches.some(...)`).
Комментарий: правило, а не список условий — «элемент появляется, когда несёт факт»; рисовать
всегда значило бы воспроизвести дефект, который волна лечит.

- [ ] **Step 3: Состояние и тоггл раскрытия**

`:6413` — `let grafikVersOpen = false;` рядом с `condMatrixOpen`.
`:8248` — `CR.toggleGrafikVers = function(){ grafikVersOpen = !grafikVersOpen; rerenderDetail(); };`
Ключа набора не заводим (в отличие от `grafikYearsKey`): булев без состава, сбрасывать нечего.

- [ ] **Step 4: Строка-контекст**

`· с 01.09.2026 вступает v4 (ДС-18)` — когда есть версия с `validFrom > cardAsOf`. Разметка —
`<span class="src">`, своего класса не появляется. В области «по кредиту» строки нет вовсе.

- [ ] **Step 5: Раскрытие с гридом**

### Task 2: КВ-28 — грид становится переключателем

**Files:**
- Modify: `mockups/loan-credit/credit.html` — `tabGrafik`: `posSrc` (`:7344-7347`), плитки

- Test: `scripts/inspect/credit-check.mjs` — новые кейсы `ok(135,…)`, `ok(136,…)`, `ok(137,…)`

**Interfaces:**
- Consumes: `scheduleAt`, `schedValidFrom`, `validTo`, `scheduleRowStatus` (`:4107`),
  `ledgerKey` (`:4102`), `setCardScope`.
- Produces: состояние `grafikVer`; разметка.

- [ ] **Step 1: Состояние режима**

Рядом с `grafikVersOpen`: `let grafikVer = null, grafikVerKey = null;`
`grafikVer` = `{no, ver}`. Ключ — `c.id + '|' + (sel ? sel.no : 'credit')`, сверяется в начале
`tabGrafik` по идиоме годов (`:7395-7396`): не совпал — `grafikVer = null`. Комментарий: «v1» на
другом кредите — другой контракт, номер этого не различает. Смена даты среза сбросом НЕ является:
срез меняет, какая версия действующая, но показанная существовать не перестаёт.

- [ ] **Step 2: Источник строк**

В `posSrc` вместо `trancheScheduleRows(t)` —
`shown = grafikVer && grafikVer.no === t.no ? (t.schedules||[]).find(s => s.ver === grafikVer.ver)
: scheduleAt(t, cardAsOf)`, дальше `shown.rows`. Ветка «версии нет → строим на лету»
(`:3727-3736`) остаётся только там, где `grafikVer` пуст. Версия по ключу не нашлась — молча
возврат к действующей.

- [ ] **Step 3: Плитки едут вместе с таблицей**

`trancheScheduleTotals(t, asOf, rows)` — третий аргумент необязателен, без него поведение
прежнее; существующие вызовы (`:4744`, `scheduleTotalsAll`) не трогаются. В `tabGrafik` плитки
считаются от `shown.rows`. Комментарий: плитки и есть свод таблицы под ними, разъезд
«60 позиций в плитке, 48 строк в таблице» — ложь на экране.

- [ ] **Step 4: Колонка «Статус» при просмотре не рисуется**

Условие `viewing = !!grafikVer`. При `viewing` из шапки уходит `{h:'Статус'}`, из строки позиции
— ячейка статуса, из `yearRow` — хвост `cnt`, и `colspan` пересчитывается. Комментарий: леджер
построен по действующей версии, `ledgerKey` совпадёт номером позиции, а суммы и даты другие —
статус был бы **ложным**, не «неизвестным»; прочерк на всю таблицу читался бы как «ничего не
погашено».

- [ ] **Step 5: Клик по строке грида**

Строки `verRows` получают `onclick` и `cursor:pointer`. При `sel`: `CR.setGrafikVer(t.no, s.ver)`;
клик по действующей = `CR.clearGrafikVer()`. В области «по кредиту»: `CR.setCardScope(t.no)` +
`setGrafikVer` одним действием — показывать архив одного транша внутри слитой таблицы нельзя,
там смешались бы два контракта. Кликабельна ЛЮБАЯ строка: «некоторые открываются» читается как
поломка.

- [ ] **Step 6: Плашка режима**

Над позициями, `warn-inline` (идиома Д-5). Архивная: «Показана архивная версия v1 (основание,
действовала 19.04.2026 — 11.05.2026). Действует v3. Статусы погашения не показаны — они
относятся к действующей версии.» Будущая: «Версия v4 (ДС-18) ещё не действует, вступает
01.09.2026». Кнопка «Вернуться к действующей» → `CR.clearGrafikVer()`.

- [ ] **Step 7: Гейт кнопки**

`:7431-7432` — при `viewing` вместо `actBtn` идёт `disabledBtn('Сформировать график', 'Смотрите
архивную версию — вернитесь к действующей')`. Строить новую версию, глядя на архив,
двусмысленно: неясно, от чего строим.

- [ ] **Step 8: Кейсы (пишем, не прогоняем)**

`#135` — выбор архивной версии меняет и позиции, и плитки (число в плитке «Платежей в графике» =
числу строк показанной версии).

`#137` — в режиме просмотра «Сформировать график» погашена и несёт причину в `title`.
