Заёмщик — задачи для команды разработки

20 задач, выстроенных в строгом порядке сборки: разработчик идёт сверху вниз — сначала сквозное (модель «субъект и роль», слой производных, одна дата на карточку, контракты чтения с семью соседними модулями, приёмы вкладок), затем экраны (реестр, шапка карточки, витрина), затем десять вкладок по одной, страница субъекта и миграция с действующего экрана. Не начинать следующую, пока не закрыта предыдущая. Сквозные шаги 1–5 сделаны один раз для всех вкладок специально: без них каждая из одиннадцати вкладок отдельно договаривалась бы с чужим модулем — это ровно то перепрыгивание с задачи на задачу, которого нарезка избегает. Источник истины — TODO.md, раздел «Заёмщик (целевая модель)»; полное ТЗ — requirements/tz/04-zaemshchik.html. Здесь то же самое человеческим языком: в чём боль → что сделать. Эталон интерфейса и поведения — рабочий макет mockups/borrower/borrower.html (смоук 165/165, node scripts/inspect/borrower-check.mjs): реестр и шапка карточки в нём реализованы полностью, по вкладкам 2–11 приняты решения, но кода ещё нет — такие задачи помечены «только постановка». Модуль поглощает старые задачи фазы 4 (P4-R1…P4-R5, обследование живого стенда, июнь 2026) — судьба каждой проставлена в TODO.md.

Приоритет: 🔴 блокер (без этого модуль не работает) · 🟠 важно · 🟡 средне / вторично.

Порядок сборки — строгий. Номер шага в начале карточки — обязательная очерёдность; нумерация = порядок зависимостей: каждая задача опирается на уже сделанные и ни на одну из будущих. Сквозное (шаги 1–5) — фундамент: модель роли · производные · дата · контракты чтения · приёмы вкладок; без него вкладки некуда вешать. Значок Есть эталон в макете значит, что поведение уже отрисовано и проверено в mockups/borrower/borrower.html (смоук 165/165) — разработке остаётся перенести его на боевую платформу (Jmix). Только постановка — решение принято и обосновано, но кода в макете нет: проектировать по описанию, а не копировать.

Особенность модуля: заёмщик почти ничего не хранит — он сводит факты семи соседних модулей (кредиты · взыскание · залог · кураторство · комитет · платежи и досье · реестр лиц). Отсюда правило, действующее на всех экранах: зеркальный факт здесь не редактируется (редактор в двух местах расходится молча), а после задачи P4-R22 на карточке заёмщика не остаётся ни одной точки ввода вовсе — весь ввод живёт на странице субъекта (P4-R24).
