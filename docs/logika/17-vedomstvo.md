## 0. Краткая суть

Карточка организации-оператора: кто мы, чем зарегистрированы, по каким счетам принимаем и
отправляем деньги, какими документами действуем, как с нами связаться.

Это **справочная витрина, а не операционный экран**: записи меняются редко, но на них ссылается
всё остальное — платёжные поручения (счёт организации), печатные формы договоров (реквизиты,
наименование), публичные контакты (антикоррупционная линия, обращения граждан), титульные листы
отчётов.

Семь решений, определяющих логику:

1. **Ведомство — singleton.** Одна запись на систему; кнопок «Создать» и «Удалить» нет ни в
   каком виде.
2. **Счета append-only:** закрываются датой, а не удаляются.
3. **Значения полей — из справочников**, свободный ввод запрещён.
4. **Статус документа — производный** (вычисляется из срока действия), не хранится.
5. **Оргструктура и показатели — зеркала** чужих модулей, резолвятся на дату просмотра.
6. **Журнал изменений — представление общесистемного лога** по признаку области, а не свой лог.
7. **Полнота карточки — исполняемая проверка**, а не декоративный индикатор.

## 1. Назначение и границы

### 1.1. Кто пользуется

| Роль | Что делает |
|---|---|
| **Администратор** | единственный, кто правит собственные блоки карточки; видит вкладку «Журнал изменений» |
| **Наблюдатель** (любой сотрудник) | читает карточку, копирует реквизиты счёта, печатает карточку организации, скачивает файлы документов |

### 1.2. Что НЕ входит

- **Оргструктура** — своя сущность и свой модуль; здесь только зеркало в режиме чтения.
- **Показатели** — считает модуль статистики; здесь только зеркало зафиксированных срезов.
- **Пользователи и роли** — подсистема администрирования.
- **Сотрудники как персоналии** — карточек сотрудников модуль не ведёт: ФИО руководителя
  показывается как **публичный атрибут узла** оргструктуры, ссылки на кадровую карточку нет.
- **Хранилище файлов** — вложения лежат в подсистеме документооборота; модуль хранит только
  ссылку и метаданные.

## 2. Модель данных

Карточка складывается из **собственных блоков** (хранятся здесь) и **зеркал** (хранятся в чужих
модулях, здесь только читаются).

| Блок | Кардинальность | Владелец данных |
|---|---|---|
| Общая информация | 1:1 | свой |
| Регистрационные данные | 1:1 | свой |
| Хронология (события организации) | 1:N | свой |
| Банковские счета | 1:N | свой |
| Документы ведомства | 1:N | свой |
| Контакты | 1:N + 1:1 | свой |
| Оргструктура | — | **зеркало** (модуль оргструктуры) |
| Показатели | — | **зеркало** (модуль статистики) |
| Журнал изменений | — | **представление** (подсистема администрирования) |

### 2.1. Общая информация (1:1)

| Поле | Обяз. | Примечание |
|---|:--:|---|
| Полное наименование | да | «Открытое акционерное общество «Государственный финансовый холдинг»» |
| Краткое наименование | да | выводится в шапке и печатных формах |
| Краткое описание | да | чем занимается организация |
| Логотип (SVG/PNG) | нет | показывается в шапке и в печатной карточке |

**Двуязычие наименования (кырг./рус.) не вводится** — только русский.

### 2.2. Регистрационные данные (1:1)

Номер свидетельства о регистрации · дата свидетельства · **орган регистрации (справочник)** ·
ИНН (14 цифр) · ОКПО (8 цифр).

### 2.3. Хронология (1:N)

Событие = дата + заголовок + описание; сортировка по дате по убыванию. Используется в публичных
материалах и справках («Учреждение ОАО», «Переход на АСУБК», «Открытие Ошского филиала»).

**Единственный блок, где удаление записи допустимо** — событие не финансовый факт. Но и оно
пишется в журнал изменений.

### 2.4. Контакты

| Блок | Кардинальность | Состав |
|---|---|---|
| Телефоны | 1:N | тип (**справочник**: приёмная, горячая линия, антикоррупционная линия, канцелярия, факс) + номер (формат +996) + примечание |
| Электронная почта | 1:N | тип (**справочник**: общий, для обращений граждан, СЭД) + адрес + примечание |
| Адрес сайта | 1:1 | http/https |
| Юридический адрес | 1:1 | текст |
| Фактический адрес | 1:1 | текст |
| Режим работы | 1:1 | текст |
| Часы приёма граждан | 1:1 | текст |

**Телефон антикоррупционной линии** — требование к госоргану: его отсутствие даёт
предупреждение на вкладке и минус в индикаторе полноты карточки.

## 3. Справочники вместо свободного ввода

Значения перечисленных полей берутся из модуля справочников, ввод текстом запрещён:

| Поле | Справочник |
|---|---|
| Банк счёта | банки — **вместе с БИК**: БИК принадлежит банку, а не нашему счёту, и отдельным полем не вводится |
| Валюта счёта | валюты |
| Назначение счёта | расчётный, спецсчёт бюджетных средств, валютный, депозитный… |
| Орган регистрации | органы регистрации |
| Тип телефона | типы телефонов |
| Тип e-mail | типы почт |
| Тип документа | устав, свидетельство, лицензия, разрешение, постановление |

**Почему это блокер, а не удобство.** Свободный текст даёт расхождение написаний между модулями
(«ОАО «РСК Банк»» / «РСК банк» / «RSK»), после чего ни один отчёт по этому полю не сходится, а
платёжка уходит с реквизитами, которых нет в справочнике банков.

## 4. Банковские счета

### 4.1. Состав записи

Банк (справочник, БИК подтягивается) · номер счёта (16 цифр) · валюта (справочник) · назначение
(справочник) · признак «основной» · дата открытия · дата закрытия (пусто = действующий).

### 4.2. Append-only: счёт не удаляется, а закрывается

Удаления счёта **нет**. Счёт выводится из обращения простановкой даты закрытия.

**Почему.** Реквизит из платёжного поручения трёхлетней давности должен оставаться разрешимым:
если удалить счёт, старый платёж ссылается в пустоту, а печатная форма договора перестаёт
воспроизводиться.

### 4.3. Инвариант «основного» счёта

> **Не более одного «основного» счёта в разрезе валюты. Считается ТОЛЬКО по действующим
> счетам.**

- **Закрытый счёт основным быть не может:** при закрытии флаг «основной» снимается
  автоматически.
- Нарушение инварианта — **блокирующая ошибка сохранения**, а не предупреждение; на вкладке
  красный баннер с перечнем валют, где инвариант нарушен.
- Основной счёт по валюте — тот, что подставляется в платёжные документы по умолчанию.
  **Двух умолчаний быть не может.**

Если бы инвариант считался по всем счетам, включая закрытые, открыть новый основной счёт в той
же валюте стало бы невозможно — а это нормальная операция при смене банка.

### 4.4. Вкладка «Реквизиты»

- Фильтр **«Действующие / Все»**, по умолчанию действующие; закрытые показываются приглушённо с
  датой закрытия.
- Действие **«Копировать реквизиты»** — блок реквизитов в буфер обмена, доступно и наблюдателю.
- Действия администратора: «Добавить счёт», «Изменить», **«Закрыть»** (вместо «Удалить»).

## 5. Документы ведомства

### 5.1. Состав записи

Тип (справочник) · наименование · номер · дата выдачи · срок действия (пусто = бессрочный) ·
выдавший орган · файл (вложение документооборота: имя, размер, скачивание).

### 5.2. Статус — производный, не хранимый

| Условие | Статус | Индикация |
|---|---|---|
| срок действия не задан | Бессрочный | нейтральный |
| до истечения > 90 дней | Действует до ДД.ММ.ГГГГ | зелёный |
| до истечения ≤ 90 дней | Истекает через N дн. | жёлтый |
| срок прошёл | Истёк ДД.ММ.ГГГГ | красный |

Статус вычисляется **на текущую дату** и в базе не хранится — иначе он протухает ровно в тот
день, когда становится важен.

### 5.3. Сводка по вкладке

Над списком — один индикатор состояния комплекта: сколько документов просрочено, сколько
истекает в ближайшие 90 дней, либо «все действительны». **Просроченная лицензия — это остановка
кредитных операций, а не косметика.**

## 6. Зеркала

### 6.1. Оргструктура

- Вкладка **только для чтения**; редактирование — в модуле оргструктуры. Здесь ссылка, а не
  копия данных.
- Источник **версионен**: узлы создаются, переименовываются, ликвидируются; руководители
  сменяются. Витрина показывает **срез на выбранную дату**, а не «текущее состояние»: имя узла
  берётся последним по дате, действовавшим на эту дату; руководитель — тот, чей отрезок
  назначения покрывает дату.
- Глубина — до подразделений, **без персоналий**.
- **Вакансия — валидное состояние** узла («— вакансия»), а не ошибка данных.
- На дату, когда организации ещё или уже не существовало в этом виде, показывается пустое
  состояние, а не сегодняшнее дерево.

### 6.2. Показатели

**Срезы, а не расчёт на лету.** Агрегаты считает модуль статистики батчем в нерабочее время и
складывает срезами с датой расчёта. Витрина берёт **последний срез на дату ≤ выбранной** и
показывает дату расчёта. Считать на лету по живой базе на этой странице запрещено — это витрина,
а не отчётный движок.

Состав (только всеорганизационные агрегаты, без разрезов по подразделениям):

| Показатель | Единица | «Хорошо» — это |
|---|---|---|
| Объём портфеля | сом | рост |
| Выдано с начала года | сом | рост |
| Доля просрочки | % от портфеля | снижение |
| Количество заёмщиков | активных | рост |

**Дельта к предыдущему срезу:**

- сравнение с предыдущим срезом, дата сравнения подписана;
- **доля просрочки меняется в процентных пунктах**, а не в «процентах от процента»:
  4,5% → 4,2% — это «↓ 0,3 п.п.», а не «↓ 6,7%»;
- направление окрашивается **по смыслу показателя**: рост портфеля — хорошо, рост просрочки —
  плохо;
- первый зафиксированный срез сравнивать не с чем — так и пишется, а не рисуется «0%».

## 7. Валидация и полнота карточки

### 7.1. Валидаторы форматов

| Поле | Правило |
|---|---|
| ИНН | 14 цифр |
| ОКПО | 8 цифр |
| БИК | 6 цифр (приходит из справочника банков) |
| Номер счёта | 16 цифр |
| E-mail | стандартный формат |
| Адрес сайта | http/https |
| Телефон | +996, далее цифры, скобки, дефисы |

Проверка **жёсткая на сохранении** + подсветка поля при потере фокуса. Кнопку «Сохранить»
блокировать **не** нужно: проверка всё равно на сохранении, лишнее состояние не плодим.

### 7.2. Полнота карточки — исполняемая проверка

В шапке — индикатор «Карточка заполнена N/M» со всплывающим списком незаполненного. Чек-лист
обязательного минимума:

полное наименование · краткое наименование · краткое описание · ИНН · ОКПО · свидетельство о
регистрации (номер + дата) · юридический адрес · **хотя бы один действующий счёт** · хотя бы
один телефон · **телефон антикоррупционной линии** · электронная почта · адрес сайта ·
**документ типа «Устав»**.

Индикатор не декорация: пункты вычисляются **теми же валидаторами**, что и формы, а отсутствие
антикоррупционной линии дополнительно выводится предупреждением на вкладке «Контакты».

## 8. Журнал изменений

### 8.1. Общесистемное хранилище, а не свой лог

Записи аудита всех модулей лежат в **одном хранилище** подсистемы администрирования и
различаются полем области. Вкладка ведомства — отфильтрованное представление по своей области;
собственного журнала модуль **не заводит**.

### 8.2. Состав записи

| Поле | Назначение |
|---|---|
| Когда | дата и время |
| Кто | пользователь |
| Блок | «Общая информация», «Хронология», «Регистрационные данные», «Банковские реквизиты», «Документы», «Контакты» |
| Объект | идентификатор **и** человекочитаемая подпись («Счёт EUR · Айыл Банк», «Телефон · Горячая линия») |
| Поле | что именно изменено |
| Было → Стало | старое и новое значение |

**Идентификатор и подпись объекта обязательны для блоков с множественностью** (счета, документы,
контакты, хронология): без них по записи журнала невозможно найти объект, к которому она
относится, и журнал превращается в поток бессвязных строк.

### 8.3. Это журнал, а не версионность

Откат по записи журнала не предусмотрен: журнал отвечает на вопрос «кто и когда изменил», а не
«вернуть как было». Версионируется только источник оргструктуры — и это его собственное
свойство, а не свойство ведомства.

### 8.4. Интерфейс

Фильтры: блок · пользователь · период (с/по). Пагинация по 10 записей. Выгрузка CSV. Вкладка
видна **только администратору**.

## 9. Вкладки, роли, срез «на дату»

### 9.1. Восемь вкладок

| # | Вкладка | Тип | Кто правит |
|---|---|---|---|
| 1 | Общая информация | своя | администратор |
| 2 | Хронология | своя | администратор |
| 3 | Реквизиты (счета) | своя | администратор |
| 4 | Документы | своя | администратор |
| 5 | Контакты | своя | администратор |
| 6 | Оргструктура | зеркало | никто (источник — модуль оргструктуры) |
| 7 | Показатели | зеркало | никто (источник — модуль статистики) |
| 8 | Журнал изменений | представление | никто (пишется автоматически); видна только администратору |

### 9.2. Режим «только чтение»

Наблюдатель видит те же вкладки без кнопок правки (в заголовке секции — метка «только чтение»).
Доступные ему действия **не являются редактированием**, и отбирать их не нужно: копирование
реквизитов, печать карточки организации, скачивание файла документа, выгрузка журнала в
пределах видимости вкладки, пагинация и фильтры.

### 9.3. Срез «на дату»

В верхней панели — выбор даты просмотра (по умолчанию сегодня, кнопка «Сегодня» возвращает к
текущей). Дата влияет **только на зеркала**: собственные блоки версионности не имеют и всегда
показываются в актуальном состоянии.

---

## 10. Печатная карточка организации

Кнопка «Карточка организации» в шапке первой вкладки, доступна и наблюдателю. Формирует
одностраничную выжимку для печати или PDF: наименования и описание · регистрационные данные ·
**действующие** счета с реквизитами · контакты · дата формирования.

**Закрытые счета в печатную форму не попадают** — это карточка «как есть сейчас», по ней платят.

## 11. Швы с соседними модулями

| Сосед | Направление | Содержание |
|---|---|---|
| **Справочники** | берём | банки (с БИК), валюты, назначения счетов, органы регистрации, типы телефонов/почт/документов |
| **Оргструктура** | берём | зеркало дерева подразделений на дату |
| **Статистика** | берём | зафиксированные срезы показателей с датой расчёта |
| **Администрирование (аудит)** | отдаём | записи изменений со своей областью |
| **Документооборот** | отдаём/берём | вложения документов ведомства (ссылка и метаданные) |
| **Платежи, договоры, отчёты** | отдаём | реквизиты основного счёта по валюте, наименования, ИНН/ОКПО для печатных форм |

## 12. Ключевые решения и их причины

| Решение | Причина |
|---|---|
| Singleton без создания и удаления | организация одна; кнопка «Создать» открывает возможность второй карточки, на которую потом сошлётся половина платёжек |
| Счета append-only с датой закрытия | старый платёж и старый договор должны оставаться воспроизводимыми |
| Инвариант «один основной на валюту» считается по действующим | иначе смена банка блокируется навсегда |
| Флаг «основной» снимается при закрытии автоматически | закрытый счёт по умолчанию — гарантированная ошибка платежа |
| Нарушение инварианта — блокирующая ошибка | два умолчания на валюту означают случайный выбор счёта при платеже |
| БИК приходит из справочника банков, а не вводится | БИК — свойство банка; введённый руками он разойдётся со справочником |
| Справочники вместо свободного ввода | расхождение написаний ломает отчёты и платёжные реквизиты |
| Статус документа вычисляется, а не хранится | хранимый статус протухает в день, когда становится важен |
| Порог предупреждения 90 дней | перевыпуск лицензии требует времени; предупреждать в день истечения бесполезно |
| Оргструктура и показатели — зеркала, а не копии | копия расходится с источником; зеркало не может |
| Зеркала резолвятся на дату, а не «сейчас» | справка за прошлый год должна показывать прошлогоднюю структуру |
| Вакансия — валидное состояние | руководитель узла может отсутствовать месяцами; «ошибка данных» здесь ложь |
| Показатели берутся срезами, а не считаются на лету | витрина организации не должна быть вторым отчётным движком |
| Просрочка в процентных пунктах | «↓ 6,7%» от 4,5% вводит в заблуждение: изменение — 0,3 п.п. |
| Первый срез не сравнивается | «0%» вместо «сравнивать не с чем» — выдуманное число |
| Журнал — представление общего лога | свой лог модуля даёт второй формат аудита и второй экспорт |
| Идентификатор + подпись объекта в записи журнала | без них запись не связать с объектом |
| Полнота карточки — исполняемая проверка теми же валидаторами | декоративный индикатор расходится с формами |
| Антикоррупционная линия — отдельный пункт чек-листа | требование к государственному органу, а не один из телефонов |
| Наблюдателю оставлены копирование, печать, скачивание | это чтение, а не редактирование |
| Закрытые счета не печатаются | по печатной карточке платят сегодня |

## 13. Открытые вопросы

| # | Вопрос | Почему важно |
|---|---|---|
| 1 | Кто, кроме администратора, вправе править контакты (например, канцелярия — часы приёма)? | сейчас модель «правит только администратор»; если полномочия шире — нужна вторая роль |
| 2 | Нужна ли **версионность** собственных блоков или журнала изменений достаточно? | журнал отвечает «кто изменил», но не даёт «покажи карточку на 01.01.2025» |
| 3 | Порог предупреждения об истечении документа — 90 дней? | зависит от сроков перевыпуска лицензий и разрешений |
| 4 | Кто утверждает состав чек-листа полноты карточки? | список обязательного минимума должен закрепить владелец |
| 5 | Требуется ли публичная выдача карточки организации на сайт? | определяет, нужен ли отдельный read-only экспорт или API |

## 14. Словарь терминов

| Термин | Значение |
|---|---|
| **Ведомство** | сама организация-оператор (ОАО «Госфинхолдинг») как запись в системе |
| **Singleton** | сущность, существующая в единственном экземпляре |
| **Append-only** | режим, где записи добавляются и закрываются, но не удаляются |
| **Зеркало** | read-only отображение данных, которыми владеет другой модуль |
| **Срез (снимок)** | зафиксированное на дату значение, рассчитанное заранее |
| **Производный статус** | значение, вычисляемое при чтении, а не хранимое в базе |
| **п.п. (процентный пункт)** | разница между двумя процентными величинами |
| **БИК** | банковский идентификационный код |
| **ОКПО** | общероссийский/национальный классификатор предприятий и организаций |
| **СЭД** | система электронного документооборота |
