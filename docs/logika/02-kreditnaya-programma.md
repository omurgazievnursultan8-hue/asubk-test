## 0. Краткая суть

Кредитная программа — **шаблон кредитного продукта**. Она держит все параметры, из которых
потом рождаются заявки и кредиты: правовое основание, назначение и вид кредита, сроки
действия, параметры суммы и срока, процентные и штрафные ставки, льготные периоды,
параметры графика платежей, перечни документов и требования к залогу.

Программа ссылается **ровно на одно госрешение**, причём только на решение в статусе
«Действует», и является родительской сущностью для заявок и кредитов.

Четыре вещи, которые определяют логику модуля:

1. **Мастер из 9 вкладок с прогрессивным гейтом.** Вперёд по вкладкам нельзя, пока не
   заполнены обязательные поля текущей и предыдущих; назад — свободно.
2. **Двухуровневая валидация.** «Сохранить» (черновик) проверяет только вкладки
   0..текущую. «Отправить на согласование» валидирует все девять целиком.
3. **Почти каждый финансовый параметр — пара «тип + значение»**: Фиксированная / Диапазон
   (у штрафов ещё и Плавающая). Тип обязателен всегда, значение — условно по типу.
   Это порождает большую часть правил модуля.
4. **Залог — сквозной гейт.** Флаг «Требуется залоговое обеспечение» скрывает и исключает
   из валидации целые куски двух вкладок; выбор вида залога каскадом наследует типовые
   залоговые документы.

Жизненный цикл — тот же паттерн, что у госрешения (6 статусов, админ-возврат из
терминальных), плюс **запрет самосогласования** (правило четырёх глаз).

## 1. Назначение и место в конвейере

```
Госрешение  ──N:1──  Кредитная программа  ──1:N──  Кредитная заявка  →  Комиссия
                            │
                            └──1:N──  Кредит  (наследует параметры программы при выдаче)
```

Маршрут: `/loan-programs`.

Программа — единственное место, где условия кредитования задаются **до** появления
конкретного заёмщика. Всё, что кредит потом считает (проценты, штрафы, график), задаётся
здесь как рамка; конкретные значения фиксируются на кредите и в условиях транша.

Три независимые классификационные оси программы (подтверждено владельцем как **не дубли**):

| Ось | Поле | Отвечает на вопрос |
|---|---|---|
| Цель | Назначение кредита | **зачем** берутся деньги (оборотные, техника, строительство) |
| Продукт | Вид кредита | **какой механизм**: бюджетный кредит · бюджетная ссуда · иностранный кредит |
| Заёмщик | Отрасль | **кто заёмщик** — сектор экономики (справочник из 15 отраслей) |

Аналогично разведены **Источник финансирования** (категория: бюджет / донор / собственные)
и **Кредитная линия** (конкретный донор внутри категории: АБР, МАР, ВБ). Кросс-валидация
источника с госрешением **не требуется** (решение владельца).

## 2. Модель данных: 9 вкладок мастера

Обозначения обязательности: **Да** — обязательно для отправки на согласование;
**Условно** — обязательно при включении соответствующего блока; **Нет** — необязательное;
**readonly** — выводится системой.

### 2.2. Вкладка 2 — Сумма и срок

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| Тип суммы кредита | выбор | Да | Фиксированная / Диапазон |
| Фиксированные суммы | таблица | Условно | При «Фиксированная»: ≥1 значение |
| Минимальная / Максимальная сумма | число | Условно | При «Диапазон»: оба обязательны, таблица скрывается |

### 2.3. Вкладка 3 — Процентные ставки

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| Тип основной ставки | выбор | Да | Фиксированная / Диапазон |
| Значение фиксированной ставки | множественный выбор | Условно | При «Фиксированная»: ≥1 значение **из регламентированного справочника ставок** (список — намеренно, не свободный ввод) |

| Использовать плавающую ставку | флаг | Нет | Флаг-заготовка; **если включён — тип плавающей ставки обязателен** |

### 2.4. Вкладка 4 — Штрафы

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| Тип штрафной ставки за основную сумму | выбор | Да | Фиксированная / Диапазон / **Плавающая** |
| Значение штрафной ставки за основную сумму | число | Да | При «Плавающая» вместо значения требуется тип плавающей ставки |
| Максимальный размер штрафа за проценты | число | Да | Потолок в % от суммы кредита («Ограничение штрафа за просрочку процентов») |

| Значение штрафной ставки за проценты | число | Да | Аналогично |

Все четыре параметра обязательны: штрафы задаются на уровне программы, а не кредита.

### 2.5. Вкладка 5 — Льготный период

Три **независимых** блока, каждый со своим флагом:

| Блок | Что отсрочивает |
|---|---|
| Льготный период по основной сумме | платежи по основному долгу |
| Льготный период по **начислению** процентов | само начисление процентов |
| Льготный период по **уплате** процентов | уплату уже начисленных процентов |

Второй и третий — **не дубли**: начисление и уплата разведены намеренно. Отсрочка уплаты
процентов по первоначальным условиям даёт обычные проценты, подлежащие уплате позже, а не
«накопленные» — это важно для модуля реструктуризации.

Правило блока: флаг выключен → блок свободен и из валидации исключён. Флаг включён →
обязательны **тип льготы** и **продолжительность**; при типе «Диапазон» — обе границы
(«от» и «до»), при «Фиксированный» — ≥1 значение срока.

### 2.6. Вкладка 6 — Платежи и расчёты

| Поле | Тип | Обяз. | Значения |
|---|---|---|---|
| Способ задания графика | выбор | Да | **Стандартная периодичность** / **По конкретным месяцам** — взаимоисключающие |
| Периодичность платежей | выбор | Условно | При «Стандартная»: Ежемесячно · Ежеквартально · Ежегодно |
| Конкретные месяцы платежей | множественный выбор | Условно | При «По месяцам»: любой набор месяцев календарного года |
| День месяца для платежа | целое | Да | 1–31; короткий месяц → последний день |
| Обработка нерабочих дней | выбор | Нет | Не переносить · на следующий рабочий · на предыдущий рабочий (производственный календарь КР) |
| Метод расчёта дней в периоде (числитель) | выбор | Да | Финансовый (30) · Фактический |
| База дней в году (знаменатель) | выбор | Да | 360 · 365 · Фактическая |
| Метод погашения кредита | выбор | Да | Аннуитетный · Дифференцированный; при графике «По конкретным месяцам» — авто **«Индивидуальный»** (readonly) |

| Мин. / Макс. кол-во дней до первого платежа | целое | Нет | Окно от освоения до первого платежа; `мин ≤ макс` |

**Числитель и знаменатель разведены намеренно** (решение 19.06.2026): это свободные пары
(30/360, факт/факт, факт/365), а не один список. Прежнее поле «Тип расчёта процентов»
удалено как порождавшее путаницу с методом расчёта дней.

### 2.7. Вкладка 7 — Документы

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| Обязательные кредитные документы | таблица | Нет | Перечень из справочника кредитных документов |
| Опциональные кредитные документы | таблица | Нет | То же |

| Шаблоны договоров | таблица | Нет | Генерируются **после одобрения** с подстановкой данных |

**Кросс-дедуп (R20):** документ, добавленный в «обязательные», нельзя добавить в
«опциональные», и наоборот.

| Товары в обороте | отчёт об оценке | страховой полис |
| Депозит / денежные средства | договор банковского вклада, заявление о залоге прав по вкладу | — |
| Сельхозтехника | ПТС, отчёт об оценке | страховой полис |
| Скот / поголовье | ветеринарная справка, документы учёта поголовья (бирки), отчёт об оценке | — |
| Поручительство · Банковская гарантия | — | — |

### 2.9. Вкладка 9 — Предпросмотр

Сводка программы только для чтения, собирается автоматически из вкладок 1–8. Блоки:
сводная информация, финансовые параметры, условия погашения, требуемые документы,
настройки проверки.

**Предпросмотр строится тем же построителем секций, что и страница «Просмотр»** — один
построитель, один источник правды. Поэтому расхождения между «что я вижу перед отправкой»
и «что видно в действующей программе» невозможны по построению, а не по дисциплине.

### 2.10. Визуальная семантика полей

Все поля показываются в **трёх различимых состояниях сразу при открытии формы**, а не
только после неудачной валидации:

| Состояние | Вид |
|---|---|
| Обязательное-редактируемое | белый фон + рамка + красная звёздочка у подписи |
| Опциональное-редактируемое | белый фон + рамка, без звёздочки |
| Только для чтения / вычисляемое | серый фон, без рамки |

Пример третьего состояния: «Валюта» на вкладке 2, «Метод погашения = Индивидуальный» при
графике по месяцам, вся вкладка 9.

## 3. Валидация: как именно работает гейт

### 3.1. Два уровня

| Действие | Что проверяется |
|---|---|
| **Сохранить** (черновик) | только вкладки 0..текущая; дальше можно оставить пустым |
| **Отправить на согласование** | **все** вкладки целиком; при незаполненном обязательном отправка отклоняется |

### 3.2. Прогрессивный гейт навигации

Переход «Далее» или клик по вкладке **вперёд** возможен только если обязательные поля
текущей и всех предыдущих вкладок заполнены. Иначе — прыжок на **первую незаполненную**
вкладку с подсветкой. Навигация **назад свободна** всегда.

### 3.3. Счётчик ошибок с областью видимости

Вкладка с невалидными полями помечается красным индикатором **со счётчиком ошибок**; под
каждым невалидным полем — текст «Обязательное поле», а не только красная рамка.

Тонкость: счётчик показывается **только для вкладок в пределах области текущего действия**.
При переходе на вкладку 3 счётчики вкладок 4–9 не показываются — иначе новая форма
открывалась бы с девятью красными индикаторами, и сигнал терял бы смысл.

### 3.4. Проверки, которые не сводятся к «поле не пустое»

| Вкладка | Дополнительная проверка |
|---|---|
| 1 | «Дата по» ≥ «Дата с» (если «Дата по» задана); «Дата с» ≥ даты связанного госрешения |
| 2 | ≥1 значение суммы **и** срока; при диапазоне — `0 < мин ≤ макс` |
| 3 | тип ставки + значение; включённая плавающая ставка требует тип; включённый блок платы за неосвоенный остаток требует свои тип и значение |
| 4 | макс. % штрафа + по каждой из двух сторон: значение (или тип плавающей при «Плавающая») |
| 5 | по каждому включённому блоку льготы — тип + продолжительность |
| 6 | ровно один способ графика: при «По месяцам» — ≥1 месяц, иначе — периодичность; `мин ≤ макс` дней до первого платежа |
| 8 | при включённом залоговом гейте — ≥1 вид залога |

### 3.5. Клиент и сервер

Валидация выполняется **на клиенте и на сервере**. Серверная проверка — обязательное
условие отправки и одобрения: UI-гейту не доверять, потому что через API он обходится.

## 4. Состояния и переходы

### 4.1. Шесть статусов

**Черновик** → **На рассмотрении** → **Действует**, плюс **На доработке** (возврат автору),
**Отклонена** (отказ в согласовании) и **Закрыта** (действовавшая программа отменена).

### 4.2. Одиннадцать переходов

| Из статуса | Действие | В статус | Роль |
|---|---|---|---|
| — | Создать | Черновик | Автор |
| Черновик | Отправить на согласование | На рассмотрении | Автор |
| Черновик | Удалить | удалено (soft-delete) | Автор |
| На рассмотрении | Отозвать | Черновик | Автор |
| На рассмотрении | Одобрить | Действует | Согласующий |
| На рассмотрении | Отклонить | Отклонена | Согласующий |
| На рассмотрении | Вернуть на доработку | На доработке | Согласующий |
| На доработке | Отправить повторно | На рассмотрении | Автор |
| Действует | Закрыть | Закрыта | Согласующий / уполномоченный |
| Отклонена | Вернуть на согласование | На рассмотрении | Администратор |
| Закрыта | Вернуть на согласование | На рассмотрении | Администратор |

Статусная модель **намеренно совпадает** с моделью госрешения — с поправкой на род
(«Отклонена»/«Закрыта»). Это единый паттерн жизненного цикла подсистемы, а не совпадение.

### 4.3. Правило четырёх глаз

**Самосогласование запрещено:** пользователь, отправивший программу на согласование, не
может её одобрить — требуется другой пользователь. Это не совет, а проверка.

### 4.4. Матрица прав

| Статус | Автор | Согласующий |
|---|---|---|
| Черновик | Изменить · Удалить · Отправить на согласование | только просмотр |
| На рассмотрении | Отозвать | Одобрить · Отклонить · Вернуть на доработку |
| На доработке | Изменить · Отправить повторно | только просмотр |
| Действует | только просмотр | Закрыть |
| Отклонена | только просмотр | только просмотр |
| Закрыта | только просмотр | только просмотр |

Роли: **Автор** (создаёт, правит, отправляет, отзывает, удаляет черновик), **Согласующий**
(одобряет/отклоняет/возвращает/закрывает), **Администратор** (служебный возврат из
терминальных статусов). Тулбар: **скрывать по роли, гасить по статусу**.

### 4.5. Причины и аудит

Действия **Отклонить**, **Закрыть**, **Вернуть на доработку** и **Вернуть на согласование**
(админ) — через диалог подтверждения с **обязательной причиной**. Причина видна в просмотре
и пишется в единый журнал аудита, отображаемый вкладкой «История».

## 5. Правила и инварианты (сводка)

1. **Начальный статус — «Черновик»**; статус меняется только действиями жизненного цикла,
   не правкой формы.
2. **Редактирование** возможно только в «Черновике» и «На доработке».
3. **Самосогласование запрещено** (§4.3).
4. **Связанное госрешение — только в статусе «Действует»**, серверный enforcement (§6.1).
5. **Даты:** «Дата с» ≥ даты госрешения; «Дата по» опциональна (пусто = бессрочно), если
   задана — ≥ «Даты с» (равенство допустимо). **Будущие даты для программы допустимы** —
   в отличие от госрешения, это проверка порядка, а не запрет будущего.
6. **Суммы/сроки/ставки:** `0 < мин ≤ макс`; при фиксированном типе — ≥1 значение.
7. **Удаление** — только в «Черновике», soft-delete, серверная защита ссылок: нельзя
   удалить программу, на которую ссылается хотя бы одна заявка или кредит. Сообщение —
   локализованное деловое («Нельзя удалить: на программу есть ссылки»), не сырой стек
   исключения.
8. **Залоговый гейт:** снятый флаг скрывает залоговые поля вкладок 7–8 и **исключает их из
   валидации** — не «оставляет пустыми», а выводит из набора.
9. **Взаимоисключающие способы графика:** либо стандартная периодичность, либо конкретные
   месяцы; второй вариант принудительно ставит метод погашения «Индивидуальный».
10. **Кросс-дедуп документов** между обязательными и опциональными наборами.
11. **Журнал аудита** един: переходы, отклонения, закрытия, удаления — кто, когда,
    действие, причина.
12. **Семантика кнопок сохранения:** «Сохранить» (остаться) · «Сохранить и закрыть»
    (вернуться **в список программ**, а не на главную) · «Отмена».

## 6. Швы с соседними модулями

### 6.1. Программа → Госрешение (N:1)

- Связанное решение должно быть в статусе **«Действует»**; иначе сохранение отклоняется
  **на сервере** с внятным сообщением.
- В окне выбора неодобренные решения **скрываются жёстким условием загрузчика**, а не
  снимаемым фильтром-чипом: снимаемый фильтр даёт пользователю возможность выбрать
  недопустимое и получить отказ уже после заполнения формы.
- Окно выбора ограничено **режимом выбора**: из формы программы нельзя создать, изменить,
  удалить, одобрить или отклонить госрешение.
- **Дата начала программы не может быть раньше даты акта** — у решения есть только дата
  принятия, она и служит нижней границей.

**Известный дефект направления связи.** В обследованной системе delete-policy была
инвертирована: удаление программы без реальных downstream-ссылок блокировалось со ссылкой
на «references from GovDecision», хотя ссылается программа на решение, а не наоборот.
Направление связи и политику удаления требуется проверить.

### 6.2. Программа → Заявка (1:N) и → Кредит (1:N)

- Заявка ссылается на программу как на шаблон; кредит — тоже.
- **Пул ответственных сотрудников программы наследуется кредитам при выдаче** — это вход
  в модуль кураторства: куратор кредита берётся из программы, а не назначается с нуля.
- Наличие ссылок блокирует удаление программы (§5 п. 7).
- Вкладка «Заявки» на странице деталей показывает обратные ссылки.

### 6.3. Программа → справочники

Читаемые справочники: цели кредита, вид кредита, отрасли и направления (15 значений),
вид валют (KGS, USD, EUR, AUD, RUB, KZT, SUM), источник финансирования, кредитная линия,
вид счёта погашения, справочник ставок, вид очередности погашения, виды залога, кредитные
документы, залоговые документы, печатные формы, шаблоны договоров, уровни проверки
документов, сотрудники, физические и юридические лица (whitelist заявителей).

Плюс **админ-ведомый справочник связей «вид залога → типовые залоговые документы»** (§2.8)
— он не просто список, а таблица соответствий, которая ведёт каскад.

### 6.4. Программа → расчётное ядро

Программа задаёт входы будущего расчёта: метод расчёта дней (числитель), базу дней в году
(знаменатель), метод погашения, очередь погашения, периодичность/месяцы, день платежа,
обработку нерабочих дней. Сами суммы считает расчётное ядро на уровне кредита и транша —
программа держит только рамку.

## 8. Ключевые решения и их причины

| Решение | Причина |
|---|---|
| Мастер из 9 вкладок, а не одна длинная форма | ~50 полей; без группировки форма нечитаема |
| Прогрессивный гейт вперёд, свободная навигация назад | не даёт «проскочить» финансовое ядро, но не мешает вернуться и поправить |
| Двухуровневая валидация (черновик / отправка) | иначе черновик невозможно сохранить, не заполнив всё, — и работа теряется при прерывании |
| Счётчик ошибок ограничен областью действия | иначе новая форма открывается с девятью красными вкладками и индикатор перестаёт значить что-либо |
| Предпросмотр и «Просмотр» строит один построитель секций | два построителя разошлись бы, и отправляющий видел бы не то, что увидит согласующий |
| Валюта обязательна на вкладке 1, на вкладке 2 — зеркало readonly | сумма без валюты бессмысленна; два редактируемых поля валюты разошлись бы |
| Числитель и знаменатель day-count разведены | это свободные пары (30/360, факт/факт, факт/365), а не один список |
| «Тип расчёта процентов» удалён | путался с методом расчёта дней; смысл покрыт парой числитель+знаменатель |
| Начисление и уплата процентов — разные льготные блоки | отсрочка начисления и отсрочка уплаты дают разные суммы долга |
| Заявители оставлены как поимённый whitelist | подтверждено владельцем: есть адресные программы под конкретных заявителей |
| Кредитная линия отделена от источника финансирования | источник — категория, линия — конкретный донор; отчётность требует обоих |
| Каскад «вид залога → типовые документы» с правом донастройки | без каскада оператор набирает 4–6 документов руками на каждый вид; без донастройки каскад нельзя приспособить к программе |
| Печатные формы отделены от шаблонов договоров | разные жизненные циклы: бланк печатается пустым до решения, шаблон заполняется после одобрения |
| Жёсткий фильтр в окне выбора решения вместо снимаемого | снимаемый даёт выбрать недопустимое и получить отказ после заполнения формы |
| Правило четырёх глаз | программа определяет условия выдачи государственных средств |
| Статусная модель повторяет госрешение | единый паттерн ЖЦ подсистемы: одна модель прав, один тулбар, один журнал |
| «Сохранить и закрыть» ведёт в список | в обследованной системе вело на главную страницу, и оператор терял контекст |

## 9. Открытые вопросы и долги

1. **Финализация справочников** — единственный формально открытый вопрос заказчику:
   какие справочники нужны, какие в них нормативные значения, чистка тест-данных стенда
   (источник финансирования, вид кредита, отрасль, кредитная линия, способ погашения,
   методы расчёта дней, очередь погашения, виды залога, кредитные и залоговые документы,
   печатные формы, шаблоны договоров).
2. **Кырг./англ. наименования скрыты** до появления мультиязычности интерфейса; модель
   данных под них сохранена. Кыргызский — государственный язык, то есть это отложенный
   долг, а не отказ.
3. **Плавающая ставка** — флаг-заготовка: параметры (база, маржа, частота пересмотра) не
   спроектированы. Валидация требует только тип.
4. **Пересечение ролей** «Ответственные сотрудники» (вкл. 1) и «Ответственный за проверку
   документов» (вкл. 7) не проверено.
5. **Направление связи и delete-policy** `Программа ↔ Госрешение` (§6.1) — дефект
   обследованной системы, исправление не подтверждено.
6. **Что происходит с действующими программами**, когда связанное госрешение уходит из
   «Действует», в спецификации не описано.
7. **Бейджи макета** подлежали правке под унифицированный словарь («Одобрена» → «Действует»,
   добавляется «На доработке»); в текущей версии макета словарь уже унифицирован.
8. **Длительность льготного периода** окончательно хранится в условиях транша, а на уровне
   программы задаётся рамочно — граница между «рамкой программы» и «фактом транша» описана
   словами, но не формализована.

## 10. Словарь терминов

| Термин | Значение |
|---|---|
| **Кредитная программа** | шаблон кредитного продукта: условия, из которых рождаются заявки и кредиты |
| **Госрешение** | запись о нормативном акте, разрешающем кредитование; правовое основание программы |
| **Транш** | часть кредита с собственными условиями и расчётом; единица учёта освоения |
| **Освоение** | фактическое использование заёмщиком выданных средств |
| **Плата за неосвоенный остаток** | ставка, начисляемая на неиспользованную часть кредита |
| **Day-count (метод расчёта дней)** | пара «числитель/знаменатель» для расчёта процентов: 30/360, факт/факт, факт/365 |
| **Аннуитетный / дифференцированный** | методы погашения: равными платежами / равными долями основного долга |
| **Очередь погашения** | порядок, в котором платёж закрывает статьи долга |
| **Льготный период** | отсрочка платежей, начисления или уплаты процентов |
| **Куратор** | сотрудник, сопровождающий кредит; наследуется кредиту из пула программы |
| **Правило четырёх глаз** | отправивший на согласование не может сам одобрить |
| **soft-delete** | помечание записи удалённой с сохранением в базе |
| **Прогрессивный гейт** | запрет перехода вперёд по вкладкам мастера до заполнения текущей |
| **whitelist заявителей** | поимённый список лиц, допущенных к адресной программе |
