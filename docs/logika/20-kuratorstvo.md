## 0. Краткая суть

Кураторство отвечает на **один вопрос: кто вёл этот объект на эту дату**. Всё остальное
существует ради того, чтобы ответ был у каждого объекта, всегда и без ручного ввода.

**Зачем модуль нужен.** Роль одна, держателей роли много: пятнадцать кредитных специалистов с
одинаковыми правами. Права говорят, **что** человек может делать, и молчат о том, **с чем
именно**. Кураторство и есть ответ на второе — зона ответственности, посчитанная правилом, а не
расписанная руками по каждому договору.

Модуль владеет **двумя вещами**: правилами распределения и журналом закреплений. Наружу
публикует ровно два ответа: закреплённого работника с подразделением на дату и список объектов
работника. Кто из-за этого получит задание в почту — решает не он.

Одиннадцать решений, определяющих логику:

1. **Закрепление — журнал, а не поле объекта**: ответ считается на дату, поля «куратор» нет ни у
   одного объекта.
2. **Четыре объекта и пять ролей**, оба списка закрыты; заёмщик объектом закрепления не является.
3. **Две ступени правила**: холдинг даёт подразделение, отдел даёт работника — кадровое знание
   остаётся там, где оно есть.
4. **Ключ правила объявляется**, признак попадает в справочник только через гейт, доли берутся
   из группировки, а не пишутся строкой.
5. **«Объект без куратора» невозможен**: незакрытую ячейку держит заведующий, отсутствующее
   правило — администратор; давность держания меряется порогом.
6. **Редакция вступает днём сохранения** и хранит снимок таблицы целиком; даты вступления в
   будущем нет.
7. **Правило применяется само и сразу**, единственный след — квитанция; кнопок «пересчитать»,
   предпросмотра и фонового пересчёта нет.
8. **Рука переживает применение правила**: закрепление с причиной держится вне правила до
   отдельного «вернуть к правилу».
9. **Задним числом можно, пока период не заперт** фактом, закрытым именем прежнего куратора.
10. **Ведущий куратор заёмщика вычисляется**, а не назначается.
11. **Один вопрос, два ответа**: наружу модуль отвечает формой «объект, роль, дата», а замещение
    спрашивает у модуля сотрудников.

## 1. Владение и границы

### 1.1. Что кому принадлежит

| Что | Кому |
|---|---|
| Журнал закреплений — единственный носитель факта «кто вёл объект на дату» | **кураторство** |
| Правила распределения обеих ступеней, их редакции и снимки таблиц | **кураторство** |
| Справочник признаков распределения, группировки и их редакции | **кураторство** |
| Пороги давности фолбэка по видам объектов | **кураторство** (справочник видов) |
| Сотрудники, отсутствия, замещающие, учётные записи, маршрутизация задания на живого человека | модуль сотрудников |
| Подразделения, должности, дерево холдинга | модуль оргструктуры |
| Сами объекты — заявка, кредит, предмет залога, требование | их модули |
| Домены признаков (отрасль, территория, вид кредита, вид залога…) | справочники соседних модулей |
| Курс НБКР для приведения валютных остатков | справочник курсов |
| Закрытые факты, которыми запирается период | модули-источники |

**Граница одной фразой.** Кураторство **называет** ответственного. Кому фактически уйдёт задание
при отпуске, кого можно уволить и как устроена очередь заданий — не его вопросы.

### 1.2. Кто пользуется

| Роль | Что делает |
|---|---|
| **Администратор кураторства** | правила верхней ступени, справочник признаков и группировок, все квитанции. Роль одна на холдинг, выдаётся в модуле сотрудников; **вакантной не бывает** — снять её можно только вместе с назначением преемника |
| **Заведующий отделом** | таблица распределения своего подразделения и квитанции по ней; держит объекты незакрытых ячеек своего отдела |
| **Работник** | видит только свои объекты на дату среза, без права правки |
| **Читатель** (кредитный специалист, взыскание, аудит) | чтение по объекту: кто ведёт сейчас, кто вёл тогда, каким источником получен |

## 2. Журнал закреплений

**Почему журнал, а не поле.** Поле «куратор» отвечает только на вопрос «кто сейчас», а у модуля
спрашивают другое: **кто отвечал в марте, когда был пропущен срок**. Этот ответ нужен
обязательствам, дефектам, разбору увольнения и любому спору о просроченной мере. Поле плюс
история в аудите дают **две правды**, и расходятся они на первой же правке задним числом.

### 2.1. Запись журнала

| Реквизит | Содержание |
|---|---|
| Объект | тип и ключ: заявка · кредит · предмет залога · требование |
| Роль | одна из пяти назначаемых |
| Работник и подразделение | кто ведёт и в каком отделе на этот отрезок |
| Период | дата начала и дата окончания; открытая запись — без окончания |
| **Источник** | одно из трёх: **правило** · **рука** (переопределение) · **фолбэк** |
| Ссылка на редакцию | та редакция правила, по которой решали |
| **Снимок признаков** | значения признаков объекта на дату решения — по нему видно, чем решали тогда |
| Причина и автор | обязательны у руки и у ретро-правки; у применения правила автор — само применение |

### 2.2. Правила журнала

- На объект в одной роли **открытая запись ровно одна**.
- Журнал **append-only**: смена куратора закрывает прежнюю запись днём раньше и открывает новую;
  правка существующей записи на месте **запрещена**.
- Закрепление меняется и **без человека**: применение правила само закрывает прежнюю запись и
  открывает новую со ссылкой на редакцию.
- **Вопрос без даты не принимается.** Дата — обязательный параметр; умолчание «сегодня»
  подставляет вызывающий, а не хранилище.
- **Закрепление не закрывается концом объекта:** погашенный кредит и закрытое требование
  сохраняют куратора — спрашивают о них и после закрытия.

### 2.3. Единственная законная пустота

Пустой ответ бывает ровно в одном случае — **вопрос на дату раньше рождения объекта**. Он значит
«объекта тогда не было», а не «куратор неизвестен»: второго состояния у модуля нет, и лестницу
держателей такой вопрос не поднимает.

### 2.4. Чего не хранится никогда

Хранимая копия расходится с журналом на первой же передаче, поэтому список запрещённых полей
назван явно:

- у объекта **нет атрибута «куратор»** — ни на заявке, ни на кредите, ни на предмете залога, ни
  на требовании;
- нет полей «текущий куратор», «ведущее подразделение», «ведущий куратор заёмщика», «загрузка
  сотрудника», «объект без куратора»;
- всё перечисленное — **функции** от журнала, правил и даты.

**Правило проверки:** значение выводится из журнала и справочников — значит, это не поле.

### 2.5. Четыре объекта и пять ролей — списки закрыты

Соблазн закрепить куратора «за заёмщиком» ломается на первом же клиенте с пятью кредитами в трёх
отделах: один человек не ведёт всё, а карточка требует одно имя. **Ответственность живёт на
предмете работы**; заёмщик остаётся слоем сборки.

| Объект закрепления | Роли на нём | Точка рождения |
|---|---|---|
| **Заявка** | специалист заявки | регистрация заявки |
| **Кредит** | куратор кредита | подписание кредитного договора |
| **Предмет залога** | куратор залога · региональный исполнитель | постановка предмета на учёт |
| **Требование по взысканию** | куратор требования | открытие требования в модуле взыскания |
| Заёмщик — **не объект** | ведущий куратор заёмщика — производная роль (§10) | — |

- **Список ролей закрыт:** новая роль вводится доработкой, а не записью в справочник — иначе
  читающие модули перестают знать, о какой роли спрашивать.
- На одном объекте роли живут **одновременно и независимо**: у предмета залога есть и куратор
  залога, и региональный исполнитель, и **приезжают они в разные подразделения**.
- Открытие взыскания **куратора кредита не снимает** — он остаётся на кредите до конца.
- У кредита может быть **несколько требований** (заёмщик и поручитель), значит и несколько
  кураторов требования: в карточке кредита это **список**, а не одно имя.

## 3. Каркас: три экрана и дата среза

| Экран | Что на нём | Владелец |
|---|---|---|
| **Признаки и группировки** | справочник признаков, их домены, отметка сверенности, группировки и редакции группировок | администратор |
| **Политика распределения** | обе ступени: выбор правила, объявленный ключ, таблица ячеек, список объектов ячейки | администратор (верхняя) · заведующий (своя таблица) |
| **Что изменилось** | квитанции применений: кто и когда правил, сколько просмотрено, переставлено и не тронуто рукой, «было → стало» | читают все по своей области |

Четвёртого экрана нет. **Своего экрана журнала объекта у модуля тоже нет** — в системе журнал
живёт врезкой в карточках заявки, кредита, предмета залога и требования.

**Дата среза** одна на модуль; при её смене пересчитываются **все** экраны, а не текущий. Срез
**смотрит назад**: редакций правила с будущей датой не бывает. Вперёд в списке срезов стоят
только даты вступления редакций **группировок**. Дата среза не меняет данные — только то, какой
срез журнала показан. Прямая ссылка на экран открывает его вместе с датой из ссылки.

**Три слова, три уровня:** *политика распределения* — свод обеих ступеней; *правило* — таблица
одной ступени для одной пары «объект и роль»; *ячейка* — одно сочетание долей ключа и одно имя
против него.

> Слово «политика» занято и в администрировании («Роли и политики») — там оно про доступ и к
> кураторству отношения не имеет.

## 4. Две ступени правила

Одноступенчатое правило «признаки объекта → работник» заставляет администратора холдинга знать
поимённо каждого специалиста в каждом филиале и переписывать общий справочник при любом отпуске.
Разделение ступеней отдаёт кадровое знание туда, где оно есть.

| | Верхняя ступень | Нижняя ступень |
|---|---|---|
| Что даёт | признаки объекта → **подразделение** | признаки объекта → **работник** внутри отдела |
| Чем опознаётся | пара «объект и роль» | пара «подразделение и роль» |
| Сколько правил | **ровно пять** — по одному на назначаемую роль, у каждого свой ключ | по одному на пару; двух правил одного отдела на одну роль не бывает |
| Владелец | администратор кураторства | заведующий отделом |

**Почему ключ — пара «объект и роль», а не один объект.** У предмета залога куратор залога сидит
в залоговом управлении, а региональный исполнитель — в областном отделе: одним подразделением на
объект их не развести. **Общей таблицы «объект → отдел» поэтому не существует.**

Правила взаимодействия ступеней:

- **Подразделение объекта меняется только правилом верхней ступени.** Очереди передач и приёма в
  кураторстве нет: отдел и работник меняются **одной записью журнала**.
- **Живы обе ступени одинаково:** сохранение редакции любой ступени переставляет и живущие
  объекты её ячеек — сразу, записью журнала. Иначе после отмены передач сменить объекту
  подразделение было бы нечем.
- Закрепления, сделанные рукой, применение **обходит**.
- **Согласования между ступенями нет:** заведующий меняет свою таблицу, не спрашивая
  администратора, и наоборот; уведомляются обе стороны.
- Администратор **не может назначить работника напрямую**, минуя таблицу отдела; заведующий не
  может открыть на правку правило холдинга.
- **Крайний случай — правило отдела без объектов.** Пока администратор не отдал отделу ни одной
  доли, правило отдела живёт впустую, и заведующий обязан видеть **свою таблицу до первого
  объекта**, а не пустой экран «правил нет».

## 5. Ключ, признаки, группировки

Разные отделы режут поток по-разному: отраслевой — по территории, промышленный — по территории и
форме собственности, залоговый — по виду обеспечения. Зашитый набор колонок заставит держать
пустые измерения, свободный текст в ячейке сделает правило непроверяемым, а признак, взятый
откуда попало, — необъяснимым.

### 5.1. Объявленный ключ и ячейки

- Ключ — **список признаков и на каждый ссылка на группировку**; значения ячеек — все сочетания
  долей.
- Число ячеек есть **произведение долей**, а не значений домена. Экран его считает, и за мягким
  пределом (умолчание — **40 ячеек**) состав ключа подтверждается рукой.
- Редакция ключа **ссылается на группировку**, а не носит раскладку в себе: имя доли обязано
  значить одно и то же во всех правилах холдинга, иначе счёт двух подразделений не складывается.
- Доля **выбирается из группировки, строкой не вводится** — иначе «Ошская» и «Ошская обл.»
  станут двумя ячейками.
- Смена состава ключа или выбранной группировки — **новая редакция правила**: переносятся только
  те ячейки, чей ответ доказуемо не изменился, и экран заранее говорит, сколько останется без
  имени.
- **Одна ячейка — одно имя.** Правило не делит поток по загрузке и не считает очередь:
  распределение обязано быть **воспроизводимым** — те же признаки на ту же дату дают то же имя.
  Перекос заведующий видит числом объектов против ячейки и лечит правкой таблицы или рукой.

### 5.2. Гейт допуска признака

В справочник признаков попадает величина, прошедшая **четыре условия разом**:

1. **конечный домен из справочника** — либо числовой признак с объявленным разбиением на пороги;
2. **принадлежит виду объекта**, который она различает;
3. **известна в момент рождения** объекта — иначе правилу нечем решать;
4. **читается у названного источника на дату** — и сама кураторством не считается.

Отказ называет **нарушенное условие**, а не «нельзя». Источник объявлен на признаке — заёмщик
либо сам объект; **заёмщицкие признаки доступны объектам всех видов и на объекте не хранятся**:
правило спрашивает их у заёмщика запросом на дату.

Четвёртое условие закрывает круг: **подразделение и работник признаками распределения быть не
могут** — иначе правило ключевалось бы своим же ответом.

### 5.3. Двенадцать признаков и сверенность доменов

**Сверенность** — состояние домена относительно источника, объявленное человеком: справочники
системы строятся не одновременно с кураторством, и два непохожих случая иначе сливаются в один.

| Признак | Источник значения | Сверенность |
|---|---|---|
| Отрасль | заёмщик | сверен |
| Кредитная программа | объект (заявка · кредит · требование) | сверен |
| Вид кредита | объект (кредит · требование) | сверен |
| Кредитная линия | объект (заявка · кредит · требование) | сверен |
| Сумма договора | объект (заявка · кредит) | сверен — **числовой**, доли задаются порогами в редакции правила |
| Вид залога | объект (предмет залога) | сверен |
| Основание открытия требования | объект (требование) | сверен |
| Роль обязанного лица | объект (требование) | сверен |
| Территория | заёмщик (у предмета залога — сам объект) | **ждёт справочника** — справочника АТЕ в системе нет, район лежит свободной строкой |
| Вид заёмщика | заёмщик | **ждёт справочника** |
| Форма собственности | заёмщик | **ждёт справочника** |
| Размер бизнеса | не назван | **источник не назван — в ключ не встаёт** |

| Отметка | Что значит | В ключ? |
|---|---|---|
| сверен | домен списан со строки живого справочника-источника, адрес происхождения приложен | да |
| ждёт справочника | источник **назван**, но справочника у соседа ещё нет; домен собран вручную и поедет за источником | да, с плашкой |
| источник не назван | величину никто не ведёт: прошлый ответ нечем воспроизвести | **нет** |

Признак без источника **не выкидывается**: «Размер бизнеса» виден в справочнике, но гейт его в
ключ не пускает — он стоит там, чтобы про него не забыли, когда источник назовут.

### 5.4. Группировки и их редакции

**Группировка** — именованное разбиение домена признака на доли, объявленное в справочнике самого
признака: «по подвижности», «по ликвидности», «по областям».

- Группировку заводит **только администратор кураторства**: доли едины на холдинг. Имя доли
  уникально в пределах признака.
- **Доля «Прочие» стоит в каждой группировке безусловно**, даже когда домен разложен без остатка:
  справочник-источник пополняется чужими руками, и новая строка обязана приехать в существующую
  ячейку, а не родить ячейку без имени.
- Раскладка набирается руками; из колонки справочника-источника её можно **списать одним
  нажатием — списать, а не привязать**: связь не хранится, иначе чужая правка в чужом справочнике
  переписывала бы наши прошлые ответы.
- Группировка **версионируется своими редакциями с датой вступления**; ответ на дату берёт ту
  редакцию, что действовала тогда. Первая редакция — не раньше сегодня.
- **Удаления нет:** группировка закрывается датой снятия, и лишь если после этой даты на неё не
  смотрит ни одна редакция ни одного правила. Обратный индекс «кто на неё смотрит» показывается
  до снятия.
- У **числового** признака доли задают пороги, и они объявляются **в редакции правила**: единого
  разбиения денег по холдингу нет.
- **Новая редакция группировки, из которой ушла доля, сиротит названную ячейку** во всех
  смотрящих правилах, и задача уходит владельцу каждого из них.

> **Дату вступления вперёд объявляет только группировка** — у редакции правила её нет. Поэтому
> будущая редакция группировки закрепления сама не двигает, а показывает расхождение с правилом с
> того дня, и разбирается оно решением человека.

### 5.5. Сочетаемость и невозможные ячейки

Признаки не независимы: программа сужает вид кредита и линию до набора, вид заёмщика сужает форму
собственности. **Сужение объявлено на признаке-сузителе** и проверяется попарно, когда обе стороны
стоят в одном ключе.

Ячейка, за которой не стоит ни одного возможного сочетания, — **не дыра**: её не закроет никто и
никогда. Невозможные ячейки **вычитаются** из счёта покрытия и из мягкого предела и показываются
отдельной строкой с объяснением. Считать их дырами значило бы врать счётчиком и держать вечную
тревогу.

Открытая доля «Прочие» невозможной не бывает.

**Граница проверки:** сочетаемость проверяется **попарно** — тройное противоречие, где каждая
пара порознь возможна, а вместе нет, не ловится.

## 6. Редакции и применение

### 6.1. Редакция вступает днём сохранения

Правило распределения — **документ**, а не настройка: по нему потом объясняют, почему кредит
достался именно этому специалисту.

| Реквизит редакции | Содержание |
|---|---|
| Номер, автор, дата создания | кто и когда правил |
| **Дата вступления** | **день сохранения**; поля ввода на экране нет |
| Дата закрытия | у действующей пуста — открыта бессрочно |
| **Снимок таблицы** | полный, а не разница: ключ и все ячейки целиком |

- **Даты вступления в будущем нет и выбрать её нечем:** фонового применения, которое включило бы
  редакцию первого числа, в модуле не существует — ждать её было бы некому.
- **Две правки одного дня ложатся в одну редакцию этого дня.** Двух редакций с одной датой
  вступления не бывает — интервалы не пересекаются.
- Применение — **часть сохранения**, а не отдельная кнопка.
- Задним числом правится **не редакция, а закрепление**, и только пока период не заперт (§8).
- Уведомление уходит **обеим сторонам**.
- Прежние редакции доступны на чтение и участвуют в объяснении старых назначений.
- **Правка вслепую запрещена.** Экран рисует редакцию на дату среза, а правка ложится поверх
  **действующей**: уехал срез в прошлое — правились бы одни ячейки, а показывались другие. Такая
  правка закрыта плашкой с кнопкой «показать нужный срез», а после сохранения срез **сам встаёт
  на сегодня** — иначе «сохранено» читается как «ничего не произошло».

### 6.2. Применение: само, сразу, с квитанцией

Пересчёт отдельной кнопкой откладывал ответственность: между правкой и нажатием объект жил по
старой ячейке, а очередь необработанных правок росла. Цена мгновенности — **правка правила молча
переписывает живущие объекты**, поэтому у каждого применения обязан быть след.

**Три причины применения — и ни одна не человек:**

1. **рождение объекта**;
2. **сохранение редакции правила** — в том же вызове переписываются закрепления живущих объектов
   её ячеек;
3. **смена признака объекта** в соседнем модуле — правило применяется заново сразу, расхождение
   не накапливается.

- У обеих ступеней применение **одинаковое**.
- **Отложенного состояния, очереди необработанных правок и фонового применения по расписанию
  нет**; кнопок «пересчитать» и предпросмотра нет ни на одном экране.
- Применение обходит закрепления с источником «рука» — они считаются отдельным числом квитанции.
- Запись журнала за прошлые даты **не переписывается**: применение открывает новую запись днём
  применения.
- Применение **идемпотентно**: повторное сохранение той же ячейки просматривает объекты и
  переставляет ноль.

**Квитанция об изменении:**

| Часть | Содержание |
|---|---|
| Кто, когда, почему | причина: рождение объекта · применение редакции N · смена признака объекта |
| **Три числа** | просмотрено · переставлено · **не тронуто рукой** |
| «Было → стало» | по каждому переставленному объекту: работник и подразделение до и после |
| Где живёт | экран «Что изменилось», новые сверху |

**Квитанция отвечает за своё применение и только.** Её числа задним числом не пересчитываются:
«что сделала эта правка» и «сколько у кого сейчас» — разные вопросы, и квитанция, открытая через
месяц, показывает те же числа, что в день правки. **Отмены у применения нет**: обратная правка —
своё применение со своей квитанцией. Квитанция с нулём переставленных тоже пишется.

### 6.3. Экран правила: покрытие, пустоты, цена правки

- Строка ключа сверху, ниже таблица «доли ключа → работник», в шапке **счётчик закрытых ячеек из
  всех** (невозможные вычтены).
- **Пустая ячейка подсвечена и подписана именем держателя**, а не оставлена серой.
- Против каждой ячейки — **число объектов**, которые по ней ведутся: это и есть **цена правки,
  видимая до сохранения**. Диалога «вы уверены?» поэтому нет.
- Список объектов ячейки раскрывается по клику и несёт колонку **«сверка с правилом»** —
  расходятся с ним только закрепления, сделанные рукой. Там же давность фолбэка в рабочих днях.
- Правка доступна **только владельцу** правила; остальным экран открывается на чтение — **без
  полей ввода**, а не с ошибкой после нажатия.
- Экран верхней ступени устроен так же — в ячейке стоит подразделение, а не работник.
- Таблица на дату среза в прошлом показывает **ту редакцию, что действовала тогда**, и правится
  только действующая.

## 7. Фолбэк-лестница и пороги давности

Появилась новая область, новый вид залога, уволился специалист — ячейка пуста, а объект уже
родился и уже течёт срок. Если модуль в этот момент отвечает «куратора нет», ответственность
повисает молча и всплывает через месяц просроченным сроком.

| Что случилось | Кто держит объект |
|---|---|
| Пустая ячейка работника на нижней ступени | **заведующий отделом** |
| Пустая ячейка верхней ступени либо правила подразделения нет вовсе | **администратор кураторства** |

Запись пишется в журнал с источником **«фолбэк»** и датой начала — держание такое же закрепление,
как любое другое.

**Порог давности — свой на каждый вид объекта:**

| Заявка | Требование | Кредит | Предмет залога |
|---|---|---|---|
| 2 рабочих дня | 3 рабочих дня | 5 рабочих дней | 5 рабочих дней |

Пороги живут **в справочнике** и правятся без доработки; счёт идёт в рабочих днях от даты начала
записи фолбэка. Правка порога меняет подсветку сразу и **не трогает журнал**.

**Фолбэк — это ответ, а не отказ:**

- ответ о кураторе **никогда не бывает пустым**, если объект существует: он либо работник, либо
  держатель;
- **держатель отвечает наравне с работником:** сроки и обязательства адресуются ему;
- заполнение ячейки **закрывает запись фолбэка** и открывает обычную — держатель перестаёт
  отвечать со дня нового закрепления;
- снятие работника из ячейки возвращает его объекты держателю, а не оставляет их за уволенным;
- **превышение порога становится дефектом отдела**: видно давностью в списке объектов правила и
  числом объектов на фолбэке в подвале модуля.

Состояния «объект без куратора» не существует; существует «объект держится держателем дольше
срока», и это дефект.

## 8. Рождение объекта, рука, ретро-правка

### 8.1. Рождение объекта и снимок признаков

- Момент первого закрепления назван для каждого из четырёх объектов поимённо (§2.5).
- Рождение запускает правила **по всем ролям его вида**: у предмета залога их две, и
  подразделения у них разные — каждая роль идёт своим правилом холдинга по своему ключу.
- Значения признаков читаются **на дату решения** и остаются **снимком** в записи журнала.
- Смена признака в соседнем модуле **применяет правило заново, сразу**; прежняя запись остаётся
  со своим снимком.
- **Заявка и кредит закрепляются независимо:** куратор кредита определяется правилом кредита по
  признакам кредита, **преемства от специалиста заявки нет** — даже если признаки совпадают, это
  два разных назначения, и связи между ними в журнале нет.

### 8.2. Переопределение рукой и возврат к правилу

Правило не покрывает всё: специалист вышел из отпуска и забирает своего клиента, заведующий
разгружает перегруженного, у работника конфликт интересов с этим заёмщиком. Такое назначение
обязано **пережить применение правила**, иначе им перестанут пользоваться и начнут править
правило под один случай.

- **Причина обязательна** текстом; без неё закрепление не сохраняется.
- Запись получает источник **«рука»** и держится вне правила до отмены; применение её не трогает.
- Кнопка **«вернуть к правилу»** закрывает ручную запись и открывает обычную по действующей
  редакции. Доступна владельцу правила и автору записи.
- Рука видна колонкой «сверка с правилом» — с причиной и давностью; причина видна и в журнале
  объекта.
- **Рукой меняется только работник**, и только из того подразделения, которое ведёт объект:
  список кандидатов — работники того же отдела. Подразделение меняет исключительно правило
  верхней ступени.
- **Конфликт интересов лечится этой же рукой**, причина называется в записи журнала.
  Датированного запрета вести объекты заёмщика в модуле **нет**.

### 8.3. Задним числом — пока период не заперт

Приказ подписан первого, в систему внесли десятого — за эти девять дней уже закрыты факты именем
прежнего куратора: акты, решения, отчёты. Разрешить правку без оглядки значит переписать
авторство закрытых документов; запретить совсем значит расходиться с приказом.

- **Период запирается фактами, а не календарём:** период заперт, если в нём есть факт, закрытый
  именем прежнего куратора. Какие именно факты запирают — определяют модули-источники.
- Дата вступления назначения **поджимается к первому свободному дню**, и это показывается
  человеку **с названием мешающего факта** — не отклоняется молча.
- Если свободных дней нет вовсе, назначение вводится текущей датой.
- Причина ввода задним числом обязательна; запись помечается и видна в журнале отдельно.
- **Ни один закрытый факт не меняет автора** после операции; ответ о кураторе на дату до поджатой
  даты остаётся прежним.

## 9. Период ответственности

Период, за который с работника спрашивают по объекту, — **его закрепление целиком**. Вычетов из
него не бывает: **отсутствие работника период не сокращает** (задание на время отпуска уходит
замещающему, а спрос остаётся на кураторе), а иных оснований вычета в системе нет. Кончается
только следующим закреплением.

Замещающего называет модуль сотрудников; кураторство его не выбирает и не хранит. Если
замещающего нет — действует заведующий отделом.

## 10. Ведущий куратор заёмщика — производная роль

Часть обязанностей предписана по **заёмщику целиком**, а не по одному кредиту: запросить пакет
финансовых документов, проанализировать состояние, вынести на комитет. Если такое обязательство
адресовать всем кураторам заёмщика сразу, его не сделает никто.

**Правило старшинства:**

- ведущий — куратор того кредита, у которого **наибольший остаток на дату начала периода
  обязательства**;
- остаток — **основной долг** в сомах; проценты и пеня в сравнение не входят, иначе старшинство
  достаётся самому запущенному кредиту, а не самому крупному;
- валютный кредит приводится к сомам по **курсу НБКР на ту же дату**; курс виден в объяснении;
- **внутри периода роль не меняется**, даже если остатки поменялись местами; новый период
  пересчитывает ведущего заново;
- при равенстве остатков берётся **самый ранний по дате договор**.

**Лестница, когда действующих кредитов нет:**

| Состояние заёмщика | Кто ведущий |
|---|---|
| есть действующие кредиты | куратор крупнейшего по остатку основного долга |
| действующих нет, закрытые есть | держатель по последнему закрытому кредиту |
| кредитов не было, есть заявка | специалист последней заявки |
| ни одного объекта | **никто**: вести ещё нечего; показывается причина «объектов нет», обязательство не адресуется |

Роль **не назначается и не хранится**: вычисляется на дату и объясняется прямо в карточке
заёмщика — с кредитом, по которому получена. Отсутствие ведущего переводит адресата на
замещающего, роль при этом не пересчитывается.

## 11. Контракты наружу

Пять модулей ждут от кураторства ответа, и каждый норовит спросить по-своему. Форма вопроса
должна быть **одна**, иначе в каждом модуле заведётся своя трактовка «текущего куратора».

| | Содержание |
|---|---|
| **Вопрос** | всегда один: **объект, роль, дата**. Ответа без даты не существует |
| **Ответ 1** | работник · подразделение · **источник** (правило, рука, фолбэк) и — если сработала подмена — кто действует вместо него и почему |
| **Ответ 2** | по работнику: список его объектов на дату с ролями и подразделениями |

**Врезка журнала в карточке чужого модуля** (кредит, заявка, предмет залога, требование):

- **действующий куратор по каждой роли** на дату среза — с источником и подразделением; смена
  даты среза меняет его в шапке врезки;
- ниже журнал строками: периоды, работники, источники, причины;
- **разрывов в датах нет** — конец прежней записи и начало следующей смыкаются;
- строка подмены (отсутствие работника) показана **рядом** с записью, а не вместо неё;
- у кредита кураторы требований показаны **списком**, а не одним именем.

**Граница с модулем сотрудников:**

- замещающего кураторство **не хранит и не выбирает** — спрашивает контрактом «кто действует за
  работника на дату»; отсутствий не ведёт;
- **лестница подмены:** замещающий → заведующий отделом → администратор кураторства. Молчание
  контракта трактуется в безопасную сторону; пустого действующего не бывает;
- **отсутствие ответственности не снимает:** задание уходит замещающему, спрос остаётся на
  закреплённом, период ответственности не сокращается.

**Чего кураторство не делает:**

- **гейта увольнения нет** — кадровое решение принимает модуль сотрудников, а список объектов
  работника он спрашивает вторым ответом;
- **перевода хвостов пачкой нет** — объекты уволенного переезжают правкой ячейки либо рукой по
  одному;
- исключение одно: **администратора кураторства** нельзя снять без преемника, и гейт этот живёт в
  модуле сотрудников;
- маршрутизация задания на учётную запись и вёрстка карточек объектов — не здесь.

## 12. Инварианты

Двадцать один живой инвариант. Снятые номера (ИУ-17, 18, 21, 22, 26) **не переиспользуются**.

| # | Инвариант |
|---|---|
| ИУ-1 | атрибута «куратор» нет ни на одном объекте — ответ даёт журнал на дату |
| ИУ-2 | ответов два: **закреплённый** (ответственность за период) и **действующий** (кому уходит работа); путать нельзя |
| ИУ-3 | единственный законный пустой ответ — вопрос на дату, когда объекта ещё не было |
| ИУ-4 | журнал append-only: запись закрывается датой и добавляется новая, правки на месте нет |
| ИУ-5 | закрепление не закрывается судьбой объекта: куратор жив и после погашения |
| ИУ-6 | правил холдинга столько, сколько назначаемых ролей; общей таблицы «объект → отдел» нет; ячейки — произведение долей; раскладка живёт в справочнике признака, редакция хранит ссылку |
| ИУ-7 | живы обе ступени: правка верхнего правила переставляет живущие объекты так же, как правка нижнего |
| ИУ-8 | пустая ячейка нижней ступени отдаёт объект заведующему; пустая или отсутствующая верхняя — администратору |
| ИУ-9 | «объект без куратора» невозможен; дефект переформулирован в «держится фолбэком дольше порога» |
| ИУ-10 | правка создаёт новую редакцию, та вступает днём сохранения; правка вслепую закрыта; вторая правка дня дописывает редакцию дня |
| ИУ-11 | распределение детерминировано: те же признаки на ту же дату дают то же имя; нагрузка в правило не входит |
| ИУ-12 | подразделение меняется тем же правилом и той же записью, что работник: очередей передач, приёма и отклонения нет |
| ИУ-13 | роли не вытесняют друг друга; у предмета залога их две, и приезжают они в разные подразделения |
| ИУ-14 | ведущий куратор заёмщика не назначается — вычисляется; в журнале его нет |
| ИУ-15 | решение хранит снимок признаков на свою дату; смена признака применяет правило сразу |
| ИУ-16 | правило применяется само и сразу; кнопок «пересчитать», предпросмотра и фонового пересчёта нет |
| ИУ-19 | закрепление рукой требует причины, держится вне правила до отмены и снимается только действием «вернуть к правилу» |
| ИУ-20 | задним числом можно, пока период не заперт: дата поджимается, а не отклоняется |
| ИУ-23 | замещающего называет модуль сотрудников; лестница подмены — замещающий → заведующий → администратор; пустого действующего не бывает |
| ИУ-24 | период ответственности — отрезок журнала целиком: отсутствие его не сокращает |
| ИУ-25 | ведущий куратор вычисляется на период: наибольший остаток основного долга, валюта по курсу НБКР, внутри периода ответ не меняется |

## 13. Чего в модуле нет — и это решение, а не недоделка

Решение заказчика от 17.08.2026 сжало модуль вдвое. Дословно: «пересчёт должен примениться сразу,
автоматом; витрины не надо; передачи тоже не надо, просто меняем куратора; отстранения убираем».

| Снято | Чем закрыт тот же случай |
|---|---|
| **Пересчёт как отдельная операция** — кнопка, предпросмотр, четыре корзины | правило применяется само при сохранении редакции; след — квитанция |
| **Очередь передач** с приёмом, отклонением и рукопожатием | подразделение и работник меняются одной записью журнала правкой верхней ступени |
| **Четыре витрины** — нагрузка, перекос, «живут вне правила», просроченный фолбэк | число объектов в строке ячейки, колонка «сверка с правилом», давность фолбэка и подвал модуля |
| **Отстранение как измерение** и реестр по конфликту интересов | конфликт лечится сменой куратора рукой с причиной; отсутствие держателя — замещением |
| **Гейт увольнения** с переводом хвостов пачкой | кадровое решение — модуль сотрудников; объекты двигают правило и рука |
| **Дата вступления редакции в будущем** | редакция вступает днём сохранения — ждать будущей даты было бы некому |

Вместе со снятым **отменён ADR-0118** (отстранение как отдельное измерение), сняты карточки
P18-R10, R12, R15, R18, R19, R20 и пять инвариантов — все номера заморожены.

**Цена решения, названная честно:** правка правила переписывает живые объекты без чьего-либо
подтверждения; откат — только обратной правкой со своей квитанцией.

**Пятая роль на паузе.** Модель называет **пять** назначаемых ролей и список закрывает; в
прототипе их четыре — «Региональный исполнитель» снят с макета 16.08.2026 решением заказчика.
Расхождение намеренное: строить по модели, а не по числу кнопок в макете.

## 14. Что меняется у соседей

| Модуль | Что правится |
|---|---|
| **Кредит** | убрать зеркало куратора полем карточки; вместо него — врезка журнала на дату среза. Кураторы требований — списком |
| **Заявка** | врезка журнала; специалист заявки закрепляется при регистрации, преемства в куратора кредита нет |
| **Обеспечение и залог** | врезка журнала на предмете; постановка предмета на учёт рождает **две** роли в разных подразделениях |
| **Взыскание** | закрепление живёт **на требовании**, а не на процессе; куратора нигде не хранит. «Передача требования» — операция взыскания, снятием передач не тронута |
| **Заёмщик** | ведущий куратор показывается **вычислением** с объяснением, полем не хранится. Нужны реквизиты-источники признаков: «вид лица», «организационная форма», «форма собственности», отрасль, территория |
| **Сотрудники** | контракт «кто действует за работника на дату» — **единственная внешняя зависимость** модуля; гейт «снять роль администратора кураторства только с преемником»; при увольнении список объектов работника спрашивается у кураторства |
| **Оргструктура** | подразделения — адресаты верхней ступени; переименование и перемещение отдела не должны рвать ссылки в журнале |
| **Задания** | список ответственных строится из ответа кураторства (роль плюс подразделение); маршрутизация на учётную запись остаётся у сотрудников |
| **Справочники** | пороги давности фолбэка по видам объектов; справочник АТЕ для домена территории; курс НБКР |

## 15. Открытые вопросы

| # | Вопрос | Умолчание, на котором строим |
|---|---|---|
| 1 | Три домена ждут справочников соседей — территория (АТЕ), вид заёмщика, форма собственности | признак встаёт в ключ с плашкой «ждёт справочника», домен собран вручную и поедет за источником |
| 2 | «Размер бизнеса» — источник не назван нигде | гейт не пускает признак в ключ; он виден в справочнике, чтобы про него не забыли |
| 3 | Мягкий предел числа ячеек ключа — правило Фонда или параметр? | 40 ячеек, подтверждение состава ключа рукой за пределом |
| 4 | Тройная несочетаемость признаков (каждая пара возможна, вместе нет) | проверка попарная, тройное противоречие не ловится; нужен ли механизм — открыто |
| 5 | Пятая роль «Региональный исполнитель» — на паузе | модель держит пять ролей, список закрыт; макет показывает четыре |
| 6 | Какие именно факты соседних модулей запирают период | определяют модули-источники; кураторство поджимает дату и называет мешающий факт |

## 16. Словарь терминов

| Термин | Значение |
|---|---|
| **Закрепление** | отрезок, в течение которого названный работник вёл названный объект в названной роли |
| **Объект закрепления** | предмет работы, которому нужен ответственный: заявка, кредит, предмет залога, требование. Список закрыт |
| **Роль кураторства** | вид ответственности за объект; роли на одном объекте живут одновременно и независимо; роль ≠ право доступа |
| **Политика распределения** | свод обеих ступеней раздачи целиком |
| **Правило распределения** | таблица «признаки объекта → кто ведёт» одной ступени для одной пары «объект и роль» |
| **Объявленный ключ** | список признаков правила и выбранная группировка для каждого |
| **Признак распределения** | величина, которой правилу разрешено различать объекты (прошла гейт из четырёх условий) |
| **Группировка признака** | именованное разбиение домена признака на укрупнённые доли, версионируемое |
| **Ячейка правила** | одно сочетание долей ключа и один работник против него; без работника — незакрытая |
| **Держатель незакрытой ячейки** | тот, кому объект достаётся, пока в ячейке никого нет: заведующий либо администратор |
| **Применение правила** | появление закрепления из правила записью журнала; случается само и сразу |
| **Квитанция об изменении** | след одного применения: кем, когда, почему, три числа и «было → стало» |
| **Переопределение (рука)** | закрепление вопреки правилу, с обязательной причиной, переживающее применение |
| **Фолбэк** | источник записи, когда объект держит держатель незакрытой ячейки |
| **Ведущий куратор заёмщика** | производная роль: куратор кредита с наибольшим остатком основного долга |
| **Период ответственности** | отрезок закрепления целиком; отсутствие работника его не сокращает |
| **Сверенность домена** | объявленное человеком состояние домена признака относительно справочника-источника |
| **НБКР** | Национальный банк Кыргызской Республики (источник курсов) |
| **АТЕ** | административно-территориальные единицы (справочник территорий) |
