## 1. Что это, кому принадлежит и где границы

**Модуль по имуществам ведёт вещи и имущественные права, которые Фонду предлагают или уже
передали в счёт задолженности по бюджетным кредитам, — от предложения до ухода вещи из
собственности Фонда.** Глагол модуля — «принимает и отчуждает».

Владелец — **Управление по работе с активами** (лист согласования ТЗ, стр. 1102–1103).

### 1.1. Где модуль начинается и кончается (`ИМ-1`)

```
 ВЕЩЬ ДОЛЖНИКА (собственник — должник/залогодатель)         ВЕЩЬ ФОНДА (собственник — Фонд)
 ────────────────────────────────────────────────┐          ┌───────────────────────────────────
  залог / иное имущество                          │          │
     ▼                                            │          │  на учёте
  обращение взыскания — ВЗЫСКАНИЕ                 │          │     ▼
     ▼                                            │ ПЕРЕХОД  │  попытки продажи → договор КП
  торги ПССИ / залогодержателя — ЗАЛОГ (P13)      │  ПРАВА   │     ▼
     ├─ состоялись → выручка → ADR-0054           │ ═══════► │  оплачен / передан / выбыл /
     └─ не состоялись ─┐                          │          │  возвращён → СНЯТ С УЧЁТА
                       ▼                          │          │
            ┌──── ПРЕДЛОЖЕНИЕ ИМУЩЕСТВА ──── решение органа ── акт ┘
            │  (+ банкрот через спецадминистратора, должник,
            │     залогодатель, третье лицо — добровольно)
            └──────────────── МОДУЛЬ ПО ИМУЩЕСТВАМ ─────────────────────────────────────────►
```

- **Вход** — предложение от любого из пяти источников (`ИМ-17`). Модуль рассматривает его и
  решает «принять» или «отказать» по каждой позиции (п. 35: «принятие **либо отказ**»).
- **Середина** — переход права (`ИМ-20`): с него вещь Фонда, и с него же погашен долг.
- **Выход** — один из пяти путей выбытия, после которого объект снят с учёта (`ИМ-7`).

### 1.2. Чего в модуле нет

| что | где живёт | почему |
|---|---|---|
| торги по предмету залога, начальная продажная цена, раздел выручки по п. 48 | Залог (P13) публикует, Взыскание делит | `ADR-0004`, `ADR-0054`; модуль их **читает** |
| деление суммы принятия между кредитами | Взыскание (`ИМ-4`) | правило одно на вещь, кто бы её ни отчуждал |
| разнесение внутри кредита, сторно, корректировка суммы, курс | Платежи | `ADR-0058`, `ADR-0061`, `ADR-0090`; один реестр денег |
| учёт задолженности должника | Кредит и Платежи | `ADR-0020`: модуль владеет фактами, а не долгом |
| бухгалтерский учёт объекта (баланс, амортизация, проводки) | бухгалтерия Фонда вне АСУБК | `ИМ-11` |
| аренда и иное использование объекта, доход от него | вне АСУБК | `ИМ-30`; в модуле только факт обременения (`ИМ-31`) |
| ход торгов Фонда (участники, ставки, задатки) | площадка торгов | `ИМ-10`; у модуля только итог попытки |
| регистрация входящих и исходящих документов | будущий документооборот | `ИМ-34`; у модуля только факт документа |
| регресс поручителя к заёмщику | спор сторон, Фонд не участник | `ИМ-27` |
| уведомления и поручения | Задания | `ИМ-15`; модуль объявляет поводы |
| числа на дату и отчётные формы | Статистика и Отчётность | `ИМ-22`, `ADR-0222` |

## 2. Единица учёта

### 2.1. Три сущности (`ИМ-2`)

```
 Предложение имущества П-1   (источник · обязанное лицо · отчуждатель · документ · срок ответа)
 ├─ Позиция 1 ── итог: ПРИНЯТА ──► Объект имущества ИО-1 ─► … ─► снят с учёта
 ├─ Позиция 2 ── итог: ОТОЗВАНА источником
 └─ Позиция 3 ── итог: ОТКАЗАНА решением органа
```

- **Предложение имущества** — обращение одного источника. Короткий процесс: регистрация,
  рассмотрение, решение органа, закрытие.
- **Позиция предложения** — одна вещь внутри предложения. Несёт своё решение и итог.
- **Объект имущества** — вещь или право Фонда. Длинная жизнь: годы, если продана в рассрочку.

Уровни разведены потому, что у них разные сроки и разные финалы: отказанной позиции нужен
след решения, но не нужен баланс, а объекту не нужен срок ответа источнику.

### 2.2. Реквизиты предложения (`ИМ-17`, `ИМ-27`, `ИМ-32`)

| реквизит | смысл | правило |
|---|---|---|
| источник | ПССИ · спецадминистратор · должник · залогодатель · третье лицо | закрытый перечень; задаёт вид документа и отчуждателя по умолчанию |
| обязанное лицо | чей долг гасится: **заёмщик или поручитель** | ссылка на обязанное лицо взыскания (`ADR-0024`), не на заёмщика вообще |
| отчуждатель | чья вещь до перехода права; кому причитается доплата | ссылка на субъекта (`ADR-0016`), не ввод ФИО |
| документ-основание | постановление ПССИ, акт спецадминистратора, соглашение об отступном | реквизиты + вложение (`ИМ-34`) |
| срок ответа | из документа источника; иначе — умолчание настроек по источнику | `ИМ-32` |
| кредиты | какие кредиты обязанного лица затронуты | для проекции во взыскание и деления (`ИМ-4`) |

**Таблица источников:**

| источник | документ-основание | отчуждатель по умолчанию | кому доплата |
|---|---|---|---|
| ПССИ | постановление о передаче нереализованного имущества взыскателю | должник (или залогодатель — по предмету) | депозит ПССИ |
| спецадминистратор | решение или акт по конкурсной массе | банкрот | конкурсная масса |
| должник | соглашение об отступном | должник | должник |
| залогодатель (не должник) | соглашение об отступном / по п. 49 | залогодатель | залогодатель |
| третье лицо | соглашение об исполнении за должника | третье лицо | третье лицо |

Поручитель шестым источником **не является** (`ИМ-27`): он обязанное лицо, и его вещь идёт
источником «должник» с обязанным лицом = поручитель и отчуждателем = поручитель. Гасится его
линия во взыскании, а с ней — в той же сумме — долг заёмщика.

**Пробный случай.** Брат должника Х отдаёт свой гараж: источник — третье лицо, обязанное
лицо — Х, отчуждатель — брат. Долг гасится Х, доплата уходит брату. При «отчуждатель =
должник» доплата ушла бы на счёт Х — ошибка с деньгами, ради которой реквизиты и разведены.

### 2.3. Реквизиты позиции

| реквизит | правило |
|---|---|
| вид имущества | общий справочник видов с Залогом (`ИМ-12`, `ИМ-35`) |
| характеристики | по схеме параметров вида; у вещи из залога — **ссылка «происходит из предмета залога»** |
| заключения | осмотр, оценка, ликвидность, расходы на содержание — готовит специалист |
| стоимость принятия | из документа-основания, в его валюте (`ИМ-3`, `ИМ-24`) |
| ожидаемая доплата | производная на дату расчёта: стоимость минус остаток долга обязанного лица после ранее принятых позиций того же решения, в порядке плановой даты перехода права; при равных датах — по номеру позиции; показывается органу как цена решения (`ИМ-5`, `ИМ-43`) |
| решение | ссылка на решение органа + итог по этой позиции |
| итог | принята · отказана · отозвана · принятие не состоялось (`ИМ-33`, `ИМ-21`) |

### 2.4. Объект имущества

Возникает **только** двумя путями (`ИИ-1`):

1. из принятой позиции — актом приёма-передачи;
2. вводом остатка при запуске системы (`ИМ-29`, §13).

Характеристики при возникновении из залога **копируются снимком** на дату акта (`ИМ-12`):
собственник сменился, и у двух записей дальше разные истории. Ремонт Фонда не должен
переписать обследования предмета залога, по которым, может быть, шёл суд.

### 2.5. Вид имущества — признаки справочника

Справочник видов общий с Залогом. Модулю нужны от него три признака (`ИМ-ДС-12`):

| признак | на что влияет |
|---|---|
| **право подлежит госрегистрации** | дата перехода права = дата регистрации, а не акта (`ИМ-20`) |
| **делимая** | доступно ли разделение (`ИМ-28`) |
| **класс: вещь / имущественное право** | у права выключены осмотры, местоположение и разделение; кураторство режет по месту регистрации или эмитента (`ИМ-35`) |

## 3. Предложение: рассмотрение и решение

### 3.1. Жизненный цикл

```
 Предложение:  ЗАРЕГИСТРИРОВАНО ─► НА РАССМОТРЕНИИ ─► РЕШЕНИЕ ВЫНЕСЕНО ─► ЗАКРЫТО
                 входящий документ    заключения по       решение органа:     у каждой позиции
                 срок ответа          позициям; ответ     итог по каждой      есть итог
                                      в срок / промежут.  позиции
                                      письмо

 Позиция:   предложена ─► на рассмотрении ─► ПРИНЯТЬ ─► акт ─► [переход права] ─► Объект
                 │               │              │         └─► право не перешло ─► НЕ СОСТОЯЛОСЬ
                 │               │              └─► (до акта) ─► ОТОЗВАНА
                 │               └─► ОТКАЗАТЬ (основание) ─► ОТКАЗАНА
                 └───────────────┴─► ОТОЗВАНА источником (документ)
```

Состояние предложения и позиции — производная от фактов, как и у объекта (`ИМ-13`).

Предложение «закрыто», когда у каждой позиции есть итог. Принятая позиция при этом ещё ждёт
акта: пока акта нет, она остаётся исполнимой, а по истечении порога ожидания Задания получают
повод `pk-im-act-pending` (§9, `ИМ-42`). Из ожидания акта три выхода: акт, отзыв источником
(§3.4) или решение о прекращении принятия (§4.3).

### 3.2. Кто решает (`ИМ-6`)

**По позиции всегда решает коллегиальный орган.** Решение — документ органа с номером и
датой, **одно на предложение, итог — по каждой позиции**: одно заседание вправе принять дом и
отказаться от трактора.

- Орган — ссылка на общий справочник коллегиальных органов взыскания (§11 канона взыскания,
  `ADR-0089`). Естественный кандидат из пятёрки нормы — **Комитет по вопросам правового
  обеспечения и управления имуществом**; подтверждение — `ИМ-ВЗ-3`.
- Гейта «принятие имущества» в таблице гейтов взыскания пока нет — `ИМ-ДС-2`.
- Если Инструкция введёт порог «до N решает начальник Управления», это **настройка поверх**
  того же правила: орган — реквизит правила, а не код. Модель не меняется.

Почему не единолично: принятие гасит долг и может потребовать доплаты — необратимо и стоит
денег; P9-R8 уже ставит «принятие имущества» в ряд действий, разрешаемых комитетом.

### 3.3. Срок ответа (`ИМ-32`)

- Срок — **реквизит предложения из документа источника**: у ПССИ он записан в постановлении,
  у спецадминистратора задан процедурой, у добровольного предложения его может не быть.
- Нет в документе — подставляется умолчание из настроек **по источнику**, со своим источником
  значения (норма · Инструкция · внутренний акт).
- Ответом в срок считается решение органа **или промежуточное письмо** («рассматриваем, просим
  продлить») — факт документа с номером и датой.
- Истёкший срок без ответа — повод для Заданий (§9).
- **Решение после срока не блокируется**: оно выносится с пометкой «вынесено после истечения
  срока ответа». Запрет оставил бы вещь, которую источник ещё не отозвал, без решения навсегда.

### 3.4. Отзыв источником (`ИМ-33`)

- До акта приёма-передачи источник вправе отозвать **любую позицию** — фактом «отозвана» с
  документом (постановление ПССИ о возврате должнику, письмо должника).
- Решение органа «принять», если оно было, остаётся в истории **неисполненным**.
- После акта отзыва нет. До перехода права выход — только прекращение принятия (`ИИ-20`,
  §4.3); после перехода права вещь уходит от Фонда только путём «возврат» через суд (`ИМ-14`).
- «Отозвана» и «отказана» — **разные итоги**: отказ — решение Фонда, отзыв — решение
  источника. Смешение сделало бы ложным отчёт «Фонд отказал в N % предложений».

### 3.5. Рассмотрение не останавливает долг (`ИМ-19`)

Пока предложение рассматривается, **пени начисляются до перехода права, меры взыскания
продолжаются**. Нормы о паузе нет (у реструктуризации она есть — п. 18, у предложения нет);
выдуманная пауза дала бы должнику рычаг «предложил неликвид — взыскание встало»; решение `М-7`
взыскания: «пауза останавливает действия Холдинга, а не обязательство должника». Давят только
сроки ответа. Ставит ли паузу Инструкция — `ИМ-ВЗ-9`.

## 4. Принятие и деньги

### 4.1. Стоимость принятия (`ИМ-3`)

**Стоимость принятия берётся из документа-основания; модуль её не вычисляет.** У каждого
источника цена записана: в постановлении ПССИ, в акте спецадминистратора, в соглашении об
отступном, в отчёте оценщика. Модуль вводит её, прикладывает документ и выносит на решение
органа.

Правило «начальная цена минус N % за несостоявшиеся торги» не зашивается: его задаёт закон или
Инструкция, которых у нас нет. Есть ли такое правило — `ИМ-ВЗ-1`.

Принятие — это **погашение, а не списание** (`ADR-0076` §2): ценность получена.

### 4.2. Дата погашения — переход права (`ИМ-20`)

**Долг гасится на дату перехода права:**

- вид с признаком «право подлежит госрегистрации» (недвижимость, доля) — **дата регистрации**;
- прочие виды — **дата акта приёма-передачи**.

Между актом и регистрацией объект в состоянии **«принят, ждёт регистрации»**: Фонду он ещё не
принадлежит, погашения ещё не было, продавать его нельзя (`ИИ-9`). Юридическое правило перехода
права в КР подтверждается у юристов Фонда — `ИМ-ВЗ-10`; модель от ответа не зависит, меняется
только набор видов с признаком.

### 4.3. Отказ регистратора и прекращение принятия (`ИМ-21`, `ИМ-41`)

- **Устранимый отказ** (не хватает справки) — просто факт; объект продолжает ждать
  регистрации, документы подаются повторно.
- **Окончательный отказ** (арест третьего лица на годы) или **решение органа о прекращении
  принятия** (`ИМ-41`) — закрывается состоянием **«принятие не состоялось»** (объект, если акт
  уже подписан; иначе только позиция). Денег не движется: погашения не было.
  Позиция получает итог «принятие не состоялось» с основанием. Повторить можно новой позицией
  или новым предложением, если препятствие снято.
- **Решение о прекращении принятия.** Выносится, когда право не перейдёт, а окончательного
  отказа регистратора нет. Причина обязательна, перечень закрытый: отчуждатель уклоняется от
  регистрации · вещь погибла или утрачена до перехода права · отчуждатель умер, правопреемника
  нет · иное (с пояснением). Инициатор — куратор предложения (после акта — куратор объекта),
  обычно по поводу `pk-im-act-pending` или `pk-im-registration-pending` (§9); решение выносит
  орган по §3.2; публикует специалист вторым ключом (§10.2). Применяется к принятой позиции без
  акта (§3.1) и к объекту до перехода права; в первом случае объекта ещё нет (`ИИ-1`), итог
  получает позиция.
  Гибель или утрата до перехода права — не «выбытие» (§5.3): путь «выбытие» только для объекта
  на учёте. Риск гибели и страховое возмещение до перехода права — у отчуждателя, вне модуля:
  вещь Фонду ещё не принадлежала (`ИМ-37`).
  Пример: акт на квартиру ИО-1 от 12.03.2027, регистрации нет; 15.05.2027 Комитет решает
  «отчуждатель уклоняется» → ИО-1 «принятие не состоялось», погашения и сторно нет, долг не
  тронут.
- Это **не путь выбытия** и **не возврат**: пять путей `ИМ-7` описывают выход из собственности
  Фонда, а здесь собственности не было.

### 4.4. Три шага, три владельца (`ИМ-4`)

Принятие проходит тот же шов, что выручка от торгов (`ADR-0054`):

```
  МОДУЛЬ ПО ИМУЩЕСТВАМ           ВЗЫСКАНИЕ                          ПЛАТЕЖИ
  публикует факт принятия  ──►   делит между кредитами        ──►   поступление вида «имущество
  (стоимость, дата перехода      обязанного лица:                   в счёт погашения» по каждому
   права, обязанное лицо,        залог — по отнесениям и п. 48;     кредиту → разнесение обычной
   вещь, связь с залогом)        иное имущество — ИМ-ДС-1           матрицей (слой решения суда
                                 → «распределено» + «не вошло»      первым, затем пени → % → ОД)
```

Модуль **не делит и не разносит** (`ИИ-5`). Правило деления одно на вещь, кто бы её ни
отчуждал: ПССИ на торгах или Фонд на баланс.

Делить взыскание обязано по долгу на дату перехода права, **уже уменьшенному** прежними
принятиями того же обязанного лица (`ИМ-43`, `ИМ-ДС-1`): объекты с разными датами перехода права
публикуются и делятся по очереди этих дат, а не вместе.

**Пробел у соседа.** Канон взыскания (§13, стр. 920) задаёт деление только для предмета залога.
Для иного имущества (п. 33) правила нет — `ИМ-ДС-1`.

### 4.5. Доплата (`ИМ-5`)

Если стоимость принятия больше задолженности обязанного лица на дату перехода права, **Фонд
доплачивает разницу отчуждателю**:

- **сумма доплаты** = стоимость принятия − распределённое взысканием на шаге 2 (производная,
  `ADR-0001`);
- **адресат** — по таблице источников §2.2 (депозит ПССИ, конкурсная масса, должник,
  залогодатель, третье лицо);
- **исполнение** — сущность «Возврат» в Платежах (§2.3 канона платежей: «получатель бывает не
  заёмщиком… привязки к кредиту может не быть»), долга соседу нет;
- пока доплата не исполнена, у объекта признак **⚑ «принятие не завершено»**, и продавать его
  нельзя (`ИИ-9`).

При решении органу показывается **ожидаемая доплата** на дату расчёта — как цена решения. Если
принято несколько позиций, она считается **нарастающим итогом** по плановым датам перехода права
(`ИМ-43`). Плановая дата: для вида без госрегистрации — дата акта (пока акта нет — дата
решения органа); для вида с госрегистрацией — дата акта, пока регистрации нет, затем дата
регистрации. Она нужна только для очерёдности; при равных датах — номер позиции. Пример: долг 1 000 000, трактор 500 000 (акт 15.03), квартира 700 000 (переход права
01.06). Трактор: 500 000 против долга 1 000 000 → доплаты 0. Квартира: 700 000 против остатка
500 000 → 200 000. На 15.03 «не вошло» 0, на 01.06 — 200 000; ⚑ «принятие не завершено»
ставится только на квартиру. Каждая позиция отдельно против полного долга дала бы 0 + 0 при
реальных 200 000. На дату перехода права доплату по-прежнему считает взыскание по живому
долгу. Это оценка: она пересчитывается при каждом новом факте (акт, регистрация,
прекращение принятия выпавшей позиции); окончательная сумма известна только на дату перехода
права, потому что долг до неё живёт (`ИМ-19`). Обязательна ли доплата или Инструкция разрешает отказ — `ИМ-ВЗ-2`.

Вариант «разница остаётся Фонду бесплатно» отвергнут: Фонд получал бы вещь дороже своего
требования, ничего не платя, — прямое основание для иска.

### 4.6. Валюта (`ИМ-24`)

- Стоимость принятия хранится **в валюте документа-основания**; учётная стоимость объекта — в
  ней же, навсегда.
- Пересчёт в валюту кредита делают **Платежи** по курсу на дату перехода права (§2.4 канона
  платежей: курс — реквизит связи, справочник курсов НБКР, «нет курса на дату — действует
  последний установленный»).
- Модуль курсов не знает (`ИИ-18`). Второй конвертер разошёлся бы с первым на копейки — ровно
  там, где родилась «сирота 0,01» (E2E-13/14).

### 4.7. Сквозной пример

Должник Х: кредит К-1 (сомы), долг 900 000; кредит К-2 (сомы), долг 900 000. Кредиты обеспечены
залогом квартиры ПЗ-88 (отнесения 50/50). Двое торгов ПССИ не состоялись.

| дата | факт | кто | что меняется |
|---|---|---|---|
| 10.01.2027 | постановление ПССИ, срок ответа 5 р.д. → предложение П-1: квартира, гараж, трактор | специалист | П-1 зарегистрировано; проекция в журнал дела Х |
| 15.01.2027 | промежуточное письмо «рассматриваем» | специалист | срок соблюдён |
| 01.02.2027 | ПССИ отзывает гараж | специалист | позиция 2: отозвана |
| 20.02.2027 | решение Комитета: квартира — принять за 2 400 000, трактор — отказать (неликвид) | секретарь органа | позиция 1 принята; позиция 3 отказана; ожидаемая доплата ≈ 550 000 |
| 12.03.2027 | акт приёма-передачи квартиры | специалист + второй ключ | ИО-1 «принят, ждёт регистрации»; снимок характеристик ПЗ-88 |
| 05.04.2027 | регистрация права Фонда | специалист + второй ключ | **переход права**: публикация принятия 2 400 000 на 05.04 |
| 05.04.2027 | взыскание делит: долг на 05.04 = 1 850 000 (с пенями) | взыскание | К-1 925 000, К-2 925 000; не вошло 550 000 |
| 05.04.2027 | платежи разносят по К-1 и К-2 | платежи | К-1, К-2 погашены |

| 20.04.2027 | Возврат 550 000 исполнен | бухгалтер | ⚑ снят; ИО-1 «на учёте»; ПЗ-88 «перешёл к Фонду» |

Продолжение примера — §7.5.

## 5. Объект: состояние на дату

### 5.1. Состояние выводится из фактов (`ИМ-13`)

**Состояние объекта не хранится и вручную не ставится** — оно вычисляется по фактам на
выбранную дату (`ИИ-2`, `ADR-0001`, `ADR-0026`). Факты:

| факт | документ |
|---|---|
| акт приёма-передачи | акт |
| регистрация права / отказ регистратора | выписка / уведомление об отказе |
| исполнение доплаты | Возврат в Платежах |
| вводный остаток | документ бухгалтерии |
| осмотр | акт осмотра |
| оценка | отчёт оценщика |
| расход содержания | платёжный или первичный документ |
| обременение (с–по) | договор, постановление об аресте |
| попытка продажи и её итог | объявление, протокол площадки |
| договор КП, оплаты по нему, претензия, расторжение | договор, Платежи, письма |
| разделение | решение органа или распоряжение |
| решение о прекращении принятия | решение органа с причиной (`ИМ-41`) |
| документ выбытия | акт о гибели / утрате, решение о передаче, судебный акт |
| исправление любого из опубликованных | исправленный документ или решение органа |

Следствие для интерфейса: кнопки «сменить статус» нет; есть кнопки «ввести факт».
Следствие для статистики: «сколько объектов было нереализовано на 01.01.2027» — тот же расчёт
на другую дату, без отдельной истории полей.

### 5.2. Машина состояний

```
                         акт приёма-передачи
                                 │
                                 ▼
                      ПРИНЯТ, ЖДЁТ РЕГИСТРАЦИИ ── отказ регистратора / прекращение принятия ──► ПРИНЯТИЕ НЕ СОСТОЯЛОСЬ
                                 │ переход права (или сразу — если регистрация не нужна)
                                 ▼
              ┌──────────── НА УЧЁТЕ ◄──────────────────────────┐  попытка не состоялась /
              │          ▲     │                                 │  договор КП расторгнут /
              │          │     ▼                                 │  покупатель не подписал
              │     ВЫСТАВЛЕН НА ПРОДАЖУ (идёт попытка)          │
              │                │ попытка состоялась + договор    │
              │                ▼                                 │
              │     ПРОДАН ── разово ──────► оплачен ────────────┼────► СНЯТ С УЧЁТА
              │       └─ в рассрочку ─► оплаты … ─► оплачен ─────┘          ▲
              ├──► ПЕРЕДАН БЕЗВОЗМЕЗДНО (решение органа + акт) ─────────────┤
              ├──► ВЫБЫЛ (акт о гибели, утрате, сносе) ─────────────────────┤
              ├──► ВОЗВРАЩЁН (судебный акт) — сторно погашения ─────────────┘
              └──► РАЗДЕЛЁН ──► новые объекты (каждый со своей жизнью с этой точки)

   Поперёк: ⚑ принятие не завершено (доплата не исполнена) · ⚑ обременён (на дату)
```

| состояние | что значит | можно продавать |
|---|---|---|
| принят, ждёт регистрации | акт есть, права нет | нет |
| на учёте | вещь Фонда, ничего не идёт | да, если нет ⚑ «не завершено» |
| выставлен на продажу | идёт попытка | — (вторую попытку параллельно не открыть) |
| продан (разово / в рассрочку) | договор КП действует, оплата не завершена | нет |
| снят с учёта | путь выбытия завершён | — |
| разделён | закрыт разделением, жизнь продолжают части | — |
| принятие не состоялось | право так и не перешло | — |

### 5.3. Пути выбытия (`ИМ-7`)

Закрытый перечень из пяти. Пути различаются поведением денег, а не названием:

| путь | документ | деньги | конец |
|---|---|---|---|
| продажа разовая | договор КП | поступление цены (через Платежи) | снят с учёта, когда оплачен |
| продажа в рассрочку | договор КП с графиком | поступления по графику | снят с учёта после последнего платежа (`ИМ-9`) |
| безвозмездная передача | решение органа + акт передачи | нет — потеря стоимости | снят с учёта на дату акта |
| выбытие (гибель, утрата, снос) | акт о гибели / утрате | нет — потеря стоимости | снят с учёта на дату акта |
| возврат (принятие отменено) | судебный акт | **сторно погашения**, долг восстановлен (`ИМ-14`) | снят с учёта на дату акта |

- Снятие с учёта — **только следствие** завершённого пути (`ИИ-7`).
- Шестой путь — правка модели с ADR, а не строка справочника. Намеренно: справочник не скажет
  движку, что делать с деньгами нового пути.
- Расторжение договора КП — **выход из пути**, а не новый путь: объект возвращается «на учёт».

### 5.4. Разделение делимого объекта (`ИМ-28`, `ADR-0261`)

**Путь выбытия всегда берёт объект целиком** (`ИИ-7`). Делимая вещь (зерно, скот, мешки) уходит
по частям только через разделение:

```
 ИО-410 зерно 120 т · 1 440 000 ──разделение (основание)──► ИО-410/1  50 т ·   600 000 → продан А
                                                          ├► ИО-410/2  65 т ·   780 000 → продан Б
                                                          └► ИО-410/3   5 т ·    60 000 → выбыл
 исходный ИО-410 — «разделён» (не путь выбытия: вещь от Фонда не ушла)
```

- Учётная стоимость частей — пропорционально количеству; **сумма частей равна целому до
  копейки**, остаток округления — последней части (`ИИ-8`).
- Части наследуют всё от исходного: источник, дату перехода права, снимок характеристик,
  ссылку на происхождение. Их история начинается с даты разделения, история исходного до неё
  остаётся у исходного.
- Разделение доступно только видам с признаком «делимая». Для квартиры его нет.
- Разделение публикуется вторым ключом: оно меняет учётную стоимость объектов.

### 5.5. Обременение (`ИМ-31`)

Факт «на вещи висит чужое право»: вид (аренда, пользование, арест третьего лица, ответственное
хранение, иное), даты с–по, документ. **Денег, графика и дохода у обременения нет** — договор
использования ведётся вне системы (`ИМ-30`).

**Гейт попытки продажи:** активное на дату попытки обременение её не запрещает, но требует
отметки в попытке: «продаётся с обременением» или «после снятия» (`ИИ-17`). Без гейта признак
не читают в тот единственный момент, когда он важен.

### 5.6. Характеристики и связь с предметом залога (`ИМ-12`)

```
 Предмет залога ПЗ-88 (собственник: должник)       Объект ИО-1 (собственник: Фонд)
 вид: квартира · 54 м² · кадастр …                 вид: квартира · 54 м² · кадастр …  ← снимок на 12.03
 состояние: удовл. (обследование 2025)             состояние: после ремонта (2027)    ← своя жизнь
 статус: ПЕРЕШЁЛ К ФОНДУ (финал, только чтение) ◄── происходит из: ПЗ-88
```

- Справочник видов и схема параметров — **общие с Залогом**: «квартира» не значит разное в
  двух модулях, статистика режет сквозным разрезом.
- Объект из залога копирует характеристики **снимком**; ссылка на предмет — только происхождение.
- У Залога появляется финальное состояние предмета **«перешёл к Фонду»** — с ним же снимается
  обременение и показывается трек взыскания «реализация завершена» (`ИМ-ДС-4`).
- Вещь не из залога (иное имущество, отступное) заводится по той же схеме с нуля.

## 6. Стоимость, оценки, расходы, результат (`ИМ-11`)

```
 стоимость принятия      2 400 000   ← учётная стоимость; долг уже погашен этой суммой, навсегда
 + расходы содержания       90 000   ← журнал расходов объекта
 − цена продажи          2 250 000
 ══════════════════════════════════
 результат по объекту     −240 000   ← производная, не хранится; подпись: «без учёта доходов
                                        от использования — они учитываются вне АСУБК»
```

| величина | правило |
|---|---|
| **учётная стоимость** | = стоимость принятия; не меняется ни переоценкой, ни курсом (`ИИ-4`); меняется только исправлением (`ИМ-23`) или разделением (пропорционально) |
| **оценка** | справочная история: дата, оценщик, сумма, валюта, документ; нужна для решения о цене продажи, на учёт не влияет |
| **расход содержания** | журнал: дата, статья (охрана, налог, коммунальные, оценщик, площадка, страхование, ремонт, хранение), сумма, валюта, документ |
| **результат по объекту** | цена продажи − учётная стоимость − расходы; у безвозмездной передачи и выбытия цена = 0 (или страховое возмещение, `ИМ-37`); производная |

**Должника это не касается.** Его долг закрыт фиксированной суммой на дату перехода права;
пересчитывать его из-за того, как Фонд потом продал вещь, нельзя — иначе погашение стало бы
«временным». Этим принятие отличается от торгов по залогу, где расходы реализации **уменьшают**
выручку, гасящую долг (п. 48): здесь всё после перехода права — деньги Фонда, а не должника.

Бухгалтерский учёт объекта — вне модуля: ТЗ просит «характеристику с указанием стоимости» и
мониторинг, а не проводки.

## 7. Продажа

### 7.1. Попытка продажи (`ИМ-10`)

У объекта 0…N попыток. Пока попытка идёт, объект «выставлен на продажу»; параллельно вторую не
открыть.

| реквизит | правило |
|---|---|
| способ | аукцион · конкурс · прямая продажа (допустимость способов — `ИМ-ВЗ-5`) |
| стартовая цена | **с основанием**: отчёт оценщика или решение органа о снижении |
| площадка, номер лота | внешняя система торгов; до интеграции — вводится руками со ссылкой на протокол |
| даты | объявление, проведение |
| отметка об обременении | обязательна, если на дату есть активное обременение (`ИИ-17`) |
| итог | состоялась (покупатель, цена) · не состоялась · состоялась, договор не заключён (`ИМ-40`) |

- **Ход торгов — у площадки.** Участники, ставки, задатки, шаги в модуле не ведутся: второй
  аукцион у себя разошёлся бы с официальным протоколом.
- **Основание снижения цены** обязательно: без него каждое снижение выглядит произволом.
  Правило снижения между попытками (шаг, минимум, кто решает) — `ИМ-ВЗ-6`.
- Шов с внешней системой узкий — номер лота и итог. Когда интеграция появится, итог придёт
  машинно, модель не изменится. Какая система — `ИМ-ВЗ-5`.
- Слово «торги» в модуле не используется: оно занято мерой взыскания по предмету залога
  (`ADR-0028`). У Фонда — попытка продажи.
- Попытка невозможна до перехода права, при ⚑ «принятие не завершено» и при действующем договоре
  КП (`ИИ-9`, `ИИ-10`).

### 7.2. Договор купли-продажи (`ИМ-8`)

Удачная попытка порождает договор КП. **Не более одного действующего договора на объект**
(`ИИ-10`).

| реквизит | правило |
|---|---|
| покупатель | ссылка на субъекта |
| цена, валюта | из итога попытки |
| вид | разовый · рассрочка |
| график | у рассрочки: даты и суммы платежей |
| неустойка | ставка и база из договора — простое правило, без расчётного ядра кредита |
| сохранение права | по умолчанию «право переходит после полной оплаты» (`ИМ-9`) |

**Деньги — только через Платежи** (`ИИ-6`). Оплата по договору КП регистрируется в Платежах как
поступление **нового вида «оплата по договору купли-продажи»** с адресатом «договор», а не
кредит. Сейчас платёж в Платежах всегда адресован кредиту (`creditId`, канон платежей стр. 85) —
второй адресат привязки — `ИМ-ДС-3`. Так оплата попадает в сверку с казначейством и в окно
ожидания зачисления, как любое поступление.

Модуль сопоставляет поступления с графиком и сам считает **немного**: факт по графику,
просроченную сумму, дни просрочки, неустойку по ставке договора. Это ведение договора, а не
кредит.

Почему не кредит: у рассрочки нет ни госрешения, ни программы, ни заявки — цикл 01→05 держится
именно на них, и «кредит без основания» сломал бы инварианты корня.

### 7.3. Право переходит после полной оплаты (`ИМ-9`)

```
 договор КП в рассрочку                         при неоплате
 ─────────────────────────────                  ──────────────────────────────────────────
 объект «продан в рассрочку», НЕ снят с учёта   претензия → решение органа → расторжение
 оплаты по графику … последний платёж           → объект снова «на учёте»
 → путь завершён → СНЯТ С УЧЁТА                 → уплаченное: удерживается неустойка по
                                                  условию договора, остаток — Возвратом
```

- Пока идёт рассрочка, право у Фонда: покупатель не перепродаст вещь, а при неоплате Фонд
  возвращает вещь, а не судится годами за деньги.
- **Расторжение — выход из пути**, а не новый путь.
- Судебная работа против покупателя (не освобождает склад) — **журналом мер по договору**: дата,
  вид, документ, итог. Без машины фаз взыскания: долг покупателя — не бюджетный кредит, Порядок
  №41 к нему не относится.
- Режим «право переходит при подписании» — если его потребует Инструкция, добавится признаком
  договора (`ИМ-ВЗ-4`).

### 7.4. Безвозмездная передача и выбытие

- **Безвозмездная передача** (например, госоргану) — решение органа + акт передачи; второй
  ключ. Денег нет; результат по объекту = −(учётная стоимость + расходы).
- **Выбытие** (гибель, утрата, снос) — акт; второй ключ. Если объект был застрахован, страховое
  возмещение — поступление в Платежах; в результате по объекту оно учитывается как цена
  (`ИМ-37`).

### 7.5. Сквозной пример (продолжение §4.7)

| дата | факт | состояние ИО-1 |
|---|---|---|
| 20.04.2027 | — | на учёте |
| 01.06.2027 | попытка 1: аукцион, старт 2 500 000 (оценка №…), лот №… | выставлен на продажу |
| 15.06.2027 | итог: не состоялась | на учёте |
| 20.08.2027 | решение органа о снижении стартовой цены до 2 200 000 | на учёте |
| 01.09.2027 | попытка 2: аукцион, старт 2 200 000 | выставлен на продажу |
| 15.09.2027 | итог: состоялась, покупатель Y, цена 2 250 000 | выставлен на продажу |
| 20.09.2027 | договор КП, рассрочка 12 × 187 500 | продан в рассрочку |
| 03.2028 | Y не платит 2 месяца → повод «просрочка рассрочки» | продан в рассрочку |
| 09.2028 | последний платёж | **снят с учёта**; результат −240 000 (расходы 90 000) |

## 8. Возврат и исправления

### 8.1. Возврат — принятие отменено (`ИМ-14`)

Суд признал принятие недействительным (например, оценка занижена), вещь возвращается
отчуждателю.

- Модуль публикует факт **«принятие отменено»** с судебным актом — путь выбытия «возврат».
- Бухгалтер в Платежах делает **сторно поступления** «имущество в счёт погашения» задним числом
  — механизмом §4.1 канона платежей (`ADR-0058`). Сторнированное остаётся видимым.
- Пеня за разрыв «дата перехода права → дата отмены» **выводится, но помечается спорной** и
  уходит на Комиссию по спорным начислениям (§4.4 канона платежей, `ADR-0089`): чья вина в
  разрыве — заранее не ясно.
- Если доплата отчуждателю была исполнена, её возврат Фонду — требование к отчуждателю; сумма
  публикуется модулем, взыскивается вне модуля (`ИМ-ВЗ-7`).
- **Возврат возможен, только пока объект на учёте.** Если вещь уже продана третьему лицу, суд
  обычно присуждает деньги: это не путь выбытия, а денежная компенсация отчуждателю через
  Возврат в Платежах (`ИМ-ВЗ-7`).

**Оговорка.** У поступления «имущество в счёт погашения» нет строки казначейства — денег не было.
Сверка с ЦК обязана такие поступления пропускать (`ИМ-ДС-5`).

### 8.2. Исправление опубликованного факта (`ИМ-23`)

**Публикация** — момент, когда факт уходит наружу: решение органа, акт, переход права,
исполнение доплаты, итог попытки, договор КП, разделение, документ выбытия.

- **До публикации** черновик правится свободно: предложение на рассмотрении, позиция без
  решения, попытка без итога.
- **После публикации** факт неизменяем (`ИИ-12`). Ошибка лечится **исправлением** — новым фактом
  с основанием (исправленный документ или решение органа), который **замещает исходный с даты
  исходного**. Видны оба; исходный помечен «исправлен».
- Соседи получают «факт исправлен» и пересчитывают свою часть: Платежи — **корректировкой суммы
  поступления** (§8.3 канона платежей), не сторно; взыскание переделит.
- Исправление публикуется вторым ключом.

Пример: в акте набрали 2 040 000 вместо 2 400 000, погашение уже разделено, месяц закрыт в
статистике. Исправление → корректировка поступления на +360 000 с даты перехода права →
переделение → закрытый месяц статистики **помечается** (`ИС-50`), и видно почему.

Сторно здесь не подходит: оно сделало бы пени за три недели спорными и вынесло вопрос на
Комиссию — механизм для отмены принятия, а не для опечатки.

## 9. Мониторинг и поводы (`ИМ-15`)

**Модуль публикует поводы, Задания поручают.** Модуль ведёт журнал осмотров и объявляет
критерии; модуль Задания забирает их **опросом** (`ADR-0229`, ключ «вид + объект + период») и
адресует ответственному по кураторству (`ИМ-16`).

| вид повода | объект | условие | порог по умолчанию |
|---|---|---|---|
| `pk-im-offer-overdue` | предложение | срок ответа истёк, ответа нет | срок предложения |
| `pk-im-no-inspection` | объект (класс «вещь») | с последнего осмотра прошло больше порога | 6 мес. |
| `pk-im-not-listed` | объект | на учёте больше порога без единой попытки | 6 мес. |
| `pk-im-unsold` | объект | число несостоявшихся попыток ≥ порога | 3 |
| `pk-im-instalment-overdue` | договор КП | есть просроченный платёж по графику | 1 день |
| `pk-im-topup-pending` | объект | ⚑ «принятие не завершено» дольше порога | 30 к.д. |
| `pk-im-registration-pending` | объект | «ждёт регистрации» дольше порога | 60 к.д. |
| `pk-im-encumbrance-ending` | объект | обременение кончается в пределах порога | 30 к.д. |
| `pk-im-act-pending` | предложение (позиция в ключе) | итог «принята», акта приёма-передачи нет дольше порога, считая от даты решения органа | 30 к.д. |

- Пороги — **настройки с источником** значения: норма · Инструкция · внутренний акт. Норма их не
  задаёт; до ответа заказчика (`ИМ-ВЗ-8`) стоят умолчания с источником «внутренний акт».
- Ключ повода устойчив: вид + id объекта + период (месяц для «давно не осматривали», номер
  платежа для просрочки; для `pk-im-act-pending` — id предложения + номер позиции + месяц; адресат — куратор
  предложения).
- **Журнал осмотров**: дата, участники, состояние, фото и видео, документ. Без него повод «давно
  не осматривали» нечем измерить, а решения о снижении цены и о выбытии опираются на акт осмотра.
- Реестр объектов дополнительно даёт **фильтры** поверх поводов — удобство, а не контроль.
- Мониторинг **не видит** просрочку арендатора (`ИМ-30`) — осознанная граница.

## 10. Кураторство, роли и второй ключ

### 10.1. Кто ведёт (`ИМ-16`, `ADR-0259`)

Кураторство расширяется: в закрытые списки добавлены **два объекта закрепления** — предложение
имущества и объект имущества — и **одна роль** — куратор имущества.

- Правило холдинга называет подразделение — по умолчанию Управление по работе с активами.
- Правило подразделения называет работника по признакам: **область и район местоположения**,
  вид имущества (для права — место регистрации или эмитента).
- Ответ «кто ведёт» — только закреплением на дату (`ИИ-16`); поля «ответственный» у объекта нет.
- Куратор кредита объект **не ведёт**: другая работа, другое подразделение, а долг после
  принятия может быть закрыт, тогда как склад остаётся.
- Задания берут адресата поводов отсюда; без этого — хардкод адресата, как `E4` в волне 4 заданий.

### 10.2. Роли доступа и второй ключ (`ИМ-26`)

Роли доступа — не роли кураторства (глоссарий). **Специалист по имуществу** — право вводить
факты модуля; куратором конкретного объекта он становится закреплением.

| действие | готовит | публикует вторым ключом |
|---|---|---|
| предложение, позиции, заключения, осмотры, оценки, расходы, обременения | специалист по имуществу | — (черновик / денег не движет) |
| решение органа по позициям | секретарь органа | — (документ органа сам контроль) |
| акт приёма-передачи, переход права, отказ регистратора, решение о прекращении принятия | специалист | **начальник Управления по работе с активами** |
| исполнение доплаты | бухгалтер (в Платежах) | — (контур Платежей) |
| попытка продажи и итог | специалист | — (итог из протокола площадки) |
| договор КП, условия рассрочки, расторжение | юрист | начальник Управления |
| разделение | специалист | начальник Управления |
| безвозмездная передача | специалист | начальник Управления + решение органа |
| выбытие | специалист | начальник Управления |
| исправление опубликованного | любая роль модуля | начальник Управления |

Второй ключ — **только на факты, двигающие деньги или стоимость** (`ИИ-15`): ключ на всё
превратил бы начальника в штамп, и контроль пропал бы именно там, где нужен. Состав ролей в
модуле пользователей — `ИМ-ДС-10`.

### 10.3. Журнал

Каждый факт несёт: кто ввёл, кто опубликовал, когда, документ. Исправления и замещённые факты
видны. Аудит пользовательских действий — общий модуль аудита, не этот.

### 11.1. Взыскание видит, но не владеет (`ИМ-18`)

```
 Взыскание · дело Х · журнал мер
 ├─ 2026-11  иск подан ................................ (мера взыскания)
 ├─ 2027-01  торги 1, 2 не состоялись ................. (мера взыскания, по залогу)
 ├─ 2027-01  ⟶ предложение имущества П-1 зарегистрировано   ┐ проекции из модуля
 ├─ 2027-02  ⟶ решение: принять ИО-1                         │ по имуществам —
 ├─ 2027-04  ⟶ переход права ИО-1, 2 400 000                 ┘ только чтение
 └─ 2027-04  погашение (Платежи) → требование закрывается обычным правилом §9
     «реализация принятого имущества» (продажа ИО-1 в 2027–2028) — в журнале дела НЕТ
```

- Меры-проекции не правятся и не заводятся руками во взыскании: один факт в двух местах — копия,
  запрещённая `ADR-0004` и `ADR-0026`.
- **Продажа объекта Фондом в дело должника не попадает**: долг уже закрыт стоимостью принятия, и
  показывать продажу в деле — намекать, что она что-то меняет в его долге. Вторую меру ТЗ
  («реализация принятого имущества») закрывает сам модуль: попытки и договор КП и есть она.
- Как машина фаз реагирует на проекции — решает канон взыскания (`ИМ-ДС-7`); предложение
  модуля — проекции фазу **не двигают**, фазу закрывает погашение по обычным правилам.

### 11.2. Статистика и отчётность (`ИМ-22`)

Модуль — производитель строк на дату; число на дату берётся только у статистики (`ADR-0222`).

| объект статистики | показатели | разрезы |
|---|---|---|

## 12. Виды модуля (`ИМ-25`)

```
 Имущество (группа меню)
 ├─ Предложения (реестр) ─────► Карточка предложения
 │     фильтры: источник, обязанное лицо,   шапка: источник · обязанное лицо · отчуждатель ·
 │     состояние, срок ответа, орган        документ · срок ответа · ответ (дата, вид)
 │                                          позиции: вещь · заключения · стоимость · ожидаемая
 │                                          доплата · итог · → объект
 │                                          решение органа · журнал фактов
 ├─ Объекты имущества (реестр) ─► Карточка объекта
 │     фильтры: состояние НА ДАТУ, вид,     вкладки: Характеристики (снимок) · Переход права ·
 │     класс, область, дней на учёте,       Осмотры · Оценки · Расходы · Обременения ·
 │     источник, ⚑ не завершено,            Попытки продажи · Договор КП и оплаты ·
 │     ⚑ обременён, куратор на дату         Выбытие · Журнал фактов
 ├─ Договоры купли-продажи (реестр) — вид, покупатель, остаток, просрочка, претензии
 └─ Настройки — пороги поводов, сроки ответа по источнику; у каждого значения — источник
```

- Три реестра отвечают на три разных вопроса разных людей: «что предлагают и где ответ
  просрочен» (куратор), «что у нас лежит» (руководство, куратор), «кто нам должен за проданное»
  (юрист, бухгалтерия).
- Фильтр «состояние на дату» — прямое следствие `ИМ-13`: не текущий статус, а вычисление.
- Вкладка «Обременения» добавлена к составу `ИМ-25` решением `ИМ-31`.
- Кнопок «сменить статус» нет — только «ввести факт» (§5.1).
- Во взыскании предложение видно проекцией (`ИМ-18`), отдельного входа там не нужно.

## 13. Вводный остаток и миграция (`ИМ-29`)

На дату запуска у Фонда уже есть объекты, принятые в прошлые годы. Старая система экранов
имущества не имеет (`requirements/legacy/`), погашения по ним прошли видом «принятие имущества
в счёт погашения».

- Объект возникает **вводом остатка**: основание — документ бухгалтерии (выписка, ведомость);
  стоимость принятия, дата перехода права, обязанное лицо, источник — из документов, если есть.
- Ссылки на предложение и решения органа нет; фиктивные предложения не заводятся — это были бы
  ложные документы в системе с аудитом.
- **Вводный остаток погашения не порождает** (`ИИ-3`): оно уже прошло и переносится вместе с
  платежами. Иначе долг уменьшится второй раз.
- **Контроль миграции:** сумма мигрированных погашений вида «имущество в счёт погашения» по
  каждому обязанному лицу сходится с суммой стоимостей его вводных объектов; расхождение —
  блокирующий отчёт миграции.
- Дальше вводный объект живёт как любой другой: осмотры, попытки, выбытие.
- Где сейчас учитывается имущество и в каком виде его отдадут — `ИМ-ВЗ-11`.
