## 0. Краткая суть

Главное отличие от плоского справочника сотрудников — **статус нигде не хранится полем, а
вычисляется на дату**. Сотрудника принимают, переводят, отправляют в отпуск, блокируют его
учётную запись, увольняют — и каждое событие меняет своё измерение независимо. Модуль
показывает состояние **на любую выбранную дату**: не только «как сейчас», но и «кем он был на
день подписания кредитного договора».

Восемь решений, определяющих логику:

1. **В данных — только факты.** Поля «статус» нет ни у одной сущности.
2. **Три независимые оси статуса** с разными владельцами: кадровый статус (кадры) ·
   доступность (из отсутствий) · учётная запись (администратор). Сливать их нельзя.
3. **Три вида в одном модуле:** Обзор (только кадры) · Список · Карточка.
4. **Доступ прячет классы данных (A/B/C), а не экраны.**
5. **Физлицо ≠ сотрудник:** человек живёт в общем справочнике, сотрудник на него ссылается.
6. **Перевод — одна транзакция** (закрыть старый период, открыть новый).
7. **Сотрудника нельзя удалять** — на него ссылаются кредитные документы; увольнение
   блокирует, а не удаляет.
8. **Стаж — единый источник**, не считается двумя способами; паспорт приходит из госреестра и
   версионируется.

Наружу модуль отдаёт один главный контракт — **маршрутизацию задания на дату** («кому
фактически уйдёт задание»).

## 1. Назначение и границы

### 1.1. Кто пользуется

| Роль | Что делает | Видит классы |
|---|---|---|
| **Кадры** | основной пользователь: заводит и увольняет, ведёт личное дело, оформляет назначения, переводы, отсутствия | A/B/C + вид «Обзор» |
| **Администратор** | ведёт учётные записи и роли (отдельная ось) | A |
| **Руководство** | смотрит подчинённых, награды и взыскания | A/C |
| **Кредитный специалист** | смотрит, кто курирует заёмщика и кому уйдёт задание | A |
| **Сам сотрудник** | видит свою карточку целиком | всё |

### 1.2. Что НЕ входит

- **Оргструктура** — подразделения и должности ведёт отдельный модуль; здесь они справочник
  для назначений.
- **Справочник физлиц** — общий с заёмщиками, поручителями, залогодателями; сотрудник только
  ссылается.
- **Учётные записи и роли** — ведёт администратор; кадры их только читают.
- **Кредитные документы** — сотрудник фигурирует в них как исполнитель или куратор, сам
  документ ведут кредитные модули.
- **Кураторство** как распределение заёмщиков — отдельный модуль-потребитель.

## 2. Модель данных: только факты

В данных лежат: сотрудники · назначения · отсутствия · учётные записи · роли · кураторство ·
задания · документы · аудит · справочники. **Ни у одной сущности нет поля «статус».** Всё, что
выглядит как статус, вычисляется функцией на дату среза.

**Зачем.** Сотрудника приняли, перевели, отправили в отпуск, заблокировали запись, уволили —
пять событий на разных осях в разное время. Хранимый «статус» пришлось бы пересчитывать при
каждом событии, и рано или поздно он разойдётся с фактами. Расчёт на дату не расходится
никогда.

### 2.1. Основные сущности

| Сущность | Состав |
|---|---|
| **Сотрудник** | ссылка на физлицо + табельный номер (4 цифры, уникален) + категория + контакты (телефон, кабинет) + фото |
| **Назначение** | период (с / по; открытый = без «по») + подразделение + должность + вид + ставка + приказ-основание со сканом |
| **Отсутствие** | вид + период (с / план по / факт по) + основание + замещающий + признак «отменено» |
| **Учётная запись** | логин + состояние (активна/заблокирована) + кем и когда создана + последний вход + признак «роли не пересмотрены» |
| **Физлицо** (внешний справочник) | ПИН, ФИО, дата рождения, пол, адрес, код территории |

Виды назначения: **основное** · **совмещение** · **исполнение обязанностей**.

## 3. Три оси статуса

«Статус сотрудника» — это три разных ответа, у каждого свой владелец. **Их нельзя объединять:**
заблокированная учётная запись не делает сотрудника уволенным, а отпуск не отменяет того, что он
«Работает».

### 3.1. Ось 1 — кадровый статус (владелец: кадры)

Назначения — это **периоды**, а не события. Правило вычисления на дату:

1. есть дата увольнения → **«Уволен»**;
2. есть открытое основное назначение → **«Работает»**;
3. иначе → **«Оформляется»** (черновик; в рабочих списках не виден).

Подразделение, должность и непосредственный руководитель тоже **вычисляются на дату** из
основного назначения.

### 3.2. Ось 2 — доступность (вычисляется из отсутствий)

Состояние записи об отсутствии (Запланировано / Идёт / Завершено) **вычисляется**; «Отменено» —
единственный хранимый флаг.

Доступность на дату: «В отпуске / на больничном / в командировке до … · замещает X» либо
«**замещения нет**» (красным); обратная сторона — «На месте · замещает Y». **Досрочный выход
снимает замещение**, и это отражается в подписи.

### 3.3. Ось 3 — учётная запись (владелец: администратор)

Состояние на дату: активна / заблокирована / **не заведена**.

- **Заблокированная запись ≠ удалённая.**
- Работающий сотрудник может вообще не иметь записи — это **краевой случай для «Обзора»**, а не
  молчаливая норма.

> **Ключевое для маршрутизации:** кураторство висит на **учётной записи**, а не на сотруднике.
> Поэтому блокировка записи и увольнение по-разному влияют на маршрутизацию заданий.

## 4. Дата среза

В верхней панели всегда стоит дата среза (по умолчанию сегодня, быстрые кнопки «до перевода» /
«сегодня» / «в отпуске»). Любой экран — список, карточка, счётчики, выгрузка — считается на эту
дату.

**Краевые случаи:**

- карточка, заведённая будущей датой, на более ранней дате **невидима**;
- перевод будущей датой не показывает новое подразделение на текущей дате — модуль **предлагает
  сдвинуть дату среза**, а не молча «теряет» перевод.

Состояние экрана (вид, карточка, вкладка, дата, роль) сохраняется и переживает перезагрузку.

## 5. Три вида модуля

### 5.1. Обзор — сводка, только для кадров

Шесть счётчиков на дату: **Работает · Отсутствует · Без замещения · Без учётной записи ·
Оформляется · Уволен**.

**Список «Требует внимания»**, ранжированный по тяжести; каждая строка кликабельна и ведёт прямо
в нужную карточку, вкладку или форму:

- отсутствие без замещения;
- работа без учётной записи либо с заблокированной;
- истекающий паспорт;
- заканчивающееся исполнение обязанностей;
- роли не пересмотрены после перевода.

**Паспортные проблемы показываются только тем, кому открыт класс B** — список подчиняется тем же
правилам доступа, что вкладки.

**«Ближайшие дни»** (14 дней): кто уходит, кто выходит, у кого заканчивается исполнение
обязанностей.

Пустой список показывается как «На выбранную дату проблем нет», а не прячется — иначе пустота
читается как «не проверяли».

### 5.2. Список

Фильтры: кадровый статус · подразделение · доступность · поиск по ФИО или табельному номеру,
со сбросом. Грид, где **все колонки — на дату среза**: ФИО · подразделение · должность ·
доступность · телефон · кабинет.

**Уволенные — приглушённой строкой, не спрятаны.** Счётчик «N из M на ‹дату›». Пустой результат
— «Под фильтр на ‹дату› никто не подходит».

### 5.3. Карточка

| Элемент | Содержание |
|---|---|
| Шапка | фото, ФИО, табельный номер, подразделение и должность **на дату**, **три бейджа осей** |
| Панель действий | по статусу: «Оформляется» → «Провести приказ о приёме»; «Работает» → меню «Оформить» (Перевод / Отсутствие / Увольнение); уволенный или нет прав → только чтение **с пояснением причины** |
| Лента вкладок | только доступные по уровню, со счётчиком записей; навигация ←→ по текущему списку; печать карточки |

Вкладки: Общая · Назначения · Учётная запись и заёмщики · Отсутствия · вкладки личного дела ·
Паспорт · История.

## 6. Уровни доступа A/B/C

Доступ прячет **классы данных**, а не экраны — иначе видимость по ролям пришлось бы прописывать
в каждом месте и где-то забыть. Класс — свойство **вкладки**:

| Класс | Вкладки |
|---|---|
| **A** | Общее · Назначения · Учётная запись · Документы |
| **B** | Паспорт · Образование · Семья · Стаж · Языки · Воинский учёт |
| **C** | Награды · Взыскания |

Видимость по ролям: кадры — A/B/C · администратор — A · руководство — A/C · кредитный
специалист — A · сам сотрудник — всё.

**Документ наследует класс своей вкладки** и своего класса не имеет. Скрытые строки и документы
показываются плашкой **«Скрыто по уровню доступа»**, а не молча пропадают — иначе пользователь
считает, что данных нет.

## 7. Назначения и перевод

На вкладке «Назначения» — историчная таблица периодов (с / по / подразделение / должность / вид /
ставка / основание со сканом); действующий период отмечен бейджем. Показывается **сумма
действующих ставок на дату** с лимитом; при превышении 1.5 — сообщение.

**Перевод — одна транзакция:** закрыть действующее основное назначение (по = дата − 1) и открыть
новое (с = дата) **одной операцией**. Половинчатое выполнение рвёт историю — получаются либо два
открытых основных назначения, либо дыра в стаже.

Перевод **поднимает на учётной записи признак «роли не пересмотрены»**: он не блокирует работу, а
уходит в «Требует внимания» и в уведомление администратору. Сотрудник, переведённый из
кредитного отдела в юридический, сохраняет прежние права до пересмотра — это факт, который
должен быть виден, а не скрытая проблема.

Перевод будущей датой на текущей дате нового подразделения не показывает — предлагается сдвинуть
дату среза. Каждый перевод пишется в аудит.

---

## 8. Физлицо ≠ сотрудник

Человек живёт отдельно от сотрудника: он может быть заёмщиком, поручителем, залогодателем.
Поэтому справочник физлиц **общий**, а сотрудник лишь **ссылается** на физлицо, не дублируя ФИО,
ПИН и адрес.

Диалог выбора физлица: поиск по ФИО и ПИН; физлицо, на которое **уже заведена карточка
сотрудника**, помечается «уже сотрудник» и не выбирается — второй кадровой карточки на того же
человека быть не должно.

Новое физлицо можно создать прямо из диалога: ФИО от двух слов, ПИН ровно 14 цифр, запрет дубля
ПИН — с подстановкой в карточку.

## 9. Приём и увольнение

### 9.1. Приём — двухшаговый

Статус получается **сам**, его не выставляют руками:

1. **Создание карточки:** ссылка на физлицо + табельный номер + категория + контакты. Назначения
   ещё нет → статус «Оформляется», в рабочих списках не виден.
2. **Приказ о приёме:** открывает первое основное назначение (подразделение / должность / дата /
   ставка / основание) → статус «Работает».

Учётную запись заводит администратор — до этого сотрудник попадает в «Требует внимания» как
работающий без записи. Приём будущей датой оставляет «Оформляется» на текущей дате.

### 9.2. Увольнение — блокируется, не удаляет

**Удалять сотрудника нельзя** — на него ссылаются кредитные документы.

**Блокеры увольнения** читают кураторство, задания и отсутствия; пока их не ноль — кнопка
«Уволить» неактивна, а сработавшие блокеры перечислены. Смысл: уволить можно только тогда, когда
**передавать нечего**.

**Увольнение** одной операцией: закрыть открытые назначения · отменить будущие отсутствия ·
**заблокировать (не удалить)** учётную запись · снять закреплённых заёмщиков · перевести карточку
в режим чтения. Пишется в аудит; карточка сохраняется и открывается только на чтение.

## 10. Отсутствия и замещение

На вкладке — таблица (вид / с / план по / факт / основание / замещающий / состояние) и блок
«Замещает других».

**Проверка замещающего** — ключевое правило модуля. Замещающий обязан:

- работать на дату начала;
- не быть в отсутствии в пересечении периодов;
- иметь действующую учётную запись;
- не быть тем, кого самого в этот период замещают;
- не быть самим замещаемым.

**Без замещающего оформление разрешено**, но с предупреждением «задания будут копиться» — и это
же попадает в рабочий список «Обзора». Запретить отсутствие без замещения нельзя: отпуск и
больничный случаются независимо от наличия сменщика.

---

## 11. Учётная запись и маршрутизация заданий

Вкладка «Учётная запись и заёмщики» — стык модуля с кредитным контуром. Карточки только для
чтения (ведёт администратор): учётная запись · роли по подразделениям · что курирует (отрасль,
регион, вид заёмщика, число заёмщиков).

**Маршрутизация задания на дату** — главный контракт модуля наружу. Отвечает на вопрос «кому
фактически уйдёт задание»:

| Ситуация | Результат |
|---|---|
| обычная | на учётную запись куратора |
| активное замещение | уходит **замещающему**, но **ответственность остаётся на кураторе** |
| отсутствие **без** замещения | задания **копятся** (подсвечивается в «Обзоре») |
| записи нет или заблокирована | назначать не на кого — баннер краевого случая |

Разделение «исполнитель ≠ ответственный» принципиально: замещающий выполняет, но отчитывается
куратор.

**Встречный контракт** (для гейтов перевода и увольнения): «сколько закреплённых заёмщиков и
открытых заданий у сотрудника» — пока не ноль, увольнение не проходит. Это данные **чужих**
модулей (кураторство, задания), а не собственная модель сотрудников.

## 12. Личное дело и паспорт

### 12.1. Единая форма-строка

Шесть табличных вкладок (образование, семья, стаж, языки, воинский учёт, награды/взыскания) —
**один паттерн строки**, а не шесть отдельных форм. Единая модалка описывается набором полей:
вид и уровень с зависимым списком, проверка обязательных полей и порядка дат.

Справочники — единым источником: уровни образования зависят от вида документа; органы поощрения
и взыскания (**взыскание налагает только работодатель**); языки и уровни владения; категории
годности.

Вычисляемое на дату: истёкший сертификат, действующее взыскание (снято / не снято), возраст члена
семьи, стаж по месту работы.

Правка, удаление строки и добавление — только у кого есть право.

### 12.2. Паспорт — из госреестра, версией

Вкладка помечена источником **«Тундук · ГРС»** (государственная система межведомственного
взаимодействия / Государственная регистрационная служба), **ручной правки нет**; кнопка
«Обновить из Тундук» с отметкой времени.

**Замена паспорта — новой версией:** прежний уходит в историю и **не затирается**, потому что
старые кредитные документы ссылаются на прежний номер.

### 12.3. Стаж — единый источник

Смежные (зазор ≤ 1 дня) и перекрывающиеся периоды **сливаются**, месяцы считаются один раз на
слитый интервал. **Одно и то же число стажа нельзя считать двумя способами** — иначе «стаж в
организации» на карточке и в отчёте расходятся.

## 13. Проверки данных

| Проверка | Правило |
|---|---|
| Пересечение основных периодов | двух перекрывающихся основных назначений быть не может |
| Сумма ставок | сумма действующих ставок на дату не больше 1.5 |
| Одно открытое основное | более одного открытого основного назначения запрещено |
| Открытый период у уволенного | красный баннер — увольнение должно было закрыть назначения |
| Замещающий | пять условий из §10 |
| Табельный номер | 4 цифры, уникален |
| ПИН физлица | ровно 14 цифр, дубль запрещён |
| Дубль сотрудника | на физлицо с существующей кадровой карточкой вторую не завести |

Без проверок в кадровые данные молча проходят абсурды, которые всплывают потом — в расчёте
стажа, в маршрутизации или в зарплате.

---

## 14. Выгрузка, история, печать

- **Аудит:** каждое действие — создание, приём, перевод, отсутствие, увольнение, правки строк
  личного дела, замена паспорта — пишет запись; вкладка «История» показывает таймлайн.
- **Выгрузка списка** на дату среза с учётом фильтров: Excel (.xls) / CSV (разделитель `;`,
  UTF-8 с BOM под русский Excel) / Word (.doc).
- **Печать карточки** сотрудника.
- После увольнения или удаления открытой карточки экран корректно уводит в список.

## 15. Швы с соседними модулями

| Сосед | Связь |
|---|---|
| **Оргструктура** | подразделения и должности — справочник для назначений; при переименовании или перемещении подразделения карточка показывает актуальное **на дату** |
| **Справочник физлиц** | общий с заёмщиками, поручителями, залогодателями; сотрудник ссылается |
| **Задания** | получают исполнителя через маршрутизацию на дату: куратор → замещающий при отсутствии → «копятся» без замещения |
| **Кураторство** | кто какого заёмщика курирует; висит **на учётной записи**, снимается при увольнении; спрашивает у сотрудников, активна ли учётная запись куратора |
| **Кредитные документы** | сотрудник фигурирует исполнителем и куратором — поэтому его нельзя удалять |
| **Тундук · ГРС** | паспортные данные, только чтение, версиями |

Три модуля образуют связку, решённую 15.07.2026: **Сотрудники** владеют фактами и производят
маршрутизацию; **Задания** вызывают маршрутизацию; **Кураторство** спрашивает о доступности
куратора и не даёт оставить заёмщиков на неработающем.

## 16. Ключевые решения и их причины

| Решение | Причина |
|---|---|
| Только факты, никаких хранимых статусов | пять событий на разных осях; хранимый статус расходится с фактами |
| Три оси, а не один статус | блокировка записи ≠ увольнение, отпуск ≠ «не работает»; у осей разные владельцы |
| Всё считается на дату среза | «кем он был на день подписания договора» — обязательный вопрос кредитного контура |
| Доступ прячет классы данных, а не экраны | ролевые условия по месту показа пришлось бы писать десятки раз и где-то забыть |
| Скрытое показывается плашкой | молчаливое исчезновение читается как «данных нет» |
| Документ наследует класс вкладки | свой класс у документа означал бы вторую матрицу доступа |
| Физлицо отдельно от сотрудника | один человек бывает и сотрудником, и заёмщиком; дубль ФИО/ПИН разойдётся |
| Физлицо с карточкой не выбирается повторно | две кадровые карточки на человека ломают стаж и маршрутизацию |
| Приём двухшаговый | статус должен получаться из факта назначения, а не выставляться руками |
| Перевод — одна транзакция | половина операции даёт два открытых основных или дыру в стаже |
| Признак «роли не пересмотрены» не блокирует работу | иначе перевод парализует сотрудника; но факт обязан быть виден |
| Сотрудника нельзя удалить | на него ссылаются кредитные документы |
| Увольнение блокируется, пока есть что передавать | иначе заёмщики остаются на неработающем сотруднике |
| При увольнении запись блокируется, а не удаляется | удаление рвёт аудит и историю входов |
| Отсутствие без замещения разрешено с предупреждением | отпуск не отменяется отсутствием сменщика; но задания начнут копиться |
| Замещающий проверяется пятью условиями | замещение в отпуск, на себя или на заблокированную запись бессмысленно |
| Кураторство висит на учётной записи | маршрутизация идёт по учётной записи; блокировка и увольнение дают разные последствия |
| Ответственность при замещении остаётся на кураторе | иначе передача обязанностей размывает ответственность |
| Паспорт только из госреестра, новой версией | ручная правка паспорта — подделка реквизита; старые документы ссылаются на прежний номер |
| Стаж — один источник со слиянием интервалов | два способа подсчёта дают два разных стажа |
| Шесть вкладок личного дела — один паттерн строки | шесть форм = шесть наборов правил и шесть мест для ошибки |
| Уволенные видны приглушённо, а не скрыты | их упоминают договоры и задания прошлых лет |
| Пустой рабочий список показывается явно | иначе читается как «не проверяли» |
| Обзор виден только кадрам | это кадровый рабочий экран, а не витрина |

## 17. Открытые вопросы

| # | Вопрос | Почему важно |
|---|---|---|
| 1 | Лимит суммы ставок 1.5 — правило Фонда или настраиваемый параметр? | от этого зависит, класть его в справочник или в код |
| 2 | Признак «роли не пересмотрены» — просто пометка или с дедлайном и эскалацией администратору? | сейчас только строка в «Требует внимания»; нужен ли SLA |

| 5 | Что происходит с личным делом при повторном приёме уволенного | в модели не описано |

## 18. Словарь терминов

| Термин | Значение |
|---|---|
| **Дата среза** | дата, на которую считается весь экран |
| **Ось статуса** | независимое измерение состояния сотрудника со своим владельцем |
| **Кадровый статус** | Работает / Оформляется / Уволен — вычисляется из назначений |
| **Доступность** | на месте / в отпуске / замещает — вычисляется из отсутствий |
| **Назначение** | период работы на должности в подразделении с видом и ставкой |
| **Основное / совмещение / и.о.** | виды назначения; основное — ровно одно открытое |
| **Ставка** | доля рабочего времени; сумма действующих ≤ 1.5 |
| **Замещение** | передача исполнения обязанностей на период отсутствия |
| **Маршрутизация задания** | расчёт «кому фактически уйдёт задание» на дату |
| **Классы данных A/B/C** | группы вкладок с разной чувствительностью |
| **Табельный номер** | внутренний кадровый номер сотрудника (4 цифры) |
| **ПИН** | персональный идентификационный номер физлица (14 цифр) |
| **Тундук · ГРС** | система межведомственного взаимодействия и Государственная регистрационная служба КР |
