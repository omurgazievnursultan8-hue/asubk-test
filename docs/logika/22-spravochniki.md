## 0. Краткая суть

**Справочник** — нормативный перечень значений (валюты, виды кредита, отрасли, статусы), на
который ссылаются lookup-поля и select-поля форм. Из формы открывается **picker-диалогом**, из
левого меню — самостоятельным экраном-списком с CRUD.

Шесть решений, определяющих логику слоя:

1. **Не всякий перечень — справочник.** Признак разграничения: **есть ли у записи собственная
   работа, которую можно закрыть**. Есть — рабочий список; нет — справочник.
2. **Набор значений классификатора справочником быть перестаёт:** он принадлежит **версии
   классификатора** и подписывается вместе с ней. Экран остаётся только на чтение.
3. **Значение нормы несёт редакцию и дату начала действия.** Гейт, сработавший в 2026 году,
   объясняется редакцией, действовавшей тогда, а не сегодняшней.
4. **Курс — производная от справочника и даты, а не поле операции.** Отсутствующая дата —
   действует последний установленный курс.
5. **Календарей три, и они не сливаются.** Производственный отвечает «рабочий ли день»,
   календарь сдачи — «чем мы обязаны наружу», учётный — «что уже нельзя менять».
6. **Picker — режим выбора, а не CRUD.** Сегодня это нарушено: picker открывает полный CRUD
   вместе с «Одобрить/Отклонить».

## 1. Что справочник есть и чем он не является

### 1.1. Определение

Экран управления **нормативным перечнем значений**. Две поверхности входа:

| Вход | Что открывается |
|---|---|
| левое меню «Справочники» | самостоятельный экран-список с CRUD и фильтром |
| поле формы (кнопка «···») | **полноэкранный picker-диалог** со списком значений |

### 1.2. Справочник против рабочего списка

Разграничение принципиальное и **решается по одному признаку: есть ли у записи собственная
работа, которую можно закрыть.**

- **Есть** ⇒ рабочий список. Пример: реестр заёмщиков — досье собирается, документы истекают,
  категория пересматривается, и это делает конкретный человек по конкретной записи.
- **Нет** ⇒ справочник. Пример: реестр залоговых договоров — договор либо оформляется (и вся
  работа идёт на его карточке), либо зарегистрирован, и дальше работа привязана к **предмету**
  (обследование, переоценка, запрет) или к **кредиту** (падение обеспеченности), но не к
  договору.

Что из этого следует для справочника:

- **порядок по умолчанию хронологический**, а не «сначала проблемные»: справочник упорядочен
  по тому, чем запись опознаётся;
- **провал гейта показывается как свойство записи, а не как задача** — красит пилюлю и
  отбирается фильтром, но не даёт ни «взять в работу», ни «отложить»;
- **отметки — признаки, а не сигналы:** они рассказывают о записи, а не требуют реакции;
- **дублировать очередь колонкой нельзя** — две очереди на один факт неизбежно расходятся:
  закрытая в одном месте остаётся открытой в другом.

Отвергнут промежуточный вариант «справочник и очередь одновременно, только показать, без
действий»: сигнал, с которым нельзя работать, остаётся таким и в сорока пикселях.

### 1.3. Что справочником быть перестаёт

**Набор значений классификатора.** Состав значений, их порядок и правила принадлежат **версии
классификатора** и подписываются вместе с ней. Правка строки в справочнике молча ломала бы
правило версии и подпись зафиксированных записей прошлых периодов.

На стенде это два обычных словаря с CRUD — «Группа заёмщика» и «Группа платежеспособности». В
целевой модели их экраны **остаются только на чтение**, со ссылкой «правится в конструкторе
классификации»: **у классификации одна дверь**.

## 2. As-is: инвентарь и архетипы

### 2.1. Объём

**47 справочников**, на которые ссылаются сущности кредитного конвейера (госрешение → …→
обслуживание). За границей обследования — справочники внешних модулей (субсидии, корпоративное
управление, поручительства, взыскание, кураторство, гео-справочники, безопасность).

### 2.2. Два архетипа экрана

| | `S` — простой словарь | `R` — расширенный классификатор |
|---|---|---|
| **сколько** | 40 из 47 | 7 из 47 |
| **колонки** | одна-две: «Наименование», иногда доменная («Процент», «Период (кол-во мес.)», «Код» + «Наименование») | «Наименование» · **«Код»** · **«Статус»** · **«Дата создания»**; у реестров субъектов — доменные (ИНН/ФИО/паспорт, ИНН/ОКПО/адрес) |
| **тулбар** | «+ Добавить условие поиска» · Создать · Изменить · Удалить. **Без «Просмотр»** | то же **плюс «Просмотр»** (read-only страница) |
| **редактор** | модальное окно с минимальным набором полей | то же |

Архетип `R` — более новый стандартизованный шаблон сущности (код + статус + аудит-дата). Он
применён к семи экранам: отрасли и направления, виды обеспечения, комиссии, сроки кредита,
расчётные коэффициенты, физические лица, организации.

**Вывод обследования:** платформа уже содержит «правильный» шаблон, но он применён лишь к
семи экранам из сорока семи. **Разнобой архетипов — основной структурный дефект слоя.**

### 2.3. Группировка по потребителю

Витрина справочников разложена не тематически, а **по странице или вкладке, где справочник
потребляется** — одиннадцать корзин в порядке жизненного цикла:

| Корзина | Что в ней |
|---|---|
| 01 · Госрешение | статус решения, вид решения (на форме решения реально только эти два поля-справочника) |
| Классификаторы вне формы | документы, пакеты документации, списки получателей — backing-енумы сущностей, на формах не потребляются |
| 02 · Программа · вкл. 1 | источник финансирования, валюта, кредитная линия, назначение кредита (плюс общие: вид кредита, отрасль, счёт погашения, физ/юр лица, сотрудники) |
| 02 · Программа · вкл. 3 | ставки: фиксированные, процентные, виды плавающих |
| 02 · Программа · вкл. 6 | платежи и расчёты: цикл и период начисления, метод счёта дней, вид начисления, очерёдность погашения, льготные периоды, типы расчёта процентов |
| 02 · Программа · вкл. 7 | шаблоны договоров, коды шаблонов, уровни проверки документов |
| 02 · Программа · вкл. 8 | виды залога |
| 02–03 · Субъекты | сотрудники, комиссии, физические лица, организации |
| 04 · Заёмщик и отрасли | группа заёмщика, вид заёмщика, организационные формы, виды отраслей, группа платежеспособности, отрасли и направления |
| 05 · Кредит | виды кредита, кредитные условия, сроки, расчётные коэффициенты, статус кредита, счета погашения |
| 06–07 · График и погашения | статус графика, вид погашений, виды товаров, счета назначения, счета для оплаты |

**Один справочник — одна основная корзина**, но общий справочник, служащий полем нескольких
страниц, показывается в обеих (шесть таких: вид кредита, отрасль, счёт погашения, физлица,
организации, сотрудники).

### 2.4. Три справочника без пункта меню (picker-only)

**«Цели кредита»** (поле «Назначение кредита»), **«Уровни проверки документов»**, **«Типы
расчёта процентов»** — открываются только picker-ом изнутри формы. Управляющего экрана в меню
«Справочники» нет ⇒ непоследовательная поверхность администрирования.

## 3. Как справочник работает (as-is)

1. **Из левого меню** — экран-список своего архетипа.
2. **CRUD** через тулбар, редактор — модальное окно. На `S`-экранах открыть запись «только
   посмотреть» **нельзя** — лишь «Изменить», то есть аудит значения вынуждает входить в
   редактирование (риск случайной правки).
3. **Фильтр** — конструктор «Добавить условие поиска» присутствует на всех экранах; пагинация
   снизу. Для словаря из трёх строк конструктор фильтра практически не нужен.
4. **Из формы (picker-режим)** — поле открывает полноэкранный справочник-диалог.

**Дефект picker-режима (проверено 19.06.2026).** Picker «Решение правительства» открывает
экран с действиями **Создать / Изменить / Удалить / Одобрить / Отклонить** — недопустимо
широкий доступ из формы программы; фильтр статуса при этом — съёмный интерфейсный чип,
**серверной проверки нет**. Должно быть: **режим только выбора** плюс жёсткий фильтр
загрузчика.

## 4. To-be: как ведётся нормативное значение

Отдельного «модуля справочников» в целевой модели нет. Вместо него — пять решённых случаев,
каждый про свой род нормативных данных.

### 4.1. Норма (регуляторный предел)

**Величина, пункт, редакция и дата начала действия — запись справочника, а не число в коде.**

Причина: гейт, сработавший в 2026 году, обязан объясняться **той редакцией, которая
действовала тогда**, а не сегодняшней. Иначе перечитывание старого решения даёт другой ответ,
чем дало в своё время.

Пример устройства (пределы реструктуризации): наибольший срок продления и наименьшая ставка
стоят на пунктах Положения о работе с бюджетными кредитами. Полов ставки два, применяется
больший: 50 % от первоначальной ставки транша **и** минимум по виду проекта (1 % социально
значимые и инфраструктурные, 4 % инфраструктура госпредприятий и АО с госдолей ≥ 50 %, 6 %
коммерческие). Для проектов за счёт средств иностранных кредиторов ставка **внешняя** и
машинно не вычисляется — гейт работает по первому полу и показывает флаг «пункт не проверен».
Жёстко блокировать нельзя: атрибута нет у мигрированных кредитов, блокировка остановила бы
работу по всей унаследованной базе.

Из того же решения — общий приём: **пол считается от первоначального значения, а не от
действующего.** Иначе три последовательные уступки «не ниже половины» сводят величину к одной
восьмой, и норма, ограничивающая уступку, превращается в лестницу для неё.

### 4.2. Курс валюты

**Курс берётся из справочника НБ КР на дату фактического поступления.**

- Дата — **поступления**, а не опознания и не сверки. Опознали невыясненный платёж через
  полгода — считаем по курсу того дня, когда деньги пришли.
- Курс — **производная, а не поле**: справочник и дата дают его однозначно, поэтому реквизит
  «курс» у платежа не хранится.
- **Сомовый эквивалент валютного долга выводится на дату среза** тем же справочником и не
  хранится ни на одной операции.
- Источник — НБ КР напрямую (публичные суточные значения); загрузка файлом — штатный резерв, а
  не альтернатива. Нужна **полная история**: опознание задним числом читает старые даты.
- **Правило отсутствующей даты — действует последний установленный курс на дату или ранее.**

Решающий довод: валютный кредит с оплатой в сомах (валютная оговорка) физической конвертации
**не содержит вовсе** — курс НБ в нём и есть норма договора, а «фактический курс банка» —
величина, которой не существует.

Отвергнуто: курс как реквизит факта («приходит с документом о конвертации») — при валютной
оговорке конвертации нет, а при её наличии число из документа расходилось бы с нормой
договора, и разница осела бы недостачей, которую никто не признавал. Отвергнут и гибрид
(«справочник подставляет, куратор правит»): если истина в справочнике, ручное переопределение
создаёт второй источник для одной величины.

### 4.3. Учётный период

**Календарь учётных периодов — общий справочник, лежащий ниже всех слоёв; владение в строке
поколоночное.**

- **Строка = период** («май 2026»). В строке — **колонка-защёлка на каждый слой**: учёт ·
  классификация · статистика. Колонка несёт актора, дату простановки и — при повторной —
  номер распоряжения.
- **Колонку пишет только свой модуль, читают все.** Учётную проставляют платежи (там же живут
  «закрыть» и «открыть по распоряжению»).
- **Порядок обязателен и проверяется справочником:** колонка слоя не проставляется, пока не
  проставлена нижележащая. Каскадное закрытие перестаёт быть процедурой в чьём-то коде и
  становится **состоянием строки** — любой участник видит, до какого слоя доехало закрытие
  мая, не спрашивая никого.
- **Перезакрытие двухшаговое и по распоряжению:** сброс верхних колонок сверху вниз, повторная
  простановка снизу вверх; номер распоряжения ложится в колонку. Классификация при этом
  **не открывается никогда** — открывается учёт, а классификация переспрашивает и
  защёлкивается заново.
- **Журнал закрытий — реквизит строки периода**, а не отдельная сущность: кто, когда, сколько
  строк изменилось и по каким объектам поимённо. Прогонные журналы остаются у своих модулей.
- **Справочник — не актор.** Он хранит защёлки и стережёт порядок, но ни одной колонки не
  проставляет сам: период закрывает человек.
- **Справочник не хранит чисел** — ни строк среза, ни итогов, ни выпусков; только состояние
  периода и его журнал.
- **Пустой период** (строка заведена, ни одной колонки) — законное состояние: месяц идёт.
  **Отсутствие строки периода вовсе — не то же самое**, и справочник обязан их различать.
- Сигнал «закрытый период без записи» адресуется **поводом** модулю заданий, а не письмом
  дежурному.

**Календарей три, и сливается только один.** Производственный отвечает «рабочий ли день» (общий
с платежами), календарь сдачи отчётности держит обязательства и их состояние, учётный — «что
уже нельзя менять». Общего у них только слово «календарь».

Отвергнуто: календарь у статистики (развернул бы единственную стрелку слоёв — учётный контур
начал бы зависеть от аналитического, и остановка витрины останавливала бы закрытие месяца);
календарь у ядра целиком (верхние защёлки стали бы полями чужого модуля); у каждого модуля
свой период (рассогласование слоёв стало бы штатным, а не ошибкой, и отличить «ещё не доехало»
от «сломалось» нечем); **отдельный модуль под календарь** (справочник с тремя колонками не
стоит модуля).

### 4.4. Признак распределения (справочник с гейтом)

Справочник, в который значение попадает **не по желанию, а по четырём условиям разом**. Признак
допускается, если:

1. **домен конечен и берётся из справочника** — либо признак числовой и несёт объявленное
   разбиение на доли;
2. **принадлежит виду объекта** (заявке, кредиту, предмету залога, требованию), а не
   вычисляется из соседей;
3. читается на дату без обращения к самому потребителю (иначе рекурсия);
4. устойчив — не меняется каждый год.

Зачем гейт: без него в справочник одинаково просятся «отрасль» (конечный справочник) и
«работает ли уже этот куратор с этим заёмщиком» (рекурсия), «сумма договора» (число с
порогами) и «застрахован ли предмет» (состояние, меняющееся ежегодно).

Отдельный вывод того же разбора: **домены нельзя выдумывать в макете.** Прототип держал «вид
кредита» как «инвестиционный · оборотный · потребительский», тогда как живой справочник даёт
бюджетный кредит, бюджетную ссуду, МАР, ЮСАИД, фонд развития регионов и имущественные активы.
**Правило, ключуемое выдуманным доменом, на живых данных не срабатывает вовсе.**

### 4.5. Форма отчётности

**Форма ведётся справочником, а не только документом.** Запись несёт имя, вид (отчёт или
бланк), основной объект, основание (нормативное с пунктом и редакцией либо рабочее), признак
обязательности и ссылку на шаблон, **если тот заведён**.

**Форма без шаблона законна:** «шаблон не заведён» — состояние формы, а не ошибка данных.
Именно это состояние и есть единственная причина держать в системе запись о том, чего в ней
нет: срок по норме идёт независимо от того, завели мы шаблон или нет, а пустой экран в этом
месте не нейтрален — он утверждает «всё в порядке».

Цена молчания измерена: форм 41, обязательных по норме 12, из них **шесть не заведены нигде**.
Человек, которому нужно написать повторную претензию, не находит её, пишет в Word — и бумага
живёт вне системы, без серии, без адресата, без следа в журнале. Тем же способом старая
система нажила двенадцать шаблонов-дублей: чего не нашли, то сделали заново рядом.

| Рамка грида | `1px solid rgba(28,55,90,0.16)` |
| Заголовок грида | 14 px / 500 / `rgba(24,39,57,0.94)` / padding 4×16 px |

**Единообразны на всех 47 экранах:** заголовок, primary-кнопка, рамка грида, padding
контейнера, заголовок грида — по одному значению.

**Расходятся:** размер шрифта тела грида (14 px на части экранов, 16 px на других) и высота
строки (29 / 30 / 32 / 34 px / auto — разная плотность).

Дизайн-система макетов **реверс-инжинирена из приложения**: базовые токены (шрифт, `#006AF5`,
`#192434`, `#005FDB`, рамка, радиус 4 px, высота кнопки 36 px) совпали с замерами один к
одному. Это подтверждает: целевой стиль = текущая тема приложения плюс доработки, а не новая
тема.

**Чего в живых справочниках нет против целевого:** статусы бейджами (везде простой текст),
режим просмотра (у 40 из 47 экранов), семантика полей в редакторе (обязательное = белое с
рамкой и звёздочкой, только для чтения = серое — модалки наследуют серый «disabled»-вид),
единая плотность грида, **заблокированный на выбор picker**.

## 8. Ключевые решения и их причины

| Решение | Причина |
|---|---|
| Справочник против рабочего списка — по признаку «есть ли своя закрываемая работа» | без записанного основания два реестра одного продукта выравнивают «по аналогии», не зная, что различие намеренное |
| Дублировать очередь колонкой нельзя | две очереди на один факт расходятся: закрытая в одном месте остаётся открытой в другом |
| Порядок в справочнике хронологический | справочник упорядочен по тому, чем запись опознаётся, а не по срочности |
| Провал гейта — свойство записи, не задача | действия «взять в работу» / «отложить» существуют только там, где есть ответственный |
| Набор значений классификатора — не справочник | правка строки молча ломает правило версии и подпись зафиксированных записей прошлых периодов |
| У классификации одна дверь | второй вход в те же данные = второй источник истины |
| Норма несёт редакцию и дату действия | гейт 2026 года обязан объясняться редакцией 2026 года |
| Пол считается от первоначального значения | иначе «не ниже половины» трижды подряд даёт одну восьмую |
| Непроверяемый машинно предел даёт флаг, а не блок | атрибута нет у мигрированных записей; блокировка остановила бы всю унаследованную базу |
| Курс — производная от справочника и даты | хранимая производная разойдётся при первом уточнении курса |
| Курс на дату **поступления**, а не опознания | опознание задним числом не должно менять сумму погашения |
| Отсутствующая дата ⇒ последний установленный курс | пропуск в суточных значениях не должен останавливать расчёт |
| Календарь учётных периодов — общий справочник ниже слоёв | пока владельца нет, каждый слой закрывает своё, и три ответа на «что было в мае» верны каждый в своей системе отсчёта |
| Владение колонкой, а не строкой | у каждой фиксации свой актор: учёт закрывает бухгалтерия, категории — администратор классификации; одна колонка «закрыт» их не вмещает |
| Порядок защёлок стережёт справочник | каскад становится состоянием строки, а не процедурой в чьём-то коде |
| Справочник не актор и не хранит чисел | иначе он превращается в модуль и обзаводится собственной истиной |
| «Строки периода нет» ≠ «период пуст» | пустой период — идущий месяц; отсутствие строки — пробел в календаре |
| Три календаря не сливаются | отвечают на разные вопросы и меняются по разным поводам |
| Признак проходит гейт из четырёх условий | открытая дверь впускает рекурсию, числа без разбиения и ежегодно меняющиеся состояния |
| Домены берутся из живого справочника, не выдумываются | правило на выдуманном домене на живых данных не срабатывает вовсе |
| Форма отчётности ведётся справочником; форма без шаблона законна | срок по норме идёт независимо от наличия шаблона, а пустой экран утверждает «всё в порядке» |
| Picker — режим выбора | CRUD из формы даёт правку нормативного перечня тому, кто заполняет заявку |
| Режим «Просмотр» обязателен | аудит значения не должен требовать входа в редактирование |

## 9. Открытые вопросы и долги

1. **Модуля справочников в целевой модели нет** — есть слой и пять решённых частных случаев.
   Общего решения «как ведётся любой справочник» (версионность, владелец перечня, порядок
   ввода значения в действие) **не записано**.
2. **Версионность общего справочника не решена.** Редакция и дата действия решены **только для
   нормы** и **только для курса**. Меняется ли задним числом «вид кредита» или «отрасль» и что
   происходит с записями, сославшимися на прежнее значение, — не описано.
3. **Владелец боевого перечня не назван ни для одного справочника** — сказано лишь «наполняет
   владелец».
4. **13 пустых справочников** остаются пустыми; какие из них нормативные, а какие мёртвые
   остатки схемы, не разобрано.
5. **Общесистемного справочника видов объекта нет** — модули объявляют виды объекта по месту.
6. **Макет справочников — зеркало as-is**, а не целевой экран: он показывает 47 живых
   перечней picker-полями и «Открыть как в системе», но целевого единого архетипа не
   рисует.
7. **Границы обследования узки:** справочники внешних модулей (кураторство, взыскание,
   субсидии, безопасность, гео) в разбор не входили, а часть из них уже обросла решениями в
   своих модулях — сводной картины слоя нет.

## 10. Словарь терминов

| Термин | Значение |
|---|---|
| **Справочник (классификатор)** | нормативный перечень значений, на который ссылаются поля форм |
| **Рабочий список** | реестр записей, у каждой из которых есть своя закрываемая работа |
| **Архетип `S`** | простой словарь: одна-две колонки, CRUD без просмотра |
| **Архетип `R`** | расширенный классификатор: Код + Статус + Дата создания + «Просмотр» |
| **Picker-диалог** | полноэкранный справочник, открываемый из поля формы |
| **Picker-only справочник** | справочник без пункта меню, доступный лишь из формы |
| **Норма-справочник** | запись, несущая величину, пункт нормы, редакцию и дату начала действия |
| **Учётный период** | строка календаря периодов с защёлками трёх слоёв |
| **Защёлка** | колонка периода, означающая «этот слой за период закрыт»; несёт актора и дату |
| **Производственный календарь** | справочник дат, отвечающий «рабочий ли день» |
| **Календарь сдачи отчётности** | перечень обязательств по формам и их состояний |
| **Признак распределения** | конечнозначный атрибут объекта, допущенный в ключ правила кураторства |
| **Форма отчётности** | предметная единица «вопрос, который организация обязана уметь задать» |
| **Версия классификатора** | подписанный набор значений, порядок и правила классификации |
