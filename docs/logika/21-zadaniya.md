## 0. Краткая суть

Модуль отвечает на вопрос **«по какому объекту нужна работа, кому она поручена и чем
кончилась»**. Ключевая особенность: **модуль не ждёт, когда сосед пришлёт событие, — он сам
опрашивает соседей** и каждый раз сверяет **полное множество** поводов.

Восемь решений, определяющих логику:

1. **Поводы берутся опросом (PULL), а не присылаются соседом (PUSH).** Сосед не знает о
   существовании заданий.
2. **Повод — состояние с устойчивым ключом «вид повода + объект + период», а не событие.**
   Живёт, пока не отпал.
3. **Задание = пара «повод × действие»**, не более одного открытого на пару.
4. **Состояние и исход не хранятся полем** — выводятся из журнала.
5. **Три реестра** (вид повода / действие / правило) вместо кода: новый случай заводится
   **записью реестра**, а не правкой движка.
6. **Молчание соседа не есть пустое множество:** непришедший ответ **замораживает** поводы
   этого соседа, а не закрывает их.
7. **Гигиена модуля идёт его же механизмом:** у модуля девять собственных видов повода, он
   опрашивает сам себя. Отдельного экрана «здоровья» нет.
8. **Адресат — формула правила, а не фамилия** (`ЗН-1`): роль кураторства по объекту повода →
   действующий при замещении → запасные → администратор, и падение на администратора само есть
   повод.

## 1. Модель: повод, действие, правило, задание

### 1.1. Повод

**Состояние с устойчивым ключом «вид повода + объект + период»**, означающее «по этому объекту
нужна работа».

- Не событие и не уведомление: **живёт, пока не отпал**.
- Появляется, когда сосед впервые называет его в ответе на опрос; **закрывается только когда
  сосед перестаёт его называть** либо человек отмечает исход вручную.
- Ключ **переживает любую редактуру формулировки действия** — иначе повторный опрос выдал бы
  второе задание поверх открытого.
- Повод несёт **признаки, а не числа**: например «дней вакансии», «прогонов подряд»,
  «дней просрочки». Датированное число — предмет модуля статистики; у заданий — строки.

Состояния повода: **появился** · **заморожен** · **отпал** (плюс «вновь появился» как событие
журнала).

### 1.2. Вид повода — запись реестра

Объявляет: владельца-соседа · вид объекта · гранулярность · ключевой период · несёт ли повод
собственную дату состояния · набор признаков · разрешённые действия · **порог свёртки** ·
признак «чувствительный» · **дату ввода в действие** · **реквизит суммы** — какая величина объекта
повода считается «суммой по заданию» (может быть пустой, `ЗН-8`) · **поглощение периодом** — да /
нет, для периодических видов (`ЗН-10`) · **форма адресата** — формула правила / названный поводом
(с пометкой «лично» или без) / очередь роли (`ADR-0271`) · **принятие в работу** — нужно / не
нужно / через очередь (`ЗН-17`) · **исполнение у владельца** — да / нет (`ЗН-18`) · **частота
опроса** (`ADR-0271`).

Порог свёртки по умолчанию — **10** на систему; вид повода вправе объявить своё (`ЗН-25`).

У **источника** (соседа, а не вида повода) свой реквизит — **порог молчания** (`ЗН-20`, §2.2).

**Формула ключа повода объявляется здесь и больше нигде.** Новый случай заводится записью этого
реестра, а не правкой движка.

### 1.3. Действие — запись реестра

Объявляет: формулировку работы · нужна ли ссылка на подтверждение · важность по умолчанию ·
адрес объекта работы.

**Тождественность действия устойчива к правке формулировки** — ровно поэтому ключ задания не
рассыпается при редактуре текста.

### 1.4. Правило — запись реестра

Связывает вид повода с условием отбора, режимом (**автоматический** или **ручной**),
владельцем-автором, составом действий (у каждого свой срок, круг адресатов, контролёр) и
переопределением важности.

**Круг адресатов — формула, а не список фамилий** (`ЗН-1`, `ADR-0262`): роль кураторства по
объекту повода, а для объекта без кураторства — подразделение или должность. Вычисляется на дату
выдачи (§3.6).

**Правка правила действует на уже выданное смешанно:**

| Что | Как |
|---|---|
| срок, адресаты, автор, контролёр | по **снимку на момент выдачи**, задним числом не двигаются |
| состав действий | по **действующей редакции**: убранное действие закрывает открытое задание исходом «снято», добавленное рождает новую пару |

Уровня «шаблон» из ТЗ в модуль **не перенесено**.

### 1.5. Задание

**Пара «повод × действие».** Устойчивый ключ, а не запись с состоянием: состояние и исход
**выводятся из журнала последней записью**.

Выдаётся тремя путями:

1. **правилом в авто-режиме** — само, на прогоне опроса;
2. **правилом в ручном режиме** — тем же кодовым путём, но по кнопке человека;
3. **человеком напрямую** — **свободное задание** без повода и без правила.

**Свободное задание обязано иметь названного контролёра:** задание без адресата контроля не
заводится ни при каких условиях.

## 2. Опрос: как поводы попадают в модуль

### 2.1. PULL, а не PUSH

Задания **спрашивают** соседа, а не подписываются на его события. Две разновидности опроса:

- **событийная** — «у соседа возникло состояние»;
- **периодическая** — период задаёт общий справочник учётных периодов, сосед лишь отвечает,
  наступил ли срок.

Частоту опроса объявляет вид повода: по умолчанию — ночной прогон, у семейства «документ» —
**5 минут** (`ADR-0271`). Принцип PULL от частоты не меняется: задания спрашивают, сосед отвечает.

### 2.2. Ответ соседа — одно из трёх

| Ответ | Что делает модуль |
|---|---|
| **полное множество на дату** | штатная сверка (§2.3) |
| **объявленный отказ с причиной** | как молчание, но с названной причиной |
| **таймаут** | **заморозка** поводов этого соседа |

**Молчание не есть пустое множество.** Непришедший ответ **замораживает** поводы этого соседа, а
не закрывает их; прогон с молчавшим соседом **полным не считается** и помечается в журнале
прогонов. Заморозка ограничена видами **только этого источника** — чужой источник молчания не
касается.

**Порог молчания — время, и объявляет его источник** (`ЗН-20`, `ИЗ-35`): через сколько молчание
становится поводом самоопроса «сосед не отвечает». По умолчанию — **два обычных интервала опроса
источника, но не меньше 30 минут**: у ночных соседей это две ночи, у документооборота — полчаса.
Счёт в прогонах («два неполных подряд») при разной частоте опроса перестал значить одно и то же.

Если сосед вернулся и отдал **полное, но пустое** множество — поводы отпадают штатной сверкой.
Это принципиально **другой путь**, чем заморозка: пустое множество — ответ, таймаут — его
отсутствие.

### 2.3. Сверка множества: полная и идемпотентная

Каждый прогон по каждому виду повода:

1. вычислить **ожидаемое множество** ключей у соседа на дату;
2. поводы, которых в ожидаемом нет, пометить **отпавшими**;
3. ключи, которых нет среди живых поводов, создать как **появившиеся**;
4. совпавшие — оставить как есть и **переиздать задание, если открытого по паре нет**.

Повторный прогон той же датой даёт **новых 0, отпавших 0** и не плодит второе задание поверх
открытого. Идемпотентность — приёмочное требование, а не пожелание.

### 2.4. Свёртка (вал-задание)

Если по одному виду повода за прогон **одному адресату** пришло больше ключей, чем **порог
свёртки** вида, вместо поштучных заданий выдаётся **одно вал-задание**, несущее список свёрнутых
ключей. Порог считается **по паре «вид × адресат»** (`ЗН-23`, `ИЗ-36`): сначала ключи раскладываются
по адресатам формулой правила, потом сворачиваются у того, у кого набралось больше порога. У вала
поэтому всегда один ответственный.

```
 40 поводов «осмотр просрочен», порог 10:
   25 — куратор Асанов   → ВАЛ (25) Асанову
   10 — куратор Бекова   → 10 поштучных
    5 — куратор Садыков  →  5 поштучных
```

Тонкость, вскрытая на реальных данных соседа: проверка «есть ли открытое задание по поводу»
обязана смотреть **и на поштучные задания, и на списки вал-заданий** — иначе повторный прогон
тихо переиздаёт задание на каждый уже свёрнутый повод.

**Вал — контейнер, а не склейка** (`ЗН-9`). Каждый ключ внутри живёт своей жизнью:

```
 ВАЛ-1 «осмотры» · 40 ключей · поручено Асанову
   ├─ 25 отпали (осмотр внесён)       → помечены «отпал» в списке вала, вал открыт
   ├─  3 сменили ответственного        → выходят из вала поштучными заданиями у нового (ЗН-2),
   │                                     пока вал не взят в работу
   └─ 12 живы                          → вал открыт
 вал закрыт, когда живых ключей нет: «исполнено», если все отпали штатно; иначе — разбор
```

Разбор вала (`ЗН-26`): поштучные задания выдаются по формуле адресата правила на дату разбора,
вал закрывается исходом «снято»; поштучные из вала «повтором» не считаются.

Исполнитель вправе **разобрать вал на поштучные задания**. Пара «повод × действие» принадлежит
ключу, а ключ лежит в одном валу — `ИЗ-5` не нарушается (`ИЗ-26`).

### 2.5. Рубильник вида повода

**Дата ввода вида повода в действие.** Вид, заведённый но не введённый в действие, **собственных
поводов не порождает**. При этом сам факт «вид не введён в действие дольше срока» — **отдельный
повод**, тоже самоопрашиваемый. Рубильник **обратим**: включение вида восстанавливает его поводы
на следующем прогоне.

### 2.6. База срока: клэмп к дате подключения

**База отсчёта срока = max(дата состояния у соседа, дата ввода вида в действие).**

Зачем: при первом подключении соседа его состояния могут быть датированы месяцами раньше. Без
клэмпа модуль выдал бы вал просроченных заданий в первый же день. При этом **признак хранит
настоящую давность** — клэмп ограничивает базу срока, а не искажает данные.

### 2.7. Ключ шва: два законных приёма

| Приём | Когда применяется | Пример |
|---|---|---|
| **пересобрать** свою тройку `вид|тип:id|` | у соседа устойчивого ключа нет, есть только плоский список строк | шесть списков оргструктуры |
| **взять ключ соседа дословно** | сосед уже держит устойчивый ключ «вид + объект + период» | статистика, отчётность |

Пересобирать уже устойчивый ключ соседа значило бы **завести вторую нумерацию того же повода**.

### 2.7а. Периодический повод после конца периода (`ЗН-10`)

Ключ периодического повода несёт период: «обследование · ПЗ-88 · 2027-Q1». Когда наступил Q2, а
работа за Q1 не сделана, **модуль ничего не додумывает**: он, как всегда, спрашивает полное
множество на дату.

- Норма соседа прощает пропуск следующим исполнением («одно обследование в квартал») — сосед
  перестаёт называть Q1 после обследования в Q2, повод отпадает штатно.
- Норма считает пропуск нарушением навсегда — сосед продолжает называть Q1, задание висит
  просроченным.

Чего ждать, видно человеку из реквизита вида повода **«поглощение периодом»**; объявляет его
владелец-сосед. Модуль сам ключ прошлого периода не закрывает (это тихое прощение пропуска) и
не переносит в новый период (ключ перестал бы быть устойчивым, `ИЗ-3`). `ИЗ-27`.

### 2.8. Зеркалится ответ, а не код соседа

Прототип повторяет **форму ответа** соседа, а не тащит к себе его движок. Причина — критерий
соседа: **сосед есть критерий, а не список**. Копия чужого механизма у себя означала бы вторую
реализацию, которая разойдётся с оригиналом; опрос по сети дал бы такой же плоский ответ.

## 3. Жизненный цикл задания

### 3.1. События журнала

**поручено** → **принято** («Взять в работу», `ЗН-11`) / **отказано** → **ожидает приёмки** (если
есть контролёр) / **заявлено** (если контролёра нет) → **возвращено** → … → **закрыто**.

Плюс **отпало** — повод исчез, пока задание было в работе.

**«Принято» — явное событие** (`ЗН-11`, `ИЗ-28`): исполнитель нажимает «Взять в работу», и только
это событие защищает задание от переадресации (§3.6). Нужен ли шаг, объявляет вид повода
(`ЗН-17`): у адресата, названного поводом, шага нет — задание сразу в работе; в очереди роли
«Взять в работу» и есть закрепление исполнителя. **«Возвращено» считается принятым** (`ЗН-15`).

События волны 5. Ось работы меняют только переадресация и переназначение: они возвращают
задание в «поручено» новому исполнителю.

| событие | кто | решение |
|---|---|---|
| **переадресовано** | система, при смене закрепления; только из «поручено» | `ЗН-2` |
| **переназначено** | автор или руководитель исполнителя по цепочке, с основанием | `ЗН-6` |
| **запрошено продление** | исполнитель: новая дата + основание | `ЗН-3` |
| **продление утверждено / отклонено** | тот, кто поставил срок | `ЗН-3` |
| **отметка о ходе** | исполнитель и любой участник: текст, ссылка, вложение | `ЗН-5` |

Состояние задания = **последнее событие журнала**; терминальное состояние — только «закрыто».

### 3.2. Исход выводится перекрёстно из двух осей

Исход не хранится полем: он выводится из двух независимых осей журнала — **оси работы**
(поручено → принято → сдано) и **оси подтверждения** (отпадение повода и/или решение
контролёра).

Исходы закрытия: **исполнено** · **снято** · **отпало** (с причиной).

**Какая ось подтверждает** (`ЗН-13`, `ИЗ-30`, `ADR-0273`):

| задание | подтверждает | «исполнено» |
|---|---|---|
| по правилу, контролёра нет | повод | повод отпал после заявления |
| по правилу, контролёр назван | **обе оси** | повод отпал **и** контролёр принял |
| свободное (повода нет) | контролёр | контролёр принял |
| вид «исполнение у владельца» | повод с атрибуцией | см. ниже |

При названном контролёре: повод отпал, пока задание «ожидает приёмки», — задание остаётся у
контролёра с отметкой «повод отпал», решает он; пока повод жив, у контролёра нет «Принять» —
только «Вернуть». Застрявшее задание выводит собственный повод «ожидает приёмки дольше срока».

**Возврат заявленного системой** (`ЗН-12`, `ИЗ-29`). Задание без контролёра «заявлено», а повод
жив: возвращается («возвращено» + уведомление) только на **полном** прогоне, у которого **дата
среза соседа позже дня заявления**. Прогон того же дня и неполный прогон не считаются: соседу
даётся одна ночь, чтобы увидеть работу (остаток у соседа может быть пакетным снимком, `E2E-09`).

**Исполнение у владельца** (`ЗН-18`, `ADR-0271` п. 3). У видов с этим реквизитом шаг делается в
карточке у владельца, а не кнопкой «сдано»: повод отпадает и несёт, кто выполнил. Исход —
«исполнено» (адресат или действующий за него), «исполнено · выполнил другой», «снято» с причиной
от владельца (объект аннулирован или удалён). «Отпало — ждёт разбора» у таких видов не бывает.

### 3.3. Переходы

| Действие | Кто | Условие | Результат |
|---|---|---|---|
| Взять в работу | исполнитель; в очереди роли — любой носитель роли | «поручено», если вид требует принятия (`ЗН-17`) | «принято»; уведомление «принято» автору и контролёру; в очереди — задание закреплено за взявшим |
| Заявить исполнение | исполнитель или замещающий (`ЗН-22`) | «принято» / «возвращено»; «поручено» — у вида без принятия | «ожидает приёмки» (есть контролёр) либо «заявлено»; ссылка на подтверждение, если её требует действие |
| Отказаться | исполнитель | нетерминальное, до заявления | «отказано» с примечанием |
| Снять | автор | **любое нетерминальное**, с основанием (`ЗН-14`); у видов «исполнение у владельца» — **нет** (`ЗН-18`) | закрыто, исход «снято»; пара по правилу **не переиздаётся, пока ключ жив** |
| Переназначить | автор **или руководитель исполнителя по цепочке** | **любое нетерминальное**, с основанием (`ЗН-6`) | новый исполнитель, снова «поручено»; прежнему — «переадресовано»; установленный срок не меняется |
| Запросить продление | исполнитель | нетерминальное | событие «запрошено продление»; срок не меняется до утверждения (`ЗН-3`) |
| Утвердить / отклонить продление | автор; если назван контролёр — контролёр | есть запрос | новый установленный срок либо прежний |
| Отметить ход | исполнитель, замещающий, любой, кому задание видно | нетерминальное | событие журнала; состояние не меняется (`ЗН-5`) |
| Принять | контролёр | «ожидает приёмки»; у задания по правилу — **повод отпал** (`ЗН-13`) | закрыто, исход «исполнено» |
| Вернуть | контролёр | «ожидает приёмки» | «возвращено»: снова в работе у того же исполнителя, установленный срок прежний (`ЗН-15`) |
| Разобрать отпавшее | человек | состояние «отпало» | закрыто с названным исходом и причиной |

**Отпавшее задание не закрывается тихо:** оно помечается «отпало — ждёт разбора» и само
становится поводом «отпавшее задание требует разбора» на следующем самоопросе.

**Снятое по правилу — решение «работа не нужна»** (`ЗН-14`, `ИЗ-31`): пока ключ жив, новое задание
по паре не выдаётся, в таблице поводов ключ помечен «снят без поручения». Ключ отпал и появился
вновь — новое задание «повтор после З-…» (§3.7). У видов «исполнение у владельца» шаг убирают у
владельца (автор документа меняет согласующих или аннулирует документ) — повод отпадает, задание
закрывается «снято» с причиной от владельца.

### 3.4. Сроки и эскалация

- срок задания считается **в рабочих днях** от базы срока (§2.6) — **по общему производственному
  календарю** системы (`ЗН-24`, `ИЗ-38`; `РС-30`): постоянные праздники КР, переносы и рабочие
  субботы записью на год. Год не заведён — рядом со сроком видна отметка «календарь года не
  заведён», а не тихий откат к «сб/вс»;
- **установленный срок — последний утверждённый** (`ЗН-3`, `ИЗ-20`). Первоначальный срок и число
  продлений остаются в журнале и уходят в статистику; «исполнено в установленный срок» меряется
  последним утверждённым. Пока запрос не утверждён, действует прежний срок — запрос срок не
  останавливает;
- за день до срока — уведомление «срок близко»;
- **просрочка — один сигнал каждому** (`ЗН-16`, `ИЗ-33`):

  ```
   срок            исполнителю — уведомление «срок истёк»; задание в его очереди красное
   +5 р.д.         повод «Просрочено задание» → ЗАДАНИЕ руководителю исполнителя
                   («разберитесь с просрочкой З-…»), пришедшее уведомлением «эскалация»;
                   руководителя нет — администратору модуля
  ```

  Руководитель получает не звонок, а задание с журналом: переназначить (`ЗН-6`), утвердить
  продление, снять;
- **очередь роли, которую никто не взял** (`ЗН-19`): просрочка — проблема распределения, а не
  исполнения. **Сразу** по истечении срока — задание «никто не взял» руководителю подразделения
  роли, всем носителям роли — уведомление «срок истёк»; на 5-й р.д. — эскалация администратору
  владельца вида (для документов — администратору документооборота, `ADR-0271`). Взятое из
  очереди и просроченное — по общему правилу выше;
- каждое уведомление шлётся **однократно** на задание — «срок близко» и «срок истёк» однократно
  **на каждый установленный срок** (`ADR-0263`).

### 3.5. Видимость

Задание видно: исполнителю · контролёру · автору · **любому руководителю по цепочке
подчинения исполнителя** · **ответственному по кураторству на дату** (`ЗН-2`) · **замещающему
исполнителя на дату** (`ЗН-22`); задание очереди роли, пока его не взяли, — **всем носителям
роли**. Это собственные основания видимости модуля, а не общесистемная модель доступа.

### 3.6. Адресат (`ЗН-1`, `ЗН-2`, `ADR-0262`)

Форму адресата объявляет вид повода (`ADR-0271`):

| форма | кто адресат | замещение |
|---|---|---|
| **формула правила** | роль кураторства по объекту повода; для объекта без кураторства — подразделение или должность | применяется |
| **названный поводом** | человек, которого назвал сам повод (согласующий, ответственный по резолюции); формула кураторства не применяется | применяется, кроме пометки «лично» — тогда замещающего подставляет владелец (`doc-sign`) |
| **очередь роли** | все носители роли; «Взять в работу» закрепляет исполнителя | — |

Цепочка формулы правила:

```
 повод pk-im-instalment-overdue · ИО-1
   ▼  правило: адресат = «роль кураторства: куратор имущества» по объекту повода
 Кураторство (на дату)   → закреплён Асанов            (ответственный)
   ▼
 Сотрудники (на дату)    → Асанов в отпуске, замещает Бекова → ИСПОЛНИТЕЛЬ: Бекова
   ▼  закрепления нет?
 запасной адресат        → руководитель подразделения-владельца вида повода
   ▼  и его нет?
 администратор модуля    → + повод самоопроса «адресат не найден»
```

- Адресат — **снимок на момент выдачи** (`ИЗ-9`, `ИЗ-18`).
- **Смена закрепления** переадресует задание, которое никто не взял в работу («поручено»),
  событием «переадресовано»; принятое в работу (и возвращённое) остаётся у исполнителя (`ИЗ-19`,
  `ИЗ-28`). Выдёргивать начатую работу нельзя, оставлять неначатую у ушедшего — тоже.
  Переадресацию запускает смена куратора, а не замещение; переназначенное человеком система
  больше не переадресует (`ЗН-26`).
- **Замещение, начавшееся после выдачи** (`ЗН-22`, `ИЗ-37`): задание остаётся у исполнителя —
  ответственность при замещении на закреплённом (§8.3), — а замещающий на дату его видит и
  действует за него (взять в работу, отметить ход, заявить, запросить продление); в журнале —
  «Бекова за Асанова». Замещение применяется к любому адресату цепочки — куратору, участнику,
  запасному (`ЗН-26`).
- **Переадресация ≠ переназначение:** первая системная и только для непринятого, второе —
  решение человека с основанием (§3.3).
- Кураторство отвечает «кто **ответственный**», сотрудники — «кто **действующий**», задания —
  «кому **поручено**» (§8.3).

### 3.7. Повтор повода (`ЗН-7`)

Ключ повода устойчив, и вернувшаяся проблема приходит тем же ключом. **Закрытое не
переоткрывается** (`ИЗ-24`): рождается новое задание с реквизитом **«повтор после З-…»** и
счётчиком повторов по ключу.

```
 01.03 вакансия руководителя Д-7 → З-1 → 10.03 исполнено (назначен Омуров)
 20.03 Омуров уволился → тот же ключ → З-2 «повтор после З-1», повторов: 1
```

Переоткрытие переписало бы исход задним числом («исполнено в срок» за март поменялось бы в
апреле). Частый возврат ключа (по умолчанию 3 раза за **30 календарных** дней) — повод самоопроса
«повод возвращается»: разбирать причину, а не симптом. Дребезг данных соседа виден той же связкой.

«Повтор после» указывает на последнее закрытое задание по ключу либо на вал, где ключ отпал;
счётчик — число таких предыдущих заданий (`ЗН-26`). Снятое по правилу (`ЗН-14`) тоже закрытое:
вернувшийся после отпадения ключ даёт новое задание «повтор после» снятого.

### 3.8. Ход исполнения (`ЗН-5`)

ТЗ, стр. 1032, 1049, 1054: «ввод информации о ходе исполнения», «проведённая работа с указанием
ссылки на подтверждающую информацию».

- Событие **«отметка о ходе»**: текст, необязательная ссылка на объект системы или вложение,
  автор, время. **Состояние не меняет, уведомлений не шлёт.**
- Отметки **не редактируются и не удаляются**; ошибку исправляет отметка «исправление к …»
  (`ИЗ-22`). Требование ТЗ «редактирование» исполнено без переписывания прошлого.
- **Ссылка на подтверждение при сдаче** — реквизит события «сдано»; обязательна, если её требует
  действие (реестр действий).
- Работа, оставившая след у соседа (претензия, поступление), попадает в отметку **ссылкой**, а не
  копией.

## 4. Собственные девять видов повода (самоопрос)

Модуль доказывает свой механизм, **опрашивая сам себя**. Отдельного экрана «здоровья» нет — его
работа выражена теми же поводами и заданиями.

| Вид повода | Условие | Признак | Порог свёртки | Срок |
|---|---|---|:--:|:--:|
| Просрочено задание | открытое задание, **5 р.д.** после установленного срока; в очереди роли, которую никто не взял, — сразу (`ЗН-16`, `ЗН-19`) | давность в рабочих днях | 20 | 2 р.д. |
| Задание отклонено | последнее событие — «отказано» | — | 20 | 1 р.д. |
| Ожидает приёмки дольше срока | «ожидает приёмки» > **3 рабочих дней** | давность | 20 | 2 р.д. |
| Отпавшее задание требует разбора | последнее событие — «отпало» | — | 20 | 2 р.д. |
| Сосед не отвечает | молчит дольше **порога молчания** источника (по умолчанию два интервала опроса, не меньше 30 мин, `ЗН-20`) | молчит минут, порог, с какой даты | 5 | 1 р.д. |
| Вид повода не введён в действие | заведён, не активирован > **3 календарных дней** | дней с заведения | 20 | 3 р.д. (**ручной** режим) |
| **Адресат не найден** (`ЗН-1`) | задание выдано администратору по концу цепочки запасных | вид объекта, роль | 5 | 1 р.д. |
| **Запрос продления без ответа** (`ЗН-3`) | «запрошено продление» без решения > **1 р.д.** | давность | 20 | 1 р.д. |
| **Повод возвращается** (`ЗН-7`) | ключ вновь появился ≥ **3 раз за 30 дней** | повторов | 20 | 3 р.д. |

Вид «сосед не отвечает» помечен **чувствительным**.

**Адресаты собственных видов.** «Просрочено задание» — руководителю исполнителя (руководителя нет —
администратору модуля), задание приходит уведомлением «эскалация» (`ЗН-16`); в неразобранной очереди
роли — руководителю подразделения роли (`ЗН-19`). «Адресат не найден» и «повод возвращается» —
администратору модуля; «запрос продления без ответа» — тому, кто должен утвердить (`ЗН-26`).

**Стопор рекурсии:** задание, рождённое видом повода X, само повода X не порождает —
просроченное задание «разобраться с просроченным заданием» не плодит бесконечную цепочку.
Стопор жёсткий, на один шаг.

Вид «вид повода не введён в действие» намеренно оставлен в **ручном** режиме — он же служит
демонстрацией второго рода ручного задания (выдача по кнопке тем же кодовым путём, что авто).

## 5. Подключённые соседи

Каждый сосед подключался **записями реестра, без правки движка** (кроме одной обобщённой ветки
шва) — это и есть проверка того, что три реестра работают.

| Волна | Сосед | Что опрашивается | Виды повода | Приём ключа |
|:--:|---|---|---|---|
| 1 | **сам механизм** (самоопрос) | свои шесть списков | 6 своих | своя тройка |
| 2 | **Оргструктура** | шесть рабочих списков «Требует внимания»: вакансия руководителя, заканчивающееся и.о., нарушение «одно основное», подразделение без штата, заблокированная ликвидация, территория без подразделения | 6 | пересобранная тройка (у соседа плоский список) |
| 3 | **Статистика** | единственная «дверь» соседа, отдающая один жанр — «сосед молчит» | 1 | **ключ соседа дословно** (у него устойчивый ключ вид+объект+период) |
| 4 | **Отчётность** | обязательства по формам; поводом становится **только** состояние «просрочено» из четырёх возможных | 1 | **ключ соседа дословно** |
| — | **Документооборот** (принят моделью, `ADR-0271`; в макете не подключён) | шаги документа: доработать, согласовать, подписать, зарегистрировать, отправить, рассмотреть, исполнить резолюцию, подтвердить на контроле, ознакомиться, сдать в дело, вернуть оригинал | 11 | ключ соседа («документ × участник», «резолюция × исполнитель») |
| 8 | **Госрешение** (`ЗГ-1`…`ЗГ-11`, макет 11.10.2026) | шаги согласования (рассмотреть, доработать) по механизму `ADR-0271`; по данным — решение «Закрыт» при действующих программах, «Действует» без основного документа | 4 | своя пара «вид · госрешение:id» / «вид · программа:id», период пуст |
| 8 | **Кредитная программа** (`ЗКП-1`…`ЗКП-12`, макет 11.10.2026) | шаги согласования (рассмотреть, доработать) по механизму `ADR-0271`; по данным — срок истекает (≤ 30 к.д. до «Даты по»), срок истёк при статусе «Действует»; ответ о программах под закрытым решением для вида Госрешения | 4 (+1 вид Госрешения) | своя пара «вид · программа:id», период пуст |

Фильтрация «что из ответа соседа является поводом» — **код шва, а не код соседа**: сосед ничего
не решает за модуль заданий.

**Отдельно зафиксированные границы:**

- **Кадры не подключены:** у самих кадров рабочий список числится макетом, подключать нечего —
  это долг соседа, а не модуля.
- **Заёмщик не является источником опроса:** поток архитектурно односторонний — датированные
  строки приходят в витрину заёмщика **из** заданий, а не наоборот.
- **Отчётность показывает, но не поручает:** её собственная «заглушка автозадачи» намеренно не
  вызывается; зеркалится только идея формы основания (что / когда / кто).
- **Адресация поводов соседей** — формула правила через кураторство, запасные адресаты и повод
  «адресат не найден» (`ЗН-1`, `ADR-0262`). Хардкод администратора (`E4`), которым прототип
  адресовал виды соседей до волны 5, снят волной макета 10.10.2026 (§14); ответ кураторства и
  сотрудников на дату в прототипе — зашитые демо-данные.
- **Омоним, который нельзя путать:** организационный отдел «Взыскание» и модуль-сосед
  «взыскание» — разные объекты; адресация их намеренно не смешивает.
- **Документооборот — первый сосед с другой механикой шага** (`ADR-0271`): адресат названный или
  очередь роли, исполнение у владельца, опрос раз в 5 минут. Всё это — **реквизиты вида повода**
  (`ИЗ-34`), ветки кода на слово «документ» в движке нет.
- **Госрешение — второй сосед с механикой шага** (`ЗГ-1`…`ЗГ-4`): `gd-review` «Рассмотреть
  госрешение» — очередь роли «Согласующий», `gd-revise` «Доработать госрешение» — автор, названный
  поводом; исполнение у владельца, опрос раз в 5 минут, своей очереди «на согласовании» у
  Госрешения нет. Поводы по данным: `gd-closed-live-programs` — **объект программа** (повод на
  каждую действующую программу под закрытым решением, очередь роли «Согласующий» программ,
  `ЗГ-6`) и `gd-active-no-doc` — «Действует» без основного документа, автору, без автора —
  администратору (`ЗГ-7`). Программа и госрешение **не объекты закрепления**: формула через
  кураторство к ним не применяется. Сроки — позиция проекта на подтверждение заказчику (`ЗГ-8`).
- **Кредитная программа — третий сосед с механикой шага** (`ЗКП-1`, `ЗКП-2`, по умолчанию как
  `ЗГ-1`…`ЗГ-4`): `lp-review` «Рассмотреть программу» — очередь роли «Согласующий» (по своей
  программе автору-носителю роли не виден — 4 глаза, ТЗ 02 §7), `lp-revise` «Доработать программу» —
  автор, названный поводом. Поводы по данным (`ЗКП-4`): `lp-expiring` «Срок истекает» — до «Даты
  по» ≤ 30 к.д., срок задания — день перед «Датой по»; `lp-expired` «Срок истёк» — «Дата по»
  прошла, а статус «Действует», срок 5 р.д. Оба — очередь «Согласующий», действие «Продлить срок
  или закрыть» (`ЗКП-5`); на «Дате по» `lp-expiring` снимается с причиной «перешло в истёкший»,
  после продления возникает заново по `ЗН-7` (`ЗКП-6`); бессрочные программы поводов о сроке не
  дают (`ЗКП-7`). Исправление — в карточке программы новыми узкими действиями Согласующего
  «Продлить срок» и «Сменить основание» (`ADR-0274`); `gd-closed-live-programs` остаётся видом
  Госрешения, каскада статуса нет (`ЗКП-3`). Отвергнуто владельцем: «нет действующих
  ответственных сотрудников». Сроки — позиция проекта на подтверждение заказчику (`ЗКП-8`).
- **Просрочка формы отчётности — событийный вид**, хотя ключ несёт период; поглощение периодом у
  подключённых видов пусто и требуется только у периодических (`ЗН-26`).

## 8. Швы с соседними модулями

### 8.1. Что модуль берёт

| Сосед | Что берёт | Форма |
|---|---|---|
| **Оргструктура** | шесть рабочих списков проблем на дату | опрос, зеркало ответа |
| **Статистика** | «какие соседи молчат» | опрос, ключ дословно |
| **Отчётность** | обязательства по формам (только просроченные) | опрос, ключ дословно |
| **Сотрудники** | кому фактически уйдёт работа на дату (замещение), руководитель исполнителя для эскалации | контракт маршрутизации |
| **Кураторство** | список ответственных: роль плюс подразделение | ответ кураторства на дату |
| **Анализ** | два повода (решения ADR-0250, ADR-0251) | опрос |
| **Документооборот** | шаги документа — 11 видов семейства «документ» с атрибуцией исполнителя | опрос раз в 5 минут, ключ соседа (`ADR-0271`) |
| **Госрешение** | статусы решений с атрибуцией смены статуса, автор, наличие основного документа | опрос раз в 5 минут, своя пара (`ЗГ-4`) |
| **Кредитные программы** | статусы программ с атрибуцией, автор, «Дата по», ссылка на госрешение | опрос раз в 5 минут, своя пара (`ЗКП-2`) |
| **Справочник учётных периодов** | границы периодов для периодического опроса | справочник |
| **Производственный календарь** | рабочие дни для счёта сроков | общий справочник дат (`РС-30`, `ЗН-24`; в прототипе пока сб/вс) |

### 8.2. Что модуль отдаёт

- Датированные строки в витрины соседей (например, в карточку заёмщика) — **поток
  односторонний**.
- **Строки заданий статистике** (`ЗН-8`): статистика заводит объект «задание» (после двух
  объектов имущества). Реквизиты строки: ключ, вид повода, действие, адресат,
  подразделение, **чей повод** (владелец-сосед вида повода, `ЗН-21`), даты выдачи,
  первоначального и установленного срока, сдачи и закрытия, исход, число продлений, повтор.
  Показатели строятся **с разрезом по владельцу-соседу**: шаги документов (одно письмо — 4–6
  заданий) не смешиваются с кредитной работой, а нагрузка на человека видна целиком. Показатели ТЗ (стр. 722–731: назначено, в работе, просрочено,
  исполнено в срок / с опозданием, отказано, процент исполнения) считает статистика.
- **«Сумма по заданиям»** — не поле задания (`ИЗ-25`): статистика берёт её у владельца объекта
  повода на дату выдачи, а **какую** величину считать, объявляет вид повода («реквизит суммы»). У
  заданий без денежного объекта (вакансия, обязательство по форме) реквизит пуст.
- **Установленный срок и исход по ключу повода** — для документооборота и статистики
  (показатели «в срок / с опозданием» и «из них с продлением» по `doc-execute`, `ADR-0271`,
  `ADR-0272`). Читают то же, что уже отдаёт строка `ЗН-8`, адресуя её ключом повода.
- Ничего не пересчитывает за соседей и не пишет в их данные.

### 8.3. Разделение с модулем сотрудников

Кураторство называет **ответственного**, сотрудники называют **действующего** (при замещении),
задания **адресуют работу**. Три разных вопроса, три владельца; ответственность при замещении
остаётся на закреплённом.

## 9. Ключевые решения и их причины

| Решение | Причина |
|---|---|
| Поводы берутся опросом (PULL) | PUSH требует, чтобы каждый сосед знал о заданиях и умел их звать; при отказе доставки повод теряется молча |
| Повод — состояние с устойчивым ключом, а не событие | событие нельзя «отменить», когда проблема ушла; состояние отпадает само |
| Ключ переживает правку формулировки действия | иначе редактура текста плодит второе задание поверх открытого |
| Каждый опрос — полная сверка множества | инкремент расходится с источником при первом пропущенном прогоне |
| Молчание ≠ пустое множество | закрытие поводов при недоступности источника — тихая потеря работы |
| Заморозка ограничена видами одного источника | молчание статистики не должно гасить поводы оргструктуры |
| Задание = пара «повод × действие», ≤ 1 открытое | иначе один повод даёт стопку дублей |
| Состояние и исход выводятся из журнала | хранимое поле состояния расходится с журналом при первой правке |
| Ось подтверждения независима от оси работы | «сделано» и «принято» — разные факты; у части заданий подтверждения нет вовсе |
| Три реестра вместо кода | новый случай — запись реестра; иначе каждый новый повод стоит правки движка |
| Правка правила действует смешанно | срок и адресат задним числом менять нельзя (это переписывание истории), а состав действий обязан быть текущим |
| Повод несёт признаки, а не числа | датированное число — предмет статистики; у заданий числа разошлись бы с её срезами |
| Свёртка по порогу | 300 поштучных заданий на одно системное событие делают очередь нечитаемой |
| Проверка открытого задания смотрит и в списки вал-заданий | иначе повторный прогон переиздаёт задание на каждый свёрнутый повод (реальный дефект, найденный на живых данных) |
| Рубильник вида повода — дата, а не флаг | нужно знать, с какого дня вид работает, чтобы считать сроки |
| «Вид не введён в действие» — сам повод | иначе заведённый и забытый вид молчит незаметно |
| База срока = max(дата состояния, дата активации) | первое подключение иначе даёт вал просроченных заданий из чужой истории |
| Ключ соседа берётся дословно, если он устойчив | пересборка завела бы вторую нумерацию того же повода |
| Зеркалится ответ, а не код соседа | копия чужого механизма — вторая реализация, которая разойдётся |
| Стопор рекурсии на один шаг | иначе просроченное задание о просроченном задании плодит цепочку |
| Уведомления — закрытый список из двенадцати | открытый список превращает модуль в рассылку |
| Отпавшее задание помечается, а не закрывается тихо | исход должен разобрать человек: работа могла быть сделана, а могла и нет |
| Свободное задание требует контролёра | задание без адресата контроля никогда не закрывается по существу |
| Гигиена модуля идёт его же механизмом | отдельный экран «здоровья» — второй механизм, который придётся поддерживать |
| Эскалация руководителю по цепочке подчинения | срок, истёкший у исполнителя, обязан стать чужой проблемой |
| Адресат — формула правила через кураторство (`ЗН-1`) | фамилии в правиле — вторая таблица ответственных, расходящаяся при ротации |
| Падение на администратора — повод «адресат не найден» | хардкод перестаёт быть тихим, невидимых заданий нет |
| Переадресуется только непринятое (`ЗН-2`) | начатую работу нельзя выдёргивать, неначатую нельзя оставлять ушедшему |
| Продление: запрос + утверждение; установленный — последний утверждённый (`ЗН-3`) | срок, который двигает исполнитель, не срок; честный запрос не наказывается «опозданием» |
| Уведомлений двенадцать (`ЗН-4`) | о переадресации и продлении человек обязан узнать, а не догадаться по очереди |
| Ход исполнения — событие журнала без правки (`ЗН-5`) | перезаписываемое поле теряет хронологию, нужную при эскалации |
| Переназначать может руководитель по цепочке (`ЗН-6`) | эскалация без права действия — пустой звонок |
| Закрытое не переоткрывается; повтор — новое задание со ссылкой (`ЗН-7`) | переоткрытие переписывает исход прошлого периода |
| Задание не несёт сумм; реквизит суммы — у вида повода (`ЗН-8`) | копия числа соседа расходится с источником (`ADR-0222`) |
| Вал — контейнер ключей (`ЗН-9`) | закрытый вручную вал прячет живые поводы от повторного прогона |
| Судьбу периода решает сосед (`ЗН-10`) | модуль, закрывающий прошлый период, тихо прощает пропуск |
| «Взять в работу» — явное событие (`ЗН-11`) | без него система не знает, что работа начата, и переадресация выдёргивает задание с отметками о ходе |
| Заявленное возвращается не раньше среза следующего дня (`ЗН-12`) | данные соседа отстают (пакетный остаток, `E2E-09`); возврат в тот же день наказывает за чужую задержку |
| При контролёре нужны обе оси (`ЗН-13`, `ADR-0273`) | любая ось по отдельности даёт закрытие в обход контролёра или цикл переиздания |
| Автор снимает из любого состояния; снятое не переиздаётся (`ЗН-14`) | снятие только после отказа не закрывает ненужное, а переиздание делает кнопку пустой |
| «Возвращено» нетерминально (`ЗН-15`) | возврат — «доделать», а не исход; исходов три |
| Просрочка — один сигнал каждому (`ЗН-16`) | два сигнала об одном (уведомление + задание) приучают не читать ни тот, ни другой |
| Принятие, форма адресата, исполнение у владельца — реквизиты вида (`ЗН-17`, `ЗН-18`) | ветка кода на слово «документ» — второй движок внутри первого |
| Неразобранная очередь — сразу руководителю роли (`ЗН-19`) | у очереди нет исполнителя; ждать 5 дней при сроке в 1 день — потерять письмо |
| Порог молчания — время, объявляет источник (`ЗН-20`) | «два прогона» при опросе раз в 5 минут — шум, при ночном — разумно |
| Разрез по владельцу-соседу (`ЗН-21`) | шаги документов в 15 раз увеличат «назначено», не сказав, чья это работа |
| Замещающий видит и действует, задание не переезжает (`ЗН-22`) | отпуск временный, ответственность на закреплённом |
| Свёртка по паре «вид × адресат» (`ЗН-23`) | общий вал на троих кураторов уходит запасному, и формула адресата молча не срабатывает |
| Общий производственный календарь (`ЗН-24`) | «сб/вс» даёт просрочку в праздник |
| Порог свёртки по умолчанию 10 (`ЗН-25`) | ниже вал не экономит, выше очередь нечитаема; без умолчания новый вид входит с пустым порогом |

## 11. Словарь терминов

| Термин | Значение |
|---|---|
| **Повод** | состояние с устойчивым ключом «вид + объект + период», означающее «нужна работа» |
| **Вид повода** | запись реестра, объявляющая всё о своём роде поводов, включая формулу ключа |
| **Действие** | запись реестра: формулировка работы и её реквизиты |
| **Правило** | запись реестра, связывающая вид повода с действиями, режимом, сроками и адресатами |
| **Задание** | пара «повод × действие» |
| **Свободное задание** | задание, заведённое человеком без повода и правила; требует контролёра |
| **Опрос** | форма, которой задания берут поводы у соседа (PULL) |
| **Прогон** | один цикл опроса всех источников на дату |
| **Сверка множества** | сопоставление ожидаемых ключей соседа с живыми поводами |
| **Заморозка** | состояние поводов источника, не ответившего на опрос |
| **Свёртка (вал-задание)** | одно задание вместо множества, когда число новых поводов превысило порог |
| **Рубильник** | дата ввода вида повода в действие; обратим |
| **База срока** | дата, от которой считается срок задания |
| **Ключ шва** | идентификатор повода на границе с соседом |
| **Стопор рекурсии** | запрет поводу порождать сам себя через своё же задание |
| **Контролёр** | тот, кто принимает или возвращает выполненную работу |
| **Эскалация** | уведомление руководителю исполнителя при длительной просрочке |
| **Установленный срок** | последний утверждённый срок задания |
| **Переадресация** | системный перенос непринятого задания к новому ответственному при смене закрепления |
| **Отметка о ходе** | событие журнала о проделанной работе; состояния не меняет и не правится |
| **Реквизит суммы** | реквизит вида повода: какая величина объекта повода считается «суммой по заданию» |
| **Поглощение периодом** | реквизит периодического вида повода: прощается ли пропуск исполнением в следующем периоде |
| **Взять в работу** | явное действие исполнителя «поручено» → «принято»; защищает задание от переадресации, в очереди роли закрепляет исполнителя |
| **Очередь роли** | форма адресата: задание видят все носители роли, пока один не возьмёт его в работу |
| **Исполнение у владельца** | реквизит вида повода: шаг делается у соседа, задание закрывается отпадением повода с атрибуцией, снятия в заданиях нет |
| **Порог молчания** | реквизит источника: через сколько времени молчание соседа становится поводом «сосед не отвечает» |
