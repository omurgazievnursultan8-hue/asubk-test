## Answer

Внесено в `mockups/collection/collection.html` по всем 21 пункту плана выше, с одним
осознанным отходом от буквы карты (map.md) — зафиксирован там же и в коде.

**Справочник и связанные константы.** «Мировое соглашение» (:1501) заменено тремя
видами: «Проект мирового соглашения» (наш документ, `basisKinds:['Исковое заявление']`,
исход «направлен на утверждение»), «Определение об утверждении мирового соглашения»
(внешний акт, `basisKinds:['Проект мирового соглашения']`, исходы утверждено/отказано),
«Констатация нарушения мирового соглашения» (наш документ, `basisKinds:['Определение…']`,
исход «нарушено»). Переименовано по всему файлу «Мировое соглашение» →
«Определение об утверждении мирового соглашения» в: `COURT_ACT_BASIS_KINDS`, basisKinds
«Заявления о выдаче исполнительных листов» и «Исполнительного листа», `AWARD_KINDS`,
`KIND_SECTION` (+2 новых вида), `SUD_CLOSERS`, `COURT_ACT_KINDS`, `DAVNOST_INTERRUPT_KINDS`.
`MEASURE_SUBDIV['Мировое соглашение']` (['ОПК']) переехал на «Проект…», добавлена
запись для «Констатации…» — «Определение…» без записи (внешний акт, тем же профилем,
что «Решение суда»). `PRECONDITIONS` — «Проект…» и «Констатация…» получили `{basis:true}`
(МС-5 и требование живого утверждения соответственно, реализующие через существующий
`basisLiveFor`); «Определение…» без записи (внешний акт, §3.4).

**Пауза «действует МС» — отход от буквы карты.** Карта предполагала добавить `'mirovoe'`
в `PAUSE_KINDS`/`r.states`. При разведке кода обнаружено: `r.states`-пауза несёт
МАНУАЛЬНЫЙ closer (`liftPause()`/toolbar «Снять паузу с требования») поверх ХРАНИМОЙ
записи — для guarantee_letter/restructuring это верно (закрыватель — действие
куратора), но у МС закрыватель — мера («Констатация нарушения…»), а не кнопка; общая
запись создала бы ложную кнопку «Снять паузу» на живом МС и развилку двух разных
closer'ов на одном пути. Решение: `mirovoeApprovalOf(r)`/`mirovoeBreachOf(r,appr)` —
пара НОВЫХ функций рядом с `msComputeRows`, тем же паттерном, что судебный/
исполнительный трек (ADR-0032 п.1 — свёртка журнала мер, без стораджа вовсе).
`measureGate` — отдельная проверка ПОСЛЕ существующей `r.states`-паузы (не внутри),
с явным исключением для `'Констатация нарушения мирового соглашения'` (иначе тупик:
паузу нечем закрыть, если сама закрывающая мера ею же блокируется). `PAUSE_KINDS`
осталась `{guarantee_letter, restructuring}` — НЕ пополнена. `dobrovolnoe` вышло из
блокировки САМО, без единой строки нового кода: единственный источник его
`r.states`-записи (`p.agreements`-цикл в `normalize()`) удалён вместе со всей второй
бухгалтерией.

**Баннер/карточка/статус.** `msBanner(r)` (было `msBanner(a)`), `msStatusPill(status)`
(было `(a)`), `msSchedTable(m)` (читает «Определение…» вместо `a`), `msCards(p,r)` —
переписаны на чтение живых мер: карточка строится по корню «Проект…»
(`mirovoeProjectsOf`), статус вычисляется по цепочке `basedOn` (проект → определение →
констатация). Действий-кнопок в карточке больше нет — регистрация обычной формой.
`headerBanners` — вызов `msBanner(r)` вынесен из цикла по `r.states` (там убрана ветка
`s.agreement`) в отдельное условие по `mirovoeProjectsOf(r).length`. `stateCount` —
второе слагаемое читает `mirovoeProjectsOf(r).length` вместо `r.states.filter(mirovoe)`.
`stateRows`/`STATE_LABEL`/`panelSpecial` (кнопка «Соглашение», section-note) очищены от
mirovoe/dobrovolnoe.

**Форма регистрации.** `openMeasureModal` — новая секция `mMsWrap`/`renderMMs(kind,r)`,
видна при `kind==='Проект мирового соглашения'`: чекбокс истёкших сроков (дефолт
`msExpiredDefault(r)`), число «предполагаемый срок, лет» (живой `msTermGate`-варнинг),
чекбокс+текст «не льготнее», текст «проект подготовил»/«график предоставит».
**Важная находка при тестировании**: секция изначально перестраивалась ЦЕЛИКОМ на
каждый `onchange`/`oninput`, теряя только что введённые значения (тот же класс дыры,
что и «форма теряет ввод») — исправлено разделением на `renderMMs` (полный ре-рендер,
только по смене вида, из `syncMeasureWarnings`) и `refreshMsGate()` (лёгкое обновление
гейта/save.disabled, из onchange полей секции), с общей точкой решения `refreshSaveGate()`.
`saveMeasure` пишет `m.ms={expiredTerms,estimatedYears,notWorse,draftedBy,scheduleBy}`.

**Пометка меры.** `openAnnotationModal`/`saveAnnotation` — новая `scheduleSection`,
видна при `m.kind==='Определение об утверждении мирового соглашения'`: ставка, старт,
шаг, число платежей, итог → `msSeedSchedule`; пишет `m.schedule`/`m.rate` c тем же
reason-на-правку приёмом, что `aAward_*`. Решение вопроса 3 тикета 01 соблюдено:
поле «итого» независимо от «Присуждено» рядом, не читает `aAward_*`.
