# Карта: исковая давность (наряд п.7б, МП5-4)

Вторая из трёх карт наряда п.7 (после [7а — возврат ИЛ](../collection-vozvrat-il/map.md),
закрыта). Третья и последняя — 7в (МП5-11, два счётчика), после этой.

## Destination

**`ADR-0051` §1 (МП5-4, исковая давность).** Давность — не поле, а срок на контроле
(§10), экземпляр `{tpl, due, base}`. База — дата самого раннего неоплаченного просроченного
взноса, зеркалом кредита. Один срок на требование (самый ранний). Перерыв/приостановление
выводятся из журнала мер (`ADR-0032`) — признание долга (гарантийное письмо, соглашение о
добровольном исполнении), частичная оплата (зеркало платежей), утверждение мирового, подача
иска — не второй хранимый признак.

## Notes — реальный обход

- **База — не `overdueStart` сама (даты нет на кредите), а `overdueDays` (счётчик),
  обратимо.** `buildCredit` (:3249-3250) считает `overdueStart = opened - 5` и
  `overdueDays = round((TODAY - overdueStart)/день)` — но на возвращаемый `credit` (:4388,
  `Object.assign({ id, num, overdueDays, ... })`) уходит ТОЛЬКО счётчик, не дата. Читатель —
  `overdueOf(r) = r._credit.overdueDays` (:2715). Раз `overdueDays` определён РОВНО как целое
  число дней от `overdueStart` до `TODAY`, дата восстанавливается точно, без потери:
  `base = ruSub(TODAY, r._credit.overdueDays)`. Первая версия этой карты (черновик до
  проверки чтением) ошибочно предполагала прямой read готового поля-даты — поля с датой НЕТ,
  есть только счётчик; обратное вычисление даёт то же число, но это восстановление, не
  чтение готового значения.
- **Признание долга — ДВА разных источника, не один.** ADR текстом называет «гарантийное
  письмо, соглашение о добровольном исполнении» — но в коде это РАЗНЫЕ структуры: (а)
  «гарантийное письмо» — состояние ПАУЗЫ (`r.states`, `kind:'guarantee_letter'`,
  `PAUSE_KINDS`/`pauseOpenerOf`, :1896+), не мера; (б) «Соглашение о добровольном
  исполнении» — обычный вид меры (`наш документ`, `outcomes:[{value:'заключено'}]`, есть
  `basisKinds:COURT_ACT_BASIS_KINDS`). Давность обязана читать ОБА источника, не только
  журнал мер (`liveMeasuresOf`) — иначе гарантийное письмо (пауза, не мера) прошло бы мимо
  перерыва совсем.
- **Частичная оплата** — зеркало платежей `dbt.payments`/`LEDGER[cr.id].principal.payments`
  (Task 8, :3264+) — датированный массив `{date, amount}`, НЕ у каждого дела (опционален).
  У дел без `payments` перерыва этим путём нет вовсе — не дыра, а корректное «источника нет».
- **Подача иска** — «Исковое заявление» уже есть в `liveMeasuresOf(r)` (мера, наш документ).
  «Утверждение мирового» — «Мировое соглашение» (внешний акт, уже существует).
- **Тот же принцип «последний по факту выигрывает»**, что `phaseSetter`/`scopeSetter`/
  `pauseOpenerOf` (комментарий :1895 прямо так и называет) — простейший и наиболее
  согласованный с файлом обход: `due = MAX(base, самая поздняя дата любого из
  перечисленных 4 источников) + срок давности`. Не различает «перерыв» (обнуляет отсчёт) от
  «приостановление» (сдвигает, не обнуляя) как два разных правила — ADR сам не разводит их
  порознь, перечисляя одним списком через тире.
- **Длительность самой давности** (общий срок исковой давности) — не подтверждена НИГДЕ в
  репозитории (ни ADR, ни requirements/); та же дисциплина «не выдумывать номер», что уже
  применена в наряде п.7а к величинам сроков ИЛ (карта «возврат ИЛ», Q3) — та же карта уже
  ввела для этого случая приём: текстовый маркер «(по умолч., настройка)» в `term`, `origin:
  'закон'`, `point` ссылкой на ADR, а не на несуществующую статью закона.
- **Одна карта закрывает уже 45+2=47 строк каталога** (наряд п.7а добавил 46/47) — эта карта
  добавляет №48 «Исковая давность» тем же приёмом.
- **Домен:** `collection.html` — `buildCredit`/`overdueDays` (:3126-3260, :4388),
  `overdueOf` (:2715), `PAUSE_KINDS`/`pauseOpenerOf` (:1880-1900), `liveMeasuresOf`
  (:1712), `dlOf`/`hearingDeadlines`/`childGapDeadlines` (синтетические проекции очереди
  сроков вне `DEADLINE_DERIVED`, тот же слот годится для `davnostDeadlines(p)`),
  `DEADLINE_TEMPLATES`/`TPL_BY_N` (:2694+, наряд п.7а добавил `origin`). Спека:
  `ASUBK-vzyskanie-logika.md` §10.1 (МП5-4 :2168); `ADR-0051` §1, ссылается на `ADR-0001`,
  `ADR-0032`; `ADR-0060` (платежи) называет ту же базу побочно («самый ранний неоплаченный
  просроченный взнос») — общий концепт, отдельный модуль, не потребитель этой карты.

## Decisions so far

[Точки интеграции (01)](issues/01-tochki-integracii.md) — закрыт, все три вопроса решены.
(1) все 5 структур считаются; мера-основанные — `liveMeasuresOf(r)` per-target (ADR-0029),
пауза `guarantee_letter` — тоже per-target (свой фильтр, не `pauseOpenerOf` целиком —
`restructuring` не источник давности), `dbt.payments` — кредит целиком (нет targets,
единственное честное чтение). (2) длительность — текст-маркер, `origin:'закон'`,
`point:'ADR-0051 §1'`, числом ДНЕЙ (не лет — `termToCalendarDays` лет не разбирает,
а давность обязана парситься, раз проецируется в очередь). (3) видимость — обычная
строка «Сроки на контроле», `dlOriginPill` без изменений. Технический вывод из этих
трёх ответов: срок НЕ входит в `DEADLINE_DERIVED` (та материализуется один раз при
сборке, а перерыв давности должен пересчитываться на каждый рендер) — синтетическая
проекция `davnostDeadlines(p)`, тем же слотом, что `hearingDeadlines`/`childGapDeadlines`.
Каталожная строка №48 — только для отображения, в `DEADLINE_DERIVED`/`DEADLINE_CLOSERS`
не входит (статус строк 25/40/46).
