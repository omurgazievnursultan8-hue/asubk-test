# Карта: гейт предусловий вместо контурной лестницы (наряд п.5б-i, МП-6 — машина)

Наряд п.5б (МП-6) разбит пользователем на две карты подряд (тикет 01, вопрос 1):
**5б-i — машина гейта** (эта карта: `sequenceReason` → новая запись предусловий,
`phaseTimeline`, `gateBlocked`, `measureKindOptions`) первой, **5б-ii — экран
#settings** (снять вкладку «Стадии», переделать «Предусловия») отдельной картой
следом, в новой директории (`.scratch/collection-gejt-nastroyki/`, не создана) —
тем же приёмом, что наряд п.5 → 5а/5б. Экран настроен на форму записи, которую
решит эта карта, поэтому идёт вторым.

## Destination

Гейт регистрации меры в `mockups/collection/collection.html` сегодня —
`sequenceReason` (:2346-2369) — лестница по контурам (`CONTOURS` :1089,
`CONTOUR_LEVEL` :2250, `RULES.sectionClevel`/`SECTION_CLEVEL` :2258,
`RULES.contourPhases` через `phasesOf` :2278). Спека (`ASUBK-vzyskanie-logika.md`
§3.4, `ADR-0045`) требует другого механизма: **у каждого вида меры своя запись
предусловий** — требуемая фаза · требуемые факты · запрещающие обстоятельства,
проверяется **по каждой цели меры отдельно** (`ADR-0029`), не по требованию
целиком. Лестница снимается, не чинится (`ADR-0045`, «Почему лестница не
чинится»): она гейтит требование целиком (нарушает `ADR-0029`) и структурно не
умеет половины требуемого — вручение предыдущей меры, вступление решения в
силу, решение органа по договору, право безакцепта не выражаются позицией в
цепочке.

- `CONTOURS`, `CONTOUR_LEVEL`, `RULES.sectionClevel`/`SECTION_CLEVEL`,
  `RULES.contourPhases` снимаются (`ADR-0045`, «Решено»).
- `GATES`/`gateReason` (:2144-2239) **остаются своей веткой** — ADR прямо
  запрещает сливать: у гейта комитета своя сверка (предмет вопроса И договор,
  §11) и своя причина отказа на реестр вопросов. Новая общая запись
  предусловий **читает** его результат как один из требуемых фактов
  («требуемый факт: гейт «Подача искового заявления» открыт»), не подменяет.
- Новая запись живёт в `RULES` (живой слой, редактируется на #settings) —
  граница живого слоя не двигается (`ADR-0033` через `ADR-0045`): предусловия
  отвечают на вопрос «что можно зарегистрировать», это живой слой и был им;
  меняется форма записи (не порядок фаз контура — запись на вид меры).
- Требуемая фаза для видов, что сегодня стоят НА маршруте (К0/К1/К3/К4,
  `ROUTE_ORDER` :2326, наряд п.5а) — **механически выводится** из позиции в
  `ROUTE_ORDER`: предыдущая фаза перед `kindPhase(kind)` (:1665). Это тот же
  ключ, что сегодня читает `sequenceReason` часть (2), просто пересобранный
  без обращения к `CONTOURS` — контрольная точка регрессии (см. Notes).
- Требуемая фаза/факты для видов ВНЕ маршрута (К2/К5/К6/К7-виды, входящие
  акты, немилстоунные наши документы вроде жалоб/ходатайств, что сегодня
  гейтятся ТОЛЬКО частью (1) `sequenceReason` — лестницей раздела, не
  позицией вехи) — нет механического источника, нужна явная запись на
  каждый такой вид, восстановленная из СЕГОДНЯШНЕГО эффективного поведения
  (эта карта — смена МЕХАНИЗМА, не пересмотр политики гейта, кроме уже
  решённого спекой: `SECTION_CLEVEL['Безнадёжная']` уже 4, не 5, `ДС-М3`
  зафиксирован до этой карты и не переоткрывается).
- Мерам-**входящим документам** (`source:'внешний акт'`) предусловия не
  применяются вовсе (§3.4, уже так и есть — `measureGate` :7953, `kd.source
  === 'внешний акт' → return null` — эта строка ДО `sequenceReason`,
  входящие акты уже не гейтятся им сегодня; но `measureKindOptions` :1652
  зовёт `sequenceReason` напрямую, без этой проверки — см. Notes,
  расхождение к разбору).
- Видимые следствия смены механизма (не только внутренняя перепроводка):
  `phaseTimeline()` (:7165-7181) — лестница-виджет на карточке требования,
  сегодня рисует **контур текущей фазы** пошагово; при снятии `CONTOURS`
  естественная замена — единый маршрут (`ROUTE_ORDER`), а не контурный
  сегмент. `gateBlocked()` (:5927-5944) — две ветки читают `contourOf(r)===
  'К1'` как проверку принадлежности фазы множеству К1 — заменяются на прямую
  проверку по литералу. Экран #settings (вкладка «Стадии» долой, «Предусловия»
  — редактор новой записи) — карта 5б-ii, отдельно, см. заголовок и Out of
  scope.

## Decisions so far

- [Точки интеграции (01)](issues/01-tochki-integracii.md) — все шесть пунктов
  решены:
  1. Карта дробится на 5б-i (машина, эта карта) и 5б-ii (экран #settings,
     отдельная будущая карта), тем же приёмом, что наряд п.5 → 5а/5б.
  2. МП5-13 (гейт комитета читает последний решённый вопрос, не `mine[0]`) —
     входит в эту карту, не выносится отдельным пунктом.
  3. Форма записи — в этой карте мигрирует ТОЛЬКО `requiredPhase`
     (замена части (2) `sequenceReason`). Четыре хардкоженных запрета
     `measureGate` (closed/conflict/window/pause) остаются как есть, в том же
     порядке вызова. `GATES`/`gateReason` не трогаются (уже отдельная ветка
     по ADR), но новая запись читает их результат как требуемый факт —
     ровно формулировка ADR-0045.
  4. ~20 немилстоунных видов (жалобы/ходатайства/определения,
     `resultIsDocument` или неоднозначный `setsPhase`) — сегодня гейтятся
     ТОЛЬКО числовым порогом `SECTION_CLEVEL` (часть (1)). Требуемое для них
     в новой записи — **требуемый факт: жива мера-основание из `basisKinds`**
     (обход `basedOn`, уже частично есть — `basedOnValid` :6523), не
     перекодированный числовой порог. Точнее духу ADR-0045 (глоссарий прямо
     называет «вручение предыдущей меры» примером того, чего лестница не
     умеет), но требует проверки на затравке — `basedOn` сегодня необязателен
     (форма даёт «— нет —»), возможны живые записи без него.
  5. `phaseTimeline()` — редизайн на единый `ROUTE_ORDER` одной лестницей
     (7 шагов К0+К1+К3+К4). К2/К5/К6/К7 — вне маршрута, показываются иначе
     (строкой/чипом, не в лестнице) — деталь реализации.
  6. `measureKindOptions()` переводится на `measureGate` целиком (вместо
     прямого вызова `sequenceReason`) — иначе входящие акты после этой карты
     выпадут из дропдауна формы регистрации несогласованно с самим гейтом
     (найдено по ходу тикета 01, не было в исходном destination).

  Пункты 3-4 логически стыкуются: у видов БЕЗ `basisKinds` и без места на
  маршруте (К2/К5/К6/К7-виды первой вехи контура — «Извещение об обращении на
  залог», «Заявление об установлении правопреемника», «Инициирование
  банкротства», «Заключение комиссии о безнадёжности» и т.п.) готового ответа
  ни пункт 3, ни пункт 4 не даёт — они гейтятся СЕГОДНЯ только числовым
  порогом раздела и не имеют basisKinds. Разбор этого остатка — работа
  реализации (02), не отдельный вопрос грилинга: перечень короткий (проверяется
  построчно по `MEASURE_KINDS`), решение — механический перенос порога
  `SECTION_CLEVEL` в `phaseRank`-эквивалент (та же функция, что уже ввела
  5а), не новая политика.

## Out of scope

- **Экран #settings целиком** (снять «Стадии», переделать «Предусловия»,
  радиус-счётчики `openAtLevel`/`reqsInContour`/`reqsInPhase`/`movePhase`) —
  карта 5б-ii, следом за этой (тикет 01, вопрос 1). До неё экран останется
  читать снятые константы — эта карта обязана либо оставить `CONTOURS`/
  `CONTOUR_LEVEL`/`RULES.sectionClevel`/`RULES.contourPhases` НЕ удалёнными
  физически (только не читаемыми новым гейтом), либо дать экрану временную
  затычку, чтобы не падать между картами — решается тикетом 02 этой карты,
  не здесь.

- **Пересев затравки / хребет `SPINE` билдера** — ADR-0045 прямо называет
  это отдельной последующей работой («хребет SPINE… переписывается на
  маршрут и предусловия», «Последствия»); наряд §30 «Порядок волны» ставит
  пересев ПОСЛЕ этой карты, в п.6/п.7. Каталог 40 ситуаций переживает
  пересев без изменений (ADR: «выведен из осей модели, а не из контуров»).
- **Предусловия сроков закона** (`ADR-0051`, окно/предельный срок повторного
  предъявления ИЛ) — наряд п.7, блокер данных (график по взносам зеркало
  кредита не отдаёт), не вопрос этой карты.
- **МП5-13** (гейт комитета читает последний решённый вопрос, повторное
  вынесение) — реальная неопределённость: ADR-0045 содержит его правку тем
  же абзацем, что и основное решение МП-6, но наряд §30 не называет его ни в
  одном из семи пунктов. Решается тикетом 01, не молчаливым включением или
  исключением.
- **Мировое соглашение как три вида журнала** (МП-10/11, `ADR-0047`) —
  отдельная карта наряда §29 (не этой волны, не §30); упомянутые там
  предусловия («подан иск», «график отраслевого отдела», «не льготнее
  подтверждено», «срок ≤5 лет») — примеры формы записи из ADR-0047, не
  работа, которую эта карта обязана произвести (виды `MEASURE_KINDS` для
  МС ещё не заведены).
- **`bezakceptRight`** как запрещающее/требуемое обстоятельство для
  «Безакцептное списание» — сегодня это ТОЛЬКО фильтр отображения
  (`phaseTimeline`, карточка кредита), не гейт `measureGate`/`sequenceReason`
  (проверено — нигде не читается как условие регистрации). Возможный пробел,
  но не заявлен ни спекой §3.4, ни наблюдением этой карты как её задача —
  фиксируется как находка, не чинится молча в карте про смену механизма.
