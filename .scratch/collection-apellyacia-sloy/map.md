# Карта: апелляция ревизует слой решения суда (МП-2)

## Destination

Домен: `mockups/collection/collection.html`. Спека: `ASUBK-vzyskanie-logika.md` §8.5.
Решение уже принято разбором МП (`docs/superpowers/specs/2026-08-02-collection-model-gaps-design.md`
МП-2) — эта карта не решение обсуждает заново, а доводит его до кода. Явно оставлено вне
двух предыдущих карт слоя: `collection-sloy-klyuch/map.md` («Апелляция как акт, ревизующий
слой — МП-2, наряд не цитирует, отдельная будущая карта») и `collection-sloy-vyruchka/map.md`
(то же самое, повторно подтверждено).

**Принятое (МП-2, design-doc):** слой остаётся за первой инстанцией. Исход «Постановление
апелляционной инстанции» → `изменено` правит присуждённую сумму **существующего** слоя,
режим начисления остаётся по дате **первого** решения. Оба исхода `отменено` (на новое
рассмотрение / в иске отказано) слой гасят. Отвергнуто design-doc'ом: апелляционный акт
заводит свой слой (сломает `basisKinds` ИЛ — апелляции там нет); `изменено` = гашение
старого плюс новый слой (размножает слои на одном притязании, расходится с глоссарием).

Справочник уже несёт вид **«Постановление апелляционной инстанции»** (`:1451`, внешний акт,
4 исхода: `оставлено в силе` / `изменено` / `отменено, на новое рассмотрение` / `отменено,
в иске отказано`) и помощник **`isAppealReversal`** (`:1811`, `outcome` начинается с
«отменено») — уже используется `phaseSetter` для отката фазы на «Иск». Слоя эти два места
не касаются вовсе — задача карты ровно там, где `isAppealReversal` уже проведена граница,
но для денег, не для фазы.

## Notes

- Тесты: throwaway jsdom-смоук на синтетике (как у всех карт волны); трёхскриптовый прогон
  (`collection-check.mjs`/`collection-data-audit.mjs`/`collection-seed-coverage.mjs`) —
  гоняется, баз для сравнения — последний известный **660/32** (наряд «выручка/очередь»).
- Точки интеграции решены без интерактивного `/grilling` (карта работает соло, без
  доступного второго собеседника уровня ГФХ/архитектора на эту сессию) — тем же приёмом,
  что решения design-doc уже фиксировались без грилинга (документная волна МП была
  прогнана заранее). Решения ниже пишутся с явным «Предложение» + обоснование по каждому
  пункту, как обычно фиксирует грилинг, но без второго голоса — риск отмечен, а не скрыт.
- SEED — новых ситуаций апелляции-изменения не заводит (резерв до пересева, как у всех карт
  волны); существующая ситуация `K3-АПЕЛЛЯЦИЯ` (дела 340/341) использует только исходы
  `оставлено в силе` / `отменено, в иске отказано` — ни один award не установлен, регрессия
  проверяется на этих двух живых делах естественно (было null, должно остаться null/тем же).

## Decisions so far

- [Точки интеграции (01)](issues/01-tochki-integracii.md) — третий тип отношения
  `corrects:NNN` (не `new`/`absorbs`/`adds`) · форма «Присуждено» показывается для
  апелляции всегда (гейт по виду, не по исходу — тот же приём, что `AWARD_KINDS`) · для
  апелляции meню отношения предлагает ТОЛЬКО `corrects` на живые `AWARD_KINDS`-акты той же
  цели, `new` недоступен · `layerOf`/`claimChainsFor` включают апелляцию в свёртку по двум
  условиям (исход `изменено` + `m.awards` → правка; `isAppealReversal` + `m.targets` →
  смерть) · при выигрыше правящей записи **`act` в ответе `layerOf` — БАЗОВОЕ решение**
  (через `relation.of`), не сама апелляция — иначе ИЛ снова видит акт вне своих `basisKinds`
  (ровно довод №1 design-doc) · `effectiveAward` получает branch `corrects` (замена
  построчно, не сложение, как `adds`) · `ADR-0036` — «след ведёт на меру-основание, а не на
  человека»: правка сохраняется НА АПЕЛЛЯЦИИ, тело базового решения не трогается вовсе.
- [Реализация (02)](issues/02-realizaciya.md) — код в `collection.html`: `effectiveAward`
  branch `corrects`, `layerOf` расширен (правка+смерть, `act`/`correctedBy`), `layerTitle`,
  форма «Присуждено»/`relField` для апелляции, `saveAnnotation` guard, `claimChainsFor`
  fold, `ADR-0036` третий случай, спека §8.5 баннер. Регрессия: 660/32 (baseline
  побитово), 0 находок аудита, throwaway-смоук 19/19. **Destination карты достигнут —
  карта закрыта.**
