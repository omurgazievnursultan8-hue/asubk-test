## Question

Код в `collection.html` по девяти пунктам тикета 01.

## Answer

- **`effectiveAward`** (`:1855`) — четвёртая ветка `relation.type==='corrects'`: построчная
  замена вместо сложения (`adds`), «пусто ≠ ноль» на обоих уровнях сохранена.
- **`layerOf`** (`:1878`) — свёртка `acts` расширена двумя условиями: `m.kind ===
  APPEAL_REVERSAL_KIND && m.outcome==='изменено' && m.awards[rep.id]` (правка) и
  `isAppealReversal(m) && m.targets.includes(rep.id)` (смерть, тот же приём, что отмена
  приказа). При выигрыше правящей записи `act` в ответе разрешается на
  `lastAward.relation.of` (базовый акт), не на саму апелляцию — новое поле `correctedBy`
  несёт меру-апелляцию для UI. Апелляция НЕ добавлена в `AWARD_KINDS`.
- **`layerTitle`** (`:7585`) — третья ветка тернарника: `· изменено определением апелляции
  №Z от W`, когда `layer.correctedBy` задан.
- **`openAnnotationModal`** (форма «Присуждено», `:9102-9134`) — `awardTargets` гейтится и
  по `AWARD_KINDS`, и по `m.kind===APPEAL_REVERSAL_KIND` (флаг `isAppealAward`). Для
  апелляции `relField` — отдельная ветка: меню строится ТОЛЬКО из `corrects:NNN` по
  кандидатам `priorActs` (тот же список, что уже строился для absorbs/adds — без изменений
  фильтра), опции `new`/`absorbs`/`adds` не рендерятся; нет кандидатов → предупреждение
  вместо select.
- **`saveAnnotation`** (`:9228`) — условие записи расширено на `isAppealAward`; guard
  `if(isAppealAward && !relSel) continue` — без рендеренного select (нет кандидата) правка
  цели игнорируется целиком, `relation:{type:'new'}` апелляции никогда не подставляется.
- **`claimChainsFor`** (`:7629`) — fold параллельно `layerOf`: правящая и гасящая апелляция
  входят в цепочку тем же условием. Найдено при кодировании: у ЭТОЙ функции (в отличие от
  `layerOf`) не было условия для `AWARD_DEATH_KINDS` (отмена приказа) вовсе — существующий,
  вне карты МП-2, пробел; не чинится здесь (см. `map.md` Out of scope ниже).
- **`ADR-0036`** — добавлен третий случай правки пометки: след апелляции живёт на её
  собственной записи, тело базового акта не трогается.
- **Спека** `ASUBK-vzyskanie-logika.md` §8.5 — баннер ⚠️ «ничего не реализовано» заменён на
  ✅ со сводкой сделанного (МП-1/2/4/5-1/5-2/5-10/5-18) и явной пометкой, что канал
  «платежи → взыскание» остаётся вне взыскания.
