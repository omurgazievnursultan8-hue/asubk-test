# Карта: фаза как максимум по маршруту (наряд п.5а, МП5-12)

## Destination

Фаза требования в `mockups/collection/collection.html` (`phaseOf`, `phaseSetter`,
:1719-1728) сегодня — **последняя по дате события** живая веха (`ADR-0037`
исходный). Спека (`ASUBK-vzyskanie-logika.md` §3.1-§3.2) уточняет: фаза —
**максимальная по маршруту** среди живых вех, не последняя по времени
(`ADR-0037`, уточнение). Разница проявляется, когда несколько живых вех стоят
не в порядке маршрута — на одном кредите несколько исковых производств подряд
(§8.5, `ADR-0046`): новый иск на новую просрочку, поданный при живом
исполнительном производстве по прежнему решению, откатывал бы стадию из
исполнительного назад в судебное, если считать «последней по времени» —
именно ради этого `ADR-0037` меняет формулу.

- `phaseOf(r)` — вместо `phaseSetter` (последняя по дате запись из
  `liveMilestones`) читает **максимум по позиции в маршруте** среди тех же
  живых вех. Нужен явный порядок маршрута (сегодня `ROUTE_PHASES`, :2254, —
  `Set`, порядок только через порядок вставки; для «максимума» нужна ЯВНО
  упорядоченная структура — позиция, не только принадлежность).
- Новое притязание **не понижает** фазу — регистрируется, если гейт это
  разрешает (гейт не входит в эту карту, п.5б/МП-6, ниже), но максимум,
  однажды достигнутый, назад не откатывается, пока жива веха, которая его
  держит. Факт показывается **чипом «новый иск»** рядом с фазой — тем же
  приёмом, каким уже показан чип «списана, взыскание идёт» (`trackBadges`,
  :1888, наряд п.4) — новый член того же семейства, те же два места
  (:6204/6209 строка списка, :6697 плитка «Фаза» карточки).
- Отступление назад **сохраняется** там, где оно верно (§3.2, буквально): иск,
  оставленный без рассмотрения, вехой быть перестаёт (`measureSetsPhase`
  возвращает `null` на этом исходе), максимум считается заново уже без него —
  это уже так работает сегодня (свёртка каждый раз пересчитывается с нуля,
  ничего сверх не требуется), карта это не трогает, только фиксирует, что
  свойство сохраняется и после смены формулы.

## Decisions so far

- [Точки интеграции (01)](issues/01-tochki-integracii.md) — чип «новый иск»
  землится как есть (недостижим через UI до карты 5б, доказывается
  synthetic-смоуком) · новый `ROUTE_ORDER` (массив), `ROUTE_PHASES = new
  Set(ROUTE_ORDER)` — один источник правды · «Безакцептное списание» участвует
  в сравнении позиций на общих основаниях · `ROUTE_ORDER` остаётся собран
  через `phasesOf(c)`/`CONTOURS` — перевод на новый источник при демонтаже
  контуров это работа карты 5б, не этой.
- [Реализация (02)](issues/02-realizaciya.md) — регрессионный смоук на
  реальной затравке нашёл, что голый скалярный максимум ломает req 341
  (апелляционный откат) и req 356/357 (межконтурное сравнение К5 вс К3).
  Формула уточнена задним числом отдельным грилингом (вне пяти пунктов
  тикета 01): вне-маршрутные фазы (К2/К5/К6/К7) исключены из сравнения
  рангов вовсе — последняя по времени веха вне маршрута побеждает как
  раньше; апелляционный откат — явное исключение по виду+исходу
  (`isAppealReversal`), без трассировки цепочки `basedOn` (предложена,
  отклонена — новая машина не по этому наряду). Максимум по рангу теперь
  реально отличается от «последней по времени» ровно там, где иллюстрирует
  §3.2 — внутри К3/К4, без ложных срабатываний на остальной затравке. Чип
  «новый иск» тоже уточнён — счётный предикат (≥2 живых вех «Иск»
  одновременно), не «любая веха Иск позади максимума» (спамило бы на
  каждом продвинутом требовании).

## Out of scope

- **Демонтаж контуров и гейта по позиции** (`CONTOURS`, `CONTOUR_LEVEL`,
  `SECTION_CLEVEL`, `sequenceReason`, `RULES.contourPhases`/`sectionClevel`,
  экран #settings) — наряд п.5б, МП-6, отдельная будущая карта
  (`.scratch/collection-gejt-predusloviy/`, ещё не создана).
- **МП-О6** (закрытое требование показывает стадию «Наблюдение» по умолчанию)
  — спека явно относит починку к МП-6 (§3.3 ⚠️-врезка: «§29, решение МП-6 и
  пункт МП-О6»), не к МП5-12. Эта карта стадию терминальных требований не
  трогает.
- **Чип «обжаловано»** — упомянут в §3.3 как приём того же типа, но это другой
  факт (жалоба без акта) и другой МП-номер, не входящий в наряд пятой волны
  (§30). Здесь не заводится.
- **Инстанция как реквизит меры-акта** (§3.3: первая/апелляционная/
  кассационная/надзорная не двигают маршрут, двигает акт) — частично неверно
  написано изначально: **правка при реализации** — `setsPhase` действительно
  стоит только на актах вышестоящей инстанции, не на жалобах (это не
  трогалось), НО апелляционный откат («отменено, на новое рассмотрение»)
  оказался единственным реальным исключением из формулы максимума (req 341,
  issues/02) — карта была вынуждена завести явный `isAppealReversal`, а не
  просто «не трогать по отсутствию расхождения», как здесь изначально
  заявлено.
- **Трассировка цепочки `basedOn`** для различения «откат той же ветки меры»
  от «новая независимая претензия» в общем случае (не только у именованного
  вида «Постановление апелляционной инстанции») — предложена при разборе
  req 341 как более точная к духу §3.2/§3.3 альтернатива, отклонена: новая
  машина обхода цепочки, нарядом п.5а отдельно не предусмотрена. Если в
  будущем найдётся ЕЩЁ один вид меры с тем же «откатывает задним числом»
  поведением, что и апелляция — потребуется либо расширять список явных
  исключений в `isAppealReversal`-подобной проверке, либо всё-таки строить
  трассировку — решать в момент, когда такой вид найдётся, не заранее.
