## Answer

Реализовано по плану, без отклонений и без найденных регрессией дефектов.

**Словарь.** `OSNOVANIE_KINDS` — плоский массив пяти строк дословно по `ADR-0050`, рядом с
`PRECONDITIONS`, до `RULES_DEFAULTS`. `OSNOVANIE_ATTRACT_OBLIGOR = OSNOVANIE_KINDS[4]` —
именованная константа пятого значения.

**Переименование.** `o.basis` (свободный текст ссылки на договор, три декларации 307/308/309)
→ `o.contractRef`. `mkReq` получил параметр `contractRef` (независим от `basis`) и
именованный throw на `basis` вне `OSNOVANIE_KINDS` (приём `HANDOVER_STATES`).

**Buildseed/normalize.** `derived.basis` → `derived.openBasis` (сырой вход заёмщик-роли,
`c.basis || OSNOVANIE_KINDS[0]`); `normalize`'s `p.basis ??= '—'` → `p.openBasis ??=
OSNOVANIE_KINDS[0]`. Обеспечительная роль теперь ВСЕГДА получает
`OSNOVANIE_ATTRACT_OBLIGOR` как `basis` (не читает `o.basis`/`o.contractRef` для этого —
роль отвечает по своему договору, не по просрочке заёмщика, `ADR-0050`), а `o.contractRef`
идёт отдельным реквизитом `r.contractRef`. `function basisOf(p)` — свёртка
`p.requirements[0].basis`, заменила хранимое поле `p.basis`.

**Показ.** Карточка дела: `ro('Основание открытия', p.basis)` → `basisOf(p)`. Карточка
требования: `ro('Основание требования', ...)` дополняется `contractRef` в скобках, когда он
есть (обеспечительная роль).
