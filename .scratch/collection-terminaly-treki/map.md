# Карта: терминалы 5/6/7 и универсальная проверка треков (наряд п.4, МП5-7/МП5-9/МП5-16)

## Destination

Три новых терминала требования из `ASUBK-vzyskanie-logika.md` §30 (МП5-7 :2171,
МП5-9 :2173) заведены в `TERMINAL_BY_MEASURE` `mockups/collection/collection.html`
(:1165), а проверка треков (МП5-16 :2180) становится общей для всех семи, а не
только для «Полное погашение»:

- `TERMINAL_BY_MEASURE` читает пару **вид × исход** (`ADR-0038`), не только вид —
  этим же движением закрывается `МП-О3` (круг1, наряд §29 её не довёл до кода).
  Три новые строки: «Реструктурирована» ← веха-акт утверждения реструктуризации
  (мираж, ниже) · «Обеспечение прекращено» ← веха прекращения обеспечительного
  договора (мираж) · «Правопреемство» ← «Определение о замене стороны
  правопреемником» (**правка при реализации**: вида не было в `MEASURE_KINDS`
  вовсе, вопреки исходному предположению этой карты — заведён минимально, как
  закрыватель одиночной линии; реквизит «число преемников» и само разветвление
  требования вне этой карты, наряд п.6).
- Два новых миража, снимок чужого модуля с датой, тем же приёмом, что
  `p.colls[].snapshotAt` (:1842) — `RESTRUCTURING_APPROVALS[creditId] = {date}` и
  `SECURITY_TERMINATIONS[creditId] = {date, basis}`.
- `outcomeOf` (:1172) требует закрытых треков у **любого** терминала, не только у
  нулевого остатка (`МП-О4`, круг1, тоже не доведена до кода — закрывается этим
  же движением). Судебный/исполнительный трек — уже существующие `sudTrackOf`/
  `ispTrackOf` (:1821-1822), переиспользуются как есть. Залоговый трек — сегодня
  есть только зеркало (`p.colls[].stage`, `collSnapshotStale`, :1850-1855), но нет
  функции «трек закрыт»: она заводится здесь.
- Терминал 6 «Обеспечение прекращено» **недоступен после вступившего в силу
  решения** (обязанность уже подтверждена актом — прекращение договора её не
  снимает) — прокси для «вступило в силу» ищется среди точек интеграции (тикет 01).
- Требование без закрытых треков при учётном терминале (безнадёжная/списана/…)
  остаётся открытым с чипом «списана, взыскание идёт».

## Decisions so far

- [Точки интеграции (01)](issues/01-tochki-integracii.md) — прокси «вступило в
  силу» для терминала 6 = `layerOf(proc, creditId) !== null` · миражи
  `RESTRUCTURING_APPROVALS`/`SECURITY_TERMINATIONS` ключуются по кредиту ·
  «залоговый трек закрыт» = `collsOf(r).every(c => c.realStage ===
  'реализовано')`, устаревший снимок у любого предмета блокирует · чип
  «списана, взыскание идёт» — третий член семейства `trackBadges`, те же два
  места, без хранимого флага · `TERMINAL_RANK` новых терминалов — 5 Реструктурирована
  · 6 Обеспечение прекращено · 7 Правопреемство · гейт треков (МП5-16) — общий
  для всех семи терминалов, включая «Полное погашение» (не только учётных),
  чип с ЛЮБЫМ кандидатом текстом `${candidate}, взыскание идёт`.
- [Реализация (02)](issues/02-realizaciya.md) — всё внесено в `collection.html`
  построчно по тикету 01, плюс восполнен найденный пробел (вид «Определение о
  замене стороны правопреемником» заведён с нуля). `TERMINAL_BY_MEASURE`
  оставлен без изменений для единственного оставшегося читателя (:3973, вне
  наряда). Проверено throwaway jsdom-смоуком через `dom.window.eval`
  (top-level `const` classic-скрипта не становится свойством `window`) — 0
  console/pageerror, все точечные сценарии зелёные.

**Destination карты достигнут.** Три новых терминала подключены (мера/мираж/
мираж), проверка треков универсальна для всех семи терминалов (включая ранее
не проверявшееся «Полное погашение», `МП-О4`), `TERMINAL_BY_MEASURE` заменён
на пару вид×исход там, где это имеет значение (`МП-О3`). Карта закрыта.

## Out of scope

- **Карантин закрытия дела для терминала 5.** `ADR-0053` прямо говорит «карантин
  у реструктуризации есть» — но карантин как механизм (`RULES.quarantineDays`,
  `ADR-0044`, круг1 наряд §29 Task 6) **в коде не существует вовсе**: дело
  закрывается мгновенно, как только закрыты все его требования (`isTerminal`,
  :1185, читает `outcomeOfProc` без какой-либо задержки). Эта карта заводит
  терминал 5 на общих основаниях (дело закрывается сразу, как и от любого другого
  терминала сегодня) — различение «карантин только там, где новая просрочка
  возможна» ждёт отдельной будущей карты, когда карантин как механизм появится.
- **Разветвление требования и реквизит «число преемников»** (МП5-6, МП5-15,
  наряд п.6) — терминал 7 здесь только подключается как закрыватель одиночной
  линии; ветвление — предмет отдельной будущей карты.
- **Слой/деньги** (МП5-1/2/10/18, наряд п.2/п.3, уже закрыты) — эта карта их не
  трогает; учётные терминалы закрывают требование независимо от того, взыскано
  что-то по слою или нет (это уже правило §9 «учётные vs взыскание идёт», не
  новое здесь).
