## Answer

Внесено в `mockups/collection/collection.html`, по всем шести пунктам тикета
«Точки интеграции» (01), включая правку п.4 задним числом (нашёл при кодировании
прецедент `liveMilestones` — «последняя» мерится датой события, не датой пометки).

**Новые сателлиты** (после `MEASURE_KIND_NAMES`, :1551):
- `AWARD_KINDS` — `Set(['Решение суда','Судебный приказ','Мировое соглашение'])`,
  список ИМЁН, не скан `setsPhase` (апелляция отсеивается явно).

**Новая функция** `layerOf(proc, creditId)` (после `phaseSource`, :1673-1689):
представитель — `rep[r.credit]`-паттерн `tileMoney`, но по `proc.requirements`
(глобальный представитель кредита, как у `solidaryWith`); «последняя» живая мера
из `AWARD_KINDS` с `awards[rep.id]` — тем же способом, что `liveMilestones`
(дата события/регистрации, индекс как тай-брейк); представитель не в целях меры →
эта мера слоя не даёт (вопрос 1). Возвращает `{sum, relation, act, rep}` или
`null`.

**`openAnnotationModal`/`saveAnnotation`** (:7973+): секция «Присуждено» —
показывается когда `AWARD_KINDS.has(m.kind)` и у меры есть цели; по строке на
цель — сумма (`aAward_<reqId>`, `msNum`-парсинг, пусто ≠ ноль) и, только когда у
этой цели уже есть более ранняя живая мера с `awards` (вопрос 3), select
«отношение к прежнему слою» (`aRelation_<reqId>`, опции — живые меры дела с
`awards` по той же цели, кроме текущей, подпись `${kind} №${num} от ${date}`,
вопрос 2). `saveAnnotation` пишет `m.awards[reqId] = {sum, relation, by, at,
reason?}` — под тем же правилом «причина правки при перезаписи», что и `outcome`
(вопрос 6, факт, не новый код).

**`panelDebt`** (:6754-6767): плитка «Слой: X» рядом с «сумма требования», через
`layerOf(p, req.credit)` — пусто, если `null`. Тултип — вид/номер акта, дата,
поглощение (если есть).

Проверено throwaway jsdom-смоуком (`_smoke-sloy.mjs`, удалён после проверки):
- `AWARD_KINDS` — все три вида внутри, апелляция снаружи;
- `layerOf` на синтетике: две меры разной датой → берёт позднюю (30000, не 50000
  первой); representative не в targets → `null`; без мер → `null`; сторно-мера →
  `null`; вид вне `AWARD_KINDS` с теми же `awards` → `null` (апелляция не рождает
  слой, даже если бы у неё случайно оказались данные);
- `panelDebt()` на реальном SEED рендерится без исключений; с подставленным
  `awards` в реальную меру реального требования — плитка «слой» с верной суммой
  появляется в HTML;
- полный цикл `openAnnotationModal` → выставить исход → вписать сумму (с
  пробелом-разделителем «15 000») → `saveAnnotation` → `m.awards` записан верно
  (`msNum` разбирает разделитель как и остальной код);
- ни одной console/pageerror на всех шагах.

SEED/затравка слоя не заводилась — вне карты. Полный прогон
`collection-check.mjs`/`collection-data-audit.mjs`/`collection-seed-coverage.mjs`
не запускался (резерв на конец пятой волны).

Destination карты достигнут: слой рождается, ключуется по кредиту, сумма — по
представителю, отображается. Карта закрыта.
