# Карта: ключ слоя по кредиту и представитель (наряд п.2, МП5-1/МП5-2)

## Destination

Слой долга (§8.5, МП-1 / МП-4→МП5-1 / МП5-2 / МП-7 / МП-8) заведён в
`mockups/collection/collection.html`:

- Рождение — исход меры с `setsPhase:'Решение суда'` и реальным присуждением:
  «Решение суда» (удовлетворён полностью/частично), «Судебный приказ» (вынесен),
  «Мировое соглашение» (утверждено судом). Апелляция («Постановление апелляционной
  инстанции») — вне, МП-2, отдельная будущая карта.
- Ключ — пара мера-решение × **кредит** (не требование, ADR-0049 поверх ADR-0043).
- Механизм — новая секция «Присуждено» в `openAnnotationModal`/`saveAnnotation`
  (:7973-8072), по строке на цель меры (`m.targets`): сумма + отношение к прежнему
  слою (`новый слой` / `поглощает слой меры №X`, МП-8). Хранится
  `m.awards[reqId] = {sum, relation}` — форма прецедента `m.stornoTargets`.
- Сумма слоя — по представителю (МП5-2): `rep[r.credit]`-паттерн из `tileMoney`
  (:5900-5904, предпочитает роль «заёмщик»). Остальные солидарные строки — потолок
  обязательства, не сумма слоя.
- Отображение — плитка «Слой: X (акт от Y)» рядом с «сумма требования» в
  `panelDebt` (:6733), одинаково на всех солидарных строках кредита (тем же
  принципом, что и `solNote` :6725-6727), тултип — вид акта / номер меры /
  поглощение.

Явно ВНЕ этой карты:
- Апелляция как акт, ревизующий слой (не рождающий новый) — МП-2, наряд не цитирует
  явно, отдельная будущая карта.
- Смерть слоя / поворот исполнения при отмене — МП5-10, наряд п.5 область
  (фаза-максимум) не покрывает деньги; ни один из 7 пунктов наряда §30 её не
  цитирует — сознательно за периметром всей волны.
- Разбивка присуждённого по статьям — МП-9 (круг4). Пара с наряд п.3 (МП5-18,
  разбивка ТРЕБУЕМОГО, не присуждённого) — своя будущая карта, не эта.

## Notes

- Домен: `mockups/collection/collection.html`. Спека: `ASUBK-vzyskanie-logika.md`
  §8.5 (слой, круг4 МП-1…МП-9) + §30 (круг5 МП5-1/МП5-2, наряд п.2, :2233-2246).
- Эта карта переносит исполнение внутрь себя (override «plan, don't do») — тем же
  паттерном, что [карта приказной ветви](../collection-prikaznaya-vetv/map.md):
  тикет «Точки интеграции» решает вопросы один за другим (`/grilling`), тикет
  «Реализация» кодит правку `collection.html` напрямую.
  Основание: тот же паттерн только что сработал гладко на соседней карте — не
  нащупываю заново, что решать, а что кодить, переиспользую проверенное деление.
- Тесты: НЕ гонять `collection-check.mjs`/`collection-data-audit.mjs`/
  `collection-seed-coverage.mjs` целиком на этой волне — один прогон резервирован
  на конец всей пятой волны (7 пунктов наряда). Для тикета реализации достаточно,
  что страница открывается без console/pageerror (throwaway jsdom-смоук).
- SEED/затравка — вне этой карты (наряд п.6, отдельная волна).

## Decisions so far

- [Точки интеграции (01)](issues/01-tochki-integracii.md) — представитель не в
  целях меры → слой не рождается (без фолбэка) · «поглощает слой меры №X» —
  `<select>` из живых мер дела с `awards` по тому же кредиту · поле отношения
  видимо только когда у кредита уже есть более ранний слой · `layerOf` меряет
  «последняя» по дате исхода, не регистрации · сумма без потолка, пусто ≠ ноль ·
  аудит правки — существующий механизм `saveAnnotation`, отдельного не заводим.
- [Реализация (02)](issues/02-realizaciya.md) — `AWARD_KINDS` (3 вида) ·
  `layerOf(proc, creditId)` (представитель по `proc.requirements`, «последняя» по
  дате события — правка вопроса 4 задним числом, нашли прецедент `liveMilestones`
  при кодировании) · секция «Присуждено» в `openAnnotationModal`/`saveAnnotation` ·
  плитка «Слой» в `panelDebt`. Проверено throwaway jsdom-смоуком на синтетике и на
  реальном SEED. SEED слоя не заводился. **Destination карты достигнут — карта
  закрыта.**

## Out of scope

- Апелляция как ревизующий слой акт (МП-2) — наряд не цитирует её номером ни в
  одном из 7 пунктов; решение по объёму (grilling, вопрос 1) заранее исключило её
  из destination.
- Смерть слоя / поворот исполнения при отмене (МП5-10) — ни один из 7 пунктов
  наряда не цитирует МП5-10; вместе с МП5-8 (распределение выручки, три шага) —
  явный пробел в наряде, трактуемый как сознательная отсрочка денежных агрегатов
  за пределы всей пятой волны.
- Разбивка присуждённого по статьям (МП-9) — не попала в подтверждённый destination
  (вопрос 1, вариант «А»); естественно ляжет рядом с наряд п.3 (МП5-18) в будущей
  карте, не в этой.
